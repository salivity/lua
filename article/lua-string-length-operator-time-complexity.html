Lua String Length Operator Time Complexity

In the Lua programming language, retrieving the length of a native string using the length operator (#) or the string.len() function has a computational complexity of \(O(1)\) (constant time). Because Lua stores strings as internally managed objects that explicitly cache their byte counts, calculating length does not require iterating through the characters. This article explains how Lua's internal string representation guarantees constant-time length retrieval and how this differs from other data structures in the language.

Internal String Representation in Lua

In standard implementations of Lua (such as PUC-Rio Lua and LuaJIT), strings are not simple, null-terminated arrays of characters like those in C. Instead, every string is wrapped in a dedicated internal C structure—traditionally named TString.

The TString structure contains several metadata fields, including:

  • A hash value for table lookups
  • Garbage collector headers
  • An explicit integer field storing the string's length (len)
  • A pointer to the underlying byte buffer

When a string is constructed or interned, Lua calculates its length once and writes that value into the len field. Any subsequent access using the length operator (#s) simply performs a direct field read on this internal struct. Because this operation involves a single pointer dereference and memory read, the execution time remains constant regardless of whether the string contains ten characters or ten million characters.

Binary Safety and Null Characters

A critical reason for this design choice is binary safety. Unlike traditional C strings that terminate at the first null byte (\0), Lua strings are 8-bit clean and can contain arbitrary binary sequences, including embedded null characters. Because Lua cannot rely on a terminating sentinel value to determine where a string ends, tracking the explicit byte length in the string header is a structural requirement.

String Interning and Creation Cost

While reading the length with # is strictly \(O(1)\), the work of measuring the string occurs during string creation.

Lua uses string interning (particularly for short strings under 40 bytes in Lua 5.3+). When creating a string, Lua hashes the contents and verifies whether an identical string already exists in the global string table. The length calculation happens at this ingestion phase, meaning the computational cost of processing string length is paid entirely during allocation, leaving all subsequent lookups as zero-overhead operations.

Contrast with Lua Tables

It is worth distinguishing the string length operator from the table length operator. While both use the # token:

  • For strings, #s is always guaranteed to be \(O(1)\).
  • For tables, #t can take \(O(\log N)\) time if the table has sequence gaps or is not a clean array, as Lua performs a binary search to locate a border where a non-nil key is followed by a nil value.

For native strings in Lua, length lookups are consistently optimal, predictable, and run in constant time.
