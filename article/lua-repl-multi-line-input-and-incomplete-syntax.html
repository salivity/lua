Lua REPL Multi-Line Input and Incomplete Syntax

This article explains how the standalone Lua command-line Read-Eval-Print Loop (REPL) detects and processes multi-line code chunks and incomplete syntax. When a user enters code spanning multiple lines, such as control structures or multi-line strings, the REPL dynamically checks whether the input is incomplete or erroneous. By parsing syntax errors internally, switching terminal prompts, and accumulating input buffers, Lua creates a seamless interactive environment for evaluating complex expressions and blocks.

The Compilation Check Mechanism

When you submit a line of code in the standard Lua interpreter, the REPL attempts to compile the buffer in memory before executing it. Lua uses the internal C API function luaL_loadbuffer (or luaL_loadbufferx) to parse the string.

During this check:

  1. Lua first attempts to compile the input prefixed with return so expressions (such as 1 + 1 or table definitions) print their results directly.
  2. If prepending return causes a syntax error, Lua falls back to compiling the line exactly as typed.

Detecting Incomplete Syntax via the <eof> Marker

If compilation fails, Lua evaluates the resulting error message rather than immediately aborting or displaying an error. The compiler distinguishes between an unrecoverable syntax error and an incomplete statement by checking if the error occurs at the end of the file/input stream.

  • Incomplete Syntax: If the syntax error message ends with the <eof> token (indicating an unexpected end-of-file), the parser knows that the code is syntactically valid so far, but requires additional tokens to close the block. Examples include an open function, if statement without an end, unclosed parentheses (), unclosed braces {}, or multiline string literals ([[...]]).
  • Immediate Syntax Errors: If the error occurs anywhere before the end of the line (for example, typing end without an opening block, or malformed operators like 1 ++ 1), the error does not end in <eof>. The REPL immediately prints the syntax error, discards the current buffer, and returns to the base prompt.

Prompt Switching and Buffer Accumulation

When the REPL identifies an incomplete line:

  1. Prompt Change: The interpreter changes the default primary prompt (>, stored in the global variable _PROMPT) to the secondary prompt (>>, stored in _PROMPT2).
  2. Buffer Concatenation: The new line of text is appended to the existing input string with an intervening newline character (\n).
  3. Re-evaluation: The interpreter calls the compilation routine on the accumulated buffer. This loop continues, presenting the >> prompt on each new line, until the entire chunk compiles successfully or encounters a non-<eof> syntax error.
  4. Execution: Once the block is syntactically complete (such as after typing the final end), compilation succeeds, the secondary prompt disappears, and Lua executes the entire accumulated block at once.

Aborting Multi-Line Input

If you are stuck inside a secondary prompt due to an unclosed construct (such as a runaway quote or missing end), entering a deliberate syntax error or sending an interrupt signal (such as Ctrl+C on POSIX systems and Windows) forces Lua to cancel the compilation, clear the accumulated input buffer, and reset the prompt back to >.
