Single Inheritance via Metatables in Lua

This article explains how Lua uses tables, metatables, and the __index metamethod to implement prototype-based single inheritance. By chaining tables together through metatable delegation, Lua allows derived objects to dynamically inherit properties and methods from ancestor prototypes, effectively simulating a traditional single inheritance hierarchy without native class constructs.

In Lua, objects and classes are represented using tables. Because Lua lacks built-in class definitions, inheritance relies on prototype delegation. Delegation occurs when an object that cannot fulfill a read request passes that request to another table, designated as its prototype.

The mechanism that powers this behavior is the __index metamethod. When code attempts to access a key on a table and that key does not exist (evaluating to nil), Lua checks whether the table has an attached metatable containing an __index field. If __index points to another table, Lua repeats the lookup operation on that referenced table.

To build an inheritance chain, this delegation is applied recursively across multiple levels:

  1. The Base Prototype: A standard table containing shared functions and default properties. This table typically sets its own __index field to point to itself (Base.__index = Base).
  2. The Derived Prototype: A new table that acts as a subclass. Its metatable is set such that __index points to the Base prototype (setmetatable(Derived, { __index = Base })). The derived table also sets Derived.__index = Derived so that its own instances can delegate to it.
  3. The Instance: An individual object instantiated by setting its metatable to the derived class (setmetatable(instance, Derived)).

Consider the following concrete implementation:

-- Base Class
local Animal = {}
Animal.__index = Animal

function Animal:new(name)
    local instance = setmetatable({}, self)
    instance.name = name
    return instance
end

function Animal:speak()
    return self.name .. " makes a sound."
end

-- Derived Class
local Dog = {}
Dog.__index = Dog
setmetatable(Dog, { __index = Animal }) -- Dog inherits from Animal

function Dog:new(name, breed)
    local instance = Animal.new(self, name) -- Initialize base fields
    instance.breed = breed
    return instance
end

function Dog:bark()
    return self.name .. " barks!"
end

-- Instantiation
local myDog = Dog:new("Rex", "German Shepherd")

When a method call like myDog:speak() executes, Lua resolves the function through the following lookup chain:

  1. Lua inspects the myDog instance table for the key "speak". It does not exist there.
  2. Lua inspects myDog's metatable (Dog) via Dog.__index.
  3. Lua checks the Dog table for "speak". It does not exist there.
  4. Because Dog itself has a metatable pointing to Animal via its own __index, Lua delegates the search to Animal.
  5. Lua finds "speak" in Animal and executes the function, passing myDog as the self parameter.

If a derived table defines a method with the same name as an ancestor, such as overriding speak inside Dog, Lua resolves the key immediately at the Dog level and stops searching. This provides standard method overriding.

Because each link in the chain only references a single parent table via its metatable's __index, Lua enforces a strict single-inheritance path. If the lookup reaches the root table and the key is still missing, the expression resolves to nil.
