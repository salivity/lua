Closure vs Metatable Objects in Lua

In the Lua programming language, object-oriented programming is achieved through conventions rather than built-in class constructs, with the two dominant paradigms being closure-based objects and metatable-based objects. Closure-based objects use function factory scopes to achieve encapsulation and provide strict privacy for internal states, but they incur higher memory costs. Metatable-based objects rely on prototypes and Lua's __index metamethod to share method definitions among multiple instances, offering superior memory efficiency at the expense of data privacy. This article examines the mechanics, performance trade-offs, and practical implementations of both approaches.

The Closure-Based Approach

The closure-based approach relies on Lua's lexical scoping. A constructor function creates local variables to hold an object's state and returns a table containing methods that capture these variables as upvalues.

local function createAccount(initialBalance)
    local balance = initialBalance -- Private variable

    local self = {}

    function self.deposit(amount)
        balance = balance + amount
    end

    function self.withdraw(amount)
        if amount <= balance then
            balance = balance - amount
            return true
        end
        return false
    end

    function self.getBalance()
        return balance
    end

    return self
end

local acc = createAccount(100)
acc.deposit(50)
print(acc.getBalance()) -- 150

Advantages

  • Strict Privacy: Local variables are inaccessible from the outside scope, providing true encapsulation without external access to internal state.
  • Simpler Call Syntax: Methods do not rely on passing a self reference, meaning callers can use dot syntax (acc.deposit()) instead of colon syntax (acc:deposit()).
  • Safe Callbacks: Methods can be passed directly as first-class callback functions without losing their reference to the instance.

Disadvantages

  • High Memory Overhead: Every instance creates and stores its own distinct copies of each method closure, significantly increasing memory usage when generating many instances.
  • Inheritance Complexity: Implementing traditional object inheritance requires manual delegation or table cloning, which can become unwieldy.

The Metatable-Based Approach

The metatable-based approach is the idiomatic way to implement object orientation in Lua. It relies on a shared prototype table and the __index metamethod, which redirects method lookups when a key is not found directly on an instance.

local Account = {}
Account.__index = Account

function Account.new(initialBalance)
    local self = setmetatable({}, Account)
    self.balance = initialBalance -- Public property
    return self
end

function Account:deposit(amount)
    self.balance = self.balance + amount
end

function Account:withdraw(amount)
    if amount <= self.balance then
        self.balance = self.balance - amount
        return true
    end
    return false
end

function Account:getBalance()
    return self.balance
end

local acc = Account.new(100)
acc:deposit(50)
print(acc:getBalance()) -- 150

Advantages

  • Memory Efficiency: All instances share a single copy of the methods stored in the prototype table, resulting in a minimal memory footprint per object.
  • Fast Instantiation: Creating an object requires only allocating a small table and setting its metatable, which is faster than creating multiple closures.
  • Straightforward Inheritance: Establishing class hierarchies is natural by setting one class table's metatable to another.

Disadvantages

  • No Built-in Privacy: All fields in the instance table are public. Privacy must be simulated using naming conventions (such as self._balance) or external weak tables.
  • Colon Syntax Requirement: Callers must remember to use colon notation (object:method()) to pass self implicitly; using dot notation accidentally can lead to runtime errors.

Key Differences and Comparison

Feature Closure-Based Metatable-Based
Encapsulation Complete (lexical scope) Convention-only (all fields public)
Memory Usage High (new closures per instance) Low (methods shared via prototype)
Creation Cost Higher (allocates multiple functions) Lower (allocates single empty table)
Method Invocation Dot syntax (obj.method()) Colon syntax (obj:method())
Idiom in Lua Less common Standard pattern

Choosing the Right Pattern

Use the closure-based approach when creating a small number of long-lived objects (such as singletons, module services, or state machines) where strict security, API simplicity, or callback safety takes precedence over memory constraints.

Use the metatable-based approach for mass-instantiated objects (such as game entities, data structures, or GUI widgets) where memory footprint and instantiation speed are critical to performance.
