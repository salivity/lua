Invalidate Method Lookup Cache in Lua Metatables

In Lua, caching method lookups—either by copying resolved functions directly into child tables or memoizing __index resolutions—is a standard technique to bypass costly prototype chain traversals. However, when a metatable is mutated dynamically at runtime, these cached methods become stale, leading to logic bugs or missed updates. This article covers the primary mechanisms used to reliably invalidate and refresh cached method lookups when metatables change at runtime, including metametatable hooks, version counter validation, and deep cache traversal.

The Challenge of Cached Method Lookups

A typical Lua class hierarchy resolves methods via the __index metamethod. When looking up object:method(), Lua repeatedly queries metatables up the chain until it finds the function. To optimize performance, developers often "flatten" inheritance by copying functions from the base class directly into derived metatables, or they memoize lookups inside an internal cache table.

When a metatable receives a new function or overrides an existing one at runtime, any downstream tables that have already cached that method will not see the change unless an invalidation routine is executed.

Method 1: Intercepting Changes with Metametables

The most robust way to trigger cache invalidation automatically is to place a metatable on the metatable itself (a metametatable). This allows you to catch modifications using __newindex.

local function make_trackable_class(class_table)
    local metametatable = {
        __newindex = function(t, key, value)
            rawset(t, key, value)
            -- Trigger cache invalidation whenever a method is added or altered
            if t.__invalidate_cache then
                t:__invalidate_cache(key)
            end
        end
    }
    return setmetatable(class_table, metametatable)
end

By intercepting mutations through __newindex, the class can immediately broadcast the update to instances, child classes, or an internal memoization table.

Method 2: Epoch / Version-Based Validation

Instead of actively hunting down and purging every cached reference, you can use an integer-based generation or epoch counter. This approach is common in high-performance engines because it avoids recursive traversals on modification.

  1. Assign a Version: Give the base metatable a numeric version field (e.g., version = 1).
  2. Tag Cached Entries: When an instance or sub-class caches a lookup, record the version alongside the cached value.
  3. Validate on Lookup: In the caching accessor, verify that the cached version matches the metatable's current version before returning the cached method.
  4. Invalidate: To invalidate the entire cache, simply increment metatable.version = metatable.version + 1.
local Class = { version = 1 }
Class.__index = Class

function Class:update_method(name, fn)
    self[name] = fn
    self.version = self.version + 1 -- Invalidates all existing cached reads
end

function get_cached_method(instance, key)
    local cache = rawget(instance, "_cache")
    local cls = getmetatable(instance)

    if cache and cache[key] and cache[key].version == cls.version then
        return cache[key].fn
    end

    -- Cache miss or invalidated: re-resolve and update
    local fn = cls[key]
    if fn then
        if not cache then
            cache = {}
            rawset(instance, "_cache", cache)
        end
        cache[key] = { fn = fn, version = cls.version }
    end
    return fn
end

Method 3: Recursive Child and Instance Flushing

If your architecture copies resolved methods directly into child classes via rawset to maximize lookup speed, updating a base class requires an explicit tree traversal:

  1. Track Inheritors: Maintain a registry of derived classes using weak tables (__mode = "k" or "v") so that subclasses can still be garbage collected.
  2. Propagate Modifications: When a method changes on a parent, recursively traverse the registry and update or nil out the corresponding key in every descendant.
local function propagate_invalidation(parent_class, key, new_fn)
    if not parent_class.__subclasses then return end

    for subclass in pairs(parent_class.__subclasses) do
        -- Only overwrite if the subclass has not explicitly defined its own override
        if rawget(subclass, key) == nil or subclass.__is_cached_entry then
            rawset(subclass, key, new_fn)
            propagate_invalidation(subclass, key, new_fn)
        end
    end
end

LuaJIT Considerations

If using LuaJIT, the trace compiler automatically observes changes to standard metatables. When a trace is compiled with an assumed metatable layout, modifying that metatable via setmetatable or setting metamethod fields directly causes LuaJIT to invalidate the compiled machine code (trace flushes or guard failures).

However, if you implement a custom, user-space method caching table (such as a flat dispatch table), LuaJIT cannot infer the relationship between your cache and the metatable. In that scenario, manual invalidation using metametatable hooks or version tracking remains strictly necessary.
