Handling Floating-Point Precision in Lua

Floating-point precision limits in Lua stem from its reliance on standard IEEE 754 double-precision representations, which can introduce rounding errors during everyday arithmetic. This article explores the root causes of these inaccuracies and provides direct, practical strategies to handle them, including epsilon comparisons, integer arithmetic, explicit rounding techniques, and external arbitrary-precision libraries.

Understanding the Floating-Point Limitation

By default, Lua represents floating-point numbers using 64-bit IEEE 754 doubles. Because binary systems cannot precisely represent certain decimal fractions—such as 0.1 or 0.2—operations like 0.1 + 0.2 yield 0.30000000000000004 rather than 0.3. Directly comparing these results with equality operators (==) leads to unexpected logical failures in code execution.

Tolerant Comparison Using Epsilon

The standard method for comparing two floating-point numbers in Lua is to verify whether the absolute difference between them falls within a tiny, acceptable threshold known as epsilon:

local function nearly_equal(a, b, epsilon)
    epsilon = epsilon or 1e-9
    return math.abs(a - b) < epsilon
end

local result = 0.1 + 0.2
print(result == 0.3)              -- false
print(nearly_equal(result, 0.3))   -- true

Using an absolute difference works well for numbers close to zero. For values spanning vastly different magnitudes, consider a relative epsilon comparison that scales with the magnitude of the inputs:

local function relative_equal(a, b, epsilon)
    epsilon = epsilon or 1e-9
    local diff = math.abs(a - b)
    local largest = math.max(math.abs(a), math.abs(b))
    return diff <= largest * epsilon
end

Leveraging Native Integers (Lua 5.3+)

Lua 5.3 introduced a distinct 64-bit integer subtype alongside floats. Integers avoid binary fraction rounding issues entirely. When working with domain values like currency, store numbers as their smallest discrete units (e.g., cents instead of dollars):

-- Representing $19.99 and $0.01 as integer cents
local price = 1999
local fee = 1
local total = price + fee -- 2000 cents ($20.00)

To maintain integer types during arithmetic, use integer division (//) instead of standard division (/), as standard division converts results to floating-point numbers.

Rounding and Formatting for Output

When fractional calculations must be displayed or normalized, formatting functions can truncate noise introduced by precision limits:

-- Rounding via string formatting
local val = 0.1 + 0.2
local formatted = tonumber(string.format("%.2f", val)) -- 0.3

-- Mathematical rounding to N decimal places
local function round(num, decimals)
    local mult = 10^(decimals or 0)
    return math.floor(num * mult + 0.5) / mult
end

print(round(0.1 + 0.2, 2)) -- 0.3

Using Arbitrary-Precision Libraries

When applications require exact accuracy beyond standard 64-bit limits (such as cryptography, scientific calculations, or strict accounting systems), built-in types are insufficient. In these scenarios, integrate arbitrary-precision libraries:

  • lbc: A Lua binding to the GNU BC library, supporting arbitrary-precision decimal arithmetic.
  • Lua-DecNumber: A binding to IBM’s decNumber library, implementing General Decimal Arithmetic.
  • Pure Lua BigNum modules: Self-contained Lua modules that store numbers as arrays of digits or smaller integer chunks, trading execution speed for arbitrary precision without external C dependencies.
