How Lua OP_CLOSURE Instantiates Closures

In the Lua virtual machine, the OP_CLOSURE instruction is responsible for converting a compile-time function prototype (Proto) into a runtime closure object (LClosure). This article explains the technical mechanics of that process, detailing how the VM allocates memory for the new closure, reads upvalue metadata, and resolves external references from either the current execution stack or existing parent upvalues.

Function Prototypes vs. Runtime Closures

During compilation, Lua translates source code into bytecode and generates a static Proto structure for every function definition. A Proto contains immutable metadata, including bytecode instructions, constants, debug information, and definitions of expected upvalues. However, a Proto cannot be executed directly in an environment where state varies dynamically.

A closure (LClosure) is the dynamic instance of a Proto. It pairs the static bytecode with a specific execution context by binding concrete runtime variables, known as upvalues, to the prototype.

The OP_CLOSURE Instruction Format

The OP_CLOSURE instruction typically utilizes two primary operands:

  • A: The destination register index where the instantiated LClosure pointer will be stored.
  • Bx: An unsigned index into the enclosing function prototype's sub-prototype table (p->p[]).

When the interpreter encounters OP_CLOSURE A Bx, it accesses the child prototype defined at index Bx within the currently executing prototype.

Allocation of the Closure

The instantiation begins by allocating a new LClosure object on the Lua garbage-collected heap, usually via the internal function luaF_newLclosure.

During this step:

  1. Memory is allocated to hold the LClosure header, a reference pointer to the target Proto, and an array of pointers to UpVal objects sized to p->sizeupvalues.
  2. The newly created object's reference counter and garbage collection header are initialized.
  3. The closure's p field is assigned to the Proto located at cl->p->p[Bx].

Upvalue Resolution and Binding

The most critical step in executing OP_CLOSURE is resolving the closure's upvalues. In modern Lua versions (such as Lua 5.3 and 5.4), the Proto contains an array of Upvaldesc structures that dictate where each upvalue originates.

The VM iterates through each upvalue descriptor defined in the prototype:

  1. Capturing Local Stack Variables (instack == 1): If the descriptor indicates that the variable resides in the current function's local stack, the VM calls luaF_findupval. This function checks the execution thread's list of open upvalues. If an open UpVal already points to the specific stack slot (register), that existing UpVal is reused and its reference count is incremented. If none exists, a new UpVal is allocated, set to point to the stack address, and inserted into the open upvalues list.

  2. Inheriting Outer Upvalues (instack == 0): If the variable is not in the immediate local stack, it is an upvalue belonging to the parent function. The descriptor specifies an index into the parent closure’s own upvalue list (cl->upvals[idx]). The VM copies the pointer from the parent closure's upvalue array to the new child closure's upvalue array, incrementing its reference count.

Register Assignment

Once all upvalues are resolved and bound to the new LClosure instance, the VM places the resulting closure reference into register R(A) of the current stack frame. The program counter advances to the next instruction, completing the instantiation. The newly formed closure is now fully prepared for execution or assignment to a local or global variable.
