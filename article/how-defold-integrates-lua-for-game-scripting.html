How Defold Integrates Lua for Game Scripting

The Defold game engine uses Lua as its primary gameplay scripting language, pairing an embedded, high-performance Lua runtime with a lightweight C++ core. By employing standard Lua 5.1 and LuaJIT, Defold enables developers to write game logic, manage user input, control user interfaces, and handle rendering pipelines through lightweight text scripts. These scripts integrate natively with the engine's component-based hierarchy and asynchronous message-passing system, ensuring clean separation of logic without sacrificing runtime execution speed.

Embedded Runtime and Performance

Defold integrates Lua by embedding either standard Lua 5.1 or LuaJIT (Just-In-Time compiler), depending on the target platform architecture. Because the underlying engine core is written in highly optimized C and C++, the engine acts as the host environment, while Lua acts as the controller. Performance-intensive tasks—such as 2D sprite batching, 3D mesh rendering, physics simulation (via Box2D or 3D physics engines), and audio decoding—execute natively in C++. Lua scripts direct these systems through high-level engine APIs, minimizing garbage collection spikes and CPU overhead.

Script Component Types

Defold organizes game elements into Game Objects and Collections. Lua logic interacts with these elements through dedicated script components:

  • Logic Scripts (.script): Attached directly to Game Objects to control entity behaviors, state machines, and interactions.
  • GUI Scripts (.gui_script): Attached to GUI components to manage menus, HUD elements, layouts, and pointer events.
  • Render Scripts (.render_script): Control the engine's render loop, camera projections, frame buffers, and draw passes.

Lifecycle Callback System

When an engine event occurs, Defold invokes predefined lifecycle functions within the corresponding Lua script. Rather than running an unrestricted while-loop in Lua, the engine dispatches hooks at specific moments in the frame loop:

  • init(self): Called when the component is instantiated and ready for setup.
  • update(self, dt): Executed once every frame, passing the delta time (dt) for variable-rate logic.
  • fixed_update(self, dt): Executed at a constant time step for deterministic logic such as custom physics updates.
  • on_message(self, message_id, message, sender): Triggered whenever the component receives a message from another entity or the engine.
  • on_input(self, action_id, action): Receives forwarded input actions (keyboard, mouse, touch, or gamepad).
  • final(self): Executes when the component is removed or the scene is destroyed, allowing for cleanup.

The self parameter in these functions is a local table unique to each script instance, used to store instance-specific state across frames without polluting the global Lua scope.

The Message-Passing Paradigm

A core design principle of Defold’s Lua integration is asynchronous message passing. Game objects do not expose direct memory references or object instances to one another in Lua. Instead, communication occurs via the msg.post() API.

Scripts send structured key-value payloads to specific URL addresses representing target components:

msg.post("hero#controller", "take_damage", { amount = 25 })

The recipient processes the payload inside its on_message callback. This design decouples game systems, avoids complex inheritance trees, and prevents memory corruption or race conditions across different game objects.

Engine API and Native Extensions

Defold exposes its internal C++ modules directly to Lua through global namespaces:

  • go: Game object manipulation (position, rotation, scaling, spawning, deletion).
  • msg: URL handling and message dispatching.
  • vmath: Vector, matrix, and quaternion math calculations executed in compiled C++.
  • gui: Manipulation of GUI nodes, textures, and UI text.
  • sys: Low-level operating system calls, file I/O, application state, and engine diagnostics.

For features outside the standard engine distribution, Defold allows developers to write Native Extensions using C, C++, Objective-C, or Java. These native extensions register new custom C functions into Lua's environment table, allowing Lua scripts to interact directly with third-party software development kits (SDKs), hardware interfaces, and platform-specific platform libraries.
