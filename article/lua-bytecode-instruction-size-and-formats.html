Lua Bytecode Instruction Size and Formats

In modern releases of the Lua programming language, every compiled bytecode instruction occupies a fixed size of exactly 32 bits (4 bytes). This uniform instruction length has been a defining architectural feature of standard Lua since the release of Lua 5.0, continuing through modern versions such as Lua 5.3 and Lua 5.4. This article examines the exact structure, bitwise allocations, and internal layouts that comprise this 32-bit format across contemporary Lua virtual machines.

The 32-Bit Fixed-Length Architecture

Standard Lua uses a register-based virtual machine. Inside the Lua core engine (written in ANSI/ISO C), the bytecode instruction is defined via the Instruction type, typically aliasing a standard 32-bit unsigned integer (uint32_t).

Unlike stack-based runtimes or architectures with variable-length instructions, Lua's strict 4-byte instruction width offers clear computational advantages:

  • Direct Indexing: The virtual machine can traverse code using simple array pointer arithmetic (ci->u.l.savedpc++).
  • Predictable Memory Footprint: The size of a compiled code block scales deterministically with the instruction count.
  • Efficient Decoding: The virtual machine decodes opcodes and operands using simple bitmasking and bit-shifting operations without sequential parsing overhead.

Internal Instruction Formats

While every instruction is exactly 32 bits wide, the internal allocation of those 32 bits depends on the specific instruction mode. Modern Lua splits these bits into an opcode and varying operand fields.

In Lua 5.4, the instruction formats are divided into five main categories:

  1. iABC Mode:
    • Opcode: 7 bits
    • Field A: 8 bits (usually representing a target register)
    • Field B: 8 bits (register or small constant/immediate)
    • Field C: 8 bits (register or small constant/immediate)
    • Field k: 1 bit (flag indicating whether operand B/C represents a register or constant)
    • Total: 7 + 8 + 1 + 8 + 8 = 32 bits.
  2. iABx Mode:
    • Opcode: 7 bits
    • Field A: 8 bits
    • Field Bx: 17 bits (unsigned value, commonly an index into the constants table)
    • Total: 7 + 8 + 17 = 32 bits.
  3. iAsBx Mode:
    • Opcode: 7 bits
    • Field A: 8 bits
    • Field sBx: 17 bits (signed value using excess-K / bias representation, often used for conditional relative jumps)
    • Total: 7 + 8 + 17 = 32 bits.
  4. iAx Mode:
    • Opcode: 7 bits
    • Field Ax: 25 bits (extra-large single operand used when an instruction requires an index exceeding 17 bits, often following an instruction as an extension)
    • Total: 7 + 25 = 32 bits.
  5. isJ Mode (Introduced in Lua 5.4):
    • Opcode: 7 bits
    • Field sJ: 25 bits (signed jump offset, allowing direct jumps across up to 33,554,432 instructions without multi-instruction encodings)
    • Total: 7 + 25 = 32 bits.

Differences Between Lua 5.1–5.3 and Lua 5.4

The 32-bit length remains constant across all modern releases, but the distribution of bits evolved between Lua 5.3 and Lua 5.4:

  • Lua 5.1 through 5.3: Allocated 6 bits for the opcode, 8 bits for field A, 9 bits for field B, and 9 bits for field C (or 18 bits for the combined Bx/sBx fields).
  • Lua 5.4: Increased the opcode space to 7 bits to accommodate a larger suite of specialized instructions. To maintain the 32-bit boundary, Lua 5.4 reduced standard B and C register operands to 8 bits each and introduced the 1-bit k field and the dedicated 25-bit sJ jump format.

Regardless of these internal bit-level reorganizations, modern versions of standard Lua continue to rely strictly on an invariant 32-bit (4-byte) instruction format.
