Lua __newindex Metamethod Guide

In the Lua programming language, the __newindex metamethod provides a powerful mechanism for intercepting, modifying, and restricting write operations on tables. This article explains how the __newindex metamethod functions, the specific conditions required to trigger it, how to handle assignments using both functions and tables, and how to use rawset to prevent unintended infinite recursion.

How __newindex Triggers

The __newindex metamethod is not invoked on every assignment. Lua triggers __newindex only when a script attempts to assign a value to a table key that does not currently exist (i.e., its current value is nil). If the specified key is already present in the table with a non-nil value, Lua performs a standard assignment, completely bypassing the metamethod.

To attach this behavior to a table, define a metatable containing the __newindex field and assign it using setmetatable.

Handling Writes with a Function

When __newindex is assigned a function, Lua executes that function whenever an assignment to an absent key occurs. The function automatically receives three arguments: the target table, the key being assigned, and the value being written.

local mt = {}
local target = {}
setmetatable(target, mt)

mt.__newindex = function(tbl, key, value)
    print(string.format("Attempting to set key '%s' to '%s'", tostring(key), tostring(value)))
    rawset(tbl, key, value)
end

target.name = "Alice" -- Triggers __newindex
target.name = "Bob"   -- Does NOT trigger __newindex (key already exists)

When you write tbl[key] = value inside the __newindex function, it triggers __newindex again, leading to a stack overflow due to infinite recursion. To actually store the key-value pair in the table without re-invoking the metamethod, you must use the built-in rawset(tbl, key, value) function.

Handling Writes with a Table

The __newindex metamethod can also be defined as another table rather than a function. When set to a table, any write to an absent key in the original table is automatically redirected to the alternate table.

local backup = {}
local original = {}
setmetatable(original, { __newindex = backup })

original.score = 100

print(original.score) -- Output: nil
print(backup.score)   -- Output: 100

If the secondary table also lacks the key and has its own metatable with a __newindex metamethod, Lua will chain the assignment through that metatable as well.

Common Use Cases

  • Read-Only Tables: You can create immutable tables by defining a __newindex function that raises an error whenever an assignment is attempted:

    mt.__newindex = function(tbl, key, value)
    error("Attempt to modify read-only table", 2)
end

  • Data Validation and Type Checking: Assignments can be verified before being applied. The metamethod can check if a value matches an expected type or range before saving it via rawset.

  • Change Tracking and Proxies: By keeping the main table completely empty and storing values in a private internal storage table, __newindex will fire on every write operation, allowing complete observation of table updates.
