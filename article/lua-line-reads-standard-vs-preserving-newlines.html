Lua Line Reads: Standard vs Preserving Newlines

Reading input line-by-line in the Lua programming language can be accomplished using either standard line reads or line reads that preserve newline characters. In modern Lua (versions 5.3 and newer), these two approaches are controlled using the "l" and "L" format specifiers in functions like io.read() and file:read(). Understanding the functional differences between stripping and retaining newline characters is critical for text parsing, data serialization, and accurate file reproduction.

The Format Specifiers: "l" vs "L"

When reading lines from a file descriptor or standard input, Lua provides two format options:

  • Standard Line Read ("l" or "*l"): Reads the next line from the stream and discards the end-of-line delimiter (\n or \r\n). The resulting Lua string contains only the textual content of the line.
  • Newline-Preserving Read ("L" or "*L"): Reads the next line from the stream and appends the end-of-line delimiter to the end of the returned string.
local file = io.open("example.txt", "r")

-- Standard read (strips newline)
local clean_line = file:read("l")

-- Preserved read (includes newline)
local raw_line = file:read("L")

file:close()

Core Differences

1. Line Ending Retention and Cross-Platform Handling

Standard line reading automatically strips whatever newline format the host platform or stream uses (such as LF on Unix-like systems or CRLF on Windows).

Newline-preserving reads keep the exact byte sequence that terminated the line in the source stream. This makes "L" essential when working with binary-sensitive text streams or protocols where distinguishing between \r\n and \n is required.

2. File Reproduction and Streaming

When copying, filtering, or proxying text files line-by-line, standard reads ("l") require you to manually append newlines when writing output (e.g., output:write(line, "\n")). This introduces two problems:

  • It can inadvertently convert the file's original line endings to a different format.
  • It may add a newline to the final line of a file where one did not originally exist.

Using newline-preserving reads ("L") allows you to pipe input directly to output with output:write(line). The output file will match the original input file byte-for-byte.

3. Handling the Final Line (EOF Behavior)

Both methods return nil when attempting to read past the end of the file. However, they behave differently on the final line of a file if that line lacks a terminating newline:

  • With "l", there is no way to determine whether the final line had a trailing newline or ended abruptly at EOF, because the delimiter is discarded in either case.
  • With "L", you can inspect the end of the returned string (e.g., using string.sub(line, -1) == "\n"). If the final line does not contain a trailing newline character, you know the file ended without a newline delimiter.

4. Parsing and Pattern Matching

For general text parsing—such as reading configuration files, processing comma-separated values, or checking string commands—standard reads ("l") are typically preferred. They eliminate the need to run extra string-trimming operations to remove \r and \n before applying pattern matching or equality checks.
