Force Reload a Lua Module at Runtime

Reloading a module at runtime in Lua requires clearing the module from the internal cache table before calling require again. When a module is imported using require, Lua loads the file from disk, executes it, and stores the resulting value in the package.loaded table to avoid redundant disk reads and executions. By explicitly clearing or replacing a module's key in package.loaded, you can force Lua to fetch and re-execute the module file directly from the filesystem during execution.

The Basic Reload Technique

To force a reload, set the module's entry in package.loaded to nil and call require:

-- Invalidate the cached version
package.loaded["my_module"] = nil

-- Load and execute the module fresh from disk
local my_module = require("my_module")

Implementing a Generic Reload Function

A common approach for live-reloading during development is to wrap this behavior in a utility function:

function reload(module_name)
    package.loaded[module_name] = nil
    return require(module_name)
end

-- Usage
local config = reload("config")

Handling Existing References

Simply removing the module from package.loaded does not update existing variables that hold references to the old module table. If another script has already executed local m = require("my_module"), that variable m will still point to the original table in memory.

To update module contents without breaking existing references, you can overwrite the keys of the existing table in place:

function reload_in_place(module_name)
    local old_module = package.loaded[module_name]
    package.loaded[module_name] = nil

    local success, new_module = pcall(require, module_name)

    if not success then
        -- Restore the old module if the reload fails
        package.loaded[module_name] = old_module
        error("Failed to reload module: " .. tostring(new_module))
    end

    -- If the module returns a table, update the existing table's keys
    if type(old_module) == "table" and type(new_module) == "table" then
        -- Clear old keys
        for k in pairs(old_module) do
            old_module[k] = nil
        end
        -- Copy new keys into the original table
        for k, v in pairs(new_module) do
            old_module[k] = v
        end
        package.loaded[module_name] = old_module
        return old_module
    end

    return new_module
end

Important Considerations

  • Side Effects: If the module registers callbacks, modifies global variables, or opens system resources (like sockets or file handles), reloading the file will execute those actions again, which may lead to resource leaks or duplicate event handlers.
  • C Libraries: Modules loaded from compiled shared libraries (.so or .dll) generally cannot be fully unloaded or reloaded from disk at runtime purely through package.loaded, as the host process typically keeps the dynamic library linked in memory.
