lua_tointeger vs lua_tointegerx in Lua C API

In the Lua C API, both lua_tointeger and lua_tointegerx convert a value at a given stack index into a C integer (lua_Integer). The primary difference between them lies in error detection: lua_tointegerx provides a mechanism to verify whether the conversion was actually successful, whereas lua_tointeger simply returns 0 when a conversion fails, creating ambiguity if the valid value on the stack was also 0.

Function Signatures

Understanding the difference starts with their function signatures in the C API:

lua_Integer lua_tointeger  (lua_State *L, int idx);
lua_Integer lua_tointegerx (lua_State *L, int idx, int *isnum);

lua_tointegerx takes an additional parameter: a pointer to an integer (int *isnum).

The Ambiguity of lua_tointeger

When you call lua_tointeger, Lua attempts to convert the value at idx to an integer. If the value is a number or a string that can be coerced to an integer, it returns that integer value. If the value cannot be converted (for instance, if it is a table, nil, a boolean, or an incompatible string), lua_tointeger returns 0.

This creates a silent failure issue:

lua_pushstring(L, "invalid");
lua_Integer val1 = lua_tointeger(L, -1); // Returns 0

lua_pushinteger(L, 0);
lua_Integer val2 = lua_tointeger(L, -1); // Returns 0

In the example above, both calls return 0. You cannot determine whether the Lua stack contained the integer 0 or an invalid value without executing separate type-checking functions like lua_isinteger or lua_type.

How lua_tointegerx Resolves the Problem

Introduced in Lua 5.2, lua_tointegerx uses the isnum pointer to communicate the status of the operation:

  • If the conversion succeeds, *isnum is set to 1 (true).
  • If the conversion fails, *isnum is set to 0 (false), and the function returns 0.
  • If you pass NULL as the isnum argument, it behaves identically to lua_tointeger.

Example usage:

int success;
lua_Integer val = lua_tointegerx(L, -1, &success);

if (!success) {
    // Handle error: value is not an integer or convertible to one
} else {
    // Safe to use 'val', even if it is 0
}

The Relationship Between the Two

In modern Lua versions (Lua 5.2, 5.3, and 5.4), lua_tointeger is no longer an independent core function. Instead, it is defined as a macro in lua.h that wraps lua_tointegerx:

#define lua_tointeger(L,i) lua_tointegerx(L,(i),NULL)

Which One Should You Use?

  • Use lua_tointegerx whenever strict input validation is required, especially when building robust C modules where 0 is a valid input state and invalid types should trigger an error.
  • Use lua_tointeger when brevity is preferred and you have already validated the stack item's type beforehand (such as via luaL_checkinteger), or when failing silently to 0 is acceptable for your application's logic.
