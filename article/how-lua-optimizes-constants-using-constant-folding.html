How Lua Optimizes Constants Using Constant Folding

Constant folding in Lua is a compiler-level optimization technique where expressions composed strictly of literal constants are evaluated at compile time rather than at runtime. By computing the result of these static operations during the parsing phase, the Lua compiler eliminates unnecessary bytecode instructions, reduces register allocations, and delivers faster script execution. This article examines how the Lua compiler identifies constant operands, performs evaluation within its code generator, handles edge cases, and saves runtime computing cycles.

The Single-Pass Compiler and expdesc

Unlike compilers that construct complex Abstract Syntax Trees (ASTs) before performing multiple optimization passes, the standard PUC-Rio Lua compiler operates in a single pass. It parses the source code and immediately emits register-based bytecode.

To facilitate optimizations on the fly, Lua utilizes an internal data structure called expdesc (expression descriptor) defined in lparser.h. During parsing, every sub-expression is assigned an expdesc type indicating its current nature:

  • VKINT: An integer constant.
  • VKFLT: A floating-point constant.
  • VTRUE / VFALSE: Boolean literals.
  • VNIL: A nil literal.
  • VNONRELOC, VRELOC: Dynamic expressions bound to registers or awaiting relocation.

When an operation (such as addition or logical negation) is parsed, the compiler checks the descriptors of the involved operands. If all operands are marked as constant types, the compiler diverts from generating bytecode instructions and instead executes the operation directly in C using the code generator (lcode.c).

The Folding Process in lcode.c

The primary engine for constant folding resides in lcode.c, predominantly within the function constfolding().

When the parser processes a binary or unary expression via luaK_infix() and luaK_posfix():

  1. Validation: The compiler queries tonumeral() to verify whether the operand descriptors resolve to numbers (either integers or floats).
  2. Evaluation: If both sides of a binary operator are numeric literals, the compiler invokes the underlying C function responsible for that specific operator (e.g., luaO_arith()).
  3. Descriptor Mutation: The intermediate bytecode instruction (e.g., OP_ADD) is suppressed. The expression descriptor representing the operation is mutated into a single VKINT or VKFLT containing the computed result.

For example, when compiling the statement:

local timeout = 60 * 60 * 24

Instead of emitting multiple multiplication instructions (OP_MUL), the parser:

  1. Multiplies 60 by 60 to get 3600.
  2. Multiplies 3600 by 24 to get 86400.
  3. Emits a single OP_LOADK or OP_LOADI instruction that loads 86400 directly into the local variable's register.

Supported Operations

Lua's constant folding applies to a specific set of operations:

  • Arithmetic Operators: Addition (+), subtraction (-), multiplication (*), division (/), floor division (//), modulo (%), and exponentiation (^).
  • Bitwise Operators (Lua 5.3+): Bitwise AND (&), OR (|), XOR (~), shifts (<<, >>), and bitwise NOT (~).
  • Unary Operators: Unary minus (-) directly inverts the sign of numeric descriptors, while not transforms VFALSE and VNIL into VTRUE, and any other compile-time constant into VFALSE.

Edge Cases and Safe Execution

Because constant folding runs natively inside the compiler host, the compiler must prevent runtime-specific errors from disrupting compilation:

  • Division by Zero: If an integer division or modulo by zero is detected (x // 0 or x % 0), the compiler does not fold the expression. It leaves the operation intact so that Lua can throw the standard runtime error when executed. Float division by zero (x / 0.0), however, safely resolves to positive or negative infinity (inf or -inf) as defined by the IEEE 754 standard.
  • Float and Integer Discrepancies: Lua preserves integer subtypes where possible. If an operation between two integers produces a valid integer without overflow, the result is folded as VKINT. If precision demands a float (such as standard division /), it folds as VKFLT.
  • String Concatenation: Unlike arithmetic, literal string concatenation ("a" .. "b") is historically treated differently. Standard Lua relies on its string buffer mechanisms and table/interning logic, generally handling string folding through specific parser logic or deferring it to runtime concatenation routines to maintain compiler simplicity.
  • Bypassing Metamethods: Metamethods (such as __add) cannot be attached to raw, uninstantiated literals during compilation. Therefore, constant folding safely assumes standard primitive semantics, avoiding any unexpected behavior associated with metatables.

Bytecode and Performance Impact

Constant folding yields two primary benefits:

  1. Reduced Instruction Count: Operations that would typically consume multiple execution cycles are resolved entirely before bytecode emission.
  2. Register and Constant Table Efficiency: Fewer intermediate registers are needed to evaluate complex formulas, and intermediate constants are not stored in the function prototype's constant table (k), keeping memory footprints smaller.
