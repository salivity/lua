Coroutine Running States in Nested Lua Coroutines

This article explains how the Lua programming language manages coroutine states during nested execution, specifically examining what coroutine.running returns and the respective status of each coroutine in the call hierarchy. You will learn the exact distinction between the running and normal states when one coroutine resumes another, and how Lua identifies the currently executing thread.

The Role of coroutine.running

In Lua, coroutine.running() returns the handle of the currently executing coroutine, along with a boolean indicating whether the returned coroutine is the main thread (in Lua 5.2 and later).

When you invoke coroutine.running() inside a nested coroutine—meaning a coroutine that was resumed by another coroutine—it always returns the innermost, currently executing coroutine. It does not return the parent or caller coroutine.

Coroutine States in Lua

A Lua coroutine exists in one of four states at any given moment, observable via coroutine.status():

  • running: The coroutine is actively executing instructions.
  • normal: The coroutine has resumed another coroutine and is waiting for that child coroutine to yield or return.
  • suspended: The coroutine is yielded or has been created but not yet started.
  • dead: The coroutine has finished executing its body function or encountered an unhandled error.

State Breakdown During Nested Execution

When Coroutine A resumes Coroutine B, and coroutine.running() is invoked inside Coroutine B, the states of the threads in the chain are assigned as follows:

  1. The Active Child Coroutine (Coroutine B)
    • State: running
    • Because Coroutine B is currently executing the code block containing coroutine.running(), coroutine.status(coroutine.running()) will evaluate to "running".
  2. The Invoking Parent Coroutine (Coroutine A)
    • State: normal
    • Coroutine A initiated the call via coroutine.resume(b). Because it is actively waiting for Coroutine B to yield or return, Coroutine A is neither running (it is not executing instructions) nor suspended (it cannot be resumed directly by another thread until B yields). Lua classifies this specific waiting condition as normal.
  3. The Main Thread
    • State: normal (if it resumed Coroutine A)
    • If Coroutine A was originally resumed by the main thread, the main thread also enters the normal state. Every ancestor coroutine up the call stack remains in the normal state while waiting for downstream coroutines to complete or yield control.

Practical Example

Consider the following execution flow:

local co_b
local co_a

co_b = coroutine.create(function()
    local current = coroutine.running()
    print("Inside B - Status of B:", coroutine.status(current))
    print("Inside B - Status of A:", coroutine.status(co_a))
end)

co_a = coroutine.create(function()
    coroutine.resume(co_b)
end)

coroutine.resume(co_a)

In this scenario:

  • coroutine.running() inside co_b returns the thread reference for co_b.
  • coroutine.status(current) outputs running.
  • coroutine.status(co_a) outputs normal.

Once co_b yields or finishes, control returns to co_a. At that point, co_a transitions back from normal to running, and co_b transitions to either suspended (if it yielded) or dead (if it completed).
