Lua Balanced Pattern Matching with %b Explained

This article explores the purpose, functionality, and practical use of the %b item within Lua's pattern-matching engine. Readers will learn how %b solves the challenge of extracting balanced pairs of characters—such as parentheses, brackets, or HTML tags—how it functions internally via counter tracking, and the specific limitations developers should keep in mind when parsing complex nested text.

In text processing, parsing content enclosed by paired delimiters is a frequent requirement. While standard Lua patterns use quantifiers like .* or .- to capture text, these fail when handling nested structures. A pattern like %(.-%) applied to "a (b (c) d) e" stops at the first closing parenthesis, yielding "(b (c)" instead of the full nested expression.

Lua resolves this limitation with the %b pattern item. The purpose of %b is to match balanced pairs of characters, allowing developers to extract properly nested substrings without resorting to complex recursive parsing algorithms or external libraries.

The syntax for this pattern item is %bxy, where x is the opening delimiter and y is the closing delimiter. The engine begins matching when it encounters the character x. As it reads forward, it tracks nesting depth by incrementing a counter whenever x appears and decrementing the counter whenever y appears. The match successfully concludes only when the counter reaches zero upon encountering the final matching y.

Common character pairs used with %b include:

  • %b() for parentheses
  • %b[] for square brackets
  • %b{} for curly braces
  • %b<> for angle brackets

Consider this practical Lua example:

local text = "config = { user = 'admin', settings = { theme = 'dark' } };"
local match = string.match(text, "%b{}")

print(match)
-- Output: { user = 'admin', settings = { theme = 'dark' } }

In this case, %b{} successfully matches from the opening brace before user through the final closing brace, correctly accounting for the nested { theme = 'dark' } block.

Despite its utility, %b has specific constraints. It operates exclusively on single-byte characters, meaning multi-character delimiters like begin and end or multi-byte UTF-8 sequences cannot be used. Additionally, %b is purely structural and does not recognize language-level semantics; an escaped delimiter or a delimiter inside a quoted string literal will still alter the counter, potentially causing unexpected match boundaries in complex source code.
