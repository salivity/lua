Lua Multiple Returns in Table Constructors

In Lua, functions can return multiple values, but how those values are handled inside a table constructor depends entirely on the function call's position in the list. This article explains Lua's evaluation rules for multi-return functions in table constructors, highlighting the critical distinction between being the final expression in a list versus being followed by other elements.

The Last Element Rule

Lua evaluates multiple return values fully only when the function call is the very last element in a table constructor's expression list. When placed at the end, the table expands dynamically to collect every value returned by the function.

local function getCoords()
    return 10, 20, 30
end

-- The function call is the last (and only) element
local t1 = { getCoords() }
-- Result: { 10, 20, 30 }

-- The function call is the last element among others
local t2 = { "origin", getCoords() }
-- Result: { "origin", 10, 20, 30 }

In both cases, all three returned values are preserved and assigned sequential integer indices.

The Truncation Rule

If a function call returning multiple values is followed by any other expression, Lua automatically adjusts the results, keeping only the first return value and discarding the rest.

local function getCoords()
    return 10, 20, 30
end

-- The function call is followed by another element
local t3 = { getCoords(), "extra" }
-- Result: { 10, "extra" }

Because getCoords() is followed by "extra", Lua truncates the output of getCoords() to just 10. The values 20 and 30 are silently dropped.

Forcing Single-Value Evaluation

You can override Lua's expansion behavior and force a function to return only its first value—even when it occupies the final position—by enclosing the call in parentheses:

local function getCoords()
    return 10, 20, 30
end

local t4 = { (getCoords()) }
-- Result: { 10 }

Parentheses turn the multi-value expression into a single-value expression before it is added to the constructor.

Key-Value Pair Assignment

When passing a multi-return function into a named key assignment inside a table constructor, Lua always truncates the output to a single value. A key can only hold a single value at a time.

local function getCoords()
    return 10, 20, 30
end

local t5 = { point = getCoords() }
-- Result: { point = 10 }

Only the first returned value (10) is assigned to t5.point, regardless of whether this assignment is the last item in the constructor.
