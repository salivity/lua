Lua Stateless Iterators and the Pairs Function

This article explores how stateless iterators operate in the Lua programming language, focusing specifically on the standard pairs function. You will learn the underlying mechanics of Lua's generic for loop, how pairs utilizes the built-in next function to traverse tables without generating memory overhead from closures, and how to implement your own custom stateless iterators.

In Lua, a stateless iterator is an iterator that does not maintain its own state across iterations. Instead, the generic for loop maintains the iteration state entirely on the runtime stack. A generic for loop manages this using three values returned by an iterator generator expression: an iterator function, an invariant state (typically the data structure being traversed), and a control variable (the current index or key).

The built-in pairs function is the primary example of a stateless iterator constructor. When you call pairs(t) on a table t, it does not create a stateful closure. Instead, it returns three distinct values:

  1. The built-in next function, which acts as the iterator function.
  2. The table t itself, which serves as the invariant state.
  3. nil, representing the initial value of the control variable.

Under the hood, implementing a function identical to pairs looks like this:

function custom_pairs(t)
    return next, t, nil
end

The iteration lifecycle follows a strict sequence executed by the Lua runtime:

  1. Initialization: The generic for loop calls custom_pairs(t) once to obtain the iterator function (next), the invariant state (t), and the initial control variable (nil).
  2. First Call: The loop invokes next(t, nil). The next function finds the first key-value pair in the table and returns first_key, first_value.
  3. Loop Execution: The loop assigns these returned values to the declared loop variables and executes the loop body.
  4. Subsequent Calls: At the end of each iteration, the loop automatically calls next(t, current_key). The next function uses the current key to locate the subsequent entry in the internal hash table or array part of t.
  5. Termination: When next reaches the end of the table, it returns nil. Upon receiving nil as the first return value, the for loop terminates.

You can also implement custom stateless iterators that process data structures without relying directly on next. For example, a stateless iterator that traverses array-like sequences can be written by defining a dedicated stepping function:

local function array_next(array, index)
    index = index + 1
    local value = array[index]
    if value ~= nil then
        return index, value
    end
end

function custom_ipairs(array)
    return array_next, array, 0
end

In this implementation, array_next remains stateless because it receives the target array (invariant state) and the prior index (control variable) on every call. It simply increments the control variable and fetches the corresponding value.

Stateless iterators are preferred in performance-critical Lua code. Because the state is passed via function parameters rather than captured variables, the interpreter avoids allocating new closure objects or triggering garbage collection cycles when starting a loop.
