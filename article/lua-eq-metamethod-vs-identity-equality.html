Lua __eq Metamethod vs Identity Equality

In Lua, comparing two values for equality relies either on default identity comparison or on custom behavior defined via the __eq metamethod. While identity equality checks whether two references point to the exact same object in memory, operator overloading with __eq allows developers to define structural or semantic equality for tables and userdata. Understanding the distinction between these two mechanisms is critical for designing predictable object-oriented patterns, data structures, and state comparisons in Lua.

Identity Equality

By default, Lua uses identity equality when evaluating the == and ~= operators on complex types such as tables, userdata, threads (coroutines), and functions.

  • Primitive Types: Numbers, booleans, strings, and nil are compared by value. Two strings with identical contents evaluate to true because Lua internalizes strings using a global hash table.
  • Complex Types: Tables and userdata are compared by reference. Two distinct tables containing identical keys and values will evaluate to false under standard equality because they occupy different addresses in memory.
local tableA = { id = 1 }
local tableB = { id = 1 }
local tableC = tableA

print(tableA == tableB) -- Output: false (distinct memory references)
print(tableA == tableC) -- Output: true (identical reference)

Operator Overloading with __eq

Lua allows you to override the default equality operator using metatables and the __eq metamethod. When you compare two operands using == or ~=, Lua checks whether a custom equality function has been provided before falling back to identity comparison.

Rules for Invoking __eq

  1. Both Operands Must Define It: Lua requires that both operands have a metamethod for __eq, and in standard Lua (since 5.2), both values must resolve to the exact same __eq function. If one operand lacks the metamethod, or if they have different functions assigned to __eq, Lua skips the metamethod entirely and falls back to identity comparison.
  2. Boolean Return: The function assigned to __eq takes two arguments (the operands being compared) and must return a boolean value (true or false).
local Point = {}
Point.__index = Point

function Point.new(x, y)
    local self = setmetatable({}, Point)
    self.x = x
    self.y = y
    return self
end

-- Define structural equality
function Point.__eq(a, b)
    return a.x == b.x and a.y == b.y
end

local p1 = Point.new(10, 20)
local p2 = Point.new(10, 20)

print(p1 == p2) -- Output: true (structural equality via __eq)

Key Differences

Feature Identity Equality Operator Overloading (__eq)
Comparison Criteria Memory address / object reference. Custom logic (e.g., matching field values).
Performance \(O(1)\) pointer comparison with zero function overhead. Requires metatable lookup and a function call.
Requirements Works natively on all Lua data types. Requires metatables; both objects must share the same __eq handler.
Bypass Mechanism Native behavior cannot be modified for primitives. Can be bypassed using the built-in rawequal function.

Bypassing __eq with rawequal

When an __eq metamethod is defined, == will always trigger the custom logic. If you need to verify whether two variables reference the exact same instance rather than equivalent data, use Lua's built-in rawequal(v1, v2) function.

local p1 = Point.new(5, 5)
local p2 = Point.new(5, 5)
local p3 = p1

print(p1 == p2)          -- Output: true (invokes __eq)
print(rawequal(p1, p2))  -- Output: false (different tables in memory)
print(rawequal(p1, p3))  -- Output: true (same table reference)

rawequal provides a direct reference check that completely ignores metatables, guaranteeing default identity semantics regardless of operator overloading.
