How lua_pop Adjusts the Stack in Lua C API

The lua_pop macro is one of the most frequently used stack-manipulation utilities in the Lua C API, providing a convenient way to remove a specified number of elements from the top of the virtual stack. In this article, you will learn how lua_pop is defined under the hood, how it delegates stack manipulation to lua_settop, and the exact pointer mechanics the Lua runtime uses to adjust the internal stack top.

Definition of the lua_pop Macro

In lua.h, lua_pop is not implemented as an independent C function. Instead, it is defined as a preprocessor macro wrapping lua_settop:

#define lua_pop(L, n) lua_settop(L, -(n) - 1)

Here, L represents the current lua_State pointer, and n represents the number of elements to pop from the stack.

The Negative Index Calculation

Lua uses dual-indexing for its virtual stack: positive indices represent absolute positions from the bottom (where 1 is the first element pushed), while negative indices represent relative positions from the top (where -1 is the topmost element).

When you want to remove n elements, the new topmost element must become the element currently sitting n positions below the current top:

  • Index -1 is the current top.
  • Index -2 is 1 element below the top.
  • Index -(n) - 1 is the element directly underneath the n elements being discarded.

For example, if the stack contains five elements [A, B, C, D, E] and you call lua_pop(L, 2):

  1. -(2) - 1 evaluates to -3.
  2. Relative index -1 points to E, -2 points to D, and -3 points to C.
  3. Calling lua_settop(L, -3) sets the top of the stack to element C, effectively removing D and E.

Internal Pointer Adjustment in the C Core

Inside the Lua interpreter core, the virtual stack is implemented as a contiguous array of TValue structures (Lua's internal representation for tagged values). The lua_State structure maintains internal pointers tracking this array:

  • L->stack: Points to the base of the allocated stack memory.
  • L->top: Points to the memory slot immediately following the highest valid element (in Lua 5.4, represented inside StkIdRel).

When lua_settop receives the calculated target index:

  1. Index Resolution: Lua converts the relative negative index -(n) - 1 into an absolute memory address (a StkId pointer) corresponding to the new top slot.
  2. Downward Movement: Because elements are being popped, the resolved address is lower than L->top.
  3. Pointer Decrement: Lua sets L->top directly to this target address. The adjustment effectively subtracts n * sizeof(TValue) from the top pointer.
  4. Garbage Collection Safety: In modern Lua versions (such as Lua 5.3 and 5.4), the runtime clears or invalidates the memory slots between the new L->top and the old L->top to ensure references to discarded Lua objects do not remain visible to the garbage collector.
