Lua os.time: Convert Date Tables to Epoch Time

In the Lua programming language, the os.time function serves as the primary bridge between human-readable calendar components and machine-readable Unix epoch timestamps. When provided with a structured table containing temporal parameters such as year, month, and day, os.time calculates the total number of seconds elapsed since January 1, 1970, 00:00:00 UTC. This article breaks down how os.time parses structured date tables, delegates the calculation to the host platform's C runtime, and handles date normalization and time zones.

Required and Optional Table Fields

When invoked with an argument, os.time expects a table populated with specific keys representing date and time components.

The function requires three mandatory fields:

  • year: A four-digit integer representing the full calendar year (e.g., 2024).
  • month: An integer from 1 to 12.
  • day: An integer from 1 to 31.

It also accepts several optional fields:

  • hour: The hour of the day from 0 to 23 (defaults to 12 if omitted).
  • min: The minute from 0 to 59 (defaults to 0 if omitted).
  • sec: The second from 0 to 59 (defaults to 0 if omitted).
  • isdst: A boolean indicating whether Daylight Saving Time is active (true, false, or nil to let the system determine it).
local date_table = {
    year = 2024,
    month = 5,
    day = 18,
    hour = 14,
    min = 30,
    sec = 0
}

local timestamp = os.time(date_table)

Delegation to the C Standard Library

Under the hood, Lua does not implement custom date-arithmetic algorithms. Instead, the Lua standard library maps os.time directly to the C runtime function mktime.

When os.time receives a table:

  1. Lua reads the integer values from the table fields.
  2. It adjusts the Lua-friendly values to match the C struct tm specifications. For example, Lua months (1–12) are converted to C's zero-indexed months (0–11), and the year is adjusted to represent years since 1900.
  3. Lua invokes mktime(&ts), passing the populated struct tm structure.
  4. mktime calculates the linear number of seconds since the Unix epoch for that specific calendar point according to the host system's local time settings.
  5. The result (of type time_t) is cast back into a Lua number or integer and returned to the caller.

Automatic Value Normalization

Because os.time relies on mktime, it inherits automatic field normalization. If a field value falls outside its conventional range, the system automatically rolls over the excess into higher-order fields.

For instance, specifying {year = 2024, month = 1, day = 32} causes the calculation to roll over into February, producing the timestamp for February 1, 2024. Similarly, subtracting time by setting negative numbers (such as day = 0) correctly resolves to the final day of the preceding month. This makes os.time useful not only for conversion, but also for performing basic calendar arithmetic.

Local Time and Time Zone Considerations

By default, mktime assumes that the structured date provided in the table is expressed in the host operating system's local time zone, rather than UTC.

Consequently, passing identical date tables to os.time on machines configured in different time zones will yield different Unix epoch timestamps. To accurately represent UTC time using os.time, the local system's UTC offset must be calculated and factored in manually, or the system environment must be explicitly set to UTC prior to execution.
