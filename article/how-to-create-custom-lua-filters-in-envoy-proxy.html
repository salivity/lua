How to Create Custom Lua Filters in Envoy Proxy

Envoy proxy provides native support for custom filter creation by embedding LuaJIT into its HTTP filter chain. This capability allows developers to intercept, inspect, and modify HTTP requests and responses dynamically without recompiling the Envoy binary or managing external WebAssembly (Wasm) toolchains. By utilizing the built-in Lua HTTP filter, teams can rapidly implement custom routing logic, header manipulation, authentication checks, and external API lookups directly within the proxy data plane.

The Lua Filter Architecture

Envoy embeds LuaJIT directly into its envoy.filters.http.lua filter module. When placed within the HTTP connection manager's filter chain, the Lua filter executes scripts during different phases of the HTTP request-response lifecycle.

Each Envoy worker thread maintains its own independent Lua state. This design ensures thread safety and isolates executions, preventing race conditions without requiring locks. However, because each worker thread has its own isolated memory, global variables are not shared across threads or across separate HTTP requests.

Lifecycle Hooks and Script Execution

The embedded Lua engine hooks into stream events through designated callback functions. When a request traverses the filter chain, Envoy invokes these functions if they are defined in the Lua script:

  • envoy_on_request(request_handle): Executed when request headers arrive. It allows you to inspect incoming headers, modify them, buffer or stream the body, or prematurely terminate the request by sending an immediate local response.
  • envoy_on_response(response_handle): Executed when upstream response headers arrive. It allows modification of response headers, status codes, and response bodies before they are returned to the downstream client.

Core Capabilities of the Lua API

The script interacts with Envoy through an object model exposed directly to the Lua environment:

  1. Header and Metadata Manipulation: Scripts can read, add, or remove headers using methods like headers():get(), headers():add(), and headers():remove(). Dynamic metadata can also be shared with subsequent filters in the chain.
  2. Body Inspection and Modification: Payloads can be buffered and transformed. The body() method can retrieve chunks of data or buffer the entire payload for inspection, hashing, or modification.
  3. Out-of-Band HTTP Calls: Scripts can make asynchronous HTTP requests to external services using httpCall(). Envoy suspends the execution of the specific stream until the external call returns, without blocking the underlying worker thread. This is commonly used for inline token verification, authorization services, or external logging.
  4. Immediate Responses: Scripts can short-circuit the filter chain using respond(). This returns a custom HTTP status, custom headers, and a body directly to the client without forwarding the request upstream.

Configuration

The Lua filter is defined in Envoy’s configuration file under the HTTP connection manager filters. It can be loaded globally using an inline string or an external file, and can also be overridden on a per-route basis.

name: envoy.filters.http.lua
typed_config:
  "@type": type.googleapis.com/envoy.extensions.filters.http.lua.v3.Lua
  default_source_code:
    inline_string: |
      function envoy_on_request(handle)
        local auth_header = handle:headers():get("authorization")
        if not auth_header then
          handle:respond({[":status"] = "401"}, "Unauthorized: Missing Token")
        else
          handle:headers():add("x-validated-by", "envoy-lua")
        end
      end

Performance and Operational Considerations

Because Envoy utilizes LuaJIT, script execution is compiled to native machine code where possible, offering minimal latency overhead for common tasks such as header verification and routing tweaks.

However, heavy CPU-bound tasks or synchronous blocking operations should be avoided within Lua scripts. While httpCall() is non-blocking to the worker event loop, extensive memory allocations or large body transformations within LuaJIT can impact overall throughput. For lightweight, dynamic logic, the embedded Lua filter provides an efficient middle ground between native C++ extensions and complex external processing services.
