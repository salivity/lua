Lua Number Precision: Integers vs Floats Explained

This article examines the limits of numeric precision in the Lua programming language, comparing its 64-bit integer implementation against standard double-precision floating-point numbers. Since Lua 5.3, the language natively distinguishes between integers and floats, providing distinct operational boundaries for each. While floats are limited to 53 bits of safe integer precision, native integers allow exact representations across full 64-bit signed ranges.

Lua's Numeric Model

Prior to Lua 5.3, all numbers were represented internally as double-precision floating-point values (IEEE 754 standard). Lua 5.3 introduced a dual-representation system under a unified number type:

  • Integer: Typically a 64-bit signed integer.
  • Float: An IEEE 754 double-precision (64-bit) floating-point number.

You can inspect the underlying representation of any value using math.type(n), which returns either "integer" or "float".

Maximum Precision for Lua Integers

In standard builds of Lua 5.3 and later, integers are 64-bit signed values (int64_t in C).

  • Maximum Safe Value: 2^63 - 1 or 9,223,372,036,854,775,807
  • Minimum Safe Value: -2^63 or -9,223,372,036,854,775,808
  • Constants: Accessible directly via math.maxinteger and math.mininteger.

Because integers use exact binary arithmetic, every single whole number within this interval is represented with 100% precision. Arithmetic operations that exceed these boundaries will silently wrap around according to two's complement rules rather than throwing an error or automatically coercing to a float.

Maximum Precision for Lua Floats

Lua's floating-point numbers conform to standard IEEE 754 binary64 format. A float divides its 64 bits into:

  • 1 sign bit
  • 11 exponent bits
  • 52 mantissa (significand) bits, offering 53 bits of effective precision due to an implicit leading bit.

Because of the 53-bit mantissa, the maximum safe integer that can be continuously represented without loss of precision is:

  • Safe Continuous Limit: 2^53 or 9,007,199,254,740,992 (as well as -2^53).

Beyond 2^53, floating-point values can only represent every second integer, then every fourth integer at 2^54, and so forth. Consequently, calculations involving whole numbers larger than \(9,007,199,254,740,992\) will lose granularity when stored as floats.

For fractional numbers, double precision provides roughly 15 to 17 significant decimal digits of accuracy. Any fractional operations requiring more than 53 bits of significand will suffer from rounding errors inherent to binary representations of decimal fractions.

Comparison Summary

Metric Integer (math.type() == "integer") Float (math.type() == "float")
Bit Width 64 bits 64 bits (1 sign, 11 exp, 52 frac)
Exact Integer Range \(-2^{63}\) to \(2^{63} - 1\) \(-2^{53}\) to \(2^{53}\)
Max Safe Exact Value \(9,223,372,036,854,775,807\) \(9,007,199,254,740,992\)
Behavior at Limit Wraps around (two's complement) Loses lower-order digits / precision
Fractional Capability None (whole numbers only) ~15–17 decimal digits of precision

To maintain maximum numeric fidelity in modern Lua, operations requiring exact whole values larger than \(9,007,199,254,740,992\) (such as 64-bit database identifiers or file offsets) must strictly use integer arithmetic and avoid operators that force floating-point conversion, such as standard division (/) instead of integer division (//).
