Lua Single-Precision Float on Microcontrollers

Running the Lua programming language on resource-constrained microcontrollers often requires tuning its memory footprint and execution speed. By default, Lua uses 64-bit double-precision floats (and 64-bit integers in modern releases), which creates significant CPU and RAM overhead on 32-bit architectures that lack a 64-bit hardware Floating-Point Unit (FPU). This guide explains how to customize the core Lua configuration to switch the underlying numeric representation to 32-bit single-precision floats and 32-bit integers, enabling native hardware acceleration on devices such as ARM Cortex-M or ESP32 microcontrollers.

Modifying luaconf.h

All core numeric definitions in Lua are controlled by macro definitions located in src/luaconf.h. To customize Lua for microcontrollers, you do not need to rewrite the interpreter; you only need to adjust these configuration macros before compiling the source code.

Configuration for Lua 5.3 and Lua 5.4

Modern versions of Lua separate numbers into distinct floating-point (LUA_FLOAT_TYPE) and integer (LUA_INT_TYPE) representations.

Open src/luaconf.h and locate the configuration section for numeric types. Update the definitions to use 32-bit types:

/* Set the floating-point type to single-precision float (32-bit) */
#define LUA_FLOAT_TYPE LUA_FLOAT_FLOAT

/* Set the integer type to standard 32-bit signed int */
#define LUA_INT_TYPE   LUA_INT_INT

Setting LUA_FLOAT_TYPE to LUA_FLOAT_FLOAT instructs Lua to define lua_Number as float and automatically redirects math library functions to their single-precision C standard library counterparts (e.g., sinf, cosf, sqrtf instead of sin, cos, sqrt). Setting LUA_INT_TYPE to LUA_INT_INT changes lua_Integer from a 64-bit long long to a standard 32-bit int, preventing unnecessary 64-bit math emulation on 32-bit CPU registers.

Configuration for Lua 5.1 and Lua 5.2

In Lua 5.1 and 5.2, all numbers share a single type: lua_Number.

To convert this single type to a 32-bit float, edit src/luaconf.h and define:

#define LUA_NUMBER_DOUBLE
#undef LUA_NUMBER_DOUBLE
#define LUA_NUMBER_FLOAT

#define LUA_NUMBER         float
#define LUAI_UACNUMBER     float
#define LUA_NUMBER_SCAN    "%f"
#define LUA_NUMBER_FMT     "%.7g"
#define lua_number2str(s,sz,n)  \
        l_sprintf((s), sz, LUA_NUMBER_FMT, (LUAI_UACNUMBER)(n))

/* Redirect math library routines to single-precision float variants */
#define l_mathop(op)       op##f

Compiler Flags and Hardware FPU Support

Modifying the source code ensures Lua uses the float data type, but your toolchain must also be instructed to emit hardware floating-point instructions rather than software floating-point emulation routines.

When building Lua with a cross-compiler such as arm-none-eabi-gcc, apply the appropriate architecture and FPU flags in your Makefile:

# Example flags for ARM Cortex-M4 with single-precision FPU
CC = arm-none-eabi-gcc
CFLAGS = -mcpu=cortex-m4 -mfpu=fpv4-sp-d16 -mfloat-abi=hard -O2

Using -mfloat-abi=hard ensures that function calls pass floating-point arguments directly in the microcontroller's hardware FPU registers.

Verification

After compiling and flashing the custom Lua binary to your target hardware, verify the configuration by checking precision limitations:

-- In 32-bit single-precision, 1 / 3 displays roughly 7 decimal digits of precision
print(1 / 3) 
-- Expected output: 0.33333334 (instead of 0.3333333333333333)

-- In Lua 5.3+, check integer and float boundaries
print(math.maxinteger)
-- Expected output: 2147483647 (32-bit signed max)

Switching to single-precision floats reduces the size of Lua's tagged value structure (TValue) from 16 bytes down to 8 or 12 bytes depending on alignment, cutting RAM consumption significantly and allowing intensive numeric computations to run natively on the microcontroller's hardware FPU.
