LDoc Tag Syntax for Lua Parameters and Types

LDoc is a widely used documentation generator for Lua that relies on Javadoc-like comment tags to inspect code and produce structured documentation. This guide details the specific tag syntax used by LDoc to document function parameters, return values, and data types, allowing developers to create precise, type-annotated Lua APIs.

Documenting Parameters

LDoc provides two primary tags for function arguments: @param and @tparam.

  • @param: Specifies a parameter name followed by its description.

    --- Adds two numbers.
-- @param x The first number
-- @param y The second number
function add(x, y) end

  • @tparam: Directly attaches a type to the parameter before the parameter name.

    --- Sets the user's age.
-- @tparam number age The age in years
function set_age(age) end

  • Inline Types with @param: You can also embed types into the @param tag using bracket syntax:

    -- @param[type=string] name The user's name

  • Optional Parameters and Defaults: Optional parameters are denoted with [opt] or [opt=default_value]:

    -- @tparam[opt=1] number step The increment step
-- @param[type=string,opt] prefix Optional string prefix

Documenting Returns

Return values are documented using @return or the type-specific @treturn.

  • @return: Describes a returned value. For multiple returns, use multiple tags in order of appearance.

    --- Divides two numbers.
-- @return The quotient, or nil on failure
-- @return An error message if division by zero occurs
function divide(a, b) end

  • @treturn: Prefixes the return description with its explicit type.

    --- Generates a unique identifier.
-- @treturn string The generated UUID
function generate_uuid() end

Type Expression Syntax

LDoc supports a flexible type specification syntax across @tparam, @treturn, and custom types:

  • Basic Types: Standard Lua types like string, number, boolean, table, function, or thread.

  • Alternative/Union Types: Separated by vertical bars (|).

    -- @tparam string|number id The identifier

  • Nullable Types: Prefixing a type with ? marks it as allowing nil.

    -- @tparam ?string label An optional label that can be nil

  • Tables and Lists: Curly braces define array types or map structures:

    • Array list: {string,...} denotes a sequence of strings.
    • Key-value map: {string=number,...} denotes a table mapping string keys to number values.

Defining Custom Types and Tables

To document structured tables, classes, or configuration objects, LDoc uses @table or @class along with @field (or @tfield for typed fields):

--- User profile settings.
-- @table UserConfig
-- @tfield string username The display name
-- @tfield[opt=false] boolean active Account status

Once defined, UserConfig can be referenced as a valid type within any subsequent @tparam or @treturn tag across your documentation.
