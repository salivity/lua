Lua Variables Without Local Inside Functions

In the Lua programming language, any variable assigned inside a function body without the local keyword automatically defaults to global scope. This article explains how Lua handles these variables, the side effects and performance impacts of omitting the local keyword, and the best practices for preventing unintentional global variables in your applications.

Implicit Global Assignment

Unlike languages that default to local scope within function blocks, Lua resolves any unqualified variable assignment to the global environment table (_G). When you assign a value to a variable inside a function without declaring it with local, Lua checks if a local variable by that name exists in an enclosing scope. If it does not find one, Lua treats the assignment as a modification of the global environment.

function setCoordinates()
    x = 10 -- Implicitly global
    y = 20 -- Implicitly global
end

setCoordinates()
print(x, y) -- Outputs: 10   20

Even after the function setCoordinates finishes execution, the variables x and y persist in memory and are accessible from anywhere else in the program.

Consequences of Omitting local

1. Namespace Pollution and State Mutation

Global variables are shared across the entire Lua state. If two separate functions or modules inadvertently use the same variable name without local, they will overwrite each other's data:

function taskA()
    for i = 1, 5 do
        taskB()
    end
end

function taskB()
    i = 0 -- Overwrites the 'i' used in taskA's loop
end

In the example above, calling taskA() triggers an infinite loop because taskB() constantly resets the global counter i.

2. Reduced Execution Performance

Local variables in Lua are stored in the Lua virtual machine's registers and are accessed by index, making them exceptionally fast. In contrast, global variables reside in a hash table (_G). Reading or writing to a global variable requires a table hash lookup, which is significantly slower than direct register access.

3. Memory Leaks

Because global variables remain referenced in the global table indefinitely, Lua's garbage collector cannot collect the objects they point to until the variable is explicitly set to nil or the Lua state is closed.

Best Practices and Prevention

Explicit Local Declarations

Always define variables using the local keyword at the narrowest scope necessary:

function calculateTotal(price, taxRate)
    local tax = price * taxRate
    local total = price + tax
    return total
end

Static Analysis

Use static analysis tools such as Luacheck during development. Luacheck inspects your code without running it and immediately flags any implicit global definitions as warnings or errors.

Strict Mode via Metatables

You can detect accidental globals at runtime by locking the global table using metatables. Lua's official distribution includes a standard utility called strict.lua, which hooks into __newindex and __index on _G to raise an error whenever an undeclared global variable is accessed or assigned.
