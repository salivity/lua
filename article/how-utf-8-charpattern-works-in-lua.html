How utf8.charpattern Works in Lua

In the Lua programming language, utf8.charpattern is a predefined string pattern designed to match exactly one UTF-8 byte sequence. This article provides a breakdown of how utf8.charpattern is constructed, how its byte ranges map to the UTF-8 specification, and how Lua uses this pattern to iterate through and validate individual Unicode characters.

The Exact Pattern Definition

In Lua 5.3 and later, utf8.charpattern is defined as:

[\0-\x7F\xC2-\xFD][\x80-\xBF]*

This pattern consists of two distinct components: a leading byte class [\0-\x7F\xC2-\xFD] and a quantifier matching zero or more continuation bytes [\x80-\xBF]*.

Deconstructing the Byte Ranges

UTF-8 is a variable-width encoding format where characters are represented using one to four bytes (or historically up to six bytes). The pattern matches these characters based on their binary prefix rules:

  1. ASCII Characters (Single Byte): The range \0-\x7F corresponds to standard 7-bit ASCII characters (bytes 00000000 to 01111111). Because these are single-byte codepoints, they are followed by zero continuation bytes, satisfying the pattern immediately.

  2. Multi-Byte Leading Bytes: The range \xC2-\xFD identifies the start of a multi-byte sequence.

    • Bytes \xC0 and \xC1 are explicitly excluded because they would result in "overlong encodings" for characters that should fit within standard 1-byte ASCII.
    • \xC2 through \xDF represent the start of 2-byte sequences (110xxxxx).
    • \xE0 through \xEF represent the start of 3-byte sequences (1110xxxx).
    • \xF0 through \xF4 represent the start of standard 4-byte sequences (11110xxx).
    • Values up to \xFD accommodate legacy 5-byte and 6-byte UTF-8 extensions defined in earlier Unicode specifications.

  3. Continuation Bytes: The class [\x80-\xBF]* matches trailing bytes. In UTF-8, all continuation bytes must start with the bit pattern 10xxxxxx, which translates in hexadecimal to values between \x80 and \xBF. The * quantifier allows the character to possess as many continuation bytes as are present directly following the start byte.

Practical Application

Because Lua's native pattern engine does not implement full regular expressions or lookaround assertions, utf8.charpattern is designed for structural iteration rather than strict RFC 3629 conformance checking.

The standard idiom for iterating over all characters in a UTF-8 string is using string.gmatch:

local text = "Lua 编程"
for char in string.gmatch(text, utf8.charpattern) do
    print(char)
end

In this loop, utf8.charpattern extracts "L", "u", "a", " ", "编", and "程" individually, grouping the multi-byte sequences into coherent codepoint strings without splitting them across byte boundaries.
