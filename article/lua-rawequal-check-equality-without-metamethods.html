Lua rawequal: Check Equality Without Metamethods

In Lua, the rawequal function provides a way to compare two values for direct, raw equality without invoking any metamethods. While the standard equality operator (==) can be overloaded using the __eq metamethod, rawequal bypasses metatables completely. This article explains how rawequal works, why it is essential for checking reference equality in tables and userdata, and the practical scenarios where it should be used instead of standard comparison operators.

How Standard Equality Works in Lua

When you use the standard equality operator (a == b), Lua follows a specific evaluation order:

  1. It checks if the types of a and b are different. If they are, the result is false.
  2. For primitive types (numbers, booleans, strings, and nil), Lua compares their direct values.
  3. For reference types (tables, functions, threads, and userdata), Lua first checks if both operands reference the exact same memory object. If they do, it evaluates to true.
  4. If they are distinct objects, Lua checks whether both values share an identical __eq metamethod (or have one defined). If found, Lua calls that metamethod function and uses its return value.

The Purpose of rawequal

The rawequal(v1, v2) function circumvents step 4 entirely. It compares v1 and v2 purely based on their fundamental type and raw value/reference.

rawequal(v1, v2)

The function returns a boolean: true if v1 is equal to v2 without invoking any metamethods, and false otherwise.

  • Primitive values: Behaves identically to standard equality (e.g., rawequal(5, 5) is true).
  • Reference values (tables, userdata): Returns true only if v1 and v2 point to the exact same reference in memory, completely ignoring any custom __eq metamethod logic.

Demonstrating rawequal vs ==

Consider two distinct tables configured with an __eq metamethod that considers them equal if they share the same ID:

local mt = {
    __eq = function(a, b)
        return a.id == b.id
    end
}

local itemA = { id = 101, name = "Sword" }
local itemB = { id = 101, name = "Shield" }

setmetatable(itemA, mt)
setmetatable(itemB, mt)

-- Standard equality uses the __eq metamethod
print(itemA == itemB)       --> true

-- Raw equality checks actual memory reference
print(rawequal(itemA, itemB)) --> false

-- Same reference comparison
local itemC = itemA
print(rawequal(itemA, itemC)) --> true

In this example, itemA == itemB evaluates to true because the metatable defines them as equal. However, rawequal(itemA, itemB) returns false because itemA and itemB are distinct table instances.

Common Use Cases for rawequal

1. Preventing Infinite Recursion in Metamethods

When writing an __eq metamethod, developers often need to check whether two arguments are actually the same object before performing expensive property checks. Using a == b inside __eq triggers __eq again, causing a stack overflow. Using rawequal(a, b) provides a safe identity check:

local mt = {
    __eq = function(a, b)
        -- Fast path: if they are the exact same object, return true immediately
        if rawequal(a, b) then
            return true
        end
        return a.value == b.value
    end
}

2. Enforcing Strict Object Identity

In system design, state machines, or caching mechanisms, you often need to confirm whether an argument is a specific instance rather than an equivalent clone. rawequal guarantees that you are inspecting identity rather than value.

3. Security and Sandboxing

When executing untrusted Lua scripts, user code can redefine metatable behaviors to produce unexpected results or side effects during comparisons. Using rawequal ensures predictable comparisons that cannot be manipulated by arbitrary metamethod hooks.
