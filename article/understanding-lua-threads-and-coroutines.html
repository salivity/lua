Understanding Lua Threads and Coroutines

This article explores Lua's built-in thread data type, clarifying its exact role in the language and how it serves as the underlying representation of coroutines. Readers will learn the fundamental differences between operating-system-level threads and Lua threads, how the standard library manages this data type, and the mechanics of cooperative multitasking within the Lua runtime.

In Lua, thread is one of the eight basic data types, alongside nil, boolean, number, string, userdata, function, and table. While the term "thread" in computer science typically refers to an operating-system-level process that runs concurrently on multiple CPU cores, Lua uses the term differently. In Lua, a thread value does not represent a preemptive OS thread; instead, it represents an independent execution stack with its own local variables and program counter.

The relationship between the thread type and coroutines is direct and absolute: every coroutine in Lua is a first-class value of type thread. When you pass a function to coroutine.create(), the Lua virtual machine allocates a new, separate execution context and returns a thread value. Checking this value with the built-in type() function explicitly returns "thread".

The defining characteristic of Lua threads is that they are cooperative, not preemptive. A single-threaded Lua state cannot execute multiple Lua threads simultaneously. Instead, only one Lua thread runs at any given moment. A running thread continues execution until it explicitly suspends itself using coroutine.yield(). Once yielded, the caller or scheduler that resumed the thread regains control. Execution of the suspended thread can later be picked up precisely where it left off via coroutine.resume().

Because Lua threads transfer control voluntarily, they eliminate the need for synchronization primitives like mutexes, condition variables, or semaphores. Shared data between Lua threads does not produce data races because execution points are deterministic.

A Lua thread exists in one of four states at any point in its lifecycle:

  • Suspended: The thread has been created but not yet started, or it has invoked coroutine.yield() and is waiting to be resumed.
  • Running: The thread is currently actively executing instructions.
  • Normal: The thread has resumed another coroutine and is waiting for that coroutine to yield or finish.
  • Dead: The thread's main function has completely finished executing or encountered an unhandled error, meaning it can no longer be resumed.

Lua threads provide a lightweight mechanism for implementing state machines, asynchronous event loops, iterators, and generators without the resource overhead and synchronization complexities associated with native multi-threading.
