Lua rawlen: Inspecting Length Without Metamethods

In Lua, determining the size of an object typically relies on the length operator (#), which can be intercepted and overridden by the __len metamethod. The rawlen function, introduced in Lua 5.2, provides a direct alternative that bypasses all metatable mechanisms to inspect the genuine, internal size of tables and strings. This article explains how rawlen interacts with Lua's internal data structures, why it avoids invoking user-defined metamethods, and how it differs in behavior and safety from the standard length operator.

The Standard Length Operator vs. rawlen

The standard length operator (#) follows a dynamic dispatch process. When #v is evaluated, the Lua runtime first checks whether the operand v possesses a metatable containing a __len field:

  1. If __len is defined and is a function, Lua halts native length calculation and invokes that function with v as the argument.
  2. If __len is not present, Lua falls back to its default internal algorithm to compute the length.

Because of this behavior, # can execute arbitrary Lua code, introduce side effects, degrade performance in performance-critical loops, or lead to infinite recursion if a __len implementation attempts to read #self.

The rawlen(v) function circumvents this lookup entirely. It guarantees that no metatable lookup occurs, executing an immediate, raw inspection of the underlying data structure.

How rawlen Works Internally

At the C implementation level, rawlen maps directly to the Lua C API function lua_rawlen. Instead of executing the luaT_gettm routine (which queries metatables for specific event keys), the runtime directly reads Lua's internal data representations.

Strings

In Lua, strings are immutable and interned (or managed via internal string headers). The length of a string is precomputed and stored directly in the TString struct:

// Simplified representation of Lua's internal string struct
typedef struct TString {
    CommonHeader;
    lu_byte extra;
    lu_byte shrlen; /* length if short string */
    unsigned int hash;
    union {
        size_t lnglen; /* length if long string */
        struct TString *hnext;
    } u;
} TString;

When rawlen receives a string, it accesses the stored length field directly. This operation is \(O(1)\) and never triggers any metamethod, returning the byte count immediately.

Tables

A Lua table consists of an array slice and a hash map slice. When rawlen is called on a table, the engine executes Lua's native boundary-checking algorithm directly on the Table struct:

  1. It checks the size of the internal array part.
  2. If elements extend into the hash part, or if the array contains gaps, it performs a binary search to locate a boundary—a key \(n\) such that t[n] ~= nil and t[n+1] == nil.

Because rawlen invokes the internal boundary search without checking for metatables, it guarantees that no user code executes during the traversal.

Code Demonstration

The following example demonstrates the operational difference between # and rawlen:

local proxy = setmetatable({ 10, 20, 30 }, {
    __len = function(t)
        return 999
    end
})

-- Using the standard length operator
print(#proxy)       -- Output: 999 (invokes __len)

-- Using rawlen
print(rawlen(proxy)) -- Output: 3 (inspects underlying table directly)

If an object does not have a __len metamethod, #t and rawlen(t) return identical values for sequences.

Type Constraints and Errors

Unlike the standard # operator, which can be extended to arbitrary types (such as userdata) via the __len metamethod, rawlen strictly accepts only two data types:

  • Tables: Returns the raw sequence boundary.
  • Strings: Returns the byte length.

Passing any other type (such as nil, number, boolean, function, thread, or userdata) causes rawlen to raise a runtime error: bad argument #1 to 'rawlen' (table or string expected).

Primary Use Cases

  1. Preventing Recursion in Metamethods: Inside a custom __len implementation, developers use rawlen(self) to inspect the table's actual capacity or size without triggering an infinite recursive loop.
  2. Sandboxing and Defensive Programming: When dealing with untrusted user tables, standard operators can trigger malicious code execution via metamethod hooks. rawlen ensures deterministic execution and side-effect-free inspection.
  3. Serialization and Debugging: Serializers and debuggers use rawlen to inspect the literal physical elements of a table rather than its virtualized representation.
