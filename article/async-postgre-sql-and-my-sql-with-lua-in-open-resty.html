Async PostgreSQL and MySQL with Lua in OpenResty

This article provides an overview of how the Lua programming language achieves high-performance, asynchronous database access to PostgreSQL and MySQL inside OpenResty. Within OpenResty, Lua does not rely on complex callback chains or manual promise handling to execute non-blocking operations. Instead, it leverages Nginx's event-driven core and native Lua coroutines to allow developers to write clean, synchronous-looking code that performs completely non-blocking database queries under the hood.

The Cosocket Mechanism and Lua Coroutines

At the core of OpenResty’s non-blocking I/O is the "cosocket" (coroutine-based socket) API. In OpenResty, each incoming HTTP request is assigned its own Lua coroutine. When an interaction with a database takes place:

  1. The database client initiates a network read or write operation via the cosocket API.
  2. If the socket is not immediately ready to read or write, OpenResty yields the current Lua coroutine and registers the underlying socket descriptor with Nginx's native event loop (such as epoll on Linux or kqueue on BSD/macOS).
  3. The Nginx worker process does not block; it continues processing other concurrent HTTP requests.
  4. Once the database server responds and data arrives on the network socket, Nginx wakes up and resumes the yielded coroutine from where it paused.

Because of this mechanism, developers write linear, procedural Lua code without blocking the single-threaded Nginx worker process.

Dedicated Resty Database Libraries

Standard Lua database drivers (such as LuaSQL) use native C bindings or standard POSIX sockets that block the entire OS thread, which degrades Nginx's concurrency. To maintain fully asynchronous execution, OpenResty uses dedicated libraries written specifically for the cosocket layer:

  • lua-resty-mysql: An official, pure-Lua client driver implementing the MySQL binary network protocol on top of OpenResty cosockets.
  • lua-resty-postgres: A pure-Lua client driver that implements the PostgreSQL frontend/backend protocol using cosockets.

These libraries handle protocol handshakes, authentication, query formatting, and result set parsing entirely in Lua while routing all network transport through the non-blocking cosocket interface.

Connection Pooling

Establishing a new TCP and TLS handshake for every database query introduces significant latency and resource overhead. OpenResty solves this through built-in cosocket connection pooling.

Both lua-resty-mysql and lua-resty-postgres implement connection pooling using the set_keepalive method provided by OpenResty. When a request completes its database operations, the Lua code calls set_keepalive() instead of terminating the connection. This places the live database connection into an internal pool bound to the specific Nginx worker process. Subsequent requests can retrieve an existing connection instantly via connect(), eliminating connection negotiation overhead while maintaining non-blocking operation.
