Why snake_case Is Preferred in Lua Programming

In the Lua programming language, naming conventions predominantly favor snake_case for variables and functions over camelCase. While Lua itself is unopinionated and syntactically permits any naming scheme, the ecosystem overwhelmingly adopts snake_case due to Lua’s deep historical integration with C, consistency with the official standard library, and prevailing community-driven style guides. Understanding these foundational influences clarifies why snake_case remains the idiomatic choice for modern Lua development.

Alignment with C and Low-Level Heritage

Lua was developed from its inception as an embeddable extension language written in ANSI C. Because one of Lua's primary design goals was seamless interoperability with C host applications, the creators naturally aligned Lua's design philosophy with standard C idioms. In the C programming world, lowercase identifiers and snake_case have long been the established standard. Developers working between the C API and Lua scripts benefit from a unified visual syntax, minimizing cognitive friction when passing functions, variables, and data structures across the language boundary.

Standard Library Consistency

The Lua standard library sets the canonical precedent for code style within the ecosystem. Standard modules and global functions rely entirely on all-lowercase identifiers (such as tostring, tonumber, setmetatable, and rawget) or implicit lowercase separation within namespaces (such as table.insert, string.format, and math.random_seed).

When multi-word functions occur, snake_case naturally extends the all-lowercase aesthetic without introducing the abrupt casing shifts seen in camelCase. Adopting snake_case in user code ensures visual harmony with Lua’s built-in environment, making third-party scripts feel native rather than foreign.

Community Style Standards

Prominent community style conventions, such as the widely referenced Lua Style Guide, formally codify these preferences to ensure consistency across the ecosystem:

  • Variables and Functions: Standard variables and functions use snake_case (e.g., local player_count, function calculate_total()).
  • Constants: Defined in ALL_CAPS_SNAKE_CASE (e.g., MAX_RETRY_COUNT).
  • Objects and Classes: Metatable-based classes or simulated object definitions typically use PascalCase (e.g., Vector3, PlayerManager).

Using snake_case for functions and variables creates an immediate visual distinction between class constructors or modules (PascalCase) and local instances or procedural methods (snake_case).

Minimalist Philosophy and Readability

Lua emphasizes minimalism and simplicity. In typography and code analysis, underscores provide explicit visual delimiters that enhance readability in dynamic, loosely typed environments. Because Lua does not feature complex keyword structures, static type annotations, or access modifiers out of the box, clear word separation allows developers to parse variable roles and scopes quickly. By mirroring the lowercase simplicity of Lua's own keywords—such as then, elseif, function, and until—snake_case reinforces the clean, unobtrusive nature of the language.
