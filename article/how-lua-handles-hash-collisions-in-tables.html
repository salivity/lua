How Lua Handles Hash Collisions in Tables

Lua tables serve as the primary data structure in the language, utilizing a hybrid structure of an array part and a hash part to store arbitrary key-value pairs. Hash collisions occur when different keys map to the same bucket index within the hash part, caused by the mathematical constraints of mapping an infinite set of keys into a finite array size. Lua resolves these collisions using an optimized variation of coalesced hashing—specifically a chained scatter table—which manages collisions inside the existing array using a reverse search pointer (lastfree) and node relocation to keep search chains optimal.

What Causes Hash Collisions in Lua

A collision in Lua occurs when two distinct keys yield the same index, known as the key's "main position," inside the hash part of a table.

  1. Finite Table Capacity vs. Infinite Key Domain: Lua accepts almost any value as a key, including strings, numbers, tables, functions, and threads. The hash part of a Lua table always has a size equal to a power of two. Because the universe of possible keys is practically infinite while the hash vector is strictly bounded, the pigeonhole principle guarantees that different keys will eventually target the same bucket.
  2. Hash Function and Index Clamping: Lua computes a hash value for a key (for example, using a specialized string-hashing algorithm for strings or pointer addresses for reference types) and maps this integer to an index in the hash array using bitwise masking (hash & (size - 1)). Even if the hash algorithm produces unique integer values, the modulo/masking operation maps many distinct hashes to identical array slots.

How Lua Resolves Collisions: Coalesced Hashing

Lua does not use separate chaining with external linked lists, nor does it use standard open addressing like linear or quadratic probing. Instead, it utilizes an internal chained scatter table (a form of coalesced hashing) where all chain nodes reside directly inside the allocated hash vector.

Each entry in Lua's hash table is a Node structure that holds the key, the value, and a next field pointing to the next colliding node in the chain (as an offset/pointer). Lua maintains a pointer called lastfree, which initially points to the end of the hash array and moves backwards toward the beginning to locate unused nodes.

When inserting a key, Lua calculates its main position:

  • The Main Position is Free: If the calculated bucket is empty, the key and value are stored directly in that slot. The next pointer is set to null.
  • Primary Collision (The Occupant Belongs There): If the slot is occupied and the current occupant belongs in that main position, Lua searches backwards from lastfree until it finds an empty node. The new key-value pair is placed into this free slot, and the new slot is linked into the collision chain originating from the main position.
  • Secondary Collision (The Occupant is an Intruder): If the slot is occupied by a node that does not naturally belong there—meaning it was placed there as a result of an earlier collision from a different main position—Lua performs a relocation. The existing intruder node is moved to an empty slot found by lastfree, the pointers in the intruder's original chain are updated to reflect the new location, and the newly inserted key claims its rightful main position.

Rehashing and Table Growth

Because Lua searches backwards with lastfree, the array eventually runs out of free slots. When an insertion requires a free node and lastfree reaches the beginning of the table without finding an empty slot, Lua triggers a rehash.

During rehashing, Lua analyzes all existing keys, determines the optimal sizes for both the array part and the hash part, allocates a new hash vector, and re-inserts all elements into their new main positions, effectively resetting and clearing the collision chains.
