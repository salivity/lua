Stop Runaway Lua Scripts Using Debug Hooks

Sandboxing untrusted Lua code requires a robust mechanism to prevent infinite loops and resource exhaustion from freezing your application. This article provides a comprehensive guide on using instruction count hooks from Lua's debug library to track bytecode execution, set instruction budgets, and safely terminate run-away scripts using both pure Lua and the C API.

The Problem of Run-away Scripts

Because standard Lua operates as a single-threaded runtime, an infinite loop such as while true do end blocks the host process indefinitely. Standard timeouts cannot simply inspect the runtime externally without threading or signal handling. Lua solves this problem by providing execution hooks via its debug library, allowing you to monitor and interrupt execution from within the engine itself.

How debug.sethook Works

Lua's debug.sethook function registers a callback function that is invoked when specific events occur. To interrupt long-running scripts, you use the "count" hook, which fires after the Lua virtual machine executes a designated number of instructions.

The syntax for setting a hook in Lua is:

debug.sethook([thread,] hook_function, mask, [count])
  • hook_function: The function invoked when the hook triggers.
  • mask: A string containing flags: "c" (call), "r" (return), "l" (line), or an empty string "" when relying strictly on instruction count.
  • count: The number of VM instructions executed between each call to hook_function.

Implementing an Execution Limit in Lua

To stop a run-away script, configure a hook that increments a counter or checks an instruction budget, then throws an error to abort execution when the limit is exceeded.

local function run_with_instruction_limit(untrusted_code, max_instructions)
    local instructions_used = 0
    local step_size = 1000 -- Check every 1,000 instructions to reduce overhead

    -- Define the hook
    local function hook()
        instructions_used = instructions_used + step_size
        if instructions_used >= max_instructions then
            -- Clear the hook to prevent further triggers
            debug.sethook()
            error("Execution limit exceeded: script terminated.")
        end
    end

    -- Set the hook: empty mask, fires every `step_size` instructions
    debug.sethook(hook, "", step_size)

    -- Run the untrusted code safely inside pcall
    local status, result = pcall(untrusted_code)

    -- Always remove the hook after execution finishes
    debug.sethook()

    return status, result
end

-- Example usage:
local malicious_script = function()
    while true do end
end

local success, err = run_with_instruction_limit(malicious_script, 50000)
if not success then
    print("Script safely halted:", err)
end

Implementing Instruction Limits in C

When embedding Lua in C or C++, using the C API is preferred because it prevents untrusted scripts from tampering with the debug table.

You can set an instruction hook using lua_sethook:

#include <lua.h>
#include <lauxlib.h>
#include <lualib.h>

static void instruction_count_hook(lua_State *L, lua_Debug *ar) {
    // Abort execution by raising an error
    luaL_error(L, "Script exceeded the maximum allowed instruction count.");
}

int execute_sandboxed(lua_State *L, const char *script, int max_instructions) {
    // Set a count hook that fires once max_instructions is reached
    lua_sethook(L, instruction_count_hook, LUA_MASKCOUNT, max_instructions);

    // Load and execute the script in protected mode
    int status = luaL_dostring(L, script);

    // Disable the hook after execution
    lua_sethook(L, NULL, 0, 0);

    return status; // LUA_OK or an error code
}

Best Practices and Limitations

  1. Tune the Step Size: Firing a hook on every instruction (count = 1) significantly degrades performance. Instead, check every 1,000 to 10,000 instructions. This maintains high throughput while remaining responsive enough to halt runaway processes within milliseconds.
  2. Account for C Calls: Instruction count hooks only increment during the execution of Lua bytecode. If a script calls an external C library function that hangs (such as a blocking I/O operation or a native C infinite loop), the hook will not trigger until that C function yields control back to the Lua VM.
  3. Sandbox the debug Library: If you are using the pure Lua implementation, remove or restrict the debug table from the environment exposed to untrusted code. Otherwise, the script can call debug.sethook() to disable your watchdog hook.
  4. Use pcall or lua_pcall: Always run the untrusted script within a protected call so the error() raised by the hook can be intercepted and handled without crashing the host application.
