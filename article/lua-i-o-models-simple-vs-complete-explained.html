Lua I/O Models: Simple vs Complete Explained

Lua's standard io library offers two distinct paradigms for handling file operations: the simple I/O model and the complete I/O model. While the simple model relies on implicit, global file handles suitable for linear and straightforward script execution, the complete model uses explicit file objects that give developers fine-grained control over multiple open files simultaneously. Understanding the trade-offs between these two approaches is essential for choosing the right tool for file processing in Lua.

The Simple I/O Model

The simple I/O model operates using the concept of current input and current output files. All file operations implicitly target these predefined streams unless explicitly changed. By default, the current input file is standard input (stdin) and the current output file is standard output (stdout).

Functions in this model are called directly from the io table:

  • io.input(filename): Sets the current input stream to the specified file.
  • io.output(filename): Sets the current output stream to the specified file.
  • io.read(...): Reads data from the current input stream according to specified formats (e.g., "*l" for lines, "*n" for numbers, "*a" for entire files).
  • io.write(...): Writes provided arguments directly to the current output stream.

The simple model minimizes boilerplate code when processing files linearly or when redirecting standard streams. However, its reliance on a single global input and output state makes it impractical when an application must read from or write to multiple files concurrently.

The Complete I/O Model

The complete I/O model uses an object-oriented approach based on explicit file descriptors, which Lua represents as userdata containing C file handles (FILE*). Instead of relying on a shared global state, files are opened explicitly using io.open.

Key characteristics of the complete model include:

  • io.open(filename, mode): Opens a file using standard C modes ("r", "w", "a", "r+", etc.) and returns a file handle, or nil followed by an error message if the operation fails.
  • file:read(...): Reads directly from the specific file object.
  • file:write(...): Writes directly to the specific file object.
  • file:seek(whence, offset): Sets and gets the current file position.
  • file:close(): Explicitly releases the file descriptor back to the operating system.

Because each file exists as an independent handle, the complete model allows programs to interleave operations across several files without changing global states. It also standardizes error checking, as the programmer can verify the success of each file handle upon opening.

Key Differences

  • Handle Management: The simple model hides file handles behind global state transitions via io.input and io.output. The complete model exposes explicit file handles returned by io.open.
  • Multiple Files: The simple model only tracks one input and one output at any given moment, requiring constant switching if juggling multiple sources. The complete model allows simultaneous access to arbitrarily many open files.
  • Syntax: Operations in the simple model use procedural syntax (io.read()), whereas operations in the complete model use method syntax on the file handle (handle:read()).
  • Resource Lifecycle: In the simple model, closing streams is typically tied to redefining io.input() or script termination. In the complete model, developers manage the lifecycle directly with handle:close(), preventing resource leaks in long-running processes.
