Lua load Function: Restrict Chunks to Text or Binary

In the Lua programming language, the load function incorporates an optional mode parameter to control whether an incoming chunk is treated as plain source text, precompiled binary bytecode, or either format. By explicitly defining this parameter, developers can enforce strict input requirements and protect applications from security vulnerabilities associated with untrusted bytecode execution.

The Syntax of load

The standard signature of the load function in Lua 5.2 and later is:

load(chunk [, chunkname [, mode [, env]]])

The third argument, mode, is a string that determines the acceptable formats for the chunk being loaded.

Available Values for the mode Parameter

The mode string accepts three distinct options:

  • "t" (Text only): Restricts the input strictly to source code text. If the chunk begins with the Lua bytecode signature, load will reject it and return nil followed by an error message indicating that precompiled chunks are not allowed.
  • "b" (Binary only): Restricts the input strictly to precompiled bytecode. If the chunk is standard source text rather than precompiled binary data, load will fail and report an error stating that text chunks are disallowed.
  • "bt" (Binary or Text): Allows Lua to automatically detect whether the chunk is source code or bytecode. This is the default setting when the mode argument is omitted or set to nil.

How Lua Enforces the Restriction

When Lua receives a chunk, it inspects the initial bytes to identify the data format. Precompiled bytecode always begins with a standard binary signature (the escape byte \x1b followed by "Lua").

When mode is set to "t", Lua validates that the initial bytes do not match the bytecode signature. If the signature is detected, parsing halts immediately before any instructions are processed. Conversely, when mode is set to "b", Lua demands the presence of the signature and validates the header metadata against the host environment. If the signature is missing, parsing terminates without executing code.

Code Examples

Restricting input to source code text:

-- Attempting to load binary bytecode with mode set to "t"
local bytecode = string.dump(function() print("Hello") end)
local fn, err = load(bytecode, "chunk", "t")

print(fn)  -- Output: nil
print(err) -- Output: attempt to load a precompiled chunk

Restricting input to precompiled bytecode:

-- Attempting to load plain text with mode set to "b"
local source = "print('Hello')"
local fn, err = load(source, "chunk", "b")

print(fn)  -- Output: nil
print(err) -- Output: attempt to load a text chunk

Security Considerations

The primary use case for setting mode = "t" is security. Lua 5.2 removed the internal bytecode verifier because full verification of arbitrary bytecode is complex and prone to edge-case bugs. Consequently, loading malformed or intentionally corrupted bytecode can lead to memory corruption, arbitrary code execution, or host process crashes.

Whenever an application loads code from untrusted sources, such as user submissions or external network sockets, developers should explicitly pass "t" to the mode parameter to prevent the execution of malicious precompiled payloads.
