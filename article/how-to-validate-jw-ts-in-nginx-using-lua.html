How to Validate JWTs in Nginx Using Lua

Validating JSON Web Tokens (JWTs) directly within Nginx offloads authentication from upstream services, reducing backend load and centralizing security policies. This guide explains how to inspect incoming HTTP requests, extract Bearer tokens, and verify cryptographic signatures and expiration claims using Nginx combined with the OpenResty Lua engine and the lua-resty-jwt library.

Prerequisites

To execute Lua scripts within Nginx, you must use OpenResty or a custom Nginx build compiled with ngx_http_lua_module and LuaJIT. You also need the lua-resty-jwt library, which handles parsing and cryptographic operations.

Install the library using OpenResty’s package manager (OPM):

opm get SkyLothar/lua-resty-jwt

Alternatively, you can install it via Luarocks:

luarocks install lua-resty-jwt

Implementing Token Validation in Nginx

Authentication logic in Nginx with Lua is commonly placed within the access_by_lua_block directive. This phase runs before the request reaches the upstream proxy handlers, allowing Nginx to reject unauthorized requests immediately with an HTTP 401 Unauthorized status.

Below is a complete nginx.conf configuration demonstrating extraction, signature validation, and payload processing:

http {
    # Define Lua package paths if installed outside the standard directory
    lua_package_path "/usr/local/openresty/lualib/?.lua;;";

    server {
        listen 80;
        server_name api.example.com;

        location /secure-endpoint {
            access_by_lua_block {
                local jwt = require("resty.jwt")
                local auth_header = ngx.var.http_Authorization

                -- 1. Check for the presence of the Authorization header
                if not auth_header then
                    ngx.status = ngx.HTTP_UNAUTHORIZED
                    ngx.say('{"error": "Missing authorization header"}')
                    return ngx.exit(ngx.HTTP_UNAUTHORIZED)
                end

                -- 2. Extract the token from the Bearer format
                local _, _, token = string.find(auth_header, "Bearer%s+(.+)")
                if not token then
                    ngx.status = ngx.HTTP_UNAUTHORIZED
                    ngx.say('{"error": "Malformed authorization header"}')
                    return ngx.exit(ngx.HTTP_UNAUTHORIZED)
                end

                -- 3. Define secret key and verify signature
                local secret = "your-256-bit-secret-key"
                local jwt_obj = jwt:verify(secret, token)

                -- 4. Check cryptographic validity
                if not jwt_obj.verified then
                    ngx.status = ngx.HTTP_UNAUTHORIZED
                    ngx.header.content_type = "application/json"
                    ngx.say('{"error": "' .. (jwt_obj.reason or "Invalid token") .. '"}')
                    return ngx.exit(ngx.HTTP_UNAUTHORIZED)
                end

                -- 5. Validate standard claims (e.g., expiration)
                local current_time = ngx.time()
                if jwt_obj.payload.exp and jwt_obj.payload.exp < current_time then
                    ngx.status = ngx.HTTP_UNAUTHORIZED
                    ngx.header.content_type = "application/json"
                    ngx.say('{"error": "Token has expired"}')
                    return ngx.exit(ngx.HTTP_UNAUTHORIZED)
                end

                -- 6. Pass payload claims to upstream servers via headers
                ngx.req.set_header("X-User-ID", jwt_obj.payload.sub)
            }

            proxy_pass http://backend_upstream;
        }
    }
}

Key Execution Steps

  1. Extracting the Header: The ngx.var.http_Authorization variable reads the standard HTTP request header. Lua pattern matching strips the Bearer prefix to isolate the raw JWT string.
  2. Signature Verification: The jwt:verify() method automatically parses the three-part Base64URL-encoded token (header, payload, signature), identifies the algorithm (such as HS256), and validates the integrity using the shared secret.
  3. Claim Validation: While jwt:verify() ensures the signature is genuine, your script must explicitly inspect payload attributes—such as exp (expiration timestamp) or custom claims (such as roles or tenant IDs)—using Nginx's system time provider ngx.time().
  4. Context Propagation: Once verified, you can attach decoded values directly to upstream request headers using ngx.req.set_header(), allowing internal microservices to consume trusted user identifiers without needing to re-verify the signature.
