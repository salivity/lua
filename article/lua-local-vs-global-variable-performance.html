Lua Local vs Global Variable Performance

In the Lua programming language, local variable access is significantly faster than global variable access due to differences in how the Lua Virtual Machine (VM) compiles and resolves identifiers. Local variables are assigned to fixed virtual machine registers and resolved at compile time by index, whereas global variables live inside a standard Lua table (_ENV) and require dynamic hash table lookups at runtime. Understanding this architectural distinction is essential for writing high-performance Lua code, especially in tight loops and performance-critical systems like game development or embedded scripts.

Internal Mechanisms: Register Access vs. Table Lookup

The performance disparity between local and global variables stems from how Lua tracks and accesses memory:

  • Local Variables: When Lua compiles a chunk of code, it allocates local variables to virtual machine registers (slots on the activation stack). Bytecode instructions access these variables directly via an integer index (an offset on the stack). This operation behaves like a direct array read or hardware register access, incurring virtually zero computational overhead at runtime.
  • Global Variables: Lua does not have true standalone global variables in its VM architecture. Instead, globals are stored as key-value pairs in a standard Lua table known as the environment table (_ENV in Lua 5.2+ or _G in Lua 5.1). Accessing a global variable requires hashing the variable name, resolving potential collisions, and retrieving the value from the table.

Performance Impact

Because hash table access involves multiple memory dereferences, string hashing, and collision checks, accessing a global variable is intrinsically slower than reading a local register.

In microbenchmarks and tight loops, local variable lookups can be anywhere from 30% to over 100% faster than equivalent global lookups. While modern Lua implementations—especially LuaJIT—employ advanced optimizations, table lookups still consume more CPU cycles and cache lines than direct stack slot indexing.

The Idiomatic Optimization: Localizing Globals

To eliminate redundant hash lookups, a standard practice in Lua is to localize frequently used global functions or variables before entering performance-sensitive code.

Consider the following unoptimized loop:

for i = 1, 1000000 do
    local x = math.sin(i)
end

In every iteration, the Lua VM must:

  1. Look up the global table math inside the environment table.
  2. Look up the string key "sin" inside the math table.
  3. Call the resulting function.

By caching the function locally, you reduce the runtime cost to a single register lookup per iteration:

local sin = math.sin
for i = 1, 1000000 do
    local x = sin(i)
end

Best Practices

  • Default to local: Always declare variables with the local keyword unless they explicitly need to be shared across multiple modules or scopes.
  • Cache Standard Library Functions: If functions from libraries such as math, table, or string are called repeatedly inside loops, assign them to local variables at the top of the file or function scope.
  • Scope Tightening: Keep local variable declarations as close to their usage as possible to help the compiler optimize register allocation and stack cleanup.
