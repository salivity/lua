Hex Floats in Lua: Parsing 0x1.fp10 Explained

Lua supports hexadecimal floating-point literals, allowing developers to define exact binary floating-point values without the rounding issues common to decimal representation. This article explains how Lua lexes, evaluates, and stores hexadecimal floats like 0x1.fp10, detailing the syntax structure, mathematical interpretation, and underlying IEEE 754 double-precision representation.

Anatomy of a Hexadecimal Float Literal

Introduced natively in Lua 5.2 to match C99 conventions, hexadecimal floating-point literals consist of three primary components:

  • Prefix (0x or 0X): Signals to the lexer that the number is represented in hexadecimal notation.
  • Significand (Mantissa): The fractional part containing hex digits (0–9, a–f, A–F) and an optional radix point. In 0x1.fp10, the significand is 1.f.
  • Binary Exponent (p or P): Specifies the power of two by which the significand is scaled. Unlike decimal scientific notation which uses e for base-10 powers, hex floats use p (for "power") to avoid ambiguity with the hex digit E. Crucially, the integer following p is interpreted in decimal, not hexadecimal. In 0x1.fp10, the exponent is decimal 10 (\(2^{10}\)).

Mathematical Evaluation

To parse 0x1.fp10, Lua evaluates the significand in base-16 and multiplies it by two raised to the decimal exponent:

  1. Convert the Significand:
    1.f in hexadecimal converts to:
    \(1 + \frac{15}{16} = 1 + 0.9375 = 1.9375\) in decimal.

  2. Evaluate the Exponent:
    p10 denotes \(2^{10} = 1024\).

  3. Compute the Value:
    \(1.9375 \times 1024 = 1984.0\).

Thus, print(0x1.fp10) in Lua outputs 1984.0.

Lexical Parsing in the Lua Engine

During the compilation phase, Lua’s lexer (llex.c) scans the source code character by character:

  1. When it encounters 0x or 0X, it marks the literal as hexadecimal.
  2. If it encounters a dot (.) or an exponent marker (p/P), it routes the token to the floating-point parser rather than the integer path.
  3. Lua invokes its numeric conversion routine (typically relying on the C runtime's strtod or an internal equivalent like luaO_str2num) configured to parse standard C99 hexadecimal float strings.
  4. The parser consumes the hex digits, shifts the significand bits into the mantissa buffer, reads the decimal exponent, and scales the binary exponent accordingly.

Internal IEEE 754 Representation

By default, modern Lua versions (such as Lua 5.3 and 5.4) use standard IEEE 754 double-precision (64-bit) floats for floating-point numbers:

  • 1 Sign Bit: 0 (positive).
  • 11 Exponent Bits: Store the biased exponent. Since \(1984 = 1.9375 \times 2^{10} = 1.1111_2 \times 2^{10}\), the unbiased exponent is \(10\). Adding the IEEE 754 bias of \(1023\) gives \(1033\) (10000001001 in binary).
  • 52 Fraction (Mantissa) Bits: Store the fractional bits of the normalized binary number \(1.1111_2\), which are 1111 followed by 48 zeros.

Hexadecimal floats map directly to binary representations because each hex digit corresponds to exactly four binary bits. This eliminates base-conversion inaccuracies, allowing Lua to parse and represent fractional numbers with absolute bit-level precision.
