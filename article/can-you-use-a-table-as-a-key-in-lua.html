Can You Use a Table as a Key in Lua?

In the Lua programming language, you can use another table as a key inside a table. Because tables are first-class values, Lua permits almost any value to serve as an index, excluding only nil and NaN (Not a Number). This article explains how table-based keys work, how Lua evaluates key equality through references, and the memory management considerations you must keep in mind when implementing this pattern.

Reference Equality for Table Keys

When you use a table as a key, Lua uses reference identity rather than structural equality to retrieve values. Lua does not compare the contents or fields inside the tables; instead, it checks whether two table variables point to the exact same memory location.

Consider the following example:

local myTable = {}
local key1 = { id = 100 }
local key2 = { id = 100 }

-- Assign a value using key1
myTable[key1] = "Active Session"

-- Accessing via key1 succeeds
print(myTable[key1]) -- Output: Active Session

-- Accessing via key2 fails because it is a different table instance
print(myTable[key2]) -- Output: nil

-- Assigning a variable by reference allows access
local keyReference = key1
print(myTable[keyReference]) -- Output: Active Session

Even though key1 and key2 share the exact same internal structure and values, Lua treats them as completely distinct keys because they are separate objects in memory.

Mutating Table Keys

Because lookup relies on table references rather than table contents, mutating a key table does not invalidate its association in the parent table. You can add, remove, or modify fields within the key table without losing the ability to access its stored value:

local cache = {}
local user = { name = "Alice" }

cache[user] = "Profile Data"

-- Mutate the key table
user.name = "Bob"
user.role = "Admin"

-- Lookup still works because the table reference remains identical
print(cache[user]) -- Output: Profile Data

Memory Management and Weak Tables

Using tables as keys creates a strong reference by default. As long as the parent table exists, any table used as a key inside it will not be collected by Lua's garbage collector, even if all other references to that key are deleted. This can lead to memory leaks if you use tables as temporary identifiers or cache keys.

To prevent this issue, you can configure the parent table as a weak table using a metatable with the __mode field set to "k":

local cache = {}
setmetatable(cache, { __mode = "k" }) -- Keys are now weak references

do
    local tempKey = { id = 42 }
    cache[tempKey] = "Temporary Data"
    print(cache[tempKey]) -- Output: Temporary Data
end

-- Force garbage collection
collectgarbage()

-- tempKey went out of scope and was collected, automatically removing its entry
for k, v in pairs(cache) do
    print(k, v) -- Produces no output; the entry was collected
end

By marking keys as weak, Lua automatically removes the key-value pair from the table whenever the key table has no remaining strong references elsewhere in the program.
