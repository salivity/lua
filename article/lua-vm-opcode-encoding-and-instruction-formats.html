Lua VM Opcode Encoding and Instruction Formats

The Lua virtual machine relies on a register-based architecture that utilizes fixed-size 32-bit instructions to execute compiled bytecode. Within each 32-bit instruction word, Lua packs an opcode along with its associated register targets, immediate values, or table indices. This article explains how the Lua virtual machine encodes opcodes, the primary instruction formats it uses to partition the 32-bit space, and how operands and constants are addressed at the bit level.

The 32-Bit Instruction Layout

Every instruction in Lua bytecode is represented by the C type Instruction, which is typically defined as a 32-bit unsigned integer (uint32_t). Using a fixed 32-bit width simplifies instruction decoding, avoids variable-length instruction alignment issues, and maximizes CPU cache efficiency during bytecode dispatch.

The allocation of bits within the 32-bit word is defined in the Lua source header lopcodes.h. The opcode itself consistently occupies the lowest-order bits of the instruction word:

  • Lua 5.1 through 5.3: 6 bits allocated for the opcode (bits 0–5), allowing for up to 64 distinct VM instructions.
  • Lua 5.4: 7 bits allocated for the opcode (bits 0–6), accommodating an expanded set of instructions (up to 128).

The remaining 25 to 26 bits are distributed among operands depending on the instruction's designated layout format.

Standard Instruction Formats

Lua categorizes instructions into specific formats to handle different operational needs, such as arithmetic, jumps, constant loading, and function calls.

1. The iABC Format

The iABC format is the most common layout, used for operations involving multiple registers or operands (such as ADD, SUB, or GETTABLE).

  • Opcode: Bits 0–6 (7 bits in Lua 5.4)
  • A: Bits 7–14 (8 bits). Typically designates the destination register.
  • B: Bits 16–23 (8 bits in Lua 5.4). Usually holds a source register or constant.
  • C: Bits 24–31 (8 bits in Lua 5.4). Holds a second source register or immediate value.
  • k: Bit 15 (1 bit in Lua 5.4). A flag indicating whether operand B or C refers to a register or a constant pool index.

(Note: In Lua 5.1–5.3, B and C were 9 bits each, directly preceding the 8-bit A field and 6-bit opcode without the explicit k flag).

2. The iABx Format

The iABx format combines the space of the B and C fields into a single, larger unsigned operand (Bx). This format is used for operations like LOADK (loading a constant) or CLOSURE (instantiating a function prototype) that need to reference larger indices.

  • Opcode: 6–7 bits
  • A: 8 bits (destination register)
  • Bx: 17–18 bits (unsigned integer representing a constant table index or proto index)

3. The iAsBx Format

The iAsBx format is identical in field width to iABx, but the combined operand sBx represents a signed integer. This format is historically used for conditional jumps and numeric for loops.

Because it is encoded in unsigned 32-bit fields, Lua stores sBx using excess-K (biased) notation:

sBx = Bx - MAXARG_sBx

An encoded value of MAXARG_sBx corresponds to zero, values above it are positive jumps, and values below it are negative jumps.

4. The iAx Format (Lua 5.2+)

Introduced to expand the constant table address space beyond the 18-bit limit of Bx, the iAx format eliminates the A field entirely.

  • Opcode: 6–7 bits
  • Ax: 25–26 bits (large unsigned integer)

Instructions like EXTRAARG use this format to provide supplementary operand data for preceding instructions that exceed standard limits.

5. The isJ Format (Lua 5.4)

Lua 5.4 introduced the isJ format specifically for jump instructions (JMP). It reserves 7 bits for the opcode and devotes the remaining 25 bits to a signed jump offset (sJ), eliminating the unused register A operand previously present in jump instructions.

Differentiating Registers and Constants

In Lua bytecode, an operand may reference either a virtual register (a stack slot) or an entry in the constant table (\(K\)).

  • Lua 5.1–5.3: Used the highest bit (the 9th bit) of the 9-bit B or C field as a discriminator. If the MSB was set, the lower 8 bits indexed the constant table (k = 1). If cleared, the field indicated a register index (k = 0).
  • Lua 5.4: Uses an explicit 1-bit k field in the iABC format. If k is set, operand B (or C, depending on the instruction) is treated as a constant index rather than a register.

Bit Manipulation in the Lua Source

The extraction and insertion of fields are handled via C preprocessor macros in lopcodes.h. These macros use bitwise shifts and masks:

#define MASK1(n,p)   ((~((~(Instruction)0)<<(n)))<<(p))
#define GET_OPCODE(i) (cast(OpCode, ((i) >> POS_OP) & MASK1(SIZE_OP, 0)))
#define GETARG_A(i)   (cast(int, ((i) >> POS_A) & MASK1(SIZE_A, 0)))
#define GETARG_B(i)   (cast(int, ((i) >> POS_B) & MASK1(SIZE_B, 0)))

When the virtual machine loop executes (luaV_execute in lvm.c), it fetches the next 32-bit instruction, extracts the opcode using GET_OPCODE(i), and uses a large switch statement to decode and process the corresponding operands.
