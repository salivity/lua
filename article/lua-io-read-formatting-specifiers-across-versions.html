Lua io.read Formatting Specifiers Across Versions

The io.read function in Lua handles input from the standard input stream using formatting specifiers that determine how much data to capture and how to parse it. Over the evolution of the language—from Lua 5.0 through Lua 5.4—the syntax and internal handling of these specifiers evolved from required asterisk prefixes (such as *a, *l, and *n) to simplified, prefix-free formats, alongside changes in numeric representation and end-of-line handling.

Core Formatting Specifiers and Their Operations

Lua provides four primary format specifiers alongside fixed-width numeric reads:

  • *a / a (All): Reads the entire remaining input until the end of the file (EOF). If the stream is already at EOF, it returns an empty string "" rather than nil.
  • *l / l (Line without delimiter): Reads the next line, consuming the newline sequence (\n, \r\n, or \r) from the stream but excluding it from the returned string. This is the default format if no argument is passed. It returns nil on EOF.
  • *L / L (Line with delimiter): Reads the next line while preserving the terminating newline character(s) at the end of the returned string. It returns nil on EOF.
  • *n / n (Number): Skips leading whitespace and parses a number directly from the input stream. It returns nil if the characters encountered cannot be converted into a valid number.
  • Number (Length): Passing a positive integer n reads up to n bytes or characters. If the stream reaches EOF before any characters are read, it returns nil; otherwise, it returns the partially read string.

Lua 5.0 and Lua 5.1: The Asterisk Requirement

In Lua 5.0 and 5.1, the asterisk prefix was mandatory for all string-based format specifiers.

  • Valid options were strictly "*n", "*a", and "*l", along with positive integers for byte counts.
  • The *L format did not exist in these versions; preserving the newline required manual reconstruction or reading byte-by-byte.
  • The "*n" specifier relied on the underlying C runtime's scanf("%lf", ...) function, meaning it only parsed double-precision floating-point values and inherited platform-specific C library formatting quirks (such as locale dependencies for decimal separators).

Lua 5.2: Introduction of *L

Lua 5.2 expanded standard I/O capabilities while retaining the legacy format syntax:

  • Introduced "*L" to read a line while keeping the line delimiter intact. This addressed long-standing difficulties in stream piping where newlines were lost during round-trip reads and writes.
  • The asterisk prefix remained mandatory. Passing "l" or "n" without the asterisk resulted in a bad argument error.
  • Error reporting became more structured, directly identifying invalid format strings in io.read.

Lua 5.3: Syntax Modernization and Integer Support

Lua 5.3 brought fundamental architectural changes to numbers and streamlined format syntax:

  • Prefix-free Formats: Dropping the asterisk became standard. Lua 5.3 accepted "a", "l", "L", and "n". The legacy forms ("*a", "*l", "*L", "*n") remained fully functional for backward compatibility.
  • Dual Number Subtypes: With the introduction of distinct 64-bit integer and floating-point subtypes, the "n" (or "*n") specifier was updated. Instead of delegating entirely to C's scanf, Lua parsed input into either an integer or a float, preserving exact precision for integer inputs whenever possible.
  • Hexadecimal floating-point input strings (e.g., 0x1.fp3) became valid input for numeric reads.

Lua 5.4: Formal Deprecation and Strict Parsing

In Lua 5.4, the modernization initiated in Lua 5.3 became the preferred standard:

  • The asterisk-prefixed versions ("*a", "*l", "*L", "*n") were formally designated as deprecated, though the standard interpreter preserves them to avoid breaking older scripts.
  • The standalone single-letter characters ("a", "l", "L", "n") are the documented standards.
  • Numeric parsing via "n" continues to route directly through Lua's internal lexer routines rather than C-level formatting functions, ensuring uniform behavior across all platforms independent of the host system's C locale.
