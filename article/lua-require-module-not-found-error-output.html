Lua Require Module Not Found Error Output

When the require function in Lua fails to locate a requested module, it raises a runtime error indicating that the module could not be found. This article explains the structure of that error message, details the sequential search process Lua displays in its output, and demonstrates how to read the diagnostic trace to resolve pathing issues.

The Standard Error Format

When a module fails to load, Lua halts execution (unless wrapped in pcall) and prints an error message to the standard error stream. The output begins with the script location and the failure notice, followed by a list of every location checked by Lua's searchers.

An example error output for require("missing_module") in Lua 5.4 looks like this:

lua: main.lua:1: module 'missing_module' not found:
    no field package.preload['missing_module']
    no file '/usr/local/share/lua/5.4/missing_module.lua'
    no file '/usr/local/share/lua/5.4/missing_module/init.lua'
    no file '/usr/local/lib/lua/5.4/missing_module.lua'
    no file '/usr/local/lib/lua/5.4/missing_module/init.lua'
    no file './missing_module.lua'
    no file './missing_module/init.lua'
    no file '/usr/local/lib/lua/5.4/missing_module.so'
    no file '/usr/local/lib/lua/5.4/loadall.so'
    no file './missing_module.so'

Anatomy of the Error Output

The generated error message is divided into distinct sections reflecting Lua’s default module searchers:

1. The Error Header

lua: main.lua:1: module 'missing_module' not found:

This line identifies the file and line number where the require call occurred, followed by the explicit name of the module that could not be resolved.

2. Preload Searcher Check

    no field package.preload['missing_module']

Lua first checks the package.preload table to see if a loader function has already been registered in memory for that module name. If absent, it reports that no field exists in the table.

3. Lua Loader Search (package.path)

    no file '/usr/local/share/lua/5.4/missing_module.lua'
    no file './missing_module.lua'
    ...

Lua iterates through all directory patterns defined in the package.path string. It replaces question mark placeholders (?) in the path templates with the requested module name (and replaces dots with directory separators). If none of the generated file paths exist on the disk, each attempted path is appended to the error report.

4. C Library Loader Search (package.cpath)

    no file '/usr/local/lib/lua/5.4/missing_module.so'
    no file './missing_module.so'
    ...

If no Lua source file matches, Lua iterates through package.cpath looking for compiled shared libraries (.so on Linux/macOS, .dll on Windows). It attempts to locate a dynamic library matching the module name.

5. All-in-One Loader Search

If the module name contains submodules (such as parent.child), Lua performs an additional check to locate an all-in-one C library matching the root name (parent.so or parent.dll) that exports a corresponding initialization function (such as luaopen_parent_child). If this fails, that check is also listed in the output.

Handling and Resolving the Error

To resolve this error, ensure the module file exists in one of the search paths listed in the error report, or modify Lua's path variables directly in your script or shell environment:

  • Update Path in Lua: Append custom search directories via package.path = package.path .. ";/path/to/modules/?.lua"
  • Update System Environment: Set the LUA_PATH or LUA_CPATH environment variables prior to running the Lua executable.
