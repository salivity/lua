Build Lua Without Floating-Point Math

Running the Lua programming language on embedded hardware without a Hardware Floating-Point Unit (FPU) requires configuring the interpreter to operate exclusively using integer arithmetic. By modifying configuration headers in the source code prior to compilation, developers can strip out software floating-point emulation libraries, reduce binary size, and drastically increase execution speed on resource-constrained microcontrollers.

Modifying luaconf.h in Lua 5.3 and 5.4

Modern versions of Lua natively distinguish between integers and floating-point numbers. To eliminate floating-point arithmetic entirely, Lua provides a specific macro configuration within src/luaconf.h.

  1. Open src/luaconf.h in a text editor.

  2. Locate the configuration section for numeric types (LUA_FLOAT_TYPE).

  3. Set the floating-point type to none:

    #define LUA_FLOAT_TYPE LUA_FLOAT_NONE

  4. Define the desired integer width using LUA_INT_TYPE. For typical 32-bit microcontrollers (such as ARM Cortex-M0/M3), ensure it is set to a standard 32-bit integer:

    #define LUA_INT_TYPE LUA_INT_INT

    Alternatively, select LUA_INT_LONG or LUA_INT_LONGLONG depending on the target architecture's native register size.

Setting LUA_FLOAT_TYPE to LUA_FLOAT_NONE disables real numbers completely. The standard float division operator (/) will either be disabled or mirror integer floor division (//), and any syntax containing decimal points will produce a parsing error.

Configuring Lua 5.1 and 5.2

Older versions of Lua represent all numbers using a single numeric type (lua_Number), which defaults to double-precision floating-point (double). Converting older versions to integer-only requires redefining this type.

  1. Open src/luaconf.h.

  2. Locate the definition of LUA_NUMBER.

  3. Redefine LUA_NUMBER and its supporting macros to use standard integers:

    #define LUA_NUMBER_DOUBLE
/* Change to: */
#define LUA_NUMBER_INT
typedef int LUA_NUMBER;

  4. Adjust the conversion and formatting macros:

    #define LUA_NUMBER_SCAN         "%d"
#define LUA_NUMBER_FMT          "%d"
#define lua_number2str(s,sz,n)  l_sprintf((s), sz, LUA_NUMBER_FMT, (n))
#define lua_str2number(s,p)     strtol((s), (p), 10)

  5. Ensure the standard math.h functions (like floor, ceil, pow) are not called by replacing or undefining luai_num* macros with standard C integer operators.

Adjusting the Standard Libraries

An integer-only build cannot support functions that inherently rely on real numbers. You must trim or adapt the standard libraries in src/linit.c and src/lmathlib.c:

  • Disable the Math Library: The simplest approach is to remove luaopen_math from linit.c entirely to prevent compilation errors caused by missing transcendental math functions (sin, cos, exp, log).
  • Prune Floating Functions: If basic integer math functions are still required (such as math.abs, math.min, math.max, or integer pseudo-random generation), edit src/lmathlib.c and comment out any functions that call C standard library floating-point routines.

Cross-Compiling

When building the modified source with a cross-compiler (such as arm-none-eabi-gcc), pass flags to avoid linking software floating-point emulation routines:

make generic CC=arm-none-eabi-gcc AR="arm-none-eabi-ar rcu" RANLIB=arm-none-eabi-ranlib CFLAGS="-O2 -mthumb -mcpu=cortex-m0 -DLUA_FLOAT_TYPE=LUA_FLOAT_NONE"

Using these flags ensures the compiler emits pure integer instructions, producing a compact Lua runtime that runs natively on hardware lacking an FPU.
