How Lua Require Prevents Cyclic Dependencies

In the Lua programming language, cyclic dependencies between modules create the risk of infinite recursion and runtime deadlocks. Lua prevents these deadlocks through its internal caching mechanism centered around the package.loaded registry. By setting a placeholder boolean value in this table before running a module's code, the require function intercepts circular loading chains, allowing modules to load deterministically without entering an endless execution loop.

The Module Loading Sequence

When require(modname) is invoked in Lua, the runtime follows a structured sequence:

  1. Cache Inspection: It queries the package.loaded table for the key modname. If package.loaded[modname] is not nil or false, require immediately returns that value.
  2. Searchers Execution: If the module is not cached, Lua invokes the searcher functions in package.searchers (or package.loaders in Lua 5.1) to locate the file and obtain a loader function.
  3. Sentinel Assignment: Before invoking the module loader, Lua sets package.loaded[modname] = true.
  4. Chunk Execution: Lua runs the loader function, passing modname as an argument.
  5. Final Value Storage: If the loader returns a non-nil value, Lua assigns that value to package.loaded[modname]. If it returns nothing (or nil), the sentinel value (true) remains in the cache. Finally, require returns the value stored in package.loaded[modname].

How the Sentinel Prevents Cyclic Deadlocks

The critical step that prevents deadlocks is setting package.loaded[modname] = true before the module's chunk executes.

Consider two mutually dependent modules, Module A and Module B:

  • main.lua calls require("A").
  • Lua checks package.loaded["A"], finds it empty, sets package.loaded["A"] = true, and starts executing Module A.
  • During its execution, Module A calls require("B").
  • Lua checks package.loaded["B"], finds it empty, sets package.loaded["B"] = true, and starts executing Module B.
  • During its execution, Module B calls require("A").
  • Lua checks package.loaded["A"]. Because Module A previously marked its entry as true, Lua does not execute Module A again. Instead, it immediately returns true to Module B.
  • Module B completes its execution and returns its completed table to Module A.
  • Module A completes its execution and updates package.loaded["A"] with its own final module table.

Because the lookup resolves immediately on the secondary require call, execution flow does not recurse infinitely, avoiding a stack overflow or deadlock.

Implications for Module Design

While Lua stops the execution deadlock, cyclic dependencies can introduce incomplete references. In the scenario above, Module B receives true rather than Module A's final exported table, because Module A has not finished executing when Module B requests it.

To safely use cyclic references in Lua:

  • Export early: Assign the module table directly to package.loaded[modname] at the top of the file before requiring other modules.
  • Defer usage: Avoid calling functions from the dependent module at the file's root scope. Instead, reference those functions inside callback functions or methods that execute after both modules have finished their initialization phase.
