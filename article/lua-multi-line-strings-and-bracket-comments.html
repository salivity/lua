Lua Multi-Line Strings and Bracket Comments

In Lua, managing multi-line text and extended comments is handled through a versatile syntax known as "long brackets." By placing matching pairs of square brackets with an arbitrary number of equal signs between them, Lua allows developers to define multi-line string literals and block comments that can safely contain nested brackets or arbitrary code without requiring escape characters. This article explains how long bracket syntax operates, how the equal sign mechanism prevents parsing collisions, and how to apply these rules to both strings and comments.

Multi-Line String Literals

The basic syntax for a multi-line string in Lua uses double opening and closing square brackets:

local text = [[
This is a multi-line
string in Lua.
It preserves line breaks automatically.
]]

When using double brackets, Lua does not interpret escape sequences such as \n, \t, or \". Everything between the brackets is treated as raw text. Additionally, if the first character immediately following the opening bracket is a newline, Lua automatically discards it, making code formatting cleaner.

Using Equal Signs to Avoid Delimiter Collisions

A common issue occurs when the string itself contains closing brackets (]]), such as when storing Lua code, regular expressions, or XML/HTML snippets. Lua solves this by allowing any number of equal signs (=) between the opening and closing brackets:

local code_snippet = [=[
local array = data[items[1]]
print("Finished!")
]=]

To close the string, Lua searches strictly for a closing bracket sequence containing the exact same number of equal signs.

  • [==[ opens a string that can only be closed by ]==]
  • [===[ opens a string that can only be closed by ]===]

Any sequence with fewer or more equal signs (such as ]] or ]=]) will be treated as literal content:

local nested_example = [==[
Here is a string with [=[ mismatched ]=] brackets inside it.
It will only terminate at the matching tag.
]==]

Multi-Line Comments

Lua comments mirror the string literal syntax. Single-line comments begin with --, while multi-line (block) comments prepend -- to the long bracket syntax:

--[[
This is a multi-line comment.
All lines within these brackets are ignored by the compiler.
]]

Just like string literals, long bracket comments can use equal signs to enclose code blocks that already contain multi-line comments:

--[=[
--[[
This inner comment does not prematurely close the outer comment.
]]
local x = 10
--]=]

Key Rules and Behavior

  1. Equal Sign Symmetry: The number of equal signs in the opening delimiter must match the number of equal signs in the closing delimiter precisely.
  2. Leading Newlines: If the content starts immediately with a newline right after the opening delimiter ([[, [=[, etc.), that single newline is stripped. Any subsequent newlines are preserved.
  3. No Escaping: Backslash escaping is completely disabled inside long bracket literals. A sequence like \n remains two distinct characters: a backslash followed by the letter 'n'.
