Lua __concat Metamethod: Concatenating Custom Types

In Lua, the __concat metamethod allows developers to define custom concatenation behavior for non-primitive data types such as tables and userdata when using the .. operator. By default, attempting to concatenate a custom type with another value results in a runtime error because Lua only natively supports concatenation between strings and numbers. This article explains the purpose of __concat, how the Lua runtime evaluates it, and how to implement it to achieve clean, expressive string and object manipulation.

The Purpose of __concat

The primary purpose of the __concat metamethod is operator overloading for string concatenation. When Lua encounters the .. operator, it checks whether both operands are strings or numbers. If either operand is a table or userdata, Lua bypasses default string coercion and searches for a __concat metamethod in the metatables of the operands.

Without __concat, custom data structures cannot interact with string operations directly, forcing developers to write verbose explicit conversion functions (such as myObject:toString() .. " text"). With __concat, you can write idiomatic code like myObject .. " text".

How Lua Resolves __concat

When evaluating a .. b, Lua searches for the metamethod using a specific precedence rule:

  1. Lua inspects the metatable of the first operand (a). If it contains a __concat field, Lua invokes that function.
  2. If a does not define __concat, Lua inspects the metatable of the second operand (b). If present, it executes that function.
  3. If neither operand provides a __concat metamethod, Lua throws a runtime error stating that it cannot concatenate the types.

The resolved function receives two arguments: the left-hand operand and the right-hand operand, in that exact order, regardless of which operand provided the metatable.

Implementation Example

To implement custom concatenation, define the __concat function inside the table's metatable. The function must accept two parameters and return the resulting value (typically a string or a new instance of the custom type).

local Vector = {}
Vector.__index = Vector

function Vector.new(x, y)
    local self = setmetatable({}, Vector)
    self.x = x
    self.y = y
    return self
end

-- Define the __concat metamethod
Vector.__concat = function(a, b)
    -- Helper to convert an operand to string format
    local function to_str(val)
        if type(val) == "table" and val.x and val.y then
            return string.format("(%d, %d)", val.x, val.y)
        end
        return tostring(val)
    end

    return to_str(a) .. to_str(b)
end

local v1 = Vector.new(3, 4)
local v2 = Vector.new(5, 6)

-- Concatenating custom types with strings
print("Position: " .. v1)        --> Output: Position: (3, 4)

-- Concatenating two custom types together
print(v1 .. " connects to " .. v2) --> Output: (3, 4) connects to (5, 6)

Key Considerations

  • Type Checking: Because the metamethod can be invoked when either operand carries the metatable, the function must be capable of handling cases where one operand is a string, number, or entirely different type.
  • Return Types: Although __concat typically returns a string, Lua does not enforce this. It can return any value, such as a new merged custom object, though returning a string remains the standard convention to preserve developer expectations regarding the .. operator.
