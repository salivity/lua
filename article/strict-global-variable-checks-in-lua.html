Strict Global Variable Checks in Lua

Lua creates global variables by default whenever an undeclared variable is assigned, which often introduces silent bugs caused by simple typos. This article demonstrates how to eliminate these errors by intercepting undeclared reads and writes using metatables on Lua's global environment, and how to augment this runtime safety with static analysis tools.

The Problem with Implicit Globals

In standard Lua, forgetting the local keyword does not raise an error. Instead, the runtime assigns the value to the global table _G:

function calculate_total(price, tax)
    ttoal = price + tax -- Typo creates an unintended global
    return ttoal
end

Because reading a nonexistent global simply returns nil, typos in variable names can propagate silently through an application until they cause hard-to-trace runtime failures.

Enforcing Strict Globals with Metatables

The standard way to restrict global variable creation is by attaching a metatable to the global environment table (_G). By intercepting the __newindex (write) and __index (read) metamethods, you can throw an explicit error whenever an unauthorized global variable is accessed.

Here is a minimal, robust implementation:

local declared = {}

setmetatable(_G, {
    __newindex = function(t, name, value)
        if not declared[name] then
            error("Attempt to write to undeclared global variable: " .. tostring(name), 2)
        end
        rawset(t, name, value)
    end,

    __index = function(t, name)
        if not declared[name] then
            error("Attempt to read undeclared global variable: " .. tostring(name), 2)
        end
        return nil
    end,
})

-- Function to explicitly register permitted globals
function global(name, value)
    declared[name] = true
    rawset(_G, name, value)
end

How It Works:

  1. __newindex: Triggers whenever a script attempts to assign a value to a key that does not already exist in _G. If the key is not in declared, it raises an error.
  2. __index: Triggers whenever code attempts to read a key from _G that does not exist. It prevents accessing nonexistent globals that would normally return nil.
  3. rawset: Bypasses the metatable to actually write the approved variable to _G without re-triggering __newindex.
  4. error(..., 2): Sets the error level to 2 so the traceback points directly to the offending line of code rather than the metatable function itself.

Using the Canonical strict.lua

The official Lua distribution includes a standard utility called strict.lua. It allows declaring globals inside the main chunk while throwing errors if an undeclared global is assigned inside a function.

To use it:

  1. Download or locate strict.lua from your Lua distribution.
  2. Require it at the very top of your application entry point before loading other modules:
require("strict")

-- Valid in main chunk (depending on configuration)
MyGlobal = "Allowed here"

function test()
    bad_var = 123 -- Throws: "variable 'bad_var' is not declared"
end

Modern Lua: Controlling _ENV (Lua 5.2+)

In Lua 5.2 and newer, global resolution is scoped to the _ENV table. You can protect a specific module or chunk by assigning an empty or strictly checked table to _ENV:

-- Isolate a chunk's environment
local _ENV = setmetatable({}, {
    __index = _G, -- Fallback to standard libraries
    __newindex = function(_, k, _)
        error("Global creation disabled. Cannot set: " .. tostring(k), 2)
    end
})

local x = 10 -- OK: local variable
y = 20       -- Error: Global creation disabled. Cannot set: y

Static Analysis with Luacheck

While runtime metatable checks catch errors during execution, static analysis prevents undeclared globals before the code runs. Luacheck is the standard linter for Lua.

  1. Install Luacheck via Luarocks:

    luarocks install luacheck

  2. Run it against your source files:

    luacheck src/

Luacheck automatically reports:

  • Accessing undeclared globals (warning 111)
  • Setting undeclared globals (warning 112)
  • Unused local variables (warning 211)

You can define intentional globals in a .luacheckrc configuration file:

globals = { "describe", "it" } -- Whitelist test framework globals

Combining the runtime metatable check with Luacheck during continuous integration provides full coverage against unintentional global leaks.
