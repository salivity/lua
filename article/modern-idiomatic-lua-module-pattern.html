Modern Idiomatic Lua Module Pattern

This guide covers the modern, idiomatic pattern for declaring, populating, and returning modules in the Lua programming language. In contemporary Lua (5.2, 5.3, 5.4, and LuaJIT), developers have moved away from the deprecated module() function in favor of a lexical scoping pattern using plain Lua tables. You will learn the standard structure for defining private and public members, the advantages of this approach, and the variations accepted in production code.

The Standard Idiomatic Pattern

The standard way to create a module in Lua is to declare a local table, attach functions and fields to it, and return the table at the end of the file.

-- mymodule.lua
local M = {}

-- Private variable (scoped only to this file)
local DEFAULT_GREETING = "Hello"

-- Private function
local function format_message(greeting, name)
    return string.format("%s, %s!", greeting, name)
end

-- Public constant
M.VERSION = "1.0.0"

-- Public function
function M.greet(name)
    return format_message(DEFAULT_GREETING, name)
end

-- Another public function syntax
M.farewell = function(name)
    return format_message("Goodbye", name)
end

return M

To consume this module in another file:

local mymodule = require("mymodule")

print(mymodule.greet("World")) -- Output: Hello, World!
print(mymodule.VERSION)        -- Output: 1.0.0

Breakdown of the Pattern

  1. Table Declaration: local M = {} creates a local table. The name M is widely used as a convention for "module," though descriptive names like local mymodule = {} are also common.
  2. Lexical Privacy: Any variable or function prefixed with local remains inaccessible outside this file chunk. This enforces encapsulation naturally without runtime overhead.
  3. Exporting Members: Adding keys to M (e.g., M.greet = ... or function M.greet() ... end) exposes them to the consumer.
  4. Explicit Return: The file ends with return M. require() caches and returns this table to whatever script imports it.

Alternative: The Revealing Module Pattern

An alternative idiomatic approach defines all functions locally first, then constructs and returns the export table at the bottom.

-- math_utils.lua
local function add(a, b)
    return a + b
end

local function subtract(a, b)
    return a - b
end

local function internal_calc(x)
    return x * 2
end

return {
    add = add,
    subtract = subtract,
}

Advantages of the Revealing Pattern:

  • Internal calls between module functions avoid table lookups (e.g., add(x, y) is faster than M.add(x, y)).
  • Explicitly separates the API definition from function implementations.

Why the Legacy module() Function Was Replaced

In Lua 5.1, modules were often declared using module("mymodule", package.seeall). This pattern is obsolete and considered bad practice because:

  • Global Namespace Pollution: It automatically assigned the module into the global environment _G.
  • Security & Performance: package.seeall exposed the global table inside the module, introducing lookup overhead and potential security vulnerabilities.
  • Deprecation: The module() function was deprecated in Lua 5.2 and completely removed in Lua 5.3.

The modern local-table pattern relies strictly on Lua's basic scoping rules, works identically across Lua 5.1, 5.2, 5.3, 5.4, and LuaJIT, and avoids polluting the global namespace.
