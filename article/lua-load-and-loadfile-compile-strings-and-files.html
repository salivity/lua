Lua load and loadfile: Compile Strings and Files

In the Lua programming language, dynamic code execution is achieved by compiling source code at runtime into executable chunks. This article explains how the load and loadfile functions parse raw strings and external files, transform them into anonymous functions, handle syntax errors, and execute the compiled bytecode safely within defined environments.

The load Function: Compiling Raw Strings

The load function takes a string containing valid Lua code (or a reader function) and compiles it into an anonymous function, commonly called a chunk. It does not execute the code immediately; instead, it returns a callable function if the syntax is valid.

Syntax and Basic Usage

local chunk, err = load(chunk_string, chunk_name, mode, env)
  • chunk_string: The string of code to compile.
  • chunk_name (optional): An identifier used in error messages and debug traces.
  • mode (optional): Controls whether the chunk can be text ("t"), binary bytecode ("b"), or either ("bt").
  • env (optional): The environment table assigned as _ENV for the chunk.

If compilation succeeds, load returns the compiled function. If there is a syntax error, it returns nil followed by the error message.

local code = "local x, y = 10, 20; return x + y"
local compiled_func, err = load(code)

if not compiled_func then
    print("Compilation error: " .. err)
else
    local result = compiled_func()
    print("Result: " .. result) -- Outputs: Result: 30
end

The loadfile Function: Compiling External Files

The loadfile function operates similarly to load, but it reads and compiles Lua code directly from a specified file on disk instead of an in-memory string.

Syntax and Basic Usage

local chunk, err = loadfile(filename, mode, env)
  • filename: The path to the file. If omitted, it reads from standard input.
  • mode and env: Serve the same roles as in load.

Like load, loadfile does not run the file; it prepares it for execution.

-- Assume 'script.lua' contains: print("Hello from external file!")
local run_script, err = loadfile("script.lua")

if not run_script then
    print("Failed to load file: " .. err)
else
    run_script() -- Executes the file contents
end

Executing Compiled Chunks and Passing Arguments

Because compiled chunks are regular Lua functions, they can accept arguments and return values. Arguments passed to the compiled function are received inside the chunk via the vararg expression (...).

local multiplier = load("local a, b = ...; return a * b")
local product = multiplier(6, 7)
print(product) -- Outputs: 42

To safely catch runtime errors (as opposed to compile-time syntax errors), invoke the compiled function using pcall:

local safe_func = load("error('Runtime failure!')")
local success, result_or_err = pcall(safe_func)

if not success then
    print("Caught error: " .. result_or_err)
end

Controlling the Environment (Sandboxing)

In modern Lua (5.2 and later), both load and loadfile accept an optional env argument. This defines the _ENV upvalue for the compiled code, allowing you to isolate untrusted code from standard global variables like os, io, or package.

local untrusted_code = "return math.sqrt(value)"

-- Restrict the environment to safe functions only
local sandbox_env = {
    math = { sqrt = math.sqrt },
    value = 64
}

local sandboxed_func = load(untrusted_code, "sandbox", "t", sandbox_env)
print(sandboxed_func()) -- Outputs: 8

If the untrusted code attempts to access unauthorized globals, such as os.execute, it will receive nil, preventing unauthorized actions.
