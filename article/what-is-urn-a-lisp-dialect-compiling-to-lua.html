What Is Urn: A Lisp Dialect Compiling to Lua

Urn is an open-source, minimalist Lisp dialect that compiles directly into standard Lua code. This article provides an overview of what Urn is, why it was created, and how its compilation pipeline transforms S-expressions into fast, idiomatic Lua. You will learn about Urn’s powerful macro system, its deep interoperability with existing Lua environments, and the optimization steps it uses to generate lightweight output suitable for games and embedded scripts.

Understanding Urn

Urn is a Lisp-1 dialect designed specifically for developers who prefer the syntactic flexibility and metaprogramming features of Lisp, but require the portability and embeddable nature of Lua. Lua is widely used in game engines, embedded systems, and scripting layers, but lacks native compile-time macros and functional list-processing idioms.

Urn bridges this gap by letting developers write modular, expressive Lisp code that targets Lua 5.1, 5.2, 5.3, and LuaJIT runtimes without adding significant runtime overhead.

How the Urn Compiler Works

Urn acts as an ahead-of-time (AOT) transpiler. Instead of shipping a heavy virtual machine, the compiler translates Urn source code through a series of discrete phases into native Lua text:

  1. Lexing and Parsing: The compiler ingests Urn source code, converting parentheses and S-expressions into an internal Abstract Syntax Tree (AST).
  2. Macro Expansion: Urn executes macros at compile time. Because Urn is written in Urn and runs on top of a Lua engine, the compiler evaluates compile-time expressions in a sandboxed environment to modify and rewrite the AST.
  3. Semantic Analysis and Scope Resolution: Urn verifies variable bindings, resolves lexical scopes, and enforces lexical scoping rules, preventing runtime variable collisions.
  4. Optimization Pipeline: Before outputting Lua, the compiler performs aggressive static analysis and optimization passes, including:
    • Dead-code elimination: Unused functions, imported libraries, and dangling bindings are stripped out.
    • Constant folding: Simple arithmetic and static expressions are resolved ahead of time.
    • Inlining: Small functions and wrappers are embedded directly at their call sites to eliminate call overhead.
  5. Code Generation: The optimized AST is emitted as readable, idiomatic Lua source code that can be run directly by any standard Lua interpreter.

Seamless Lua Interoperability

One of Urn's primary design goals is friction-free interoperability with existing Lua libraries. Calling Lua functions from Urn does not require complex foreign function interface (FFI) bindings.

Urn provides native syntax forms to index Lua tables, call global functions, and pass data structures back and forth. Basic data types like numbers, strings, booleans, and nil map directly to their Lua equivalents. For compound structures, Urn maps its core collections onto Lua tables while preserving functional programming idioms like pattern matching and higher-order functions.

Advantages of Using Urn

  • Full Metaprogramming: Unlike vanilla Lua, Urn features a complete Lisp macro system, allowing developers to create custom domain-specific languages (DSLs) and reduce boilerplate code.
  • Zero Runtime Overhead: Thanks to dead-code elimination and direct translation to Lua constructs, the generated code often performs comparably to hand-written Lua.
  • Drop-in Deployment: Because the final build artifact is plain Lua, projects written in Urn can be integrated into existing Lua runtimes (such as LÖVE, Defold, or Neovim) without altering the host application's binary.
