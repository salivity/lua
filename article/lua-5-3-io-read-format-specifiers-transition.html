Lua 5.3 io.read Format Specifiers Transition

The transition of io.read format specifiers in Lua 5.3 marked a significant shift toward cleaner, more modern standard library conventions by removing the legacy asterisk prefix from read formats. Prior to Lua 5.3, developers relied on formats such as "*all", "*line", and "*number" (often shortened to "*a", "*l", and "*n"). With the release of Lua 5.3, the language streamlined these options into concise single-character strings—"a", "l", "L", and "n"—while retaining backward compatibility for older scripts.

Legacy Formatting in Lua 5.2 and Earlier

In Lua 5.0 through Lua 5.2, reading from standard input or file handles via io.read or file:read required string arguments prefixed with an asterisk. The primary options included:

  • "*a" (or "*all"): Read the entire remaining content of the file.
  • "*l" (or "*line"): Read the next line, stripping the newline character.
  • "*L": Introduced in Lua 5.2, read the next line while preserving the newline character.
  • "*n" (or "*number"): Read a number from the input stream.
  • Numerical values: Read a specific number of bytes or characters (e.g., file:read(10)).

The leading asterisk was originally introduced to distinguish string-based specifiers from numeric byte-length arguments and avoid name collisions.

The Lua 5.3 Simplification

Lua 5.3 eliminated the need for the asterisk prefix. The standard library updated the accepted format descriptors to single-character identifiers:

  • "a": Reads the entire file, returning an empty string at the end of the file.
  • "l": Reads the next line without the end-of-line delimiter. This remains the default behavior if no format is provided.
  • "L": Reads the next line and preserves the end-of-line delimiter.
  • "n": Reads a numeral, returning a float or an integer according to Lua 5.3's unified arithmetic engine.

Supplying a positive integer directly to specify the exact number of characters or bytes to read remained unchanged.

-- Legacy syntax (Lua 5.2 and earlier)
local all_data = io.read("*a")
local num = io.read("*n")
local line = io.read("*l")

-- Modern syntax (Lua 5.3+)
local all_data = io.read("a")
local num = io.read("n")
local line = io.read("l")

Rationale Behind the Change

The redesign was part of a broader effort in Lua 5.3 to modernize the language's core libraries, reduce unnecessary punctuation, and establish syntactic consistency across formatting modules.

  1. Syntactic Cleanliness: Dropping the asterisk made file I/O operations less verbose and more intuitive for programmers coming from other languages.
  2. Alignment with Other Subsystems: Lua 5.3 introduced string.pack and string.unpack, which heavily rely on single-character format descriptors (like "i", "s", "c") without special prefixes. Modernizing io.read aligned file parsing with this convention.
  3. Disambiguation Without Prefixing: The Lua runtime uses type checking to distinguish formats. Because numeric byte reads are passed as integers and specifiers are passed as strings, the asterisk was redundant for disambiguation.

Backward Compatibility

To prevent breaking existing codebases, Lua 5.3 retained backward compatibility for the asterisk-prefixed specifiers. The internal C implementation was updated to check whether the first character of a string format is '*'. If present, the engine simply skips the asterisk and processes the next character. As a result, older formats like "*n" and "*a" continue to function transparently in Lua 5.3 and Lua 5.4.
