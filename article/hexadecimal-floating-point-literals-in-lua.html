Hexadecimal Floating-Point Literals in Lua

Lua provides native support for hexadecimal floating-point literals, allowing programmers to define floating-point constants using a base-16 significand and a base-2 exponent. This notation mirrors the C99 standard specification, ensuring that binary floating-point numbers can be represented exactly as they are stored in memory without decimal rounding inaccuracies. This article explains the syntax, internal evaluation mechanics, and practical use cases of hexadecimal floats in Lua.

Anatomy of the Syntax

A hexadecimal floating-point literal in Lua consists of three distinct parts: the hexadecimal prefix, the significand (or mantissa), and the binary exponent indicator.

A standard literal adheres to this format:

0x[integer_part].[fractional_part]p[exponent]
  1. Prefix (0x or 0X): Instructs the Lua parser to interpret the digits as base-16.
  2. Significand: Contains hexadecimal digits (0–9 and a–f or A–F). The radix point (.) is optional if an exponent is provided. Unlike standard decimal fractions where places represent negative powers of 10, each fractional place represents a negative power of 16 (\(16^{-1} = 0.0625\), \(16^{-2} = 0.00390625\), etc.).
  3. Exponent Separator (p or P): Distinguishes the significand from the exponent. The letter p stands for "power" (since e is already a valid hexadecimal digit).
  4. Exponent Value: Written as a decimal integer (not hexadecimal), which may be positive or negative. This number represents the power of two (not 16 or 10) by which the significand is multiplied.

Mathematical Evaluation

The mathematical value of a Lua hex float is calculated using the following formula:

\[\text{Value} = \text{Significand}_{16} \times 2^{\text{Exponent}_{10}}\]

Consider the following examples:

  • 0x1p0 evaluates to \(1 \times 2^0 = 1.0\).
  • 0x1p4 evaluates to \(1 \times 2^4 = 16.0\).
  • 0x1p-2 evaluates to \(1 \times 2^{-2} = 0.25\).
  • 0x0.8p0 evaluates to \((8 \times 16^{-1}) \times 2^0 = 0.5\).
  • 0x1.8p1 evaluates to \((1 + 8 \times 16^{-1}) \times 2^1 = 1.5 \times 2 = 3.0\).
  • 0xA.Cp2 evaluates to \((10 + 12 \times 16^{-1}) \times 2^2 = 10.75 \times 4 = 43.0\).

Why Lua Uses Base-2 Exponents

While the digits of the significand are base-16, the exponent scales the number by powers of two. Because 16 is a power of two (\(2^4\)), hexadecimal digits map directly to 4-bit nibbles in IEEE 754 binary floating-point formats. Using a power-of-two exponent allows the literal to shift the binary point bit-by-bit without causing fractional inaccuracies or requiring intermediary rounding.

Practical Applications

Writing floating-point values in decimal notation often introduces precision issues. Numbers like 0.1 cannot be stored precisely in binary floating-point representation, leading to small rounding discrepancies.

Hexadecimal floating-point notation solves this problem:

  • Exact Value Preservation: Every valid IEEE 754 double-precision number has an exact, finite hexadecimal representation.
  • Lossless Serialization: Exporting floating-point numbers via string.format("%a", number) produces hexadecimal float notation, guaranteeing that re-importing the string into Lua reproduces the exact same binary value bit-for-bit.
  • Bit-Level Debugging: It allows systems developers, game programmers, and graphics engineers to reason about floating-point bit patterns directly within Lua source code.
