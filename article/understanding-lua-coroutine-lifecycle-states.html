Understanding Lua Coroutine Lifecycle States

Coroutines in the Lua programming language provide a collaborative multithreading mechanism that allows execution to be paused and resumed at specific points. Throughout its lifecycle, a coroutine transitions between four distinct operational states: suspended, running, normal, and dead. You can query the current state of any coroutine at runtime by passing its thread object to the coroutine.status() function.

1. Suspended

A coroutine enters the suspended state in two scenarios:

  • Upon Creation: When a coroutine is created using coroutine.create(), it does not start executing immediately. Instead, it is initialized and set to the suspended state, waiting to be triggered.
  • Upon Yielding: When a running coroutine calls coroutine.yield(), it voluntarily pauses its execution, saves its current execution context, and returns control to the caller. The coroutine remains in the suspended state until it is explicitly resumed.

2. Running

A coroutine is in the running state when it is actively executing its body on the processor. If coroutine.status() is called from within the currently executing coroutine (for example, by passing coroutine.running()), the returned status will be running.

3. Normal

The normal state applies to a coroutine that is active but not currently executing because it has resumed another coroutine.

For example, if Coroutine A invokes coroutine.resume() on Coroutine B, Coroutine B becomes running, while Coroutine A enters the normal state. Coroutine A is neither running (it is not actively executing commands) nor suspended (it is not waiting to be directly resumed from an external caller; it is waiting for Coroutine B to finish or yield). Once Coroutine B yields or completes, Coroutine A transitions back to running.

4. Dead

A coroutine transitions to the dead state when its lifecycle has ended. This occurs under two conditions:

  • Natural Completion: The main function of the coroutine finishes execution and returns.
  • Runtime Error: An unhandled error occurs inside the coroutine during its execution, halting the thread.

Once a coroutine is dead, it cannot be resumed. Attempting to call coroutine.resume() on a dead coroutine will result in an error or return false accompanied by an error message.

Summary of State Transitions

  1. Creation: coroutine.create() \(\rightarrow\) Suspended
  2. Start / Resume: coroutine.resume() \(\rightarrow\) Running
  3. Sub-call: Resumes another coroutine \(\rightarrow\) Normal
  4. Pause: coroutine.yield() \(\rightarrow\) Suspended
  5. Termination: Function return or unhandled error \(\rightarrow\) Dead
