Can Lua Goto Jump Into Local Variable Scope?

In the Lua programming language, a goto statement cannot jump into the scope of a local variable. If a jump bypasses the declaration of a local variable to reach a label where that variable would be visible, the Lua compiler rejects the code with a syntax error. This article explains the technical rules governing goto jumps, demonstrates the resulting compiler errors, and details the standard workarounds to structure jumps cleanly.

The Rule: Jumps Cannot Enter Local Scopes

Lua introduced the goto statement in version 5.2. According to the official language specification, a jump cannot enter the scope of a local variable. A label is visible throughout the entire block where it is defined, but a goto can only jump to a label if that jump does not bring a new local variable into scope without executing its declaration.

The Invalid Pattern

The following code illustrates an illegal jump:

goto target

local x = 10

::target::
print("Reached target")

When compiling this code, Lua produces a syntax error:

<goto target> at line 1 jumps into the scope of local 'x'

Because ::target:: resides in the same block as local x, the variable x is in scope at the label. Jumping directly to ::target:: skips the allocation and initialization of x, which Lua forbids to prevent undefined states in its register-based virtual machine.

Permitted Jumps

While jumping into a local scope is forbidden, Lua permits jumping out of a scope or within the same scope without crossing over declarations.

1. Jumping Out of a Scope

A goto can exit an inner block to an outer block. Doing so properly closes any local variables defined in the inner scope:

while true do
    local temp = "processing"
    if condition then
        goto exit_loop -- Valid: exits the scope of 'temp'
    end
end

::exit_loop::
print("Loop exited")

2. Variable Declared Before the Jump

If the local variable is declared prior to the goto statement, jumping forward to a label within that same variable's scope is completely valid:

local x = 10

goto target -- Valid: 'x' is already in scope prior to the jump

print("This is skipped")

::target::
print(x) -- Prints 10

How to Resolve the Error

If a jump must bypass code containing local variables, use explicit do ... end blocks to restrict the lifetime of those variables.

goto target

do
    local x = 10
    print("Inside block: " .. x)
end

::target::
print("Valid jump: 'x' is out of scope here")

By confining local x to the do ... end block, the label ::target:: no longer falls within the scope of x, allowing the jump to compile successfully.
