Unsigned Integer Comparison with math.ult in Lua

Modern versions of Lua treat integers as signed 64-bit values by default, which can cause unexpected results when working with binary data, bitmasks, or unsigned integer formats. The math.ult function solves this issue by enabling unsigned "less than" comparisons without requiring manual bit-manipulation workarounds. This article explains the underlying signed integer problem in Lua, how math.ult evaluates operands at the engine level, and how to apply it effectively in your code.

The Problem: Signed Arithmetic in Lua

Starting in Lua 5.3, the language introduced a dedicated integer subtype using standard two's complement representation, typically spanning 64 bits (-2^63 to 2^63 - 1). When values represent unsigned data (such as memory addresses or network protocols), the standard comparison operator < fails because it respects the sign bit.

For example, the hexadecimal value 0xFFFFFFFFFFFFFFFF represents -1 as a signed 64-bit integer, but 18,446,744,073,709,551,615 as an unsigned integer. Using standard operators:

local a = -1  -- 0xFFFFFFFFFFFFFFFF
local b = 10

print(a < b) -- Outputs: true (because -1 < 10)

In an unsigned context, a should be considered greater than b.

How math.ult Works

The math.ult(m, n) function takes two integers, m and n, and returns true if m is strictly less than n when both operands are interpreted as unsigned integers.

Under the hood, modern Lua engines implement math.ult directly in the C source (lmathlib.c). Instead of performing arithmetic emulation in bytecode, the C implementation casts both Lua integers (lua_Integer) to their unsigned equivalent (lua_Unsigned, typically standard C's uint64_t):

static int math_ult (lua_State *L) {
  lua_Integer m = luaL_checkinteger(L, 1);
  lua_Integer n = luaL_checkinteger(L, 2);
  lua_pushboolean(L, (lua_Unsigned)m < (lua_Unsigned)n);
  return 1;
}

By casting to unsigned types, the CPU ignores the sign bit semantics and executes a native unsigned hardware comparison instruction. This makes math.ult virtually as fast as native signed comparisons while preventing overflow or underflow issues.

Practical Usage

Using math.ult, the previous comparison behaves correctly according to unsigned rules:

local a = -1
local b = 10

print(math.ult(a, b)) -- Outputs: false
print(math.ult(b, a)) -- Outputs: true

Deriving Other Relational Comparisons

While Lua provides only math.ult out of the box, all other unsigned relational comparisons can be derived directly from it:

  • Unsigned Greater Than (>): math.ult(n, m)
  • Unsigned Less Than or Equal (<=): not math.ult(n, m)
  • Unsigned Greater Than or Equal (>=): not math.ult(m, n)
  • Equality (== and ~=): Can use standard == and ~=, because two's complement bit patterns are identical between signed and unsigned values for identical bit representations.
