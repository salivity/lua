Lua Bitwise Shifts with Negative Offsets

In the Lua programming language, bitwise shift operations handle negative offsets by reversing the direction of the shift rather than causing an error or undefined behavior. Introduced natively in Lua 5.3, the bitwise left shift (<<) and right shift (>>) operators invert their actions when passed a negative displacement integer. This behavior provides a predictable, symmetric mechanism for bit manipulation directly within the language's core specifications.

Direction Reversal Mechanism

When a negative displacement is supplied to either shift operator, Lua automatically executes the opposite operation using the absolute value of the offset:

  • Shifting left by a negative offset x << -y is strictly equivalent to shifting right by the positive offset: x >> y.
  • Shifting right by a negative offset x >> -y is strictly equivalent to shifting left by the positive offset: x << y.

Unlike languages such as C, C++, or Java, where shifting by a negative number results in undefined behavior or requires masking, Lua cleanly defines this interaction to prevent runtime faults.

Zero-Filling and Logical Shifts

Lua performs logical shifts, meaning vacant bit positions are always filled with zeros regardless of whether the operand is positive or negative. The sign bit is not preserved during right shifts.

Consider the following examples:

-- Normal left shift
print(2 << 2)   -- Output: 8

-- Negative left shift acts as a right shift
print(8 << -2)  -- Output: 2

-- Normal right shift
print(16 >> 2)  -- Output: 4

-- Negative right shift acts as a left shift
print(4 >> -2)  -- Output: 16

Magnitude Boundaries and Underflow

Lua integers are typically 64-bit signed values (two's complement). When the absolute value of a shift offset is equal to or greater than the bit width of the integer representation (typically 64 bits), the result is always 0:

-- Shifting 64 bits or more in either direction results in 0
print(16 << -64) -- Output: 0 (equivalent to 16 >> 64)
print(16 >> -64) -- Output: 0 (equivalent to 16 << 64)

Because of this rule, any negative offset with a magnitude of 64 or greater clears all bits, yielding zero.
