How lua_typename Works in the Lua C API

The lua_typename function in the Lua C API converts numeric type indicators into human-readable string descriptions through a direct, constant-time array lookup. By taking a lua_State pointer and an integer constant representing a type, the function maps internal engine tags—such as LUA_TNUMBER or LUA_TTABLE—to static string literals like "number" or "table". This mechanism provides developers with a zero-allocation, thread-safe method to inspect and debug Lua types directly within C host applications.

Numeric Type Constants

In Lua, every basic data type is assigned an integer constant defined in lua.h. These constants range from -1 to 8:

  • LUA_TNONE (-1): Represents an invalid index or a non-existent value.
  • LUA_TNIL (0): Represents nil.
  • LUA_TBOOLEAN (1): Represents boolean values.
  • LUA_TLIGHTUSERDATA (2): Represents light userdata (raw C pointers).
  • LUA_TNUMBER (3): Represents integers and floating-point numbers.
  • LUA_TSTRING (4): Represents strings.
  • LUA_TTABLE (5): Represents tables.
  • LUA_TFUNCTION (6): Represents Lua functions and C functions.
  • LUA_TUSERDATA (7): Represents full userdata (managed memory).
  • LUA_TTHREAD (8): Represents coroutines.

When you call lua_type(L, index), the engine retrieves the value at the given stack index, inspects its internal tagged value (TValue), and returns the corresponding integer tag.

Internal Lookup Mechanism

Rather than relying on conditional switch statements or dynamic string formatting, the Lua core maintains a predefined, static array of string literals within ltm.c (often named luaT_typenames_).

The array is laid out in exact alignment with the sequential values of the type constants:

static const char *const luaT_typenames_[LUA_TOTALTYPES] = {
    "no value",
    "nil", "boolean", "userdata", "number",
    "string", "table", "function", "userdata", "thread"
};

Because LUA_TNONE has a value of -1, the internal implementation shifts the incoming type tag by +1 to map it into a zero-based C array index.

The implementation of lua_typename behaves essentially as:

const char *lua_typename (lua_State *L, int tp) {
    UNUSED(L);
    return (tp == LUA_TNONE) ? "no value" : luaT_typenames_[tp + 1];
}

If an out-of-bounds integer is passed that does not correspond to any valid type, the function accounts for bounds checking and falls back to "no value".

Memory Safety and Performance

The strings returned by lua_typename reside in the static data segment of the compiled Lua library binary. Because the returned const char* points directly to program memory rather than Lua-managed memory:

  • No Garbage Collection: The returned pointer is never subject to garbage collection, so it remains valid throughout the lifecycle of the host application.
  • Zero Allocation: The conversion does not allocate memory on the heap, ensuring predictable performance in low-latency environments.
  • No Mutability: The memory is read-only, meaning callers should not attempt to free, modify, or cast away the const qualifier of the returned pointer.
