Lua State Machines with Mutual Tail Calls

This article explores implementing finite state machines (FSM) in Lua using mutual tail calls. By leveraging Lua’s proper tail-call optimization, developers can represent states directly as functions that call one another upon transition without causing a stack overflow. Below, you will learn the core mechanics behind this architectural pattern, observe a working code implementation, and understand critical syntax rules required to maintain proper tail calls.

How Tail Calls Enable State Transitions

In Lua, a function call is considered a proper tail call when it is executed as the final action of another function using the syntax return func(args). When this occurs, the Lua runtime does not allocate a new stack frame for the called function. Instead, it reuses the current stack frame.

Because Lua guarantees proper tail calls without stack growth, two or more functions can call each other indefinitely. In the context of a finite state machine, this means every individual state can be modeled as an isolated function. Transitioning to a new state simply requires returning a call to the target state function. This eliminates the need for explicit state variables, large switch/if-else blocks, or external transition-dispatch loops.

Implementing a State Machine

To implement mutual tail calls between states, state functions must be forward-declared so they can reference each other regardless of their definition order. Persistent machine context can be passed down as arguments during each transition.

Here is an example representing a simple turnstile state machine:

-- Forward-declare state functions
local locked, unlocked

-- Implementation of the 'locked' state
locked = function(tokens, action)
    if action == "coin" then
        print("Coin accepted. Unlocking turnstile.")
        return unlocked(tokens + 1)
    elseif action == "push" then
        print("Turnstile is locked. Cannot pass.")
        return locked(tokens)
    elseif action == "exit" then
        print("Shutting down. Total coins collected: " .. tokens)
        return tokens
    end
end

-- Implementation of the 'unlocked' state
unlocked = function(tokens, action)
    if action == "coin" then
        print("Coin refunded. Turnstile already unlocked.")
        return unlocked(tokens)
    elseif action == "push" then
        print("Pushed through. Locking turnstile.")
        return locked(tokens)
    elseif action == "exit" then
        print("Shutting down. Total coins collected: " .. tokens)
        return tokens
    end
end

-- Initial state entry
local state = locked(0, "push")
state = locked(0, "coin")
state = unlocked(1, "push")

If the machine needs to process an interactive stream of inputs, the state functions can yield through coroutines or request the next input token directly from an event queue:

local state_a, state_b

state_a = function(context)
    local event = coroutine.yield("In State A")
    if event == "go_b" then
        return state_b(context)
    end
    return state_a(context)
end

state_b = function(context)
    local event = coroutine.yield("In State B")
    if event == "go_a" then
        return state_a(context)
    end
    return state_b(context)
end

local fsm = coroutine.create(state_a)
print(select(2, coroutine.resume(fsm, {})))     -- Output: In State A
print(select(2, coroutine.resume(fsm, "go_b"))) -- Output: In State B
print(select(2, coroutine.resume(fsm, "go_a"))) -- Output: In State A

Critical Syntax Rules for Tail Calls

To prevent unintentional stack overflows, the tail call must strictly match Lua’s tail-call syntax:

  1. Direct Return: The call must be written strictly as return target_function(args).
  2. No Expressions: Writing return (target_function(args)) with parentheses wraps the call in an expression, which forces Lua to adjust the return values to a single result before returning, breaking the tail call.
  3. No Post-Call Operations: Returning a computation such as return 1 + target_function(args) or performing clean-up operations after the call prevents the frame from being recycled.
