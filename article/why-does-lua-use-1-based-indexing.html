Why Does Lua Use 1-Based Indexing?

The Lua programming language uses 1-based indexing primarily because it was designed for non-programmers, draws from mathematical convention rather than hardware architecture, and inherits syntax from its predecessor languages. While languages like C use 0-based indexing to represent memory address offsets, Lua abstracts away low-level memory management to favor human-friendly counting. This article explains the historical context, linguistic roots, and design philosophies that led Lua's creators to start array counting at one instead of zero.

Designed for Non-Programmers

Lua was developed in 1993 at the Pontifical Catholic University of Rio de Janeiro (PUC-Rio) in Brazil. The language was commissioned to solve software challenges for Petrobras, the Brazilian state oil company. The primary users were not professional software engineers or computer scientists, but geologists, petroleum engineers, and administrative staff who needed a simple configuration and scripting language.

To non-programmers, the concept of a "zeroth" element is counterintuitive. Natural human language and everyday counting start at 1. By adopting 1-based indexing, Lua's creators removed a common source of confusion for domain experts who had little interest in the internal mechanics of a computer.

Mathematical Sequences vs. Memory Offsets

In systems-level languages like C, 0-based indexing is a direct reflection of pointer arithmetic. An array index in C is an offset from the array's base memory address:

array[0] == *(array + 0) // zero offset from the start

Because C was tied closely to hardware architecture, 0-based indexing became a staple of computer science.

Lua, however, was designed as a high-level scripting language with no manual pointer arithmetic. Its conceptual foundation is based on mathematics rather than hardware architecture. In standard linear algebra and set theory, matrix rows, vector coordinates, and sequences typically begin at index 1 (e.g., \(x_1, x_2, \dots, x_n\)). Aligning the language with mathematical conventions made it more natural for technical users working with numerical and scientific data.

Heritage from SOL and DEL

Before Lua existed, PUC-Rio created two separate languages for Petrobras: DEL (Data Entry Language) and SOL (Simple Object Language).

SOL was an object-oriented, declarative language that used 1-based indexing. When the developers realized they needed a complete, lightweight scripting language that unified the data description features of SOL with procedural capabilities, they created Lua. To maintain familiarity and backward compatibility for existing users within Petrobras, Lua inherited SOL's 1-based data structures.

Lua Tables and Index Flexibility

Unlike many traditional languages, Lua does not have a distinct native array type. Instead, Lua provides a single, flexible data structure: the table. A Lua table is an associative array that can map any key (except nil and NaN) to any value.

Because tables are associative dictionaries, Lua does not strictly forbid index 0:

local my_table = {}
my_table[0] = "zero"
my_table[1] = "one"

However, Lua's standard library, length operator (#), and iterator functions (such as ipairs) treat integer keys starting at 1 as a contiguous "sequence." Using index 0 is valid, but it is treated as an arbitrary dictionary key rather than part of the standard sequence, reinforcing 1-based indexing as the standard convention.
