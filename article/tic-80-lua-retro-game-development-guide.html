TIC-80 Lua Retro Game Development Guide

The TIC-80 is a popular fantasy console that provides a self-contained, retro-inspired development environment replicating the technical limitations of 1980s 8-bit systems. This article explores how TIC-80 integrates the Lua programming language to power game logic, handle hardware inputs, render pixel graphics, and manage strictly budgeted virtual resources.

The Virtual Architecture and Lua Integration

TIC-80 acts as an idealized 8-bit computer with a 240x136 display resolution, a 16-color palette, 4-channel sound, and strict memory limits. While TIC-80 supports multiple scripting languages, Lua is its primary, default language. Lua's lightweight footprint, simple syntax, and fast execution speed make it ideal for running within an emulated sandbox that enforces rigid performance boundaries.

The Core Loop: TIC()

At the heart of any TIC-80 Lua cartridge is the execution cycle. Unlike event-driven frameworks or high-level scene graph engines, TIC-80 relies on a deterministic frame-by-frame loop.

Developers define a primary function, TIC(), which the virtual machine calls 60 times per second:

function TIC()
    -- Update game logic
    -- Process player input
    -- Draw visuals to the screen
end

Because TIC() executes on every frame, all game state management—from player positioning and collision detection to physics simulation—is computed procedurally within this single entry point or its sub-routines.

Built-in Hardware APIs

TIC-80 exposes a suite of global Lua functions that interface directly with the virtual hardware registers. Developers do not need external libraries to render graphics, play sounds, or capture controller inputs.

  • Graphics and Rendering: Functions such as cls() (clear screen), spr() (draw sprite), pix() (draw single pixel), and print() (render text) manipulate the display buffer directly. Developers pass coordinates and palette indices as arguments, giving Lua scripts granular control over screen memory.
  • Input Polling: Input states are queried using btn(id) to check if a directional pad or button is held down, and btnp(id) to detect if a button was pressed during the current frame.
  • Audio Synthesis: Sound effects and music tracks created in the console's built-in sound editors are triggered via sfx(id) and music(id).

Direct Memory Manipulation

For advanced retro development, TIC-80 exposes its virtual RAM directly to Lua through the peek() and poke() functions, as well as memcpy() and memset().

The entire virtual console memory map—including the display VRAM, sprite sheets, palette registers, and audio registers—resides in a continuous 96KB memory space. By manipulating these memory addresses directly with Lua, developers can implement hardware-level tricks reminiscent of the Commodore 64 or NES, such as palette cycling, screen-shake scanline interrupts, and dynamic sprite swapping.

Code Constraints and Optimization

TIC-80 limits a standard cartridge's code to 64KB (or 256KB across banks in the professional version). This restriction forces developers using Lua to write compact, optimized code. Because garbage collection in Lua can cause frame drops if tables are created and destroyed excessively within the 60 FPS loop, developers typically employ optimization techniques like object pooling, bitwise operations, and utilizing flat numerical arrays to ensure smooth runtime performance.

Through this combination of minimal APIs, fixed execution loops, and direct hardware mapping, Lua acts as a bridge between high-level ease of programming and low-level retro computing design.
