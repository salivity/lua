How Variadic Arguments Work in Lua

This article explains the mechanism behind variadic arguments in Lua, focusing on the triple-dot (...) syntax. It details how the Lua compiler and virtual machine handle variable parameter lists on the execution stack, how the VARARG bytecode instruction operates, and the standard idioms used to capture, count, and process these arguments efficiently.

The Triple-Dot Syntax

In Lua, a function defined with three dots (...) as its final parameter is designated as a variadic function. This syntax indicates that the function can accept an arbitrary number of arguments in addition to any named parameters preceding it:

local function printAll(...)
    -- '...' represents all extra arguments passed to the function
end

local function prefixLog(prefix, ...)
    -- 'prefix' captures the first argument; '...' captures the rest
end

Inside the function body, the token ... acts as an expression representing multiple values (a tuple) that can be unpacked, assigned, or passed directly to other functions.

The Underlying Virtual Machine Mechanism

The variadic mechanism is implemented directly at the Lua virtual machine (VM) level through call stack management and specialized bytecode instructions.

  1. Stack Frame Organization: When a function call occurs, the caller pushes all arguments onto the Lua stack. For a standard function, the VM ensures that parameters match the fixed parameter list. When a function is declared with ..., the compiler sets a flag on the function prototype (Proto) marking it as variadic (VARARG_HASARG or equivalent in the C implementation).
  2. The Base Pointer and Extra Values: The VM sets the base index for the function's local registers immediately after the last fixed parameter. The surplus arguments remain on the stack directly accessible to the runtime frame (CallInfo).
  3. The VARARG Bytecode Instruction: Whenever the ... token is evaluated in code, the Lua compiler generates the VARARG opcode. This instruction instructs the VM to copy the variadic values from the caller's stack frame into the current execution registers. The opcode can request a fixed number of results (e.g., in multiple assignments like local a, b = ...) or a variable number of results (e.g., when calling another function like print(...)).

Because values are transferred directly along the existing stack, passing variadic arguments incurs minimal memory overhead until those arguments are converted into data structures.

Idioms for Processing Variadic Arguments

Because ... represents a list of values rather than a single collection object, Lua provides several mechanisms to inspect and manipulate these parameters:

The select Function

The built-in select function provides constant-time access to variadic parameters without allocating memory:

  • select("#", ...) returns the exact count of arguments passed via ..., correctly accounting for trailing or interleaved nil values.
  • select(n, ...) returns all arguments starting from index n through the end of the argument list.
local function countArgs(...)
    return select("#", ...)
end

Table Packing

To store variadic parameters for iterative access, they can be enclosed in a table constructor:

  • Literal table capture ({...}): Collects all values into an array. However, if any arguments are nil, the resulting table will contain holes, making the standard length operator (#) unreliable.
  • table.pack(...) (Lua 5.2+): Collects the values into a sequence and automatically sets an n field containing the total count of arguments, preserving information about embedded or trailing nil elements.
local function storeArgs(...)
    local packed = table.pack(...)
    for i = 1, packed.n do
        print(packed[i])
    end
end
