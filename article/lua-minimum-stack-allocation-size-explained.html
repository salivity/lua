Lua Minimum Stack Allocation Size Explained

This article examines the minimum stack allocation size required when creating a new execution state (lua_State) in the Lua programming language. It covers both the public API guarantee established by LUA_MINSTACK and the internal allocation mechanics that allocate memory for the call stack and auxiliary overhead during initialization.

The Public Guarantee: LUA_MINSTACK

From the perspective of the Lua C API, the language guarantees that any newly created execution state or C function call has at least LUA_MINSTACK free slots available on the stack. In standard Lua distributions (Lua 5.1 through Lua 5.4), LUA_MINSTACK is defined in lua.h as:

#define LUA_MINSTACK 20

This constant ensures that operations requiring up to 20 elements can run safely without explicitly calling lua_checkstack() to expand the stack.

Internal Initial Allocation Size

While the external contract guarantees 20 usable slots, the Lua virtual machine actually allocates more memory under the hood to handle internal operations, error handling, and nested calls.

In the standard C implementation of Lua (specifically Lua 5.3 and Lua 5.4 in lstate.c and lstate.h), the initial stack size is determined by two constants:

  • BASIC_STACK_SIZE: Defined as (2 * LUA_MINSTACK), which evaluates to 40 slots.
  • EXTRA_STACK: A buffer reserved for internal engine use and emergency stack unwinding, defined as 5 slots.

When lua_newstate() or lua_newthread() initializes a new execution state, it allocates:

\[\text{Initial Slots} = \text{BASIC\_STACK\_SIZE} + \text{EXTRA\_STACK} = 40 + 5 = 45 \text{ slots}\]

Consequently, Lua allocates an internal array of 45 stack slots (StackValue or TValue structs) upon initializing a new state.

Memory Footprint in Bytes

The byte size of this allocation depends on the target architecture:

  • 64-bit Architectures: A stack slot (TValue / StackValue) is typically 16 bytes (or 8 bytes for data plus 8 bytes for tagged types and alignment). At 16 bytes per slot, 45 slots require 720 bytes of memory allocated solely for the data stack.
  • 32-bit Architectures: A stack slot is typically 8 to 12 bytes depending on alignment. At 8 bytes per slot, 45 slots require 360 bytes.

In addition to the data stack slots, a new execution state initializes the CallInfo list (call frame tracking). The initial CallInfo allocation starts with a base structure:

  • BASIC_CI_SIZE: Defined as 8 call frames in Lua 5.4.

Summary

When instantiating a new execution state in Lua, the minimum usable capacity guaranteed by the API is 20 slots (LUA_MINSTACK), while the actual physical allocation made by the engine runtime is 45 slots (40 basic slots plus 5 extra slots), resulting in approximately 720 bytes on 64-bit systems.
