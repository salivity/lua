Simulating Symmetric Coroutines in Lua

This article demonstrates how to simulate symmetric coroutines using Lua's native asymmetric coroutines. While Lua natively provides asymmetric coroutines—where control is hierarchically passed between an invoker and the yielded routine—it is theoretically established that both paradigms possess equivalent expressive power. By implementing a lightweight centralized dispatcher, developers can introduce a transfer primitive that enables any coroutine to explicitly pass execution to any other coroutine as a peer.

Asymmetric vs. Symmetric Coroutines

Coroutines generally fall into two categories:

  • Asymmetric Coroutines: Provide two distinct operations for transferring control: one for resuming a coroutine (coroutine.resume) and another for suspending it (coroutine.yield). The suspended coroutine always returns control to the specific caller that resumed it.
  • Symmetric Coroutines: Provide a single control-transfer operation, typically named transfer. This operation suspends the currently running coroutine and immediately activates a designated target coroutine. There is no parent-child relationship between coroutines; all coroutines operate as equals.

Lua implements asymmetric coroutines for simplicity and structured control flow. However, you can construct a symmetric mechanism on top of Lua's runtime.

The Dispatcher Pattern

To simulate symmetric behavior, an intermediary—a dispatcher loop—must manage execution transfers. Instead of a coroutine attempting to invoke another coroutine directly (which causes nested call stack buildup and violates symmetric semantics), the active coroutine yields the target coroutine and any arguments back to the dispatcher. The dispatcher then resumes the specified target.

Implementation

The following module implements symmetric coroutines in Lua:

local Coro = {}

-- Yields execution to the dispatcher, requesting a transfer to target
function Coro.transfer(target, ...)
    return coroutine.yield(target, ...)
end

-- Wraps a standard function into a symmetric-ready coroutine
function Coro.create(fn)
    return coroutine.create(fn)
end

-- The central dispatcher loop
function Coro.run(start_coro, ...)
    local target = start_coro
    local args = table.pack(...)

    while target and coroutine.status(target) ~= "dead" do
        -- Resume the designated target coroutine with the provided arguments
        local results = table.pack(coroutine.resume(target, table.unpack(args, 1, args.n)))
        local ok = results[1]

        if not ok then
            error(debug.traceback(target, results[2]))
        end

        -- If target finished execution without transferring, stop the loop
        if coroutine.status(target) == "dead" and results.n == 1 then
            break
        end

        -- The first return value after 'ok' is the next target coroutine
        target = results[2]
        
        -- Remaining return values are arguments for the next coroutine
        args = table.pack(table.unpack(results, 3, results.n))
    end
end

return Coro

Usage Example

With this dispatcher, coroutines can transfer control directly to one another without maintaining a caller-callee relationship:

local Coro = require("coro")

local ping_co, pong_co

ping_co = Coro.create(function(count)
    while count > 0 do
        print("Ping:", count)
        count = Coro.transfer(pong_co, count - 1)
    end
end)

pong_co = Coro.create(function(count)
    while count > 0 do
        print("Pong:", count)
        count = Coro.transfer(ping_co, count - 1)
    end
end)

-- Start the execution cycle
Coro.run(ping_co, 4)

Output:

Ping: 4
Pong: 3
Ping: 2
Pong: 1

How It Works Under the Hood

  1. Decoupling Resumes: The dispatcher acts as the sole entity calling coroutine.resume.
  2. Passing Intent: When ping_co invokes Coro.transfer(pong_co, count - 1), it calls coroutine.yield(pong_co, count - 1). This suspends ping_co and sends the reference to pong_co along with its payload back to Coro.run.
  3. Execution Routing: The dispatcher extracts pong_co from the yield results and calls coroutine.resume(pong_co, count - 1).
  4. Stack Safety: Because execution continuously returns to the single while loop inside Coro.run, the Lua C call stack does not grow with each transfer, preventing stack overflows regardless of how many transfers occur.
