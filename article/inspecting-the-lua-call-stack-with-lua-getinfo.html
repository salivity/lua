Inspecting the Lua Call Stack with lua_getinfo

The lua_getinfo function in the Lua C API is the primary interface for introspecting function metadata, execution states, and call stack frames at runtime. By populating a lua_Debug record, this function allows developers to extract debugging details such as active source filenames, line numbers, function names, and parameter counts. Understanding how lua_getinfo operates—in tandem with stack traversal utilities like lua_getstack—is essential for implementing custom error handlers, profilers, and debuggers within embedded Lua environments.

The Inspection Workflow

Querying the call stack using lua_getinfo is typically a two-step process: obtaining an activation record handle, and then requesting specific debug information for that record.

+---------------+      lua_getstack(L, level, &ar)      +--------------------+
|  Call Stack   |  ---------------------------------->  | lua_Debug (handle) |
+---------------+                                       +--------------------+
                                                                  |
                                                                  | lua_getinfo(L, "Sl", &ar)
                                                                  v
                                                        +--------------------+
                                                        | Populated Fields   |
                                                        | (source, line, etc)|
                                                        +--------------------+
  1. Locate the Stack Frame: Call lua_getstack(lua_State *L, int level, lua_Debug *ar). The level parameter specifies the stack depth: level 0 refers to the currently executing function, level 1 is the function that called it, and higher numbers traverse further up the execution chain. If the level exists, lua_getstack initializes internal pointers inside the lua_Debug structure and returns 1; otherwise, it returns 0.
  2. Retrieve Field Data: Call lua_getinfo(lua_State *L, const char *what, lua_Debug *ar). The what string defines which fields Lua must populate.

Alternatively, lua_getinfo can inspect a function directly without traversing the call stack. When the target function is pushed onto the top of the Lua stack, passing a > character at the beginning of the what string instructs Lua to inspect that function, popping it from the stack in the process.

The what String Options

To minimize performance overhead, lua_getinfo does not populate all fields of the lua_Debug struct by default. The developer provides a string of character flags in the what parameter to select the required data:

  • 'n' (Name): Fills the name and namewhat fields. Lua attempts to deduce a reasonable name for the function (such as a global variable, local variable, or table field name) based on how it was invoked.
  • 'S' (Source): Fills source, short_src, linedefined, lastlinedefined, and what. The what field identifies the type of function ("Lua", "C", or "main"). source indicates the origin (e.g., a file path or chunk string), and short_src contains a truncated, printable version suitable for error messages.
  • 'l' (Line): Fills currentline, which represents the line of code currently executing inside the specified activation frame. If execution is inside a C function or outside an active line, this value is set to -1.
  • 't' (Tail Call): Sets istailcall to true if the current frame was invoked via a tail call.
  • 'u' (Parameters and Upvalues): Fills nups (number of upvalues), nparams (number of parameters), and isvararg (boolean indicating variable argument lists).
  • 'f' (Function Push): Pushes the function executing at the given level onto the Lua stack.
  • 'L' (Line Table): Pushes a table onto the Lua stack whose indices are the line numbers that contain executable code within the function.

Practical Implementation Example

The following C function demonstrates how to inspect the immediate caller (level 1) of the current function to log its file origin, current line, and name:

#include <lua.h>
#include <lauxlib.h>
#include <stdio.h>

void print_caller_info(lua_State *L) {
    lua_Debug ar;

    // Retrieve activation record for the caller (level 1)
    if (lua_getstack(L, 1, &ar)) {
        // Query source information ('S'), line number ('l'), and name ('n')
        if (lua_getinfo(L, "Sln", &ar)) {
            const char *func_name = ar.name ? ar.name : "(anonymous)";
            
            printf("Called from: %s\n", ar.short_src);
            printf("Line number: %d\n", ar.currentline);
            printf("Function:    %s (%s)\n", func_name, ar.namewhat);
            printf("Origin:      lines %d to %d\n", ar.linedefined, ar.lastlinedefined);
        }
    } else {
        printf("No caller frame found on the stack.\n");
    }
}

Stack Frame Traversal

To produce a full stack trace similar to Lua's native debug.traceback, iterate the level integer starting from 0 and increment it until lua_getstack returns 0. At each step, invoke lua_getinfo(L, "Sl", &ar) to collect the source file and line number for every active stack frame.
