Lua Tables as Arrays and Hash Maps Explained

In Lua, the table is the sole data-structuring mechanism, uniquely designed to operate as an array and a hash map simultaneously within a single data structure. This article explains the internal architecture of Lua tables, detailing how the Lua runtime seamlessly splits tables into an array part and a hash part, how the re-hashing algorithm allocates data between them, and how developers can effectively utilize both paradigms at once.

The Internal Dual-Part Architecture

Under the hood, Lua tables are implemented in C as a Table struct consisting of two separate data segments: an array part and a hash part.

  • The Array Part: A contiguous block of memory optimized for dense, 1-based integer keys. Accessing an element here is an \(O(1)\) direct array index offset. Because keys are implicit positions in memory, no storage overhead is required for storing keys.
  • The Hash Part: A closed hash table containing nodes with explicit key-value pairs. It handles non-integer keys (such as strings, booleans, and other tables) as well as sparse, non-positive, or excessively large integer keys.

When you interact with a Lua table, the runtime abstracts these two segments away, presenting them as a unified data type.

How Lua Assigns Keys to Memory

When a key-value pair is assigned to a table, Lua determines where it belongs based on the key type and value distribution:

  1. Integer Keys: If a key is a positive integer, Lua evaluates whether it fits into the dense array part. The runtime periodically runs a re-hashing routine to optimize memory usage. The array size is always resized to a power of two (\(2^n\)) such that at least 50% of the allocated array slots contain non-nil values.
  2. Other Keys: String keys, floating-point keys, negative or zero integer keys, and sparse integer keys that would violate the 50% density rule are placed into the hash part.

Code Example: Dual-Functionality in Practice

You can define and manipulate both array elements and key-value pairs within the exact same table:

local mixed = {"first", "second", "third"}

-- Add hash-map style properties
mixed.status = "active"
mixed["priority"] = 1

-- Access as an array (1-based index)
print(mixed[1]) -- Output: first
print(#mixed)   -- Output: 3 (the length operator inspects the array sequence)

-- Access as a hash map
print(mixed.status)    -- Output: active
print(mixed["priority"]) -- Output: 1

In this example, "first", "second", and "third" reside inside the internal array part at indices 1, 2, and 3. The fields status and priority are stored inside the hash part.

Iteration Behavior

Because a table holds both types of data, Lua provides different iterators to traverse them:

  • ipairs(): Iterates strictly over the sequential integer keys starting at 1 and stops at the first nil entry. It interacts exclusively with the array-like sequence.
  • pairs(): Traverses the entire table—both the array part and the hash part—using the internal next function. The iteration order over the hash part is arbitrary and not guaranteed.

Performance and Memory Benefits

This hybrid approach gives developers the ergonomics of dynamic, associative mapping without sacrificing the raw performance of native arrays. Sequential operations benefit from cache locality and minimal memory overhead, while associative lookups maintain near-constant \(O(1)\) access times.
