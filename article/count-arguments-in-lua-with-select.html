Count Arguments in Lua with select("#", ...)

In the Lua programming language, handling variable numbers of arguments often introduces subtle bugs when nil values are involved. The select("#", ...) idiom provides a built-in, allocation-free mechanism to determine the exact number of arguments passed to a variadic function. Unlike standard table-based length approaches, select("#", ...) inspects the call frame directly, ensuring that intermediate and trailing nil values are accurately preserved and counted.

The Problem with Table Lengths and Nil

When defining a variadic function in Lua using the ... syntax, developers often pack the arguments into a table using {...} and query its length with the # operator:

local function badCount(...)
    local args = {...}
    return #args
end

In Lua, tables containing nil values are considered to have "holes." The # operator is only defined for sequences—tables without holes. If you pass arguments with trailing nil values, such as badCount(1, 2, nil), the # operator will evaluate the table length as 2 instead of 3. The trailing nil is indistinguishable from an unassigned table key, causing the true argument count to be lost.

How select("#", ...) Works

Lua provides the standard library function select to manipulate argument lists. When passed an integer n, select(n, ...) returns all arguments starting from index n. However, when passed the string "#" as its first parameter, select switches behavior and returns the total count of the remaining arguments:

local function exactCount(...)
    return select("#", ...)
end

print(exactCount(1, 2, nil))       -- Output: 3
print(exactCount(nil, nil, nil))   -- Output: 3
print(exactCount())                -- Output: 0

Because select operates directly on the vararg list (...) on the Lua virtual machine stack, it does not construct a table. Every argument passed by the caller occupies a specific register slot on the stack, allowing Lua to report the exact number of parameters received, regardless of their values.

Why Verifying Trailing Nils Matters

Accurate parameter counting is critical for functions where a missing argument behaves differently from an explicitly passed nil. Common use cases include:

  • Optional Parameters with Fallbacks: Distinguishing between func() (use default value) and func(nil) (explicitly clear or set value to nil).
  • Function Wrapping and Proxies: Forwarding arguments to other functions or C-APIs where the exact argument count determines behavior or method overloading.
  • Serialization and RPC: Accurately serializing command payloads where omitted values must not collapse the payload structure.

Comparison with table.pack

In Lua 5.2 and later, the standard library includes table.pack(...). This function bundles arguments into a table and automatically adds an n field containing the total count (e.g., { [1] = 1, [2] = nil, n = 2 }).

While table.pack also preserves trailing nil information, it creates a new table on every invocation, triggering memory allocations and garbage collection overhead. Using select("#", ...) is faster, incurs zero table allocations, and remains fully backward-compatible across Lua 5.1, Lua 5.2+, and LuaJIT.
