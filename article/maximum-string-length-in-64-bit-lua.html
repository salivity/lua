Maximum String Length in 64-Bit Lua

In a standard 64-bit build of the official PUC-Rio Lua interpreter, the theoretical maximum supported length of a string is \(2^{63} - 1\) bytes (approximately 9.22 exabytes), though practical constraints are strictly limited by available host system memory. However, alternative runtimes like LuaJIT impose a much lower limit of 2 gigabytes. This article details the structural limits, memory constraints, and implementation differences governing string sizes in 64-bit Lua environments.

Standard Lua (PUC-Rio) Theoretical Limits

In standard Lua (versions 5.3 and 5.4), strings are immutable, length-prefixed byte sequences. Their size is represented internally by the C standard size_t data type.

Because Lua's native integer type (lua_Integer) is a signed 64-bit integer on standard 64-bit architectures, operations that query or manipulate string lengths—such as the length operator (#) and string.len()—are bound to the range of positive signed 64-bit integers. Consequently, the maximum representable length of a string without causing integer overflow within the language is:

\[\text{Maximum Length} = 2^{63} - 1 \text{ bytes} \approx 9,223,372,036,854,775,807 \text{ bytes}\]

Lua's internal memory allocator (luaM_realloc) must allocate memory for both the string payload, an internal header (TString), and a trailing null terminator byte (\0).

Practical Memory Constraints

While the data types theoretically permit exabyte-scale strings, real-world execution is bounded by:

  • Available RAM and Swap: Allocating a contiguous memory buffer requires the operating system to provide that space. An allocation attempt exceeding physical or virtual memory limits causes Lua to throw an "out of memory" error.
  • Address Space Limits: Operating systems and hardware architectures typically do not implement the full 64-bit physical address space, often capping virtual addresses at 48 or 57 bits (256 TB to 128 PB).
  • Contiguity: Lua strings require a single, contiguous block of memory. Memory fragmentation can cause an allocation to fail even if aggregate free memory exists.

LuaJIT 64-Bit String Limits

When using LuaJIT on a 64-bit system instead of PUC-Rio Lua, the string capacity is substantially lower:

  • 2 GB Maximum Size: LuaJIT stores string lengths internally using a 32-bit unsigned integer and historically relies on a 32-bit memory addressing model for its garbage-collected objects.
  • Effective Capacity: Strings in LuaJIT cannot exceed \(2^{31} - 14\) bytes (roughly 2 GB minus internal overhead). Any attempt to concatenate or load a string beyond this threshold results in a memory error, even on 64-bit builds compiled with the GC64 feature enabled.

Summary

For standard 64-bit PUC-Rio Lua, the maximum supported string length is capped at \(2^{63} - 1\) bytes, meaning the interpreter will support any string size up to the total contiguous memory the operating system can allocate. For systems running 64-bit LuaJIT, the hard cap remains 2 gigabytes.
