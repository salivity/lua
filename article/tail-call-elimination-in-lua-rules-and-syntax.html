Tail Call Elimination in Lua: Rules and Syntax

Lua guarantees proper tail call elimination (often called tail call optimization) only when a function call is executed as the absolute last action of another function. Under this mechanism, the calling function does not consume stack space while waiting for the called function to finish, allowing theoretically infinite recursion without triggering a stack overflow. This article breaks down the precise syntactic structures Lua requires to guarantee tail call elimination, examines valid variations, and highlights subtle syntax patterns that accidentally break the optimization.

The Standard Tail Call Structure

For Lua to guarantee tail call elimination, the call must strictly follow this syntactic form:

return <func>(<args>)

In this structure, <func> is any expression that evaluates to a function, and <args> are zero or more comma-separated argument expressions.

When the Lua virtual machine encounters this exact statement:

  1. It evaluates <func> and all expressions inside <args>.
  2. It completely discards or reuses the current function's call frame from the call stack.
  3. It performs a direct jump to the target function.

Because the caller's frame is released before the callee begins execution, any number of nested calls can be chained indefinitely.

Valid Variations Guaranteed by Lua

The guarantee holds across several standard call formats, provided the call remains the final operation tied directly to return:

  • Simple function calls:

    return func(a, b)

  • Table field calls:

    return module.func(a, b)

  • Object-oriented method calls:

    return object:method(a, b)

  • Complex argument evaluation:

    return func(x + 1, table.concat(list, ","))

    The expressions for arguments are evaluated before the function call itself takes place. As long as no additional evaluation occurs after func is invoked, it is a valid tail call.

Call Structures That Invalidate the Guarantee

A tail call guarantee is easily broken by seemingly harmless additions. If the runtime must perform any operation after the invoked function returns, the call frame must stay in memory, preventing elimination.

1. Enclosing Parentheses

return (func(x)) -- NOT a tail call

Wrapping the call in parentheses forces Lua to adjust the results to exactly one return value. Because the caller must truncate the return values before passing them upward, the stack frame cannot be released.

2. Operations on Return Values

return func(x) + 1   -- NOT a tail call
return not func(x)   -- NOT a tail call
return "Result: " .. func(x) -- NOT a tail call

Any arithmetic, logical, or concatenation operation requires the caller to wait for func to return its value before finishing execution.

3. Assignment Before Return

local res = func(x)
return res -- NOT a tail call

Storing the result in a local variable before returning requires the local variable's scope to remain intact until the assignment completes.

4. Discarded Returns

func(x)
return -- NOT a tail call

Calling a function on one line and executing an empty return on the next causes the caller to handle the destruction of return values from func(x) before exiting, keeping the frame active during the call.

Practical Implications

Tail call elimination is primarily utilized in Lua to implement infinite loops, state machines, and recursive traversals without risking stack limits. To ensure the Lua interpreter applies this optimization, ensure that the function call itself is the sole, bare expression provided to the return statement.
