Lua 5.4 VM Instruction Width and Format

In version 5.4 of the Lua programming language, the Lua Virtual Machine (LVM) operates as a register-based engine where every bytecode instruction has a fixed width of 32 bits. This article provides a technical breakdown of this 32-bit instruction width, explains how the bit fields are structured, and covers the five primary instruction formats (iABC, iABx, iAsBx, iAx, and isJ) defined in Lua 5.4's bytecode architecture.

Instruction Width

The Lua 5.4 Virtual Machine encodes every instruction into a fixed 32-bit unsigned integer, defined in the source code as Instruction (aliased to l_uint32). Using a fixed 32-bit width ensures predictable instruction decoding, efficient memory alignment, and consistent performance across modern processor architectures.

Opcode Allocation

In Lua 5.4, the primary operation code (OpCode) occupies the lowest 7 bits of the 32-bit word (bits 0 through 6). This expands upon earlier Lua versions, which allocated only 6 bits for opcodes. The 7-bit allocation supports up to 128 unique bytecode instructions, leaving the remaining 25 bits to be divided among various register and immediate value operands.

Instruction Formats

Lua 5.4 structures instructions into five distinct layouts defined in lopcodes.h. The VM determines how to interpret the remaining 25 bits based on the opcode.

1. iABC Format

The iABC format is the most common format, used for standard register operations, arithmetic, and logic commands.

  • Opcode: 7 bits (bits 0–6)
  • A: 8 bits (bits 7–14)
  • k: 1 bit (bit 15)
  • B: 8 bits (bits 16–23)
  • C: 8 bits (bits 24–31)

A, B, and C generally represent register indices. The k field is a 1-bit boolean flag introduced in Lua 5.4. It is often used to signal whether an operand refers to a constant directly or whether a condition should be inverted, reducing the need for auxiliary instructions.

2. iABx Format

The iABx format is used when an instruction requires an unsigned 17-bit integer argument, such as referencing entries in a large constant table or handling closure parameters.

  • Opcode: 7 bits (bits 0–6)
  • A: 8 bits (bits 7–14)
  • Bx: 17 bits (bits 15–31)

Field Bx is an unsigned value ranging from 0 to 131,071.

3. iAsBx Format

The iAsBx format mirrors the iABx layout but treats the 17-bit field as a signed integer.

  • Opcode: 7 bits (bits 0–6)
  • A: 8 bits (bits 7–14)
  • sBx: 17 bits (bits 15–31)

Field sBx represents signed values using a biased representation (offset binary), allowing a range from -65,536 to +65,535. It is commonly used for arithmetic loops and relative value offsets.

4. iAx Format

The iAx format handles operations that require a single, large immediate value spanning the entire remaining width of the instruction.

  • Opcode: 7 bits (bits 0–6)
  • Ax: 25 bits (bits 7–31)

The unsigned 25-bit Ax field can store values up to 33,554,431. This format is primarily used by the OP_EXTRAARG instruction to extend the constant-addressing capability of preceding instructions that exceed their native operand limits.

5. isJ Format

Introduced in Lua 5.4, the isJ format is dedicated to control-flow and jump instructions (such as OP_JMP).

  • Opcode: 7 bits (bits 0–6)
  • sJ: 25 bits (bits 7–31)

Field sJ is a signed 25-bit offset that allows the VM to perform relative jumps across a range of approximately -16,777,216 to +16,777,215 instructions. Unlike older Lua versions that used sBx alongside a register argument for jumps, Lua 5.4 dedicated isJ exclusively to branch displacement, significantly expanding the maximum jump distance within a single compiled chunk.
