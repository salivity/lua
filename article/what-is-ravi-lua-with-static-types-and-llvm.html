What Is Ravi: Lua with Static Types and LLVM

Ravi is a customized, derivative dialect of Lua 5.3 designed to overcome Lua’s performance limitations in compute-heavy scenarios through optional static typing and Just-In-Time (JIT) compilation. This article explains what the Ravi programming language is, how its optional type system enhances execution efficiency, and how it harnesses the LLVM compiler infrastructure to generate high-performance native machine code while preserving full backward compatibility with standard dynamic Lua.

Understanding Ravi

Ravi is an open-source programming language based on the core of Lua 5.3. Lua is widely praised for its simplicity, lightweight footprint, and embeddability, but its dynamic nature introduces runtime overhead during numeric computations and array operations. Ravi was created to address this bottleneck.

Rather than reinventing Lua, Ravi acts as an extended superset of Lua 5.3. It retains Lua's syntax, standard libraries, and dynamic capabilities, ensuring that existing Lua 5.3 code runs in Ravi without modification. However, it introduces syntax extensions and an enhanced execution engine aimed at developers who need near-C performance directly within a Lua-like environment.

Introducing Optional Static Types

The primary architectural enhancement in Ravi is its optional type system. In standard Lua, values have types, but variables do not; every operation must dynamically check the types of its operands at runtime. Ravi allows programmers to optionally annotate variables, function parameters, and return types with specific static types.

Supported Type Annotations

Ravi introduces distinct types, including:

  • integer: A 64-bit signed integer.
  • number: A 64-bit floating-point number (double).
  • table: A standard dynamic Lua table.
  • Specialized Arrays: Specialized types like integer[] and number[] that represent contiguous arrays of flat primitives rather than dynamic hash tables.

Optimization Mechanics

When static types are provided, the Ravi parser and bytecode generator skip the dynamic type checks usually required during execution:

  1. Direct Arithmetic: When two integer variables are added, Ravi emits specialized bytecode instructions designed exclusively for 64-bit integer addition, eliminating runtime type testing and tagging.
  2. Efficient Array Access: By using specialized array types (number[]), Ravi bypasses the standard Lua table lookup mechanisms. It reads and writes directly to contiguous blocks of memory, avoiding memory indirection and boundary checks where safe.
  3. Graceful Fallback: If a variable is unannotated, it remains dynamic, and Ravi processes it using standard Lua semantics.

LLVM Compilation in Ravi

Beyond static typing, Ravi introduces an advanced compilation pipeline that leverages LLVM (Low Level Virtual Machine) to translate code into native machine instructions.

Bytecode to LLVM IR

Standard Lua translates source code into Lua bytecode, which is executed sequentially by a register-based virtual machine interpreter. While fast for an interpreter, this loop incurs instruction dispatch overhead.

Ravi bridges this gap with a JIT compiler:

  1. Compilation Tiering: Ravi can interpret standard bytecode or invoke the JIT compiler for computationally intensive functions.
  2. Intermediate Representation: Ravi compiles typed bytecode directly into LLVM Intermediate Representation (LLVM IR). Because type annotations eliminate dynamic ambiguity, the generated IR can represent pure native arithmetic, pointer operations, and register assignments.
  3. LLVM Optimization Passes: Once the IR is generated, LLVM applies industrial-grade compiler optimizations, including dead-code elimination, loop unrolling, and vectorization.
  4. Machine Code Generation: LLVM compiles the IR into native machine code (x86-64, ARM, etc.) at runtime, allowing the CPU to execute functions directly without the virtual machine interpreter.

The Synergy of Types and LLVM

LLVM requires precise type information to generate optimal machine code. A standard dynamic language produces complex, branching LLVM IR because it must account for every possible type a variable might hold.

Ravi solves this challenge through its optional typing. By supplying static types, the developer provides the exact metadata LLVM needs to generate tight native loops free from runtime type-guards. As a result, performance-critical algorithms implemented in Ravi with static types and LLVM compilation can approach the speed of equivalent C code while maintaining the flexibility of the Lua runtime.
