How LuaDist Provides Standalone Lua Environments

LuaDist is a true multi-platform package management and deployment system designed to provide a completely standalone, relocatable distribution of the Lua programming language. By leveraging CMake as a universal meta-build engine, standardizing module metadata, and resolving runtime paths relative to the executable rather than the operating system's root directories, LuaDist enables developers to build, bundle, and distribute fully functional Lua environments without external dependencies or administrative privileges.

Universal Compilation via CMake

At the core of LuaDist's cross-platform capability is its reliance on CMake. Traditional Lua modules often rely on platform-specific build tools, such as custom Makefiles on POSIX systems or Visual Studio project files on Windows. LuaDist replaces these fragmented toolchains with standardized CMakeLists.txt configurations for every packaged library. Because CMake generates native build scripts for compilers including GCC, Clang, and MSVC across Linux, macOS, and Windows, LuaDist compiles Lua runtimes and native C extensions uniformly across different architectures.

Fully Relocatable Architecture

LuaDist achieves its standalone status by ensuring the entire distribution is relocatable. When compiled, the binaries and libraries do not rely on hardcoded absolute file paths. Instead, LuaDist configures Lua's internal package.path and package.cpath variables relative to the running executable. Dynamic libraries use relative runtime search paths (such as $ORIGIN on Linux or @executable_path on macOS) to locate their dependencies within the distribution directory. As a result, a complete Lua environment—including the interpreter, third-party libraries, and shared objects—can be moved to any directory or distributed as a portable archive without breaking runtime imports.

Automated Dependency and Manifest Management

LuaDist distributes components through lightweight archives termed "dists." Each dist contains the necessary source files, a build configuration, and a dist.info manifest describing licensing, versioning, and dependencies. When a user requests an installation, LuaDist parses these manifests, builds an internal dependency graph, and resolves both Lua-level and native system-level dependencies (such as zlib or OpenSSL). By compiling all dependencies directly into the local environment tree, it eliminates "dependency hell" and ensures that the runtime is insulated from the host system's global packages.

Isolated Deployment and Portability

Because LuaDist operates entirely in user space, multiple distinct distributions can exist side by side on a single machine. Developers can maintain separate environments with different Lua versions (such as Lua 5.1, Lua 5.2, or LuaJIT) along with their specific module ecosystems. This makes LuaDist an effective vehicle for shipping self-contained applications, where end users can execute Lua scripts immediately without manually installing compilers, runtimes, or system packages.
