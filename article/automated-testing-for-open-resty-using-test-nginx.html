Automated Testing for OpenResty Using Test::Nginx

Automated testing is critical for validating the performance and correctness of OpenResty applications. This guide explains how to set up the Test::Nginx testing framework, configure a proper environment, write Perl-driven specification files targeting embedded Lua scripts, and execute test suites via the command line and continuous integration pipelines.

Prerequisites and Environment Setup

Test::Nginx is a Perl-based test scaffold originally developed for testing the OpenResty core and its various Nginx C and Lua modules. Before writing tests, ensure that OpenResty and Perl's package manager (cpanm) are installed on your system.

Install Test::Nginx via CPAN:

cpanm Test::Nginx

Ensure the OpenResty binary is available in your shell's PATH:

export PATH=/usr/local/openresty/nginx/sbin:$PATH

Structure of a Test::Nginx Test File

Tests are placed in a t/ directory with a .t extension. Each file is a Perl script containing embedded test blocks defined below the __DATA__ token.

Create a file named t/sanity.t:

use Test::Nginx::Socket 'no_plan';

run_tests();

__DATA__

=== TEST 1: Basic Lua endpoint response
--- config
    location /test {
        content_by_lua_block {
            ngx.say("hello from openresty")
        }
    }
--- request
GET /test
--- response_body
hello from openresty
--- error_code: 200

Key Sections of a Test Block

  • === TEST [name]: Declares the test case identifier and a short description.
  • --- config: Injects custom Nginx configuration directives into the temporary server block generated for the test.
  • --- request: Specifies the HTTP method, URI, and optional headers or payload to send.
  • --- response_body: The expected response body from the server.
  • --- error_code: The expected HTTP status code (defaults to 200 if omitted).

Testing Lua Modules and Logic

When testing an application composed of separate .lua files, configure the lua_package_path within the test to point to your project's source code directory.

use Test::Nginx::Socket 'no_plan';

# Add project root to package path
our $HttpConfig = <<'_EOC_';
    lua_package_path "$TEST_NGINX_HTML_DIR/../../lib/?.lua;;";
_EOC_

run_tests();

__DATA__

=== TEST 2: Testing custom Lua module
--- http_config eval: $::HttpConfig
--- config
    location /api/process {
        content_by_lua_block {
            local mymodule = require("mymodule")
            local result = mymodule.process("input_data")
            ngx.say(result)
        }
    }
--- request
POST /api/process
--- response_body
processed: input_data
--- error_code: 200

Asserting Logs and Headers

Test::Nginx can validate HTTP response headers and ensure that no unintended errors were written to error.log.

=== TEST 3: Validate response headers and error logs
--- config
    location /headers {
        content_by_lua_block {
            ngx.header["X-Custom-Header"] = "OpenRestyTest"
            ngx.log(ngx.WARN, "Non-fatal warning")
            ngx.say("ok")
        }
    }
--- request
GET /headers
--- response_headers
X-Custom-Header: OpenRestyTest
--- error_log
Non-fatal warning
--- no_error_log
[error]
  • --- response_headers: Verifies specific key-value pairs in the returned HTTP headers.
  • --- error_log: Asserts that the specified string appears in the Nginx error log.
  • --- no_error_log: Ensures that patterns such as [error] or [alert] are absent, confirming clean execution.

Executing the Test Suite

Use Perl's built-in prove command to run the automated test suite.

Run all tests in the t/ directory:

prove -r t

To run a specific test file with verbose output for debugging:

prove -v t/sanity.t

When debugging failed tests, set the TEST_NGINX_NO_CLEAN environment variable to inspect the generated nginx.conf, logs, and temporary working directories:

TEST_NGINX_NO_CLEAN=1 prove -v t/sanity.t

The test artifacts will remain in t/servroot/ for inspection. Ensure this directory is added to .gitignore.
