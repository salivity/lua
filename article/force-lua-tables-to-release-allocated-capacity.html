Force Lua Tables to Release Allocated Capacity

In the Lua programming language, tables dynamically allocate memory for both array and hash components as elements are added, but they do not automatically shrink when keys are removed. Setting entries to nil removes references to individual values, but the underlying table vector remains at its peak allocated capacity. This article explains why Lua retains this capacity and provides the standard, direct methods developers use to release that reserved memory back to the Lua runtime and the operating system.

The Problem: Why Tables Retain Memory

Lua optimizes table access by pre-allocating contiguous memory in power-of-two blocks for both the array slice and the hash slice. When you delete elements by assigning them to nil:

myTable[key] = nil

Lua clears the reference to the value so that the garbage collector (GC) can clean up the object itself. However, the internal size of the table's hash and array buckets does not shrink. If a table previously held 1,000,000 entries, it retains the capacity for 1,000,000 slots even if only 5 entries remain.

The Solution: Migrate Elements to a Fresh Table

The only reliable way to force Lua to release a table's allocated capacity is to allocate a new table, transfer the remaining elements into it, and drop the reference to the original table so the garbage collector can reclaim it.

Shallow Copy Pattern

Iterate through the existing table, copy active keys into a new table, and overwrite the original variable:

local function shrinkTable(t)
    local newTable = {}
    for k, v in pairs(t) do
        newTable[k] = v
    end
    return newTable
end

-- Usage:
myTable = shrinkTable(myTable)

The new table is sized precisely to fit only the current active elements, discarding all unoccupied memory slots.

Retaining Metatables

If your table uses metatables (for object-oriented patterns or custom behaviors), copy the metatable reference to the new instance:

local function shrinkTableWithMetatable(t)
    local newTable = {}
    for k, v in pairs(t) do
        newTable[k] = v
    end
    setmetatable(newTable, getmetatable(t))
    return newTable
end

myTable = shrinkTableWithMetatable(myTable)

Forcing Immediate Memory Reclamation

Dropping the reference to the old table marks it for collection, but the memory remains allocated until the next garbage collection cycle. To immediately reclaim the memory, explicitly invoke the garbage collector:

myTable = shrinkTable(myTable)
collectgarbage("collect")

For performance-sensitive loops, avoid calling collectgarbage("collect") frequently, as a full collection cycle pauses execution. In most applications, allowing the incremental garbage collector to reclaim the old table automatically is the preferred approach.

What to Avoid: LuaJIT's table.clear

If you are using LuaJIT or OpenResty, you may encounter the table.clear function. While table.clear(t) removes all elements, it explicitly preserves the allocated capacity for high-speed table reuse. Do not use table.clear if your goal is to reduce the memory footprint.
