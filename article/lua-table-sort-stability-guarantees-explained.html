Lua table.sort Stability Guarantees Explained

In the Lua programming language, the built-in table.sort function provides no stability guarantees. A stable sorting algorithm preserves the original relative order of elements that have equal keys or are evaluated as equivalent by the comparison function. Lua's implementation prioritizes speed and low memory consumption, which results in an unstable sort where equivalent elements may arbitrarily swap positions. This article covers the reasons behind this behavior, the underlying algorithm used by Lua, and how developers can achieve stable sorting when needed.

The Stability of table.sort

According to the official Lua Reference Manual, table.sort does not guarantee a stable sort. If two elements \(A\) and \(B\) are considered equal under the provided comparison function (meaning comp(A, B) is false and comp(B, A) is false), their relative positions after sorting are not guaranteed to match their positions before sorting.

The Underlying Algorithm

Standard Lua uses a variant of the Quicksort algorithm (with Introsort optimizations introduced in Lua 5.4 to avoid worst-case \(O(n^2)\) time complexity). Quicksort achieves fast average-case performance and operates in-place using \(O(\log n)\) auxiliary stack space.

Because Quicksort partitions arrays by swapping elements across long distances around a selected pivot, it inherently disrupts the original relative ordering of equivalent elements. While stable variations of Quicksort exist, they require significant auxiliary memory buffers, which contradicts Lua’s core design goal of maintaining a minimal footprint suitable for embedded environments.

Comparison Function Requirements

Lua requires the comparison function passed to table.sort to define a strict weak ordering. Specifically, the function must behave like the standard less-than operator (<):

  • comp(a, a) must always be false.
  • If comp(a, b) is true, then comp(b, a) must be false.
  • If comp(a, b) is true and comp(b, c) is true, then comp(a, c) must be true.

Providing a non-strict comparison (such as using <= instead of <) violates the algorithm's preconditions and can cause table.sort to crash with an "invalid order function for sorting" error or enter an infinite loop.

How to Achieve Stable Sorting in Lua

When stability is strictly necessary, developers can achieve it using one of two primary approaches:

1. Index Tie-Breaking

The most common way to force stability with table.sort is to associate each element with its initial array index. When the primary values evaluate as equal, the comparison function falls back to comparing the original indices:

local items = {
    { name = "Alice", score = 10 },
    { name = "Bob",   score = 20 },
    { name = "Carol", score = 10 }
}

-- Record the original index
for i, item in ipairs(items) do
    item._index = i
end

table.sort(items, function(a, b)
    if a.score ~= b.score then
        return a.score < b.score
    end
    return a._index < b._index
end)

-- Clean up temporary indices if necessary
for _, item in ipairs(items) do
    item._index = nil
end

Because indices are unique, no two elements are ever considered fully equal by the comparison function, which completely prevents arbitrary reordering.

2. Implementing a Custom Stable Algorithm

If modifying the data structures is undesirable or incurs too much overhead, you can implement a naturally stable sorting algorithm in pure Lua, such as Mergesort or a binary Insertion Sort (suited for small arrays):

local function stable_sort(tbl, comp)
    comp = comp or function(a, b) return a < b end
    local len = #tbl
    if len <= 1 then return tbl end

    local function merge(left, right)
        local result = {}
        local i, j = 1, 1
        while i <= #left and j <= #right do
            if comp(right[j], left[i]) then
                result[#result + 1] = right[j]
                j = j + 1
            else
                result[#result + 1] = left[i]
                i = i + 1
            end
        end
        while i <= #left do
            result[#result + 1] = left[i]
            i = i + 1
        end
        while j <= #right do
            result[#result + 1] = right[j]
            j = j + 1
        end
        return result
    end

    local function divide(first, last)
        if first >= last then return { tbl[first] } end
        local mid = math.floor((first + last) / 2)
        return merge(divide(first, mid), divide(mid + 1, last))
    end

    local sorted = divide(1, len)
    for i = 1, len do
        tbl[i] = sorted[i]
    end
    return tbl
end

This guarantees that equivalent items remain in their exact incoming sequence, albeit at the cost of additional memory allocations.
