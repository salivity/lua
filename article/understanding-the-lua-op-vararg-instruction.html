Understanding the Lua OP_VARARG Instruction

In the Lua virtual machine, the OP_VARARG instruction handles the retrieval and assignment of variable arguments passed to functions defined with the vararg ellipsis (...). This article explains the technical mechanics of OP_VARARG, how the Lua runtime tracks dynamic arguments, and how the instruction manages register allocation for both fixed and variable-length expressions.

The Role of OP_VARARG

When a Lua function accepts dynamic arguments (defined using ...), any arguments passed beyond the explicitly named parameters are considered variable arguments. Because Lua compiles functions into bytecode ahead of execution, the compiler cannot predict how many extra arguments a caller will supply at runtime.

The OP_VARARG opcode bridges this gap. Whenever code accesses ...—such as assigning varargs to local variables, passing them to another function, or packing them into a table—the compiler emits an OP_VARARG instruction to copy those dynamic values into the current function's register window.

Instruction Structure and Operands

In Lua bytecode, OP_VARARG primarily uses two operands: A and B (or C depending on the Lua version):

  • Operand A (Destination Register): Specifies the starting register index R(A) in the current stack frame where the copied arguments should be placed.
  • Operand B (Count Specifier): Dictates how many values should be copied from the vararg list.

The behavior of the instruction changes significantly depending on the value of the count operand:

  1. Fixed Number of Values (B > 1): The instruction requests a specific count of B - 1 values. For example, in a statement like local x, y = ..., the compiler emits OP_VARARG with B = 3. The virtual machine writes the first two dynamic arguments into R(A) and R(A + 1). If fewer values exist than requested, the remaining registers are set to nil.
  2. Variable/Multiple Values (B == 0): Used when the number of target values must expand dynamically, such as in return ... or foo(...). When B is zero, the instruction copies all available varargs onto the top of the stack, starting at R(A), and adjusts the stack top (L->top) to point past the last copied element.

Stack Layout and Memory Movement

When a function call occurs, Lua pushes all supplied arguments onto the execution stack. Before entering the function body, the virtual machine rearranges the stack:

  • Fixed parameters are bound directly to standard registers starting at the function's base register.
  • The remaining dynamic arguments are sequestered in a vararg slice, located just beneath the base of the function's active register frame or tracked via the call frame's metadata (CallInfo).

When OP_VARARG executes:

  1. The virtual machine calculates the number of available varargs by comparing the position of the call's original arguments with the function’s fixed parameter count.
  2. It determines the target range based on register A and the requested count.
  3. Values are directly copied (using standard TValue assignment) from the vararg storage into the target registers R(A), R(A + 1), ....
  4. If the instruction requests more values than were supplied, it writes nil to the remaining target registers to ensure uninitialized registers do not retain stale data.

Through this mechanism, OP_VARARG enables dynamic parameter expansion with minimal runtime overhead, providing efficient array-like access and forwarding for dynamic argument lists.
