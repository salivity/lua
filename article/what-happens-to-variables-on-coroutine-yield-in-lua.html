What Happens to Variables on coroutine.yield in Lua

When coroutine.yield is called in the Lua programming language, the coroutine's execution is immediately suspended, and its entire execution state—including local variables, the call stack, temporary values, and upvalues—is preserved in memory. This article explains how Lua manages local variables, closures, and data exchange across yield and resume boundaries, as well as what happens to variable lifecycles if a coroutine is abandoned.

Local Variables and the Stack

In Lua, each coroutine has its own independent execution stack. When coroutine.yield is executed, the virtual machine stops processing the current thread and freezes the state of this stack.

Local variables defined within the running coroutine remain allocated and retain their exact values. No local variables are reinitialized, destroyed, or reset. Execution halts precisely at the point of the coroutine.yield() call. When coroutine.resume is subsequently invoked on that coroutine, execution continues from that exact point with every local variable in the identical state it was in right before the yield occurred.

Yield Return Values and Variable Assignment

Variables assigned to the result of coroutine.yield receive their values from the next coroutine.resume call.

Consider this pattern:

local my_var = "initial"
local resume_arg = coroutine.yield("yielding out")
my_var = resume_arg
  1. The value "yielding out" is passed back to the caller of coroutine.resume.
  2. The state of my_var remains "initial" while the coroutine is suspended.
  3. When the coroutine is resumed with coroutine.resume(co, "resumed value"), coroutine.yield evaluates to "resumed value".
  4. resume_arg receives "resumed value", and my_var is updated accordingly.

Closures and Upvalues

If a coroutine accesses or modifies an upvalue (an external local variable captured by a closure), that variable's state remains bound to the closure.

  • Exclusive Upvalues: If the variable is only accessed by the coroutine, it remains static during suspension.
  • Shared Upvalues: If the upvalue is shared with other functions or coroutines outside the suspended thread, those other contexts can modify the variable while the coroutine is paused. When the suspended coroutine resumes, it will read the modified value of that shared upvalue, rather than the value it held when coroutine.yield was invoked.

Memory and Garbage Collection

Variables held within a suspended coroutine's stack are rooted by the coroutine object itself. As long as there is an active reference to the coroutine thread object in your program, the Lua garbage collector will not collect the local variables or objects stored within its call stack.

If all references to the suspended coroutine are dropped, the coroutine object becomes eligible for garbage collection. At that point, the entire stack is deallocated, and any objects referenced solely by that coroutine's local variables are collected.
