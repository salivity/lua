Default Call Stack Limit in Lua Explained

This article explores the default call stack limits within the Lua virtual machine (VM), detailing the configuration constants in the Lua source code, how different versions handle stack exhaustion, and the exact thresholds that trigger a stack overflow error.

The Default Call Limits in Lua

The Lua virtual machine imposes two primary limits on function invocation depth: one for pure Lua function calls and another for calls involving the C API. These limits are defined at compile time in the Lua source file luaconf.h.

1. Pure Lua Call Stack Limit

  • Lua 5.1: In standard Lua 5.1, the constant LUAI_MAXCALLS defines the maximum call depth, defaulting to 20,000 calls. If recursion exceeds this threshold, the VM raises the error: "stack overflow".
  • Lua 5.2 and Lua 5.3: The architecture shifted away from a fixed call counter to managing overall stack slots via LUAI_MAXSTACK, which defaults to 1,000,000 slots. A parameterless recursive Lua call consumes stack slots per frame, generally hitting the limit around 1,000,000 invocations before triggering "stack overflow".
  • Lua 5.4: The virtual machine dynamically allocates call frames, still bounded by LUAI_MAXSTACK set at 1,000,000 stack elements by default. Depending on the local variables and parameters passed, practical recursion limits typically range between tens of thousands to hundreds of thousands of frames before exhausting the slot pool.

2. C Call Stack Limit (LUAI_MAXCCALLS)

When Lua calls a C function that subsequently invokes Lua (or vice versa), the execution relies on the host machine's native C stack. Because native stack space is limited and cannot be dynamically grown by the Lua VM, Lua enforces a much stricter boundary:

  • Across Lua 5.1 through Lua 5.4, the default limit defined by LUAI_MAXCCALLS is 200.
  • Exceeding this depth raises the error: "C stack overflow".

Modifying the Stack Limits

Because these thresholds are hardcoded preprocessor definitions, changing them requires recompiling the Lua interpreter:

  1. Open src/luaconf.h in the Lua source distribution.
  2. Locate the definitions for LUAI_MAXSTACK (or LUAI_MAXCALLS in 5.1) and LUAI_MAXCCALLS.
  3. Adjust the values to the desired thresholds.
  4. Rebuild Lua using your platform's makefile or compiler.

Increasing LUAI_MAXCCALLS significantly can cause the application to crash via a native segmentation fault rather than a recoverable Lua error if the operating system's native stack memory is exhausted.

Avoiding Stack Overflows with Proper Tail Calls

Lua supports proper tail recursion. When a function returns the direct result of calling another function (or itself) without needing to preserve the current stack frame, Lua reuses the existing frame:

-- Causes a stack overflow:
local function recurse(n)
    if n > 0 then recurse(n - 1) end
end

-- Tail-call optimized; does not grow the call stack:
local function recurse_tail(n)
    if n <= 0 then return end
    return recurse_tail(n - 1)
end

By ensuring recursive calls are in the return position, recursive algorithms can run infinitely without exceeding Lua's default call stack limit.
