Limit Lua Memory Usage With a Custom Allocator

Lua allows host applications to govern its memory footprint by replacing the standard runtime allocator with a custom memory allocation function. By intercepting all memory allocation, reallocation, and deallocation requests through Lua's C API, a host can track cumulative memory usage in real time and enforce a strict ceiling. If a script requests memory that exceeds this predetermined limit, the allocator rejects the request, preventing runaway scripts from consuming excessive system RAM.

The Lua Allocator Interface

When initializing a standard Lua state, developers typically call luaL_newstate(), which uses an internal wrapper around the standard C realloc. To supply a custom allocator, you must initialize the runtime using lua_newstate() instead:

lua_State *lua_newstate(lua_Alloc f, void *ud);

The lua_Alloc callback must match the following signature:

void *allocator(void *ud, void *ptr, size_t osize, size_t nsize);
  • ud: An opaque pointer passed into lua_newstate, typically pointing to a state tracking structure.
  • ptr: A pointer to the memory block being allocated, reallocated, or freed. If ptr is NULL, the operation is a fresh allocation.
  • osize: The original size of the block. If ptr is NULL, osize is either zero or a Lua type identifier.
  • nsize: The requested new size of the block. If nsize is zero, the operation is a free request.

Enforcing the RAM Cap

To enforce a memory cap, the custom allocator tracks the current allocation size and compares projected growth against a predefined threshold before delegating to the system allocator (such as realloc or free).

#include <stdlib.h>
#include <lua.h>
#include <lauxlib.h>

typedef struct {
    size_t current_usage;
    size_t max_limit;
} MemoryTracker;

void *capped_allocator(void *ud, void *ptr, size_t osize, size_t nsize) {
    MemoryTracker *tracker = (MemoryTracker *)ud;

    // Freeing memory
    if (nsize == 0) {
        tracker->current_usage -= osize;
        free(ptr);
        return NULL;
    }

    // Calculating new usage
    size_t old_size = (ptr == NULL) ? 0 : osize;
    if (tracker->current_usage + nsize - old_size > tracker->max_limit) {
        // Limit exceeded: fail the allocation
        return NULL;
    }

    // Reallocating memory
    void *new_ptr = realloc(ptr, nsize);
    if (new_ptr != NULL) {
        tracker->current_usage = tracker->current_usage + nsize - old_size;
    }

    return new_ptr;
}

Handling Allocation Failures in Lua

When the allocator returns NULL, it indicates an out-of-memory condition. Lua responds by:

  1. Invoking an emergency garbage collection cycle to reclaim unreferenced memory.
  2. Retrying the allocation request if some memory was successfully freed during the cycle.
  3. Raising a Lua runtime error (LUA_ERRMEM / "not enough memory") if the allocation still fails.

To avoid crashing the entire host application when the cap is reached, script execution should always occur within protected calls (lua_pcall or lua_pcallk). This allows the host application to catch the memory error, abort or sandbox the offending script, and clean up the state gracefully.
