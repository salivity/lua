PICO-8 Lua: Understanding the Custom Scripting Dialect

The PICO-8 fantasy console integrates a specialized dialect of Lua by combining an altered Lua runtime with strict hardware-style constraints and unique syntactic shorthand. This article breaks down how PICO-8 adapts standard Lua, detailing its custom syntax additions, fixed-point numeric architecture, strict token and memory boundaries, and the specialized application programming interface (API) that replaces standard Lua libraries to emulate retro computing limits.

Modified Syntax and Shorthand

PICO-8 modifies standard Lua syntax to help developers write more compact code, conserving both space and readability within a 128x128 pixel display environment. Key modifications include:

  • Compound Assignment Operators: PICO-8 supports C-style compound operators such as +=, -=, *=, /=, %=, and bitwise operators like &= and |=, which are absent in standard Lua.
  • Alternative Comparison Operators: Developers can use != as an alternative to Lua’s traditional ~= inequality operator.
  • Single-Line Statements: PICO-8 allows concise, single-line conditional statements without an explicit then or end, structured as if (condition) statement.
  • Short-Form Print: The ? character functions as an alias for the console's built-in print() function.

Fixed-Point Arithmetic

Standard Lua implementations typically rely on standard double-precision or single-precision floating-point numbers. In contrast, PICO-8 implements a 32-bit fixed-point number format consisting of a 16:16 representation (16 bits for the integer part and 16 bits for the fractional part).

Because of this system, numbers range strictly from -32768.0 to 32767.99998. Arithmetic operations mimic the behavior and overflow limits of authentic 16-bit computational hardware, preventing true floating-point errors while requiring programmers to account for precision limits and integer wrapping.

Artificial Resource Constraints

To enforce its "fantasy console" identity, PICO-8 restricts code size and execution complexity using an internal token-counting engine rather than relying purely on file size:

  • The 8,192 Token Limit: PICO-8 parses Lua code into tokens (identifiers, operators, brackets, and literals). Each cartridge is hard-capped at 8,192 tokens regardless of the actual code layout or compression.
  • Character and Size Limits: Raw source code cannot exceed 65,536 characters, and saved cartridges utilize compressed formats that cannot exceed 32,768 bytes.
  • Cycle Limits: PICO-8 measures processor usage relative to a simulated 8 MHz CPU. If a script executes too many operations within a single frame, the engine throttles the frame rate from 60 or 30 frames per second down to lower rates to simulate CPU bottlenecks.

Replaced Standard Library and Core Lifecycle

PICO-8 sandboxes the runtime by completely removing Lua's default operating system, file system, and standard input/output libraries (such as io, os, and standard math). In their place, it exposes a specialized set of functions divided into:

  • Lifecycle Hooks: The console looks for three developer-defined functions: _init() for setup, _update() or _update60() for game logic, and _draw() for rendering.
  • Direct Hardware Emulation: Access to graphics, sprites, audio, and map data is handled via low-level primitives like spr(), sfx(), mget(), and pget().
  • Memory Peeking and Poking: PICO-8 maps all video memory, sprite sheets, palette data, and audio channels to a 32-kilobyte virtual RAM layout. The Lua dialect provides peek(), poke(), memcpy(), and memset() functions, enabling direct, low-level manipulation of game state in a manner identical to early home computers.
