Lua Dot vs Colon Syntax for Method Calls

In the Lua programming language, tables are often used to emulate objects and classes, leading to the use of both dot (.) and colon (:) syntax for handling functions. This article explains the syntactic differences between dot and colon notation in method definitions and calls, illustrating how the colon operator functions as syntactic sugar to implicitly pass the self parameter.

The Core Difference

The fundamental difference between dot notation and colon notation in Lua is how the calling table is passed as an argument. The colon notation is syntactic sugar designed to support object-oriented programming by automatically handling an implicit reference called self.

Method Invocations

When invoking a function attached to a table:

  • Dot Notation (.): Calls the function directly from the table without modifying the argument list. You must manually supply all arguments, including any reference to the object itself.
  • Colon Notation (:): Automatically inserts the table preceding the colon as the first argument of the function call.

The following two function calls are completely identical in behavior:

-- Using colon notation
player:takeDamage(10)

-- Equivalent using dot notation
player.takeDamage(player, 10)

In the colon example, Lua automatically provides player as the first argument. In the dot notation example, player must be passed explicitly.

Method Definitions

The same rule applies when defining functions attached to tables. Using a colon automatically injects a hidden parameter named self as the first parameter of the function body.

Defining a method with colon notation:

function player:takeDamage(amount)
    self.health = self.health - amount
end

This is completely equivalent to defining it explicitly using dot notation with self declared as the first argument:

function player.takeDamage(self, amount)
    self.health = self.health - amount
end

Interchanging the Notations

Because the colon operator is purely syntactic sugar, definitions and calls can be interchanged:

  • A method defined with : can be called with . if you pass the table manually: player.takeDamage(player, 10).
  • A method defined with . can be called with : as long as its first parameter was designed to receive the instance: player:takeDamage(10).

A common error in Lua occurs when a method defined with a colon is accidentally called with a dot without passing self (such as player.takeDamage(10)). When this happens, 10 is bound to the self parameter inside the method, and the amount parameter receives nil, leading to runtime errors.

As a general rule, use dot notation for static utility functions and standard table access, and use colon notation when writing and calling methods that operate on an object's internal state.
