Lua Boolean False and Nil in Conditionals

In the Lua programming language, control structures rely on a strict definition of truthiness where only false and nil evaluate to false. This article examines how Lua processes these two values within conditional expressions, how this behavior differs from other major programming languages, and how logical operators interact with them.

The Rule of Truthiness in Lua

In Lua, any conditional test—such as those in if, while, and repeat until constructs—evaluates an expression to determine execution flow. The engine uses a simple rule: only false and nil are considered false.

Every other value evaluates to true. This includes values that are typically considered "falsy" in languages like C, Python, or JavaScript:

  • The integer 0 and float 0.0 evaluate to true.
  • The empty string "" evaluates to true.
  • An empty table {} evaluates to true.
if nil then
    -- This block will never execute
end

if false then
    -- This block will never execute
end

if 0 then
    -- This block WILL execute
end

if "" then
    -- This block WILL execute
end

Semantic Differences Between false and nil

While false and nil behave identically inside a conditional test, they represent fundamentally different concepts in Lua:

  • nil denotes the absence of a value. Uninitialized variables, nonexistent table keys, and functions that return nothing all resolve to nil.
  • false is a dedicated boolean data type used to represent an explicit negative outcome.

Because they are distinct types, they are not equal to each other:

print(false == nil) -- Output: false

Behavior with Logical Operators

Lua's logical operators—and, or, and not—use short-circuit evaluation and do not necessarily return boolean values. Instead, they return one of their operands based on truthiness:

  • and: Returns its first operand if it evaluates to false or nil; otherwise, it returns the second operand.
  • or: Returns its first operand if it is neither false nor nil; otherwise, it returns the second operand.
  • not: Always returns an explicit boolean. Applying not to either false or nil produces true.
local a = nil
local b = false
local c = "default"

print(a or c)     -- Output: "default" (since 'a' is nil)
print(b or c)     -- Output: "default" (since 'b' is false)
print(a and c)    -- Output: nil
print(b and c)    -- Output: false
print(not nil)    -- Output: true
print(not false)  -- Output: true

The Idiomatic Default Value Pattern

Because both nil and false trigger the fallback operand in an or expression, developers frequently use or to assign default values to optional function arguments:

function setStatus(message)
    local msg = message or "No status provided"
    print(msg)
end

setStatus(nil) -- Output: No status provided

However, caution is required if a variable is expected to hold a valid boolean false. If a parameter is passed explicitly as false, the expression param or default will evaluate to the default value rather than preserving false. In such cases, explicitly checking against nil (e.g., if param == nil then ... end) is necessary.
