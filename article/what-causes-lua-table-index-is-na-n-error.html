What Causes Lua Table Index Is NaN Error?

The "table index is NaN" runtime error occurs in Lua when an operation attempts to use NaN (Not a Number) as a key in a table. In Lua, tables require keys to have stable equality, but NaN does not equal itself according to IEEE 754 floating-point standards. This article explores the root causes of this error, explains why Lua rejects NaN keys, and provides practical methods to detect and prevent the issue in your code.

Understanding the Root Cause

Lua numbers are typically represented as double-precision floating-point values conforming to the IEEE 754 standard. Under this standard, undefined mathematical operations yield NaN.

A defining property of NaN is that it is never equal to any value, including itself:

local x = 0 / 0
print(x == x) -- false

Lua tables rely on hash tables and array buffers where keys must satisfy standard equality comparisons (k1 == k2) to store and retrieve data. Because NaN == NaN always evaluates to false, a table would not be able to consistently look up or overwrite an entry stored at that index. To prevent table corruption and undefined lookup behavior, Lua raises the fatal runtime error: table index is NaN.

Common Scenarios That Produce NaN

The error typically arises when numerical calculations are passed directly into table indices without prior validation. Common triggers include:

  1. Zero Divided by Zero: Dividing zero by zero results in NaN:

    local count = 0
local total = 0
local average = total / count -- average is now NaN

local cache = {}
cache[average] = "value" -- Throws: table index is NaN

  2. Indeterminate Arithmetic Operations: Operations such as subtracting infinity from infinity yield NaN:

    local inf = math.huge
local result = inf - inf -- result is NaN

  3. Invalid Domain Inputs to Math Functions: Calling functions outside their valid domains produces NaN:

    local value = math.sqrt(-1) -- value is NaN
local angle = math.asin(2)   -- value is NaN

  4. External or Unchecked Data: Parsing malformed external data (such as JSON payloads, user input, or network packets) that explicitly contains "NaN" or yields invalid math during deserialization.

How to Prevent and Fix the Error

To avoid this runtime error, sanitize and validate values before using them as table keys.

1. Checking for NaN Directly

Because NaN is the only value in Lua that is not equal to itself, you can detect it with a simple comparison check:

local function isNaN(value)
    return type(value) == "number" and value ~= value
end

local key = calculateIndex()

if not isNaN(key) then
    myTable[key] = "data"
else
    -- Handle the invalid index appropriately
    error("Attempted to index table with NaN")
end

2. Validating Inputs Prior to Math Operations

Prevent NaN from generating in the first place by checking inputs before performing division or domain-sensitive operations:

-- Guard against zero division
local key = (count > 0) and (total / count) or 0
myTable[key] = "data"

3. Providing Fallback Values

When dealing with dynamic data where mathematical edge cases are possible, supply a default fallback value if a calculation results in NaN:

local index = calculateKey()
if index ~= index then
    index = "default_key"
end
myTable[index] = "data"
