MoonRocks: Hosting and Distributing Lua Modules

This article provides an overview of how MoonRocks functions as the community package repository for the Lua programming language. MoonRocks serves as the backend platform and public web service (now integrated directly as luarocks.org) that allows Lua developers to upload, host, version, and distribute reusable libraries known as rocks. Below is an examination of its architecture, submission pipeline, manifest indexing, and how the LuaRocks package manager retrieves these community modules.

The Role of MoonRocks in the Lua Ecosystem

MoonRocks was created as an open-source web application designed to modernize module distribution for Lua. Written using the Lapis web framework and MoonScript, it provides the central infrastructure that powers the public package repository for the standard LuaRocks command-line tool. Rather than requiring developers to host their own custom server manifests, MoonRocks centralizes the storage and discovery of community modules.

Package Submission and Verification

Module distribution begins with package authors creating a rockspec—a Lua-based declarative metadata file that specifies a package's name, version, external dependencies, build instructions, and the location of the source code. Authors submit these files to MoonRocks through two main avenues:

  1. Web Interface: Users authenticate via their user accounts and manually upload .rockspec files or pre-built .rock binaries.
  2. Command-Line API: Developers use the luarocks upload command, which communicates directly with the MoonRocks REST API using an API key generated from the user's profile.

Upon receipt, MoonRocks validates the rockspec for correct syntax, ensures required metadata fields are present, verifies package naming conventions, and checks for version collisions to prevent overwriting existing releases.

Storage and Artifact Management

Once validated, MoonRocks permanently archives the module artifacts. The rockspecs and source/binary .rock packages are saved to persistent object storage. Because immutability is vital for reproducible builds, once a specific version of a module is published, its corresponding rockspec is locked to prevent silent upstream modifications from breaking dependent codebases.

Manifest Generation and Version Routing

The distribution mechanism relies on repository manifests. MoonRocks dynamically compiles and serves plain-text manifest files that list every available package, its associated versions, supported Lua versions (such as Lua 5.1, 5.2, 5.3, 5.4, or LuaJIT), and its dependencies.

MoonRocks also supports user-specific and organization-specific namespaces. When a user uploads a module, it is associated with their namespace while also being eligible for root-level indexing, enabling standard semantic version resolution across the ecosystem.

Distribution via the LuaRocks CLI

When an end-user executes luarocks install <package_name>, the client interacts with MoonRocks through the following process:

  1. Manifest Retrieval: The client queries the MoonRocks server to download the root or Lua-version-specific manifest.
  2. Dependency Resolution: LuaRocks parses the manifest to resolve the latest compatible version of the requested module along with its required dependencies.
  3. Fetching Artifacts: The client requests the necessary .rockspec and source code archives directly from the MoonRocks file distribution endpoints.
  4. Local Compilation: LuaRocks reads the instructions provided in the hosted rockspec to build, link, and place the Lua files into the developer's local environment.
