How MoonScript Compiles to Clean Lua Code

MoonScript is a dynamic, whitespace-sensitive language that compiles entirely into standard Lua without requiring an auxiliary virtual machine. This article explores the internal mechanisms MoonScript uses to transform expressive syntax—such as classes, list comprehensions, and lexical scoping—into idiomatic, highly performant Lua code that natively executes on runtimes like Lua 5.1, LuaJIT, and modern Lua implementations.

Parsing and the Abstract Syntax Tree

The compilation pipeline begins with LPeg (Parsing Expression Grammar for Lua), which MoonScript relies on to parse source text. LPeg constructs an Abstract Syntax Tree (AST) representing the program's structural logic.

Unlike compilers that translate into intermediate bytecode or rely on an omnipresent runtime library, MoonScript’s AST transformer is specifically designed to target Lua's syntactic constructs. The compiler evaluates the AST nodes not to execute them, but to rearrange them into structural patterns that mirror how an experienced Lua developer would solve the problem by hand.

Scope Resolution and Local Variable Hoisting

One of the key differences between the two languages is variable declaration. Standard Lua defaults to global scoping unless explicitly defined with local, which often leads to unintended variable leakage. MoonScript reverses this convention by making all assignments local by default.

During compilation, MoonScript traverses each lexical scope to identify variable definitions. It then injects explicit local declarations at the top of the resulting Lua scope blocks. If a variable is assigned within a conditional branch or inner block, the compiler ensures it is predeclared in the parent block if it needs to persist, avoiding uninitialized reference errors and keeping Lua's scope clean and predictable.

Transforming Object-Oriented Structures

Lua natively lacks a class statement, instead using metatables and prototypes to accomplish object-oriented programming. MoonScript introduces full class definitions with inheritance, constructors, and instance variables.

When MoonScript encounters a class, it does not invent an arbitrary object engine. Instead, it compiles the definition into standard Lua metatable boilerplate:

  • An internal table representing the class prototype is created.
  • The prototype's __index metamethod points to itself.
  • Inheritance is implemented by linking the subclass prototype to the superclass via setmetatable.
  • A constructor function is attached to an __init or class-instantiation helper that calls setmetatable({}, cls) to return new instances.

By emitting standard metatable patterns, the generated Lua remains immediately interoperable with other native Lua modules and runs without runtime translation overhead.

Comprehensions and Functional Syntactic Sugar

Features like list comprehensions, slicing, and pattern matching are converted directly into imperative loops. For example, a single-line list comprehension in MoonScript transforms into an explicit for loop that allocates a table and uses standard index increments to insert values.

Rather than wrapping functional patterns in higher-order functions (such as map or filter) that incur function-call overhead, MoonScript produces flat, imperative Lua statements. This guarantees maximum execution speed, particularly when running under LuaJIT, which optimizes sequential loops exceptionally well.

Expression Hoisting and Clean Formatting

MoonScript allows constructs like if, switch, and do blocks to yield values directly as expressions. Since standard Lua treats these strictly as statements, the compiler uses "statement hoisting" to reconcile the difference.

When a statement is used as an expression, the compiler allocates a temporary, locally-scoped variable immediately prior to the construct. The branches inside the statement are then rewritten to assign their resulting values to this temporary holder. This design eliminates the need for anonymous self-executing functions (closures) wherever possible, reducing memory allocations and keeping the generated Lua clean, readable, and easy to debug.
