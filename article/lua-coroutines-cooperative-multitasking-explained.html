Lua Coroutines: Cooperative Multitasking Explained

Coroutines in Lua are collaborative threads that enable non-preemptive, cooperative multitasking by allowing execution to be paused and resumed at specific points. Unlike traditional operating system threads where the kernel dictates context switches, Lua coroutines explicitly yield control back to the caller, preventing race conditions and eliminating the need for complex synchronization locks. This article explains how coroutines function in Lua, explores their core lifecycle methods, and demonstrates how they implement cooperative multitasking through practical examples.

What Are Coroutines?

A coroutine is an execution thread with its own stack, local variables, and instruction pointer, but it shares global variables and memory with other coroutines. The defining characteristic of coroutines is that they are collaborative: only one coroutine runs at any given moment, and it only stops running when it explicitly requests to pause.

This model is known as cooperative multitasking. Because control transfers are fully deterministic and initiated by the programmer rather than an external scheduler, coroutines avoid the overhead and hazards associated with OS-level thread preemption, such as deadlocks and race conditions.

The Lua Coroutine API

Lua manages coroutines through the built-in coroutine library. The primary functions include:

  • coroutine.create(f): Creates a new coroutine with function f as its body and returns a value of type thread. The coroutine starts in a suspended state.
  • coroutine.resume(co, ...): Starts or resumes the execution of coroutine co. Any additional arguments are passed to the coroutine function (on first run) or returned by the corresponding yield call.
  • coroutine.yield(...): Suspends the execution of the calling coroutine. Arguments passed to yield are returned by the corresponding resume call in the host thread.
  • coroutine.status(co): Returns the current state of co as a string: "suspended", "running", "normal", or "dead".

How Cooperative Multitasking Works

Cooperative multitasking in Lua relies on a continuous dialogue between coroutine.resume and coroutine.yield. When a coroutine yields, execution returns to the exact line where resume was invoked. When resumed again, the coroutine picks up immediately after its last yield.

Code Example: Basic Control Flow

local function task(name)
    for i = 1, 3 do
        print(name .. " running step " .. i)
        coroutine.yield() -- Voluntarily yield execution
    end
end

-- Create two coroutines
local co1 = coroutine.create(function() task("Worker A") end)
local co2 = coroutine.create(function() task("Worker B") end)

-- Cooperatively alternate between tasks
while coroutine.status(co1) ~= "dead" or coroutine.status(co2) ~= "dead" do
    if coroutine.status(co1) ~= "dead" then
        coroutine.resume(co1)
    end
    if coroutine.status(co2) ~= "dead" then
        coroutine.resume(co2)
    end
end

Data Passing

Coroutines also function as bidirectional data channels:

  1. Arguments passed to the first resume are received by the coroutine's entry function.
  2. Arguments passed to yield are returned by resume.
  3. Arguments passed to subsequent resume calls become the return values of the suspended yield.
local co = coroutine.create(function(x)
    local y = coroutine.yield(x * 2)
    return y + 10
end)

local _, result1 = coroutine.resume(co, 5) -- Starts co; result1 is 10
local _, result2 = coroutine.resume(co, 20) -- Resumes co with y = 20; result2 is 30

Key Advantages in Lua

  • Extremely Lightweight: A Lua coroutine requires only a few hundred bytes of memory, allowing systems to manage tens of thousands of simultaneous tasks.
  • Deterministic Execution: Context switches happen only where explicitly defined, removing the necessity for mutexes, semaphores, or atomic operations.
  • Ideal for State Machines and Game Loops: Game development frequently leverages Lua coroutines to model character behaviors, cutscenes, and timed events over multiple frames without blocking the main rendering pipeline.
