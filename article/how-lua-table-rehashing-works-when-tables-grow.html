How Lua Table Rehashing Works When Tables Grow

In the Lua programming language, tables are hybrid data structures consisting of an internal array part and a hash map part. When a new key-value pair is inserted and no available slot exists in either segment, Lua triggers an internal operation known as a rehash. This process analyzes key distributions, calculates the most memory-efficient power-of-two sizes for both the array and hash components, reallocates memory, and migrates all existing elements along with the newly inserted entry.

Triggering the Rehash

A rehash is typically initiated by the internal function luaH_newkey. When an assignment occurs and the target key does not exist, Lua attempts to find an empty slot. If the key belongs in the hash part and the main position or free-node chain has no remaining space, or if the array segment cannot accommodate the index, Lua halts the insertion and invokes rehash.

Counting Keys and the 50% Array Utilization Rule

To prevent sparse arrays from consuming excessive memory, Lua does not blindly expand the array part. Instead, it computes an optimal distribution:

  1. Histogram Generation: Lua inspects all existing integer keys in the current array, all integer keys currently stored in the hash part, and the key pending insertion. It tallies these keys into power-of-two buckets (1, 2, 4, 8, 16, etc.).
  2. Finding the Optimal Array Size: Lua iterates through the buckets to determine the largest power of two, \(2^n\), where at least half of the slots between 1 and \(2^n\) are populated (the 50% utilization rule). This guarantees that memory overhead for unused integer slots never exceeds 50%.
  3. Determining Hash Size: Any integer keys falling outside this computed array boundary, along with all non-integer keys (strings, tables, functions, booleans), are assigned to the hash part. The hash vector is sized to the smallest power of two capable of holding the remaining count.

Memory Allocation and Resizing

Once the target dimensions are established, Lua invokes luaH_resize:

  • It requests new memory blocks from the memory allocator for the newly sized array vector, the new hash node vector, or both.
  • If a dimension shrinks to zero (for instance, an array segment that is no longer justified), its pointer is set to a dummy node or freed.

Redistributing the Elements

With the new memory allocated, Lua migrates all key-value pairs from the old structures into the new ones:

  • Old Array Migration: Elements from the old array that fall within the new array boundary are copied directly into the new array segment. Elements that now fall outside the new boundary are rehashed into the new hash table.
  • Old Hash Migration: Lua walks through the old hash nodes. If a key is an integer that now qualifies for the expanded array boundary, it is moved to the new array segment. All other keys are re-inserted into the new hash node vector. During this hash insertion, Lua computes each key's main position using its hash code, resolving collisions using open addressing with a backward-searching free-position pointer (lastfree).

Finalizing and Completing the Insertion

Once all existing elements are successfully relocated:

  1. The old memory blocks for the array and node vectors are deallocated.
  2. Control returns to luaH_newkey.
  3. Because the table has been expanded to guarantee space, the insertion of the original key and value succeeds immediately without further collision or capacity failures.
