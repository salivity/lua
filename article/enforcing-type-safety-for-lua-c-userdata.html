Enforcing Type Safety for Lua C Userdata

Enforcing type safety when exposing C pointers to the Lua runtime requires binding each pointer type to a unique metatable registered in the Lua registry. Because Lua is dynamically typed, passing raw pointers directly via light userdata exposes the host application to segmentation faults and undefined behavior. By encapsulating C pointers inside full userdata and validating them with standard auxiliary library functions such as luaL_newmetatable and luaL_checkudata, C extensions can guarantee that a userdata object passed to an API function strictly matches the expected C type.

The Problem with Light Userdata

In Lua, lightuserdata represents a raw C pointer (void*). While lightweight and unmanaged by the garbage collector, light userdata objects share a single common metatable across the entire Lua state. Consequently, Lua cannot distinguish between a pointer to a Window struct and a pointer to a DatabaseConnection struct when both are passed as light userdata. Passing the wrong pointer leads to memory corruption or crashes when cast in C.

To achieve type safety, you must use full userdata, which allocates memory managed by the Lua garbage collector and supports individual metatables.

Step 1: Encapsulating the Pointer in Full Userdata

Instead of pushing raw addresses, allocate a full userdata instance sized to hold the C pointer (void**):

typedef struct {
    int id;
    char name[32];
} Connection;

int push_connection(lua_State *L, Connection *conn) {
    // Allocate userdata holding the pointer to the struct
    Connection **ud = (Connection **)lua_newuserdata(L, sizeof(Connection *));
    *ud = conn;

    // Associate the specific type metatable
    luaL_setmetatable(L, "MyLib.Connection");
    return 1;
}

Step 2: Registering the Type Metatable

During module initialization, create a unique metatable in the Lua registry for each distinct C type using luaL_newmetatable. This metatable acts as a type tag and a container for methods and garbage-collection hooks:

static const luaL_Reg connection_methods[] = {
    {"close", l_connection_close},
    {"send",  l_connection_send},
    {NULL, NULL}
};

int luaopen_mylib(lua_State *L) {
    // Creates metatable if it does not exist, and registers it in the registry
    if (luaL_newmetatable(L, "MyLib.Connection")) {
        // Set up __index for method calls
        lua_pushvalue(L, -1);
        lua_setfield(L, -2, "__index");

        // Register methods
        luaL_setfuncs(L, connection_methods, 0);
    }
    return 1;
}

Step 3: Validating Userdata on Access

Whenever a C function is called from Lua expecting a specific pointer type, validate the argument using luaL_checkudata:

static Connection *to_connection(lua_State *L, int index) {
    Connection **ud = (Connection **)luaL_checkudata(L, index, "MyLib.Connection");
    if (*ud == NULL) {
        luaL_error(L, "attempt to use a closed Connection");
    }
    return *ud;
}

int l_connection_send(lua_State *L) {
    Connection *conn = to_connection(L, 1);
    const char *data = luaL_checkstring(L, 2);

    // Operation is completely type-safe
    send_data(conn, data);
    return 0;
}

luaL_checkudata checks whether the argument at index is full userdata and whether its metatable matches the one associated with "MyLib.Connection" in the registry. If the types do not match, it throws a descriptive Lua error and aborts execution, preventing undefined pointer casts.

Non-Throwing Validation: luaL_testudata

In Lua 5.2 and later, luaL_testudata provides a non-throwing check:

void *luaL_testudata(lua_State *L, int arg, const char *tname);

If the object matches the registered metatable, it returns the pointer; otherwise, it returns NULL. This enables method overloading, optional parameters, and custom error handling without triggering an immediate Lua panic.

Summary Checklist for Type Safety

  1. Avoid lightuserdata for typed objects; use full userdata wrapping the pointer.
  2. Assign namespaced registry keys to metatables (e.g., Module.TypeName) via luaL_newmetatable.
  3. Always verify inputs using luaL_checkudata or luaL_testudata prior to casting memory inside C callbacks.
  4. Invalidate freed pointers by setting the wrapped pointer to NULL to prevent use-after-free bugs.
