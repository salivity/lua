How Fengari Implements Lua in JavaScript

Fengari is an implementation of the Lua 5.3 programming language written entirely in JavaScript. Unlike projects that compile the standard C Lua codebase to WebAssembly using Emscripten, Fengari is a direct, hand-crafted port of Lua’s C implementation into ECMAScript. This article explains how Fengari achieves this by recreating Lua’s internal virtual machine, memory architecture, execution stack, and parser to execute Lua natively within JavaScript runtimes like web browsers and Node.js.

Direct Port of the Lua 5.3 Architecture

Fengari reproduces the modular architecture of the standard PUC-Rio Lua 5.3 codebase. Rather than compiling Lua syntax into JavaScript code (transpilation), Fengari ports the core C components of the interpreter into JavaScript modules:

  • Lexer and Parser (llex.js, lparser.js): Ingests raw Lua source code, tokenizes it, and constructs an abstract syntax tree (AST).
  • Code Generator (lcode.js): Emits register-based Lua bytecode instructions directly in memory.
  • Virtual Machine (lvm.js): Executes bytecode instructions via an internal interpreter loop.
  • Lua State and C API (lstate.js, lua.js, lapi.js): Recreates Lua's stack-based C API for interacting with the VM.

Because the parser and compiler are included in the JavaScript codebase, Fengari can dynamically parse, compile, and execute Lua code at runtime using functions like luaL_dostring.

Emulating C Data Types and the Lua Value System

Lua represents internal variables using a tagged union called TValue, which associates a type tag (such as LUA_TNIL, LUA_TNUMBER, or LUA_TTABLE) with a raw value.

In Fengari, this structure is implemented as JavaScript objects:

  • TValue Representation: Each Lua value in Fengari is an instance of a TValue class. The class retains fields for the type tag and the underlying JavaScript reference or numeric primitive.
  • Numbers: Fengari handles Lua integers and floats by mapping them directly to JavaScript's IEEE 754 standard 64-bit floating-point numbers, while implementing integer-specific operations (bitwise ops and integer division) using JavaScript's 32-bit bitwise operators or custom 64-bit integer emulations.
  • Byte Buffers: C pointers and raw byte buffers used in Lua’s internal string manipulation and I/O are handled using standard JavaScript Uint8Array typed arrays.

The Virtual Machine Dispatch Loop

Lua is a register-based virtual machine, meaning instructions access virtual registers instead of relying on a push/pop evaluation stack.

Fengari's execution engine (luaV_execute) is a large switch-statement dispatch loop running inside a JavaScript function. When executing bytecode:

  1. The VM reads an instruction encoded as a 32-bit integer.
  2. It extracts the opcode and operands (such as OP_ADD, OP_GETTABLE, or OP_CALL) using bitmask operations.
  3. The internal pointer within the current activation frame's register array is updated.
  4. The requested operation is applied to the corresponding TValue instances in the register set.

To avoid hitting JavaScript call stack limits during deeply nested calls or coroutine yields, Fengari uses trampoline patterns and tracks call frames (CallInfo) manually on an internal structure rather than relying solely on JavaScript's native call stack.

Stack Manipulation and the Pseudo-C API

A cornerstone of Lua is its virtual stack, used to pass values between the host environment and Lua functions. Fengari implements this virtual stack identically to the Lua C API.

Developers interact with Fengari using familiar C API conventions mapped to JavaScript:

const fengari = require("fengari");
const lua = fengari.lua;
const lauxlib = fengari.lauxlib;
const lualib = fengari.lualib;

const L = lauxlib.luaL_newstate();
lualib.luaL_openlibs(L);

lua.lua_pushstring(L, "Hello from JS");
lua.lua_setglobal(L, "greeting");

Internal functions push, pop, and index values on a custom array acting as the lua_State stack. This ensures high compatibility with native Lua behaviors, including error handling (using pcall/lua_pcall), protected environments, and coroutines.

Interoperability with JavaScript

Fengari provides a dedicated interop library (fengari-interop) that bridges Lua and the JavaScript runtime.

  • JS Objects in Lua: JavaScript objects passed into Lua are wrapped in a Lua userdata type equipped with a custom metatable. This metatable implements the __index and __newindex metamethods, routing property accesses in Lua (like js_obj.property) directly to JavaScript property lookups.
  • Function Calls: When a JavaScript function is invoked from Lua, the interop layer converts the Lua arguments from the virtual stack into native JavaScript arguments, executes the JavaScript function, and wraps the return value back into a TValue on the stack.

Garbage Collection

Lua implements its own incremental mark-and-sweep garbage collector (lgc.js). Fengari preserves this internal collector to maintain accurate Lua lifecycle semantics, such as __gc metamethod execution and weak table handling.

While the JavaScript engine handles low-level memory allocation and deallocates abandoned JavaScript objects, Fengari’s internal GC manages the lifecycle and references of Lua-specific entities (tables, closures, threads), preventing Lua objects from being prematurely collected by JavaScript until Lua dereferences them.
