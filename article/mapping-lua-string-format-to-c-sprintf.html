Mapping Lua string.format to C sprintf

Lua’s string.format function provides string interpolation and templating modeled directly after ISO C's sprintf, sharing the majority of its format specifiers, flags, and precision options. This article outlines how Lua mirrors standard C sprintf behavior, details the common specifiers and modifiers, and highlights key distinctions, including Lua-specific options, memory safety, and unsupported C constructs.

Core Architectural Relationship

Under the hood, Lua delegates much of string.format's formatting logic directly to the C standard library's formatting functions (traditionally sprintf or snprintf). When Lua parses the format string, it extracts conversion specifications and forwards them, along with the supplied arguments converted to their native C representations, to the underlying C runtime.

Because Lua manages memory dynamically, it eliminates the buffer overflow vulnerabilities inherent to classic C sprintf. Lua calculates the necessary space or uses dynamic reallocation buffers to return a newly created Lua string object without requiring manual buffer sizing.

Shared Conversion Specifiers

Lua supports the standard set of C conversion specifiers, mapping native Lua types to corresponding C data types:

  • Integers (%d, %i, %o, %u, %x, %X): Format integer numbers. Lua converts the number argument to a standard C integer type (typically lua_Integer, which is equivalent to long long or int64_t in modern 64-bit Lua builds). %o, %u, and %x/%X format unsigned octal, decimal, and hexadecimal representations, respectively.
  • Floating-Point Numbers (%f, %e, %E, %g, %G, %a, %A): Format floating-point values. Lua maps these to standard C double representations. Modern Lua versions (5.3+) also support %a and %A for hexadecimal floating-point notation.
  • Characters (%c): Expects a number representing an ASCII or byte code and maps directly to C's int character output.
  • Strings (%s): Expects a Lua string or a number (which Lua automatically coerces to a string) and passes it as a standard character sequence. Unlike standard C sprintf, modern Lua safely formats strings containing embedded null bytes (\0).

Flags, Width, and Precision Modifiers

Lua reproduces standard C modifier behavior positioned between the % character and the conversion letter:

  • Flags: Supports - (left-justify), + (always show sign), space (insert a space before positive numbers), # (alternative form, such as prefixing 0x to hex), and 0 (zero-padding).
  • Width: An integer value defining the minimum field width. If the converted value has fewer characters, it is padded on the left (or right, if - is used).
  • Precision: Specified with a period (.) followed by an integer. For floating-point specifiers (%f, %e), it dictates the number of digits after the decimal point. For %g, it sets the maximum number of significant digits. For integers, it defines the minimum number of digits to appear. For %s, it truncates the string to the specified length.

Lua-Specific Extensions

Lua introduces specialized specifiers not present in standard C:

  • The %q Specifier: Safely formats a boolean, number, or string between double quotes, escaping newlines, double quotes, and control characters. This output can be safely evaluated or parsed back into the Lua interpreter via load or loadstring.
  • The %p Specifier: While standard C formats pointer addresses, Lua adapts %p to output the memory address of reference types (tables, functions, userdata, and threads).

Differences and Unsupported C Features

While string.format closely matches sprintf, several C features are omitted or modified to align with Lua's runtime semantics:

  • No Length Modifiers: Modifiers such as h, l, ll, j, or z (e.g., %ld, %zu) are not supported or needed. Lua automatically chooses the appropriate underlying integer or float width based on its build configuration.
  • No Dynamic Width/Precision (*): Standard Lua does not support passing * to specify field width or precision via an argument (e.g., string.format("%*d", 5, 42) is invalid in standard Lua). Widths and precisions must be hardcoded or concatenated into the format string beforehand.
  • No %n Specifier: The C %n specifier, which writes the number of characters formatted so far back into an integer pointer, is omitted entirely for security and design reasons.
  • Strict Type Checking: Unlike C, where passing a mismatched type causes undefined behavior, Lua validates argument types against the specifier before execution and raises a runtime error on mismatch (e.g., passing a table to %d).
