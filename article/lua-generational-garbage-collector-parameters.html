Lua Generational Garbage Collector Parameters

Starting in Lua 5.4, the runtime introduced a generational garbage collection mode alongside its traditional incremental collector. In this mode, the cadence and aggressiveness of collection cycles are controlled by two distinct parameters: the minor collection multiplier (minor_mul) and the major collection multiplier (major_mul). Adjusting these parameters governs how frequently the collector sweeps short-lived young objects versus running complete, expensive collection cycles across all objects.

The Two Control Parameters

Modern Lua allows developers to switch to and configure the generational collector using collectgarbage("generational", minor_mul, major_mul) in Lua code, or lua_gc(L, LUA_GCGEN, minormul, majormul) in the C API.

  1. Minor Collection Multiplier (minor_mul) The minor_mul parameter controls the frequency of minor collections, which only inspect and clean objects created since the previous collection (the "young" generation). When set to a value \(x\), a new minor collection is scheduled when memory in the young generation grows by approximately \(x\%\) relative to the memory surviving the previous collection. By default, this value is 20, meaning a minor collection triggers after young memory grows by about 20%.

  2. Major Collection Multiplier (major_mul) The major_mul parameter determines when the runtime should escalate to a major collection, which sweeps the entire heap including long-lived (old) objects. If the memory occupied by old objects grows by \(x\%\) (where \(x\) is major_mul) relative to the size after the last major collection, a full major cycle begins. The default value is typically 100, which initiates a major collection when the memory of surviving objects doubles.

Tuning the Cadence

The generational collector is optimized under the weak generational hypothesis: most allocated objects die young. Tuning these two parameters changes the collector's cadence to match specific workload characteristics:

  • Increasing minor_mul: Decreases the frequency of minor collections, allowing the program to run with fewer interruptions and lower CPU overhead at the cost of higher temporary memory usage.
  • Decreasing minor_mul: Causes minor collections to run more frequently, maintaining a tighter memory footprint at the expense of more CPU cycles spent traversing young objects.
  • Increasing major_mul: Postpones full-heap scans, reducing heavy pauses when handling stable sets of long-lived objects.
  • Decreasing major_mul: Forces full sweeps more frequently, useful when long-lived objects become garbage regularly and must be reclaimed quickly to prevent heap bloat.

Passing zero as an argument retains the parameter's current or default value, allowing individual adjustments without altering the entire collector profile.
