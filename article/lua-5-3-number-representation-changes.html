Lua 5.3 Number Representation Changes

Lua 5.3 fundamentally overhauled how the language handles numbers by introducing a dual internal representation within the single number type. Before this version, all numbers in standard Lua were represented exclusively as double-precision floating-point values. With Lua 5.3, the runtime differentiates between standard 64-bit floats and 64-bit signed integers, expanding the language's integer precision, introducing native bitwise operations, and defining explicit coercion and arithmetic rules without breaking backward compatibility for the external type() function.

The Dual Subtype Model

Prior to version 5.3, Lua used a single C type, lua_Number (traditionally an IEEE 754 double-precision float), to handle all numeric values. Integers were merely floats that happened to have no fractional part.

Lua 5.3 introduced two subtypes beneath the number primitive:

  • integer: A two's complement signed integer, configured by default to 64 bits (ptrdiff_t or long long in C).
  • float: A standard floating-point number, configured by default as a 64-bit IEEE 754 double.

While the built-in type(x) function still returns "number" for both subtypes, the new math.type(x) function distinguishes between "integer" and "float".

Precision and Overflow Behavior

Under the pure double-precision system, integers could only be represented exactly up to 53 bits (\(2^{53}\), or 9,007,199,254,740,992). Any operations exceeding this limit suffered from precision loss.

With 64-bit integers:

  • The range expanded to \([-2^{63}, 2^{63} - 1]\) (defined by math.mininteger and math.maxinteger).
  • Integer operations follow standard two's complement wraparound semantics on overflow, rather than overflowing into floating-point infinity or losing precision.

Division and Arithmetic Rules

To maintain predictable behavior between integers and floats, Lua 5.3 introduced distinct rules for arithmetic:

  • Float Division (/): Always produces a float, even if both operands are integers and the division is exact (e.g., 4 / 2 evaluates to 2.0).
  • Floor Division (//): Rounds the quotient toward negative infinity. If both operands are integers, the result is an integer; if either operand is a float, the result is a float with no fractional component.
  • Mixed Arithmetic: In addition, subtraction, multiplication, and modulo, if one operand is a float and the other is an integer, the integer is converted to a float, and the result is a float. If both operands are integers, the operation retains the integer subtype.

Native Bitwise Operations

Because numbers could now be reliably treated as exact 64-bit words, Lua 5.3 introduced native bitwise operators, eliminating the need for third-party C libraries:

  • Bitwise AND (&), OR (|), and exclusive OR (~)
  • Unary bitwise NOT (~)
  • Right shift (>>) and left shift (<<)

Bitwise operators automatically convert float operands to integers. If a float has a fractional part or falls outside the 64-bit signed integer range, Lua throws a runtime error.

Conversion and String Coercion

Lua 5.3 introduced specific helpers to handle conversions safely:

  • math.tointeger(x): Converts a float or string to an integer if it represents an integral value within the 64-bit range. If the float has a fractional part or exceeds the bounds, it returns nil instead of raising an error or silently truncating.
  • String Formatting: The %d directive for string.format strictly formats integers, while %f or %g formats floats. String-to-number conversions now parse hexadecimal integer constants (such as 0x1A) as native integers.
