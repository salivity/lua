The Origins of Lua: How SOL and DEL Converged

Before Lua emerged as one of the world's most widely adopted embedded scripting languages, it began as two distinct, specialized internal tools developed at Tecgraf (the Computer Graphics Technology Group at PUC-Rio) in Brazil. In the early 1990s, software projects developed for the state oil company Petrobras required sophisticated configuration and data entry mechanisms. Rather than using rigid external tools or clunky standalone interpreters, the team created DEL (Data Entry Language) and SOL (Simple Object Language). In 1993, the distinct procedural capabilities of DEL and the structural data-description abilities of SOL converged directly into Lua 1.0, uniting declarative syntax with procedural programming inside a single, lightweight embedded engine.

The Needs of Tecgraf and Brazilian Trade Restrictions

Between 1977 and 1992, Brazil maintained a strict regulatory reserve on domestic computer hardware and software imports. Because Brazilian developers could not easily purchase commercial software from abroad, Tecgraf had to build custom in-house tools for clients like Petrobras. Petrobras engineers needed custom graphical user interfaces and data visualization programs for complex tasks, such as lithology visualization and structural engineering simulations. These programs required intuitive ways for non-programmers to define data structures, layout forms, and control application behavior.

DEL: The Data Entry Language

DEL was developed in 1992 as a specialized, declarative language designed to create interactive data entry forms. Engineers needed to input geological profiles and interactive parameters without manually coding each interface in C.

DEL allowed users to define input forms and specify constraints, validations, and graphical interface layouts. It also provided rudimentary procedural capabilities, enabling actions and triggers to be associated with specific form fields. However, DEL lacked deep data structuring capabilities; it could not easily handle deeply nested, hierarchical, or compound data models. As users demanded more complex configuration logic, the language began outgrowing its original purpose.

SOL: The Simple Object Language

Around the same period in 1993, another Petrobras project required a system for describing complex structural models for finite element analysis. The software needed an expressive way to describe compound objects, relationships, materials, and geometric coordinates.

This led to the design of SOL (Simple Object Language). Heavily influenced by the declarative formats of BibTeX and Motif’s User Interface Language (UIL), SOL was strictly a data-description language. It introduced simple, clear syntax for defining record types, compound attributes, and lists, complete with basic type checking. SOL succeeded in making data files human-readable and clean. However, it had a major limitation: it was entirely static. It contained no control flow structures, conditional branches, loops, or user-defined procedural functions. Whenever dynamic behavior was needed, developers had to write custom C routines to parse and process the SOL declarations.

The Direct Convergence into Lua

By mid-1993, Roberto Ierusalimschy, Luiz Henrique de Figueiredo, and Waldemar Celes realized that maintaining two distinct domain-specific languages—one procedural for data entry (DEL) and one structural for data description (SOL)—was redundant and inefficient. Modern application development required both capabilities simultaneously: engineers needed to configure complex data models (SOL) while writing procedural logic to manipulate, validate, and compute that data (DEL).

The team decided to merge both paradigms into a completely new, embedded language. Because sol means "sun" in Portuguese, they named the new language Lua, meaning "moon."

Lua synthesized the primary strengths of its predecessors into a minimal core:

  • From SOL, Lua inherited its syntax for records and object constructors. The declarative nesting format of SOL directly evolved into Lua’s fundamental composite data structure: the associative array, or table.
  • From DEL, Lua inherited its procedural paradigm, incorporating full control structures (if, while), assignment statements, and first-class functions to handle user interaction and runtime computation.

Instead of keeping data description separate from programming logic, Lua unified them. A single configuration file could now describe an intricate graphical form or physical model while simultaneously containing the algorithmic code to run it. By consolidating DEL's procedural nature with SOL's structural simplicity, Lua 1.0 established the blueprint for a lightweight, general-purpose embeddable scripting language.
