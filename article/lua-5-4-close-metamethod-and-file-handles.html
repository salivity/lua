Lua 5.4 __close Metamethod and File Handles

Lua 5.4 introduced to-be-closed variables, which provide deterministic resource management through the __close metamethod. In this version, standard I/O file handles implement __close by default, allowing developers to bind file handles to local variables using the <close> attribute. This mechanism ensures that open files are safely and immediately closed as soon as the variable's declaring scope terminates, whether that termination occurs normally or due to a runtime error.

The Mechanism of <close> with File Handles

In prior versions of Lua, files were closed either manually via file:close() or non-deterministically by the garbage collector using the __gc metamethod. Lua 5.4 provides a deterministic, RAII-like (Resource Acquisition Is Initialization) alternative.

When a file handle returned by io.open is declared with the <close> annotation:

local file <close> = io.open("example.txt", "r")

Lua marks file as a to-be-closed variable. When execution leaves the block where file is declared—via reaching the end of the block, executing a return or break, or triggering an error()—Lua automatically invokes the __close metamethod defined in the file handle's metatable.

How the __close Metamethod Functions on Files

For standard file objects, Lua’s default metatable maps __close directly to the underlying C function responsible for closing file streams (the same internal routine used by io.close(file)).

The __close metamethod receives two arguments:

  1. self: The object being closed (the file handle).
  2. err: An error object if the scope was exited due to an error, or nil if the scope exited normally.

When Lua calls __close on a standard file handle, it flushes any pending writes and closes the associated system descriptor. If self has already been closed explicitly via file:close() earlier in the block, the subsequent automatic invocation of __close acts as a no-op, preventing double-close errors.

Error Handling Behavior

If an error is raised inside the execution block containing a to-be-closed file:

  1. The runtime pauses the propagation of the original error.
  2. The __close metamethod of the file handle is invoked with the active error passed as its second argument.
  3. The file descriptor is closed to prevent resource leaks.
  4. The original error resumes its propagation up the call stack.

If an error occurs inside the __close method itself (such as a failure when flushing buffers on write operations), that new error replaces or supplements the existing error depending on Lua's error-handling state, ensuring that failures during cleanup are not silently discarded.
