Lua string.byte: Extract Raw Numeric Bytes

In the Lua programming language, strings are arbitrary sequences of 8-bit bytes, meaning text characters are stored directly as underlying numerical values. The string.byte function provides direct access to these raw binary representations by converting individual characters or ranges of characters into their corresponding unsigned integer values (from 0 to 255). This guide breaks down the mechanics of string.byte, its syntax, how it processes string memory under the hood, and how it handles multi-byte character encodings like UTF-8.

Understanding the Syntax and Parameters

The string.byte function has the following signature:

string.byte(s [, i [, j]])
  • s: The input string containing the characters you want to examine.
  • i (optional): The start index. If omitted, it defaults to 1 (the first byte of the string).
  • j (optional): The end index. If omitted, it defaults to the value of i.

Lua strings use 1-based indexing. Like most string functions in Lua, negative indices are supported and count backward from the end of the string, where -1 represents the final byte.

Extracting a Single Byte

When called with only the string or with matching start and end indices, string.byte returns a single integer:

local code = string.byte("A")
print(code) -- Output: 65

local second = string.byte("Hello", 2)
print(second) -- Output: 101 (ASCII for 'e')

Extracting Ranges as Multiple Return Values

If the range defined by i and j spans more than one position, string.byte returns each byte value as a distinct return value on Lua's virtual machine stack:

local b1, b2, b3 = string.byte("Lua", 1, 3)
print(b1, b2, b3) -- Output: 76  117  97

To capture an entire string's byte sequence into an array, you can wrap the function call in a table constructor:

local bytes = { string.byte("Code", 1, -1) }
-- bytes is now: { 67, 111, 100, 101 }

Internal Mechanics: How Lua Reads Memory

Under the hood, Lua stores strings internally as immutable, length-prefixed blocks of memory backed by standard C char arrays. When string.byte executes:

  1. Boundary Checking: Lua verifies that the indices i and j fall within the valid bounds of the string length. If i is greater than j, the function returns nothing (nil).
  2. Direct Memory Access: Lua computes the pointer offset to the requested position in the string buffer without parsing or decoding text.
  3. Type Casting: Each C char at the target offset is cast to an unsigned char. This cast ensures the value lands squarely within the [0, 255] range rather than yielding negative values on platforms where char is signed.
  4. Pushing to the Stack: Each unsigned integer is pushed onto Lua's evaluation stack as a standard Lua integer type.

Because Lua strings are strictly byte-oriented and not tied to character encoding, this lookup happens in \(O(1)\) time per byte requested, bypassing the overhead of character table lookups.

Behavior with Multi-Byte UTF-8 Characters

Lua does not natively treat strings as UTF-8 sequences when executing standard string library functions. When non-ASCII UTF-8 characters are passed to string.byte, it extracts each individual byte rather than the combined Unicode code point:

-- The character 'é' in UTF-8 consists of two bytes: 0xC3 and 0xA9
local b1, b2 = string.byte("é", 1, 2)
print(b1, b2) -- Output: 195  169

To retrieve the true Unicode code point instead of individual raw bytes in Lua 5.3 and newer, the utf8.codepoint function should be used instead. For raw network protocols, file parsing, and cryptographic operations, however, string.byte provides exact, unmanipulated access to the underlying data.
