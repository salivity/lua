Lua Hot-Reloading: Update Instance Metatables

Hot-reloading in Lua allows developers to modify source code and see changes take effect immediately without restarting the host environment. This article outlines the essential steps required to clear Lua's internal module cache, recompile modified files, and update existing object instances so that live objects immediately acquire new methods without losing their current state.

1. Unload the Existing Module

Lua caches required modules inside the global package.loaded table to prevent redundant file system reads. To force Lua to read the modified file again, remove the module from the cache:

local module_name = "my_class"
package.loaded[module_name] = nil

If you are using a custom loader rather than require, ensure any references stored in global or local caches are similarly marked for garbage collection or cleared.

2. Compile and Execute the Updated File

Read and execute the updated source code using either require or loadfile. Using loadfile allows for error-handling without crashing the host application if the modified file contains syntax errors:

local chunk, err = loadfile("my_class.lua")
if not chunk then
    print("Syntax error in reloaded file: " .. err)
    return
end

local success, new_module = pcall(chunk)
if not success then
    print("Runtime error during reload: " .. tostring(new_module))
    return
end

3. Retain the Original Metatable via In-Place Mutation

The most efficient way to update existing instances is to avoid replacing the metatable itself. In Lua, objects typically reference their class table via the __index field of their metatable:

instance -> metatable.__index -> class_table

If you replace the class table with a completely new table, existing instances will continue pointing to the old memory address. Instead, mutate the existing class/metatable in-place by copying new functions into the existing table:

local old_module = package.loaded[module_name]

if old_module then
    -- Clear deleted functions (optional)
    for k in pairs(old_module) do
        if new_module[k] == nil then
            old_module[k] = nil
        end
    end

    -- Copy new and modified functions into the existing table
    for k, v in pairs(new_module) do
        old_module[k] = v
    end

    -- Restore the module cache to the mutated original table
    package.loaded[module_name] = old_module
else
    package.loaded[module_name] = new_module
end

Because existing instances hold references to the original table address, they immediately gain access to updated, added, or removed methods through standard __index lookups.

4. Update Instances Directly Using Weak Reference Tracking

If your architecture generates a unique metatable per instance rather than sharing a single class table, you must track active instances in a weak table:

-- Create a registry with weak keys so unused instances can still be garbage-collected
local instance_registry = setmetatable({}, { __mode = "k" })

-- Call this during instance construction
function MyClass:new()
    local instance = setmetatable({}, self)
    instance_registry[instance] = true
    return instance
end

During the reload phase, iterate through the tracked instances and explicitly reassign the updated metatable:

for instance in pairs(instance_registry) do
    setmetatable(instance, new_module)
end

5. Preserve Persistent State

When reloading a file, static variables or module-level state may reset to their initial definitions. To prevent active data from being wiped out:

  1. Separate data schemas from behavior definitions, storing dynamic application state outside the reloaded module.
  2. Check for the existence of existing state before initializing default values:
-- Inside the reloaded module:
local M = package.loaded["my_class"] or {}
M.active_sessions = M.active_sessions or {}

By unloading the cache, compiling the updated file, and mutating existing metatables in place, Lua applications can achieve seamless live-code reloading while preserving running instance states.
