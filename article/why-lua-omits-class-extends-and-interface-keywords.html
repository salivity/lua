Why Lua Omits Class, Extends, and Interface Keywords

Lua intentionally excludes explicit keywords such as class, extends, and interface to preserve its core philosophy of minimalism, lightweight embeddability, and flexibility. Instead of enforcing a single, rigid object-oriented programming (OOP) paradigm through dedicated syntax, Lua provides powerful meta-mechanisms—specifically tables and metatables—that allow developers to construct their own object systems tailored to their specific needs.

Mechanisms Instead of Policies

The primary architectural principle of Lua is to "provide mechanisms rather than policies." Rigid OOP keywords like class and extends dictate a specific inheritance model (such as class-based, single-inheritance hierarchies).

By refusing to establish a single policy, Lua gives developers the freedom to choose whatever paradigm best fits their project. Programmers can implement prototype-based inheritance (similar to JavaScript), traditional class-based inheritance, multiple inheritance, or pure functional patterns using the exact same underlying syntax.

The Power of Tables and Metatables

Lua uses a single data-structuring mechanism: the associative array, or table. Combined with metatables and metamethods, tables can emulate all common OOP behaviors without introducing dedicated keywords:

  • Classes and Instances: A "class" is simply a table that acts as a prototype. An "instance" is another table whose metatable delegates missing keys back to the class using the __index metamethod.
  • Inheritance (extends): Inheritance is achieved by chaining metatables. When an instance accesses a property or method not found in its immediate class, the __index metamethod resolves the lookup up the chain to the parent table.
  • Syntactic Sugar: Lua provides the : operator (e.g., object:method()), which automatically passes self as the first argument, giving developers an ergonomic OOP syntax without needing a full class grammar.

Embeddability and Interpreter Size

Lua was designed from its inception to be an embedded extension language for host languages like C and C++. Because it frequently runs on resource-constrained platforms—such as game consoles, routers, and embedded IoT devices—its footprint must remain exceptionally small.

Adding native class systems, inheritance trees, and interface validators would significantly increase the complexity of the parser, bytecode generator, and runtime virtual machine. Omitting these keywords keeps the standard Lua interpreter under 300 KB and allows it to compile and execute at high speeds.

Dynamic Typing and the Absence of Interfaces

The interface keyword is primarily a tool for static type checking, used by compilers to enforce method contracts before code execution. Because Lua is a dynamically typed, interpreted language, compile-time interfaces do not fit its execution model.

Lua relies entirely on "duck typing": if a table contains the required function, it can be invoked safely. Imposing formal interface declarations at runtime would add unnecessary overhead. In cases where contract enforcement is required, developers can perform runtime inspections via table traversal or use simple assertion helpers rather than dedicated language keywords.
