How Lua Arithmetic Metamethod Dispatch Works

In the Lua programming language, metamethod dispatch for arithmetic operations allows developers to define custom behaviors for standard mathematical operators when applied to non-numeric types, such as tables or userdata. When Lua encounters an arithmetic operator, it checks whether the operands natively support the operation. If they do not, Lua queries the operands' metatables for corresponding metamethods. If a valid metamethod is found, it is executed; otherwise, the interpreter raises a runtime type error.

Arithmetic Operators and Their Metamethods

Lua maps each arithmetic operator directly to a specific metamethod name:

  • Addition (+): __add
  • Subtraction (-): __sub
  • Multiplication (*): __mul
  • Division (/): __div
  • Floor division (//): __idiv
  • Modulo (%): __mod
  • Exponentiation (^): __pow
  • Unary minus (-): __unm

The Binary Dispatch Algorithm

When executing a binary arithmetic operation (such as a + b), Lua follows a strict, step-by-step lookup order:

  1. Primitive Evaluation: Lua checks if both operands are numbers (or strings coercible to numbers, depending on the Lua version). If both satisfy this condition, the raw CPU-level arithmetic instruction executes directly, bypassing the metatable mechanism entirely.
  2. First Operand Check: If the operation cannot be executed natively, Lua inspects the first operand (a). If a has a metatable containing the associated metamethod (e.g., __add), Lua selects that metamethod.
  3. Second Operand Check: If a has no metatable, or if its metatable lacks the required field, Lua inspects the second operand (b). If b has a metatable containing the metamethod, Lua selects that function instead.
  4. Execution: If a metamethod was found in either step 2 or step 3, Lua invokes it, passing both operands in their original order: handler(a, b).
  5. Failure: If neither operand provides the required metamethod, Lua halts execution with a runtime error (e.g., attempt to perform arithmetic on a table value).

Unlike relational metamethods (like __eq or __le), arithmetic dispatch does not require both operands to share the exact same metamethod function. The first operand takes precedence; if it defines the handler, that handler is chosen regardless of what the second operand defines.

Unary Operation Dispatch

The unary minus operator (-a) involves only a single operand. Lua's dispatch for unary operations functions as follows:

  1. If a is a number, Lua computes its negation immediately.
  2. If a is not a number, Lua checks if a has a metatable containing the __unm metamethod.
  3. If present, Lua calls the function, typically passing a as both arguments: handler(a, a).
  4. If __unm is missing, Lua raises a runtime error.

Practical Implications

Because Lua searches the left operand before the right operand, asymmetric operations are governed by the leftmost type that defines the metamethod. For example, in vector math where a vector is multiplied by a scalar (Vector * 2), the Vector metatable's __mul is called. In reverse (2 * Vector), the number 2 has no metamethod, so Lua falls back to the Vector metatable's __mul. The metamethod implementation must be designed to handle the variable types of either argument accordingly.
