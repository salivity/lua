How Lua ipairs Iterates Array-Like Tables

In the Lua programming language, the ipairs function provides a standardized way to traverse array-like tables in a strict, ordered sequence. This article explains how ipairs functions under the hood, how it handles indices and termination conditions, why it ignores non-sequential keys, and how it differs from the general-purpose pairs iterator.

The Basic Mechanism of ipairs

The ipairs function is a stateful iterator factory specifically tailored for tables with continuous, positive integer keys starting at 1. When invoked in a for loop, ipairs returns three values: an iterator function, the table itself, and the starting index 0.

During each cycle of the loop, the iterator function increments the index by 1 and evaluates whether a value exists at that index:

local fruits = {"apple", "banana", "cherry"}

for index, value in ipairs(fruits) do
    print(index, value)
end

Output:

1   apple
2   banana
3   cherry

Step-by-Step Execution

When the for index, value in ipairs(t) loop executes:

  1. Initialization: Lua calls ipairs(t), obtaining the internal iterator function, the invariant state (the table t), and the control variable initialized to 0.
  2. Iteration Step: The loop calls the iterator function with (t, 0). The iterator increments the index to 1 and fetches t[1].
  3. Condition Check: If t[1] is not nil, the loop assigns 1 to index and the element's content to value, executing the loop block.
  4. Subsequent Cycles: The iterator receives the updated index, increments it to 2, and checks t[2]. This process repeats consecutively (3, 4, etc.).
  5. Termination: The moment t[i] resolves to nil, the iterator function returns nil, and the loop terminates immediately.

Handling of Non-Integer Keys and Gaps

Unlike the general pairs function, which uses next to traverse both the array and hash parts of a table in an arbitrary order, ipairs strictly evaluates integer arithmetic on keys:

  • Gaps (Holes): If an array contains a nil between elements (such as t[1] = "a", t[3] = "c" where t[2] is absent), ipairs stops at index 2. Elements at index 3 and beyond will never be reached.
  • String and Custom Keys: Any keys that are strings, booleans, tables, or negative integers are completely bypassed by ipairs.
  • Zero and Negative Indices: Lua arrays are 1-indexed by convention. ipairs starts checking at index 1, meaning values stored at index 0 or negative numbers are ignored.
local mixed = {
    [1] = "first",
    [2] = "second",
    [4] = "fourth",    -- Gap at 3 causes ipairs to stop before this
    name = "example",  -- String key ignored
    [-1] = "negative"  -- Negative key ignored
}

for i, v in ipairs(mixed) do
    print(i, v)
end

Output:

1   first
2   second

Conceptual Lua Equivalent

To understand the internal logic, the behavior of ipairs can be represented in pure Lua as follows:

local function ipairs_iterator(t, i)
    i = i + 1
    local v = t[i]
    if v ~= nil then
        return i, v
    end
end

function custom_ipairs(t)
    return ipairs_iterator, t, 0
end

Because ipairs relies exclusively on sequential numerical indexing (t[i]), it guarantees deterministic, ascending order traversal for array structures at predictable performance.
