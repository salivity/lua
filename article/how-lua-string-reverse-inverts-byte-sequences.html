How Lua string.reverse Inverts Byte Sequences

The string.reverse function in Lua inverts a string by treating it as a raw, contiguous array of 8-bit bytes and copying those bytes from back to front into a newly allocated string. Because Lua is fundamentally byte-oriented and encoding-agnostic at its core, this operation does not parse multi-byte characters like UTF-8, resulting in a strictly mechanical reversal of raw memory.

Internal String Representation in Lua

In Lua, strings are immutable, length-prefixed byte arrays managed by the Lua C API. A string can contain any arbitrary 8-bit values, including embedded zero bytes (\0). Because the Lua runtime does not enforce or track specific character encodings such as ASCII or UTF-8, string operations work directly on sequences of char values defined by a pointer and a fixed length.

The C Implementation of string.reverse

Under the hood, string.reverse is implemented in Lua's standard library file lstrlib.c by the C function str_reverse. The inversion process follows these steps:

  1. Length Retrieval: The function extracts the source string's pointer and its exact byte length using luaL_checklstring.
  2. Buffer Preparation: A buffer (luaL_Buffer) is initialized to hold the resulting string, reserving the same number of bytes as the source string.
  3. Byte-by-Byte Copying: The function runs a loop that reads bytes starting from the last index (length - 1) down to the first index (0) of the source pointer, writing each byte sequentially from the beginning to the end of the destination buffer:
static int str_reverse (lua_State *L) {
  size_t l, i;
  luaL_Buffer b;
  const char *s = luaL_checklstring(L, 1, &l);
  char *p = luaL_buffinitsize(L, &b, l);
  for (i = 0; i < l; i++)
    p[i] = s[l - 1 - i];
  luaL_pushresultsize(&b, l);
  return 1;
}
  1. String Interning: Once the buffer is populated, luaL_pushresultsize finalizes the buffer, creates an interned string object in Lua's internal hash table, and pushes it onto the Lua stack.

Performance Characteristics

The reversal operation has a time complexity of \(O(n)\), where \(n\) is the number of bytes in the string. Space complexity is also \(O(n)\) because Lua strings are immutable; the operation cannot occur in place and must allocate memory for the reversed result.

Implications for Multi-Byte Encodings

Because string.reverse copies individual bytes rather than Unicode code points or grapheme clusters, multi-byte encodings like UTF-8 will be corrupted if reversed with this function. A two-byte UTF-8 sequence [0xC3, 0xA9] (representing é) becomes [0xA9, 0xC3], which is invalid UTF-8. Handling multi-byte text requires specialized libraries like utf8 (included in Lua 5.3+) or custom algorithms that traverse and reverse code point boundaries rather than raw bytes.
