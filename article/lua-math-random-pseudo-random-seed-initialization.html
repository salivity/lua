Lua math.random Pseudo-Random Seed Initialization

Modern versions of the Lua programming language, starting with Lua 5.4, handle pseudo-random number generation internally rather than relying on the host platform's C runtime library. This modern implementation uses the xoshiro256** algorithm and automatically initializes its pseudo-random seed when the math library loads, removing the legacy requirement of manually calling math.randomseed(os.time()) to avoid repeating sequence patterns upon startup.

The Shift to xoshiro256**

In Lua 5.3 and earlier, math.random and math.randomseed acted as thin wrappers around the standard C library functions rand() and srand(). This design led to platform-dependent quality and required developers to manually seed the generator, often using system time, to avoid identical outputs across runs.

Lua 5.4 replaced this mechanism entirely by integrating the xoshiro256** (xor-shift-rotate) algorithm directly into the core engine. This generator maintains an internal 256-bit state represented as four 64-bit unsigned integers, providing high-performance, statistically robust pseudo-random sequences across all operating systems.

Automatic Initialization at Startup

When a modern Lua state opens and loads the standard math library via luaopen_math, the engine executes an internal function that sets up the generator's state without user intervention.

To initialize the state, Lua gathers entropy from two primary sources available in standard C:

  1. System Time: The standard C time(NULL) function retrieves the current calendar time in seconds.
  2. Memory Addresses: The runtime takes the address of a local variable or internal Lua structure on the stack.

Because modern operating systems implement Address Space Layout Randomization (ASLR), memory addresses change between program executions. By combining the system time with these randomized memory addresses, Lua derives two distinct 64-bit integer values.

Expanding Seeds into Internal State

The two initial 64-bit values are not used directly as the final state. Because the xoshiro256** algorithm requires four non-zero 64-bit integers to function properly, Lua passes the initial values through a secondary, lightweight generator called SplitMix64.

SplitMix64 generates the four distinct pseudo-random 64-bit integers required to populate the full 256-bit state of the xoshiro256** engine. This expansion guarantees that even if the initial seed values have low entropy, the full state array is properly scrambled and valid.

Manual Seeding in Modern Lua

While automatic seeding handles standard execution, developers can still control the seed manually:

  • math.randomseed() with no arguments: Re-executes the automatic seeding logic, mixing fresh system time and current memory addresses to re-randomize the generator with non-deterministic values.
  • math.randomseed(x, y): Accepts up to two integers to set the seed deterministically. Lua runs these inputs through the same SplitMix64 initialization process, ensuring reproducible test environments while fully populating the internal 256-bit state.

Although this initialization strategy prevents predictable output across program restarts in non-adversarial environments, it relies on low-entropy sources and is not cryptographically secure.
