Lua Rockspecs and Dependencies Explained

A rockspec is the package specification format used by LuaRocks, the standard package manager for the Lua programming language. It serves as a blueprint that contains all necessary metadata, build instructions, and dependency requirements for distributing and installing a Lua module. This article explains what a rockspec file is, breaks down its core components, and demonstrates how to declare package and external source dependencies to ensure smooth builds and installations.

What is a Rockspec?

A rockspec is a text file written in Lua syntax, typically bearing the .rockspec extension. It describes a specific version of a Lua library or application. When a user runs luarocks install <package>, LuaRocks reads the corresponding rockspec to fetch the source code, resolve required modules, compile any native components (such as C code), and install the files into the local Lua environment.

A rockspec file name follows a strict convention: <package>-<version>-<rockspec_revision>.rockspec. For example, luasocket-3.0rc1-2.rockspec defines the second revision of the rockspec for LuaSocket version 3.0rc1.

Declaring Source Repositories

Before declaring dependencies, a rockspec specifies where to fetch the package's primary source code using the source table. This points directly to a release archive, a Git repository, or other version control systems.

source = {
   url = "git://github.com/example/example-lib.git",
   tag = "v1.0.0"
}

Declaring Lua Dependencies

Dependencies on other Lua modules are declared using the dependencies array. Each entry is a string specifying a package name followed by optional version constraints. LuaRocks uses these declarations to download and install required packages automatically before building the target package.

The dependencies list typically includes the supported Lua runtime versions alongside third-party modules:

dependencies = {
   "lua >= 5.1, < 5.5",
   "luasocket >= 3.0",
   "lpeg == 1.0.2",
   "cjson ~> 2.1"
}

Supported version operators include:

  • ==: Exact version match.
  • ~=: Incompatible with a specific version.
  • >, <, >=, <=: Relational version boundaries.
  • ~>: The "pessimistic" operator (e.g., ~> 2.1 allows >= 2.1 but < 3.0).

Declaring External Source and System Dependencies

Many Lua modules wrap native C libraries. When a module requires C header files or compiled shared libraries to build from source, these are declared in the external_dependencies table rather than the standard dependencies table.

external_dependencies = {
   OPENSSL = {
      header = "openssl/ssl.h",
      library = "ssl"
   }
}

In this setup:

  • The key (e.g., OPENSSL) acts as an identifier.
  • header defines the C header file LuaRocks must locate during the build phase.
  • library defines the system library (e.g., libssl.so or ssl.lib) required for linking.

If these external requirements are missing from the host machine, LuaRocks halts the build and prompts the user to install the appropriate system development headers or specify their custom installation paths using flags (such as OPENSSL_INCDIR and OPENSSL_LIBDIR).
