How coroutine.status Reports Dead State in Lua

In the Lua programming language, the coroutine.status function monitors the lifecycle of a coroutine and returns the string "dead" once execution has permanently stopped. This article explains the exact mechanisms that trigger the dead state, how coroutine.status reflects this transition after normal termination or runtime errors, and how to interpret this status to prevent invalid execution attempts.

What Causes the Dead State

A coroutine in Lua exists in one of four states: "running", "suspended", "normal", or "dead". The coroutine.status function checks the internal flags of a given coroutine thread and returns "dead" under two specific circumstances:

  1. Normal Completion: The coroutine's main function executes completely and returns. When control leaves the body of the function, the coroutine has no further instructions to process.
  2. Unhandled Runtime Errors: If an error occurs inside the coroutine and is not caught internally (such as with pcall), the coroutine terminates immediately.

In both scenarios, the thread context cannot be resumed, and Lua marks the internal state of the coroutine as dead.

Inspecting the Dead State with coroutine.status

When passing a coroutine object to coroutine.status(co), Lua evaluates the coroutine's execution stack. If the stack has concluded or halted due to an error, the function evaluates to the string literal "dead".

Example: Normal Completion

local co = coroutine.create(function()
    coroutine.yield()
    return "done"
end)

print(coroutine.status(co)) -- suspended
coroutine.resume(co)
print(coroutine.status(co)) -- suspended
coroutine.resume(co)
print(coroutine.status(co)) -- dead

When coroutine.create creates the coroutine, it starts in the "suspended" state. After the final coroutine.resume call processes the return statement, coroutine.status(co) shifts directly to "dead".

Example: Error Termination

local co = coroutine.create(function()
    error("Fatal execution failure")
end)

local success, message = coroutine.resume(co)
print(success)             -- false
print(message)             -- ...: Fatal execution failure
print(coroutine.status(co)) -- dead

Even though an error occurred, Lua protects the main thread by returning false along with the error message via coroutine.resume. The failing coroutine's stack is dismantled, and coroutine.status(co) instantly reflects "dead".

Resuming a Dead Coroutine

Once coroutine.status reports "dead", the coroutine cannot be revived or restarted. Attempting to call coroutine.resume on a dead coroutine will consistently return false followed by the string "cannot resume dead coroutine". To repeat the task, a new coroutine must be instantiated using coroutine.create.
