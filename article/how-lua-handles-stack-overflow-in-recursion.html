How Lua Handles Stack Overflow in Recursion

This article explores how the Lua runtime detects and handles stack overflows during recursive function execution. It covers Lua's internal virtual stack architecture, the pre-emptive limit checks that raise runtime errors, the role of protected environments in intercepting these errors, and the implementation of proper tail calls to avoid stack exhaustion entirely.

The Lua Call Stack Architecture

Unlike compiled languages that rely entirely on the operating system's native machine stack, the Lua virtual machine manages its own independent stack. Lua allocates its execution stack on the heap as an array of values (TValue) alongside a linked list or array of activation records known as CallInfo structures.

Each time a Lua function is invoked, the runtime pushes a new CallInfo record to track the function’s state, program counter, and base register index. This abstraction decouples pure Lua function execution from the operating system's hardware stack, allowing the runtime to inspect and regulate its own memory boundaries precisely.

Detection and Hard Limits

Lua prevents unbounded recursive growth through compile-time configuration limits set in luaconf.h. The primary limits include:

  • LUAI_MAXSTACK: Defines the absolute maximum number of stack slots Lua can allocate for variables and temporary registers (often set between 1,000,000 and 2,000,000 slots depending on the Lua version and platform).
  • LUAI_MAXCCALLS: Controls the maximum depth of nested non-tail calls to prevent exhausting the native C stack when Lua interfaces with C functions.

Before executing a non-tail recursive call, the Lua interpreter checks whether the upcoming call exceeds the allocated space or the maximum call depth threshold. If the requested stack growth breaches these predefined boundaries, Lua interrupts execution immediately rather than allowing memory corruption or segmentation faults.

The Runtime Error Mechanism

When a recursive function reaches the stack ceiling, Lua triggers a standard runtime error with the message:

stack overflow

Lua executes this abort sequence via its internal luaG_runerror function, which unwinds the virtual stack back to the nearest protected frame.

Because Lua treats stack overflow as a standard runtime exception rather than a fatal crash:

  1. Unprotected Calls: If the recursion occurs in the main thread without a handler, the interpreter halts the execution, prints the stack traceback to standard error, and terminates the script with an exit code.
  2. Protected Calls (pcall and xpcall): If the recursive function runs inside pcall or xpcall, the error is caught safely. Lua returns a status code of false along with the "stack overflow" error string, allowing the surrounding application to recover, log the event, or degrade gracefully without terminating the host process.

Native C-Stack Recursion vs. Lua Recursion

When recursive Lua code invokes C functions that call back into Lua, execution uses both the Lua heap-based stack and the operating system's native thread stack.

To safeguard the native machine stack, Lua tracks the depth of nested C calls through an internal counter (nCcalls). If this counter reaches its limit (typically set to 200 in standard Lua), the engine halts with a C-stack overflow error. This dual-check mechanism prevents native thread crashes caused by mutual recursion between Lua and the C API.

Proper Tail Call Optimization

Lua provides native support for proper tail calls (tail call elimination) as defined by the language specification. When a recursive call is made in the tail position—meaning the calling function simply returns the exact result of the recursive call without further operations—Lua does not push a new CallInfo frame.

-- Non-tail recursive: Causes a stack overflow
local function non_tail(n)
    if n == 0 then return 0 end
    return 1 + non_tail(n - 1)
end

-- Tail recursive: Optimized into an internal jump; no stack overflow
local function tail_optimized(n, acc)
    acc = acc or 0
    if n == 0 then return acc end
    return tail_optimized(n - 1, acc + 1)
end

In tail-optimized recursion, the Lua runtime reuses the current function's activation record and register space. This effectively converts the recursion into an internal loop at the bytecode level, allowing functions to recurse infinitely without consuming additional stack slots or triggering an overflow error.
