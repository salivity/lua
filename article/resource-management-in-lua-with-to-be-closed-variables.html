Resource Management in Lua with To-Be-Closed Variables

This article provides an overview of implementing the Resource Acquisition Is Initialization (RAII) pattern in the Lua programming language. Introduced in Lua 5.4, to-be-closed variables allow developers to manage system resources—such as file handles, network sockets, and database locks—deterministically. By binding cleanup logic to local variable lifecycles through the __close metamethod, Lua ensures that resources are reliably freed upon scope exit, even when errors occur.

Understanding RAII and To-Be-Closed Variables

RAII is a programming idiom where resource allocation is tied to the lifetime of an object. In traditional Lua code, resource cleanup relied on manual calls (like file:close()) wrapped in pcall blocks, or nondeterministic garbage collection using the __gc metamethod.

Lua 5.4 introduced the <close> attribute for local variables. When a local variable marked with <close> leaves its lexical scope—whether through normal execution flow, a return, a break, or a raised error—Lua automatically invokes the __close metamethod on the object held by that variable.

Syntax and the __close Metamethod

To enable RAII behavior for any custom object, its metatable must implement the __close metamethod. The method receives the object itself and, if the scope exited due to an error, the error object.

local Resource = {}
Resource.__index = Resource

function Resource.new(name)
    local self = setmetatable({ name = name }, Resource)
    print("Acquiring: " .. self.name)
    return self
end

function Resource:__close(err)
    print("Releasing: " .. self.name)
    if err then
        print("Scope exited with error: " .. tostring(err))
    end
end

To bind the cleanup to the scope, declare the variable with the <close> attribute:

do
    local res <close> = Resource.new("DatabaseConnection")
    -- Work with the resource
    print("Working with: " .. res.name)
end
-- Output shows release immediately after the block ends:
-- Acquiring: DatabaseConnection
-- Working with: DatabaseConnection
-- Releasing: DatabaseConnection

Standard Library Support

Lua's standard io library comes with built-in support for to-be-closed variables. Standard file handles produced by io.open() implement the __close metamethod out of the box.

local function process_file(filepath)
    local file <close> = assert(io.open(filepath, "r"))
    local content = file:read("*a")
    return content
    -- The file is guaranteed to close here, even if read fails
end

Scope Exit Mechanics and Ordering

When multiple <close> variables are defined within the same block, Lua handles their destruction using a Last-In, First-Out (LIFO) order, mirroring the destruction order of local objects in languages like C++.

do
    local a <close> = Resource.new("First")
    local b <close> = Resource.new("Second")
    -- Execution finishes
end
-- Release order:
-- Releasing: Second
-- Releasing: First

If an error is raised inside the block, Lua guarantees that all active <close> variables declared up to that point will run their __close handlers before the error propagates upward. This eliminates the need for deeply nested pcall and xpcall structures solely intended for resource cleanup.
