High-Performance Custom Kong Plugins in Lua

This guide examines the core architectural patterns for developing high-performance custom plugins for the Kong Gateway using the Lua programming language. It details strategies for leveraging OpenResty's non-blocking I/O model, reducing LuaJIT garbage collection pressure, implementing multi-tiered caching strategies, and properly delegating tasks across Kong’s request lifecycle phases to achieve sub-millisecond overhead.

Strategic Phase Delegation

Kong's execution lifecycle maps directly to OpenResty phases (rewrite, access, response, header_filter, body_filter, and log). High-performance plugins limit CPU-bound work strictly to phases that require it.

  • Move non-critical operations to log: External telemetry, metrics dispatch, and deep audit logging must be deferred to the log phase. This phase executes after the response has been sent to the client, preventing non-essential processing from increasing overall request latency.
  • Fail fast in access: Any access control, rate limiting, or input validation logic should execute as early as possible in the access phase. If a request is malformed or unauthorized, terminate it immediately via kong.response.exit() to avoid downstream connection overhead and upstream execution.
  • Avoid buffering in body_filter: Manipulating request or response bodies requires chunked streaming. Accumulating whole payloads in memory to parse JSON or XML introduces high latency and memory spikes; process streams incrementally or offload inspection downstream.

Multi-Tiered In-Memory Caching

Inter-process communication and remote lookups degrade throughput. High-performance plugins use a two-level (L1/L2) caching pattern to maximize hit rates and minimize locking.

  1. Level 1: Worker-Local Memory (lua-resty-lrucache): Store hot objects inside worker-specific memory. This eliminates cross-worker mutex contention entirely. L1 hits return raw Lua objects without deserialization overhead.
  2. Level 2: Shared Dictionary (ngx.shared.DICT via kong.cache): If an item misses L1, query the shared memory zone available across all Nginx workers. kong.cache provides built-in mechanisms to prevent cache-stampedes (dog-piling) by ensuring only one worker updates an expired key while other workers receive stale or wait-state data.

Stale-while-revalidate patterns should be implemented via ngx.timer.at, allowing stale data to be returned immediately while a background task refreshes the shared dictionary.

Non-Blocking Asynchronous I/O via Cosockets

Standard Lua libraries often execute synchronous, blocking I/O calls that stall the entire Nginx worker thread.

  • Use the Kong PDK and OpenResty Cosockets: All network communication (HTTP, Redis, database connections) must use the Kong Plugin Development Kit (PDK) or OpenResty-compatible cosocket libraries (e.g., lua-resty-http, lua-resty-redis).
  • Connection Pooling: Never establish a new TCP or TLS connection per request. Configure proper connection pooling with set_keepalive(timeout, pool_size) to reuse sockets across the worker lifecycle.
  • Background Offloading: Fire-and-forget background tasks should utilize ngx.timer.at or ngx.timer.every. Note that timers run outside the request context, so request data must be explicitly serialized and passed to the timer callback.

Minimizing LuaJIT Allocations and Garbage Collection

The LuaJIT Garbage Collector (GC) runs concurrently with execution; high allocation rates trigger frequent GC sweeps that induce tail-latency spikes.

  • Preallocate and Reuse Tables: Dynamic table creation ({}) in high-throughput hot paths forces continuous memory allocation. Preallocate array and hash sizes using table.new(narray, nhash) when using the table.new module, or clear and reuse static worker tables using table.clear.
  • Avoid String Concatenation in Loops: Lua strings are immutable; concatenation via the .. operator allocates new strings in memory. Buffer intermediate strings inside an array table and join them once with table.concat().
  • Compile Regular Expressions Ahead of Time: When using pattern matching, utilize ngx.re functions with the 'o' (compile once) flag, or precompile expressions at module initialization. Avoid the native Lua string.match for complex parsing as it bypasses the PCRE JIT engine.

Safe Initialization and Configuration Hydration

The init and configure phases occur when the Kong worker starts or reloads its declarative schema.

  • Pre-process Schema Values: Transform and index plugin configurations during the configure handler rather than parsing configurations on every request. Pre-calculate lookup maps, hash sets, and normalized headers so that request-time retrieval is \(O(1)\).
  • Avoid Global Variable Leaks: Always run with strict variable checking. Global variables (my_var = 1) bypass module isolation, are shared unpredictably across requests, and invalidate LuaJIT optimization heuristics. Use local definitions for all references, including PDK shortcuts.
