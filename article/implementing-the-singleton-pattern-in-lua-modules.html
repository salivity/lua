Implementing the Singleton Pattern in Lua Modules

In Lua, the singleton pattern ensures that a module maintains a single, globally accessible instance throughout the application lifecycle. Because Lua's require function automatically caches loaded modules inside the internal package.loaded table, any standard module naturally operates as a singleton by default. This article explains how Lua's module caching works, how to implement basic and encapsulated singletons, and how to safeguard the module instance from unintended modifications.

Lua Module Caching Mechanism

When a module is loaded using require("module_name"), the Lua runtime executes the following sequence:

  1. It inspects the package.loaded table for the key "module_name".
  2. If the key exists, Lua immediately returns the cached value (typically a table), bypassing the file execution.
  3. If the key does not exist, Lua searches for the file, evaluates it, stores the return value in package.loaded["module_name"], and returns it to the caller.

Because subsequent require calls return a reference to the exact same table in memory, the module intrinsically behaves as a single instance.

Basic Singleton Implementation

The simplest approach defines an exported table containing data and methods.

-- logger.lua
local Logger = {}

Logger.logs = {}

function Logger.log(message)
    table.insert(Logger.logs, message)
    print("[LOG]: " .. message)
end

function Logger.get_count()
    return #Logger.logs
end

return Logger

When accessed from multiple files, both references interact with the identical state:

-- file_a.lua
local Logger = require("logger")
Logger.log("Application initialized")

-- file_b.lua
local Logger = require("logger")
print("Total logs: " .. Logger.get_count()) -- Output: Total logs: 1

Encapsulating Private State with Closures

To prevent external scripts from directly modifying the singleton's internal state, store private data in local variables within the module scope rather than directly on the exported table.

-- config_manager.lua
local ConfigManager = {}

-- Private state hidden within the module's file scope
local settings = {
    theme = "dark",
    volume = 80
}

function ConfigManager.get(key)
    return settings[key]
end

function ConfigManager.set(key, value)
    if settings[key] ~= nil then
        settings[key] = value
    else
        error("Invalid configuration key: " .. tostring(key))
    end
end

return ConfigManager

In this implementation, external code can read and write values only through get and set. The settings table remains private to the module closure.

Enforcing Immutability with Metatables

To prevent other scripts from accidentally attaching new methods or overriding existing properties on the singleton, protect the exported table using the __newindex metamethod.

-- database_pool.lua
local Pool = {}
local connections = 0

function Pool.connect()
    connections = connections + 1
    return "Connection established"
end

function Pool.active_count()
    return connections
end

-- Read-only wrapper
local proxy = {}
local mt = {
    __index = Pool,
    __newindex = function(_, key, _)
        error("Attempt to modify read-only singleton member: " .. tostring(key), 2)
    end,
    __metatable = false -- Prevents unauthorized metatable modification
}

return setmetatable(proxy, mt)

Resetting Singleton State

If the singleton needs to be reset (for instance, during unit testing), remove its entry from package.loaded:

package.loaded["module_name"] = nil
local fresh_instance = require("module_name")

The next call to require treats the file as newly imported, re-running the module script and generating a clean instance.
