Defining Constants in Lua Using Uppercase

This article explores the conventional use of uppercase letters to define constants in the Lua programming language. Because standard Lua historically lacked native keyword support for immutable variables, programmers adopted naming conventions borrowed from languages like C to communicate intent. Below, we examine the traditional SCREAMING_SNAKE_CASE styling, how it functions as a social contract among developers, how immutability can be enforced programmatically with metatables, and how this convention coexists with modern Lua features.

The Screaming Snake Case Convention

In Lua, variables are mutable by default and dynamically typed. To declare that a variable's value should remain fixed throughout the execution of a program, developers traditionally write the identifier entirely in capital letters, separating words with underscores. This style is commonly referred to as SCREAMING_SNAKE_CASE.

-- Standard convention for constants in Lua
MAX_CONNECTIONS = 100
DEFAULT_TIMEOUT = 30
PI = 3.141592653589793

Because the Lua runtime does not automatically protect these variables from reassignment, the uppercase styling serves as a visual indicator and a "gentleman's agreement." When developers see an all-uppercase variable, they treat it as read-only.

Table-Based Constant Namespaces

When organizing larger projects, constants are often grouped into dedicated tables to avoid polluting the global namespace. Even within tables, keys intended to represent fixed values are written in uppercase.

local Config = {
    DATABASE_PORT = 5432,
    MAX_RETRIES = 5,
    API_BASE_URL = "https://api.example.com"
}

Enforcing Immutability with Metatables

To move beyond relying solely on visual convention, developers frequently combine uppercase naming with Lua metatables to prevent accidental modification at runtime. By utilizing the __newindex metamethod, a table can be configured to raise an error whenever code attempts to modify a constant.

local function create_constant_table(tbl)
    return setmetatable({}, {
        __index = tbl,
        __newindex = function(_, key, _)
            error("Attempt to modify read-only constant: " .. tostring(key), 2)
        end
    })
end

local SETTINGS = create_constant_table({
    SCREEN_WIDTH = 1920,
    SCREEN_HEIGHT = 1080
})

-- Reading works normally
print(SETTINGS.SCREEN_WIDTH)

-- The following line throws an error
SETTINGS.SCREEN_WIDTH = 1280

Modern Lua 5.4 and the <const> Attribute

Lua 5.4 introduced a native mechanism for constants through the <const> variable attribute for local variables. When applied, the compiler prevents the variable from being reassigned:

local MAX_USERS <const> = 500

-- This will cause a compile-time syntax error:
-- MAX_USERS = 600

Even with the introduction of native <const> support, Lua developers continue to use uppercase identifiers. Combining <const> with uppercase naming reinforces clarity, ensuring that constants are immediately recognizable to both the compiler and anyone reading the source code.
