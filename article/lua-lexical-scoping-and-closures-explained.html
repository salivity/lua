Lua Lexical Scoping and Closures Explained

This article explores how the Lua programming language implements lexical scoping and manages closures. In Lua, every function is a first-class value, and the language enforces strict static scoping rules. When an inner function references a variable from an enclosing block, Lua creates a closure by binding that function to an external local variable—termed an "upvalue." Below, we break down the mechanics of Lua's scope resolution, the transition of upvalues from the stack to the heap, and practical examples demonstrating closures in action.

Lexical Scoping in Lua

Lexical (or static) scoping means that the scope of a variable is determined by its physical location within the source code. In Lua, variables are global by default unless explicitly declared with the local keyword.

A local variable is visible only within the block in which it is declared. Blocks include:

  • The body of a control structure (such as if, while, or for)
  • Explicit do ... end blocks
  • The body of a function or chunk

Inner blocks have access to local variables declared in any enclosing outer blocks. However, outer blocks cannot access variables declared inside their nested inner blocks.

local x = 10 -- Enclosing scope

do
    local y = 20 -- Nested scope
    print(x + y) -- Valid: prints 30
end

-- print(y) would return nil or error, as y is out of scope here

First-Class Functions and Upvalues

In Lua, functions are first-class values without intrinsic names. When you define a function, you instantiate a function object and assign it to a variable.

When a nested function accesses a local variable from an outer function, that variable is known in Lua terminology as an upvalue (an external local variable).

function createCounter()
    local count = 0 -- Upvalue for the inner function
    return function()
        count = count + 1
        return count
    end
end

In the example above, count is local to createCounter. The anonymous function returned accesses and modifies count.

How Closures Work Under the Hood

A closure consists of the function's bytecode along with an array of references to its upvalues. The Lua Virtual Machine (Lua VM) manages upvalues in two distinct states: open and closed.

1. Open Upvalues

While the enclosing function is executing, its local variables reside on the Lua execution stack. Any inner function accessing these variables holds an "open upvalue," which is a direct pointer to the variable's slot on the stack.

If multiple inner functions reference the same local variable while it is on the stack, Lua ensures they point to the identical open upvalue rather than creating redundant copies.

2. Closed Upvalues

When the enclosing function finishes and returns, its stack frame is discarded. If an inner function referencing those local variables still exists, the Lua VM moves the variable off the stack and copies it into the heap inside the upvalue structure itself.

The upvalue is now "closed." The inner function's pointer is updated to reference this heap-allocated value instead of the stack slot. This mechanism ensures that the variable persists for as long as the closure remains reachable by the garbage collector.

local counterA = createCounter()
local counterB = createCounter()

print(counterA()) -- Output: 1
print(counterA()) -- Output: 2
print(counterB()) -- Output: 1 (counterB has its own distinct upvalue)

Shared Upvalues Between Closures

Because upvalues are managed as references, multiple closures created within the same execution context can share access to the same upvalue. Mutating the upvalue in one closure immediately affects the other.

function createAccount(initialBalance)
    local balance = initialBalance

    local function deposit(amount)
        balance = balance + amount
        return balance
    end

    local function withdraw(amount)
        if amount <= balance then
            balance = balance - amount
            return balance
        else
            error("Insufficient funds")
        end
    end

    return deposit, withdraw
end

local deposit, withdraw = createAccount(100)
print(deposit(50))   -- Output: 150
print(withdraw(30))  -- Output: 120

Here, both deposit and withdraw share the same closed upvalue balance. When createAccount terminates, balance moves to the heap, and both closures maintain access to that single memory location.

Memory Management

Closures and their closed upvalues are managed by Lua's automatic garbage collector. An upvalue remains in memory as long as at least one active closure references it. Once all closures referencing a specific upvalue become unreachable, the garbage collector reclaims the memory occupied by both the closures and the shared upvalue.
