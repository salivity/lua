Lua Emergency Garbage Collection Triggers

In the Lua programming language, the emergency garbage collection cycle is a fail-safe mechanism designed to recover from impending out-of-memory errors. It is triggered automatically whenever an internal memory allocation request fails. Instead of immediately aborting execution or throwing an out-of-memory error, the Lua runtime executes a synchronous, full garbage collection pass to reclaim any unreferenced memory and retries the failed allocation.

The Exact Trigger: Allocation Failure

The primary trigger for an emergency garbage collection cycle is a NULL return from Lua's memory allocation function (lua_Alloc).

During standard operation, Lua manages memory via an incremental garbage collector that runs concurrently with code execution. However, if a program allocates memory faster than the incremental collector can reclaim it, or if memory limits are strictly constrained, an allocation request for an internal structure—such as a table, string, or closure—may fail.

When the memory allocator signals failure by returning NULL, Lua intercepts this event and immediately initiates the emergency collection.

How the Emergency Cycle Operates

Once triggered, the emergency collection process follows a strict sequence:

  1. Halts Regular Execution: The incremental collection state is temporarily overridden, and Lua executes a full, "stop-the-world" garbage collection cycle immediately.
  2. Suspends Finalizers: To prevent further memory usage during the emergency, Lua does not run finalizers (__gc metamethods) during this cycle. Executing user-defined finalizer code could trigger new memory allocations, creating a recursive failure loop or worsening memory exhaustion.
  3. Re-attempts Allocation: Once the full cycle finishes sweeping dead objects, the original memory allocation is attempted a second time.
  4. Outcome Resolution: If sufficient memory was freed, the allocation succeeds, and Lua resumes normal program execution. If the allocation fails a second time, Lua raises a non-recoverable memory error (LUA_ERRMEM).

Purpose and Context

Introduced in Lua 5.2, emergency garbage collection is particularly critical in embedded systems and constrained environments. In these environments, memory pools are limited, and standard incremental collection pacing might leave dead objects lingering in memory just long enough to block a sudden, large allocation request. The emergency trigger guarantees that memory is strictly exhausted before Lua gives up and raises an error.
