Lua Length Operator with Nil Holes Explained

In Lua, the length operator (#) is designed to measure continuous arrays, meaning tables that contain internal nil values—often referred to as "holes"—break its standard guarantees. This article explains how Lua's length operator formally defines a boundary, why tables containing internal nil values produce unpredictable results, the underlying binary search mechanism Lua uses to find lengths, and how to safely handle sparse tables in your code.

The Formal Definition of a Sequence

In the Lua specification, a table is considered a sequence if its positive numeric keys form an unbroken range from 1 up to some integer n (that is, {1, 2, ..., n}). When a table qualifies as a sequence, #t reliably returns n.

If the table contains nil between positive integer keys—such as {10, nil, 30}—it ceases to be a valid sequence.

The Boundary Rule

The behavior of #t is defined by a mathematical condition called a boundary. An integer \(n\) is a boundary for table t if:

  1. t[n] ~= nil
  2. t[n + 1] == nil

Alternatively, if t[1] == nil, 0 is also a valid boundary.

When a table is a proper sequence, there is only one boundary: the final element. However, when a table contains internal nil holes, multiple indices can satisfy the boundary criteria simultaneously. In such cases, the Lua reference manual explicitly states that Lua is free to return any of those valid boundaries as the length.

Why the Result Appears Undefined

When multiple boundaries exist, the specific index returned by #t depends on Lua’s internal memory layout for tables. Lua tables consist of two internal segments: an array part and a hash (node) part.

  • Binary Search Strategy: To find a boundary quickly without traversing the entire table in \(O(n)\) time, Lua performs a binary search between the bounds of its allocated array slice and the hash map.
  • Internal Capacity Allocations: Lua allocates the array part in powers of two. Depending on how keys were inserted, updated, or removed, values may live either in the array segment or the hash segment.
  • Non-Deterministic Behavior: Because the binary search will converge on different boundaries depending on table capacity and internal key distribution, two tables with identical key-value pairs can yield different results for #t if they were constructed through different sequences of operations.

Consider this example:

local a = {1, nil, 3}
print(#a) -- Can output 1 or 3 depending on the Lua version and allocation

local b = {1, 2, 3, 4, 5}
b[2] = nil
print(#b) -- Often outputs 5 because the array allocation remains intact

Both tables contain holes, but the length operator evaluates them based on internal boundary convergence rather than a full count of non-nil elements.

How to Safely Handle Tables with Holes

If your data requires nil values to represent missing elements, do not rely on #t. Instead, use one of the following approaches:

  • Use table.pack: When capturing variable arguments that may contain nil, use table.pack(...). It creates a table with an explicit n field containing the exact parameter count, which you can read using t.n.
  • Explicit Length Tracking: Maintain a separate counter variable or store the intended capacity inside the table under a separate key (e.g., t.size = 10).
  • Use Sentinel Values: Substitute nil with a custom sentinel value (such as a unique empty table local NONE = {} or false) so the table remains an unbroken sequence of valid values.
  • Traverse via pairs: If you simply need to count how many keys currently hold values, iterate with pairs and increment a counter manually.
