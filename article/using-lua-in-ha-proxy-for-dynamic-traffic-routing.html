Using Lua in HAProxy for Dynamic Traffic Routing

HAProxy leverages an embedded Lua engine to extend its core capabilities, allowing developers to execute custom procedural code directly within the proxy's event-driven architecture. This article explains how HAProxy uses Lua to inspect payloads, execute non-blocking network calls, and dynamically alter routing decisions and traffic filters beyond the limitations of standard configuration directives and Access Control Lists (ACLs).

The Embedded Lua Engine in HAProxy

HAProxy includes an embedded Lua 5.3+ runtime designed to run cooperatively within HAProxy’s single-threaded, event-driven engine. Instead of spawning external processes or relying on heavy middleware, HAProxy exposes internal hooks and APIs directly to the Lua environment.

To maintain HAProxy's high throughput and low latency, Lua scripts run cooperatively. HAProxy provides a custom socket API (core.tcp()) that yields execution to the main event loop while waiting for I/O operations to complete, preventing external calls from blocking other concurrent connections.

Core Mechanisms for Dynamic Traffic Filtering

Lua interacts with HAProxy traffic through three primary interfaces: actions, sample fetches, and converters. For filtering traffic, actions and converters are the most commonly employed.

  1. Custom Action Registration (core.register_action):
    Lua scripts can register actions that execute during specific processing phases, such as http-request or http-response. These actions receive a transaction object (txn) that allows scripts to:
    • Inspect and alter HTTP headers and paths.
    • Read request payloads for deep packet inspection.
    • Query external datastores (such as Redis or Memcached) to evaluate IP reputation or token validity.
    • Terminate requests early by returning custom HTTP status codes and payloads (e.g., rejecting an unauthenticated request with a 403 Forbidden).
  2. Complex Authentication and WAF Rules:
    Native ACLs can struggle with multi-step validation, such as decoding JSON Web Tokens (JWT) or verifying cryptographic signatures. A Lua filter can parse incoming headers, verify cryptographic payloads, check claims, and immediately deny or sanitize the request before it reaches the backend.

Dynamic Traffic Routing

Standard HAProxy configurations rely on static backend mappings defined by map files or ACL rules. Lua enables real-time, algorithmic routing decisions based on runtime state, external metadata, or internal metrics.

  1. Sample Fetches (core.register_fetches):
    Lua functions can be registered as sample fetches that return a string, integer, or boolean. These functions compute a value based on transaction data or external state. Within the HAProxy configuration, the result can be passed directly to routing directives:

    use_backend %[lua.select_backend]

    In this scenario, the Lua function select_backend evaluates request characteristics, checks external service registries, or assesses backend health, returning the exact name of the target backend dynamically.

  2. Service Discovery and Canary Deployments:
    Lua scripts can periodically poll service discovery endpoints (such as Consul or Kubernetes APIs) in the background using core.register_task. The script updates internal routing tables in memory, routing specific percentages of traffic or designated user segments to new application versions without reloading HAProxy.

Configuration Integration

To activate Lua scripts, HAProxy references them in the global section of haproxy.cfg:

global
    lua-load /etc/haproxy/routing_logic.lua

frontend http_in
    bind *:80
    mode http
    
    # Execute a Lua filter for authorization
    http-request lua.authenticate_request
    
    # Route dynamically using a Lua sample fetch
    use_backend %[lua.resolve_tenant_backend]

Within the script, the Lua API ties into these directives:

core.register_action("authenticate_request", { "http-req" }, function(txn)
    local auth_header = txn.sf:req_fhdr("Authorization")
    if not auth_header or not validate_token(auth_header) then
        txn:done({ status = 401, content = "Unauthorized" })
    end
end)

core.register_fetches("resolve_tenant_backend", function(txn)
    local host = txn.sf:req_fhdr("Host")
    local tenant_id = extract_tenant(host)
    return "backend_" .. tenant_id
end)

Performance Best Practices

  • Use Asynchronous Sockets: Always use the native core.tcp() API for network communication rather than standard blocking Lua libraries (luasocket), which halt the entire HAProxy process.
  • Minimize State Locking: Minimize heavy CPU-bound operations inside request-path actions to ensure latency metrics remain predictable.
  • Cache External Queries: Store lookup results in HAProxy’s native stick tables or an in-memory Lua cache to avoid querying external databases on every request.
