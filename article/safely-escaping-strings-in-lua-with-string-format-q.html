Safely Escaping Strings in Lua with string.format %q

This article explains how the Lua programming language utilizes the %q conversion specifier in string.format to safely serialize and escape strings. You will learn how %q automatically handles dangerous characters like quotes, backslashes, and newlines, preventing syntax errors and code injection risks during dynamic code generation and data persistence.

When generating Lua code programmatically or writing data serialization tools, raw string interpolation using %s presents severe risks. If an input string contains double quotes, single quotes, backslashes, or control characters, simply wrapping %s in quotation marks (such as string.format("local x = '%s'", input)) causes syntax errors or arbitrary code execution vulnerabilities. The %q specifier eliminates this danger by automatically wrapping the target string in double quotes and escaping any characters that could break Lua's parsing rules.

How %q Works Under the Hood

The %q option is designed specifically to produce string literals that the Lua compiler can read back unambiguously. When applied to a string, it transforms the value by:

  • Wrapping the entire output inside double quotes (").
  • Escaping embedded double quotes (") as \".
  • Escaping backslashes (\) as \\.
  • Converting control characters, such as newlines (\n) and carriage returns (\r), into valid escape sequences.
  • Escaping embedded null bytes (\0) and non-printable binary bytes using decimal escape sequences (such as \000).

Consider the following example:

local raw_input = 'Line 1\nLine 2 with "double quotes" and a \\ backslash.'
local serialized_code = string.format("local data = %q", raw_input)

print(serialized_code)

The output will be:

local data = "Line 1\
Line 2 with \"double quotes\" and a \\ backslash."

If this generated string is saved to a file or executed with load() or loadstring(), the Lua parser interprets it safely as the exact original string without misinterpreting the quotes or backslashes as code delimiters.

Behavior Across Lua Versions

The capabilities of %q depend on the version of Lua being used:

  • Lua 5.1 and LuaJIT: %q only accepts string arguments. Passing nil, booleans, or numbers throws an error.
  • Lua 5.2 and Newer: Lua expanded %q to handle nil, booleans, and numbers in addition to strings. For non-string types, %q outputs their raw valid Lua representations without quotation marks (for example, true, false, nil, or the exact numeric representation), while continuing to quote and escape strings properly.

Implementing a Safe Serializer Pattern

Using %q, you can build a reliable primitive-value serializer without external dependencies:

local function serialize_primitive(val)
    local val_type = type(val)
    if val_type == "string" then
        return string.format("%q", val)
    elseif val_type == "number" or val_type == "boolean" then
        return tostring(val)
    elseif val_type == "nil" then
        return "nil"
    else
        error("Unsupported type for serialization: " .. val_type)
    end
end

local generated_assignment = string.format("user_name = %s", serialize_primitive('admin"; os.execute("rm -rf /"); --'))

Because %q escapes the internal quotation marks, the malicious command string is converted to a harmless string literal rather than breaking out of the quote context to execute arbitrary instructions. For any task involving code templating, configuration export, or state persistence in Lua, string.format("%q", str) is the standard, secure approach to formatting strings.
