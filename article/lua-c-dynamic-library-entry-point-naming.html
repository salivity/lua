Lua C Dynamic Library Entry Point Naming

When writing C dynamic libraries intended to be loaded by the Lua programming language, the entry-point function must adhere to a strict naming pattern so the Lua runtime can locate and execute it during a require call. This article details the naming rules for these loader functions, covering basic modules, hierarchical submodule paths, hyphenated library names, and essential export requirements.

The Base Naming Convention

When a Lua script executes require("modulename"), Lua attempts to load the corresponding shared library (.so, .dll, or .dylib) and searches for an exported C initialization function with the prefix luaopen_ concatenated with the module name.

The standard convention is:

int luaopen_<modulename>(lua_State *L);

For example, if the module is loaded via require("mymath"), the C dynamic library must export an entry point named:

int luaopen_mymath(lua_State *L);

Hierarchical Modules and Dots

Lua modules are frequently organized hierarchically using dot notation (such as require("network.http")). Because dots are illegal characters in standard C identifiers, Lua automatically replaces every dot (.) with an underscore (_) when searching for the entry-point symbol.

  • For require("network.http"), the entry point must be:

    int luaopen_network_http(lua_State *L);

  • For require("a.b.c"), the entry point must be:

    int luaopen_a_b_c(lua_State *L);

Hyphenated Module Names

Lua also supports a hyphenation rule designed to allow multiple versions or distributions of a binary module without changing the C source. When a module name contains a hyphen (-), Lua searches for the full name first, but if it fails, it strips everything up to and including the first hyphen.

For example, calling require("v1.0-engine") prompts Lua to search for:

  1. luaopen_v1_0_engine
  2. luaopen_engine

This feature allows a dynamic library file named v1.0-engine.so to export only luaopen_engine.

Function Signature and Export Rules

For the Lua interpreter to successfully call the entry point, the function must satisfy three technical criteria:

  1. Exact Signature: The function must accept a single pointer to lua_State and return an integer indicating the number of values pushed onto the Lua stack (typically 1, returning the module's table):

    int luaopen_modulename(lua_State *L);

  2. C Linkage: If compiling the library using a C++ compiler, you must declare the entry point with extern "C" to prevent C++ name mangling from altering the symbol name:

    extern "C" {
    int luaopen_modulename(lua_State *L);
}

  3. Symbol Visibility: The entry-point function must be exported in the resulting shared library. On Windows, this requires the __declspec(dllexport) attribute:

    #ifdef _WIN32
#define EXPORT __declspec(dllexport)
#else
#define EXPORT
#endif

EXPORT int luaopen_modulename(lua_State *L);
