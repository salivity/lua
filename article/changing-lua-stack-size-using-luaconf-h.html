Changing Lua Stack Size Using luaconf.h

Configuring luaconf.h allows developers to modify the limits and initial guarantees of Lua's internal virtual stack for embedded systems. While this header file controls Lua’s virtual data stack—governing how many values and registers a Lua thread can simultaneously hold—it does not alter the underlying C execution call stack provided by the host operating system or hardware architecture.

Lua Virtual Stack vs. Native C Stack

When embedding Lua in constrained environments, it is crucial to distinguish between the two types of stacks:

  1. Lua's Virtual Stack: An array of TValue structs managed internally by the Lua runtime to pass arguments, hold local variables, and return values.
  2. The C Call Stack: The native machine stack managed by the platform's processor and compiler to track C function calls and local C variables.

Modifying luaconf.h directly controls the Lua virtual stack limits. To change the C call stack size, you must adjust your compiler settings, linker scripts, or RTOS thread attributes instead.

Key Configuration Macros in luaconf.h

To modify the Lua stack for an embedded instance, you can adjust two primary macros in luaconf.h:

  • LUAI_MAXSTACK: Sets the absolute maximum number of stack slots a single Lua state or coroutine can allocate. By default, this is set to 1,000,000 entries on 64-bit systems or 40,000 entries on 32-bit systems. In microcontrollers or memory-limited devices, reducing this value (e.g., to 1,000 or 2,000) prevents rogue scripts or deep recursion from exhausting available heap memory.
  • LUA_MINSTACK: Defines the minimum guaranteed stack space available to a C function called from Lua without requiring an explicit call to lua_checkstack. The default is typically 20 slots.

Implementation Steps

  1. Locate luaconf.h in the Lua source distribution.

  2. Define or override LUAI_MAXSTACK to match the constraints of your target hardware:

    #define LUAI_MAXSTACK   2048

  3. If your embedded bindings require larger baseline parameters, you can also alter LUA_MINSTACK:

    #define LUA_MINSTACK    30

  4. Recompile the Lua core library alongside your embedded project.

Limitations and Considerations

Lowering LUAI_MAXSTACK conserves memory and bounds allocation sizes, but setting it too low can cause runtime errors (stack overflow) in scripts with nested function calls, heavy table operations, or multiple return values. Furthermore, LUAI_MAXSTACK must always remain within the limits of the integer type used for stack indices (typically signed integer bounds in Lua) and must be greater than LUA_MINSTACK.
