Coroutine.create vs Coroutine.wrap in Lua

In Lua, both coroutine.create and coroutine.wrap instantiate coroutines for cooperative multitasking, but they differ significantly in how they are invoked, how they return values, and how they handle errors. While coroutine.create provides low-level control by returning a thread object that requires explicit management via coroutine.resume, coroutine.wrap offers a higher-level abstraction by returning a callable function that conceals the underlying thread mechanics.

Return Type and Invocation

The most apparent distinction between the two functions is the type of value returned upon creation:

  • coroutine.create(fn) returns an object of type thread. To execute or continue the coroutine, you must pass this thread handle to coroutine.resume(co, ...).
  • coroutine.wrap(fn) returns a standard Lua function. Resuming the coroutine is achieved by calling the returned function directly, such as my_coroutine(...), without referencing the coroutine library again.

Error Handling

The two functions handle runtime errors inside the coroutine in fundamentally different ways:

  • Protected Mode (coroutine.create): Resuming a thread created with coroutine.create behaves like a protected call (pcall). coroutine.resume intercepts errors instead of crashing the program. Its first return value is always a boolean: true if execution succeeded, or false if an error occurred. In the event of an error, the second return value contains the error message.
  • Direct Propagation (coroutine.wrap): The function returned by coroutine.wrap does not capture errors. If an error occurs inside the coroutine, Lua halts execution and throws an unhandled error at the call site, precisely as a normal function call would.

Return Values on Success

Because coroutine.create relies on coroutine.resume, its return values always include the status flag:

  • coroutine.create: When the coroutine yields or completes, coroutine.resume returns true followed by any arguments passed to coroutine.yield() or returned by the main coroutine function.
  • coroutine.wrap: The wrapper function omits any status boolean and returns only the yielded or returned values directly.

Introspection and State Tracking

Thread objects created with coroutine.create can be inspected at any point using coroutine.status(co), which reports states such as "suspended", "running", "normal", or "dead".

In contrast, coroutine.wrap hides the underlying thread object inside a closure. Because the caller only receives a function handle, coroutine.status cannot be used directly to monitor its lifecycle.

Practical Use Cases

  • Use coroutine.wrap when writing custom iterators for for loops or when you want coroutines to blend seamlessly into interfaces that expect regular functions.
  • Use coroutine.create when building complex concurrency systems, schedulers, or state machines where you must inspect the thread's status and handle errors gracefully without aborting execution.
