Automating Wireshark Packet Filtering with Lua

Wireshark embeds a lightweight Lua engine that allows network analysts and engineers to extend the graphical interface, process live or captured traffic, and automate complex packet filtering pipelines. By leveraging Lua scripts, users can extract specific protocol fields, chain multi-stage filtering logic, build post-dissectors, and output transformed packet data directly within the Wireshark GUI without modifying or recompiling Wireshark's underlying C source code.

The Lua Engine in Wireshark

Wireshark initializes an integrated Lua interpreter during startup. The configuration is governed by init.lua, located in the global Wireshark system directory. Users can load custom Lua scripts automatically by placing them in the personal plugins directory or by referencing them using dofile() inside init.lua. Within the GUI, scripts can also be reloaded on demand using the shortcut Ctrl+Shift+L, enabling rapid development and testing of filtering routines.

Core Components for Packet Filtering Pipelines

Automating filtering pipelines in Wireshark relies on four primary Lua API abstractions:

  1. Field and FieldInfo: These objects extract specific header or payload values from packets that Wireshark has already dissected. For example, Field.new("ip.src") or Field.new("tcp.flags.syn") creates extractors for conditional checks.
  2. Listener (Tap): A Listener registers a tap interface listening to packet streams. It accepts a standard Wireshark display filter string to pre-filter traffic at native speeds before handing matching packets over to Lua.
  3. Post-Dissectors: Custom dissectors registered to run after all standard protocol dissectors finish. They can evaluate cross-protocol data, dynamically append custom fields to the packet details tree, and make those custom fields searchable via the GUI display filter bar.
  4. GUI Integration (register_menu and TextWindow): Exposes Lua scripts to the Wireshark interface via menu items, context menus, and custom windows to display the pipeline's output.

Building an Automated Filtering Pipeline

A typical Lua filtering pipeline automates the extraction, transformation, and presentation of specific network events.

1. Define Fields and Listeners

To filter packets efficiently, define the fields you need to extract and instantiate a Listener with an initial display filter. The tap callback executes exclusively on packets that satisfy the tap filter expression:

-- Define fields to inspect
local ip_src_f = Field.new("ip.src")
local ip_dst_f = Field.new("ip.dst")
local tcp_port_f = Field.new("tcp.dstport")

-- Create a listener tap targeting specific traffic
local pipeline_tap = Listener.new("frame", "tcp and not icmp")

2. Implement the Packet Processing Callback

The Listener object provides a packet function that runs once per frame matching the initial filter. Inside this function, secondary and stateful logic creates the automated pipeline:

local captured_sessions = {}

function pipeline_tap.packet(pinfo, tvb)
    local src = ip_src_f()
    local dst = ip_dst_f()
    local port = tcp_port_f()

    -- Ensure fields exist before running conditional logic
    if src and dst and port then
        local src_str = tostring(src)
        local dst_str = tostring(dst)
        local port_num = tonumber(port)

        -- Stateful filtering: track specific traffic patterns
        if port_num == 443 or port_num == 8443 then
            local session_key = src_str .. " -> " .. dst_str .. ":" .. port_num
            captured_sessions[session_key] = (captured_sessions[session_key] or 0) + 1
        end
    end
end

3. Output Results to the Wireshark GUI

The Listener provides a draw function called when Wireshark finishes reading the capture file or when a live capture redraw occurs. The pipeline can display structured output in a dedicated GUI window using TextWindow:

function pipeline_tap.draw()
    local win = TextWindow.new("Pipeline Filter Results")
    win:append("Session Aggregation Summary:\n")
    win:append("----------------------------------------\n")
    
    for session, count in pairs(captured_sessions) do
        win:append(string.format("%s | Total Packets: %d\n", session, count))
    end
end

Triggering Pipelines from the Interface

To execute the filtering pipeline on demand rather than on startup, scripts can bind the pipeline execution to the Wireshark menu structure using register_menu:

local function run_pipeline_menu()
    -- Reset previous session data
    captured_sessions = {}
    
    -- Apply tap across current capture
    retap_packets()
end

register_menu("Tools/Custom Lua Filters/Run Session Aggregator", run_pipeline_menu, MENU_TOOLS_UNSORTED)

Calling retap_packets() forces Wireshark to rescan the active capture file through all registered listeners, running the Lua pipeline against the current dataset and rendering the output within the GUI immediately.
