Unhandled Errors in Lua Coroutines Explained

When an unhandled error occurs inside a running Lua coroutine, the runtime does not crash the host program if the coroutine was launched using the standard coroutine.resume function. Instead, Lua treats the coroutine invocation as a protected call, immediately halts the coroutine's execution, marks its state as permanently "dead," and returns the error message to the caller. However, if the coroutine was created using coroutine.wrap, the unhandled error is propagated directly up the call stack to the invoking thread.

The Protected Nature of coroutine.resume

The primary method for executing a coroutine in Lua is coroutine.resume. This function behaves similarly to Lua's protected call mechanism, pcall. When code inside the coroutine raises an unhandled error—either via an explicit call to error() or due to a runtime fault like attempting to index a nil value—the error is caught at the coroutine boundary.

When this occurs:

  • Return Values: coroutine.resume returns false as its first return value, indicating a failure, followed by the error object or string as the second return value.
  • Execution Halt: The coroutine ceases execution immediately at the exact line where the error occurred. No subsequent code in that coroutine will run.
  • Main Thread Safety: The calling thread continues running normally, allowing the developer to log, handle, or ignore the failure.
local co = coroutine.create(function()
    print("Coroutine started")
    error("Something went wrong inside the coroutine")
    print("This line will never run")
end)

local success, err = coroutine.resume(co)
print(success) -- Output: false
print(err)     -- Output: [string "..."]:3: Something went wrong inside the coroutine

The State Transitions to "Dead"

Once an unhandled error occurs, the coroutine's internal status changes permanently to "dead". You can inspect this status using coroutine.status(co).

A dead coroutine cannot be revived or restarted. If your program attempts to call coroutine.resume on a coroutine that has terminated due to an error, the call will fail, returning false and the error message "cannot resume dead coroutine".

Behavior with coroutine.wrap

Lua provides an alternative interface called coroutine.wrap. Instead of returning a coroutine object that you manipulate with resume, coroutine.wrap returns a plain Lua function.

When an unhandled error occurs inside a coroutine invoked via coroutine.wrap:

  • The error is not trapped inside a boolean return value.
  • Lua propagates the error directly to the caller, effectively turning it into an unhandled error in the parent thread unless wrapped inside an explicit pcall or xpcall.
  • Despite re-raising the error, the underlying coroutine still transitions to the "dead" state and cannot be run again.
local wrapped = coroutine.wrap(function()
    error("Fatal wrap error")
end)

-- This will halt the script with a runtime error unless enclosed in pcall:
wrapped()

Stack Traces and Debugging

Because an unhandled error inside coroutine.resume unwinds the call stack up to the resume point, standard stack trace information may be lost if you only read the returned error string.

To capture the stack trace of an error inside a coroutine:

  1. Wrap the coroutine's inner logic with xpcall and pass debug.traceback as the error handler.
  2. Alternatively, invoke debug.traceback(co) immediately after coroutine.resume returns false to inspect the execution state of the failed coroutine.
