Lua __metatable: Protect Object State from Modification

In Lua, securing an object's encapsulated state requires restricting access to its internal mechanisms and metatable. The __metatable metamethod provides a built-in defense mechanism that prevents unauthorized code from reading or overwriting an object's metatable. By defining this field, developers can hide the true metatable and disallow calls to setmetatable, thereby locking down the object's behavior and shielding its internal properties from external tampering.

The Risk of Unprotected Metatables

By default, any table in Lua with an assigned metatable remains fully open to inspection and modification:

  • getmetatable(obj) returns the actual metatable reference.
  • setmetatable(obj, new_meta) allows external code to replace the metatable entirely.

If third-party or untrusted code obtains a direct reference to an object's metatable, it can modify underlying metamethods (such as __index or __newindex), overwrite shared class methods, or replace the metatable with an empty one. This breaks encapsulation, exposes private data stored in closures or hidden tables, and leaves the object vulnerable to state corruption.

How __metatable Restricts Access

The __metatable key is a special metamethod recognized by Lua's standard functions. When added to a metatable, it alters the standard behavior of both getmetatable and setmetatable:

  1. Masking with getmetatable: Instead of returning the actual metatable, getmetatable(obj) returns whatever value is assigned to the __metatable field (commonly a string message like "Access denied" or a boolean false).
  2. Blocking with setmetatable: Any attempt to reassign the metatable using setmetatable(obj, ...) immediately raises a runtime error: cannot change a protected metatable.

Practical Implementation

The following example demonstrates how to create a protected object using __metatable:

local function create_secure_account(initial_balance)
    local self = {
        balance = initial_balance
    }

    local mt = {
        __index = {
            deposit = function(account, amount)
                if amount > 0 then
                    account.balance = account.balance + amount
                end
            end,
            get_balance = function(account)
                return account.balance
            end
        },
        -- Protect the metatable
        __metatable = "Protected metatable"
    }

    return setmetatable(self, mt)
end

local account = create_secure_account(100)

-- Attempting to inspect the metatable
print(getmetatable(account)) 
-- Output: Protected metatable

-- Attempting to overwrite the metatable
local success, err = pcall(function()
    setmetatable(account, {})
end)

print(err) 
-- Output: cannot change a protected metatable

Protection Limitations

While __metatable successfully prevents external tampering via standard Lua functions, it operates within specific boundaries:

  • Raw Access Functions: The __metatable field protects the metatable itself, but standard table operations like rawset(account, "balance", 0) or rawget can still bypass metamethods on the object table directly unless the internal state is stored exclusively in C-closures or upvalues.
  • C API Access: C modules running in the same Lua state can bypass __metatable using low-level functions such as lua_getmetatable and lua_setmetatable.

Within standard Lua scripting boundaries, setting __metatable remains the definitive technique for enforcing metatable immutability and safeguarding object integrity.
