Weak Keys vs Weak Values in Lua Weak Tables

In Lua, weak tables allow developers to maintain table entries without preventing the garbage collector from reclaiming unreferenced objects. This article provides a concise guide to the differences between weak keys and weak values, explaining how the __mode metamethod influences garbage collection, the distinct mechanics of key versus value reachability, and the typical use cases for each approach.

Understanding Weak Tables in Lua

By default, tables in Lua hold strong references to both their keys and values. An object stored in a standard table will never be collected by the garbage collector as long as the table itself remains reachable.

A weak table changes this behavior by defining its reference strength using the __mode field in its metatable. The __mode field can be assigned one of three string values:

  • "k": Indicates weak keys.
  • "v": Indicates weak values.
  • "kv": Indicates both weak keys and weak values.

Weak Keys (__mode = "k")

When a table has weak keys, the table’s references to its keys are considered weak. If an object used as a key has no other strong references pointing to it anywhere else in the program, the garbage collector will reclaim that key object and automatically delete the entire key-value pair from the table.

Key Characteristics

  • Collection Trigger: The absence of outside strong references to the key triggers removal.
  • Value Retention: The value associated with the key does not prevent collection, even if the value is a strong reference to something else.
  • Primitive Types: Primitive data types (such as numbers and booleans) are values, not collectable objects, and cannot be collected. However, strings are treated uniquely; Lua handles string interning such that string keys are generally not collected from weak tables in the same manner as objects.

Typical Use Case: Object Metadata

Weak keys are primarily used to attach auxiliary data or private properties to objects without modifying the objects themselves. When the object ceases to exist elsewhere in memory, its associated metadata is cleaned up automatically, preventing memory leaks.

local metadata = setmetatable({}, { __mode = "k" })

do
    local obj = { id = 1 }
    metadata[obj] = { access_count = 0 }
end

-- At this point, 'obj' is out of scope.
collectgarbage()

-- 'metadata' is now completely empty.

Weak Values (__mode = "v")

When a table has weak values, the table’s references to the stored values are considered weak. If an object stored as a value has no other strong references in the program, the garbage collector reclaims the object and removes the entry from the table.

Key Characteristics

  • Collection Trigger: The absence of outside strong references to the value triggers removal.
  • Key Retention: The key can be any valid Lua type, but its presence does not keep the value alive.
  • Primitives: Numbers and booleans cannot be garbage collected, so entries holding primitive values will persist unless manually removed.

Typical Use Case: Object Caching and Memoization

Weak values are ideal for memoization, factory pattern caches, and object registries. A system can check the cache to reuse an existing instance, but if all active consumers discard their reference to that instance, it is safely collected to free memory.

local cache = setmetatable({}, { __mode = "v" })

local function create_user(id)
    if not cache[id] then
        local user = { id = id }
        cache[id] = user
        return user
    end
    return cache[id]
end

local user1 = create_user("alpha")
print(cache["alpha"]) -- Prints table address

user1 = nil
collectgarbage()

print(cache["alpha"]) -- Prints nil (garbage collected)

Summary of Differences

Feature Weak Keys (__mode = "k") Weak Values (__mode = "v")
Garbage Collection Factor Only evaluates references to the key. Only evaluates references to the value.
Entry Deletion Condition Key has no outside strong references. Value has no outside strong references.
Primary Use Case Associating external data with objects. Caching, registries, and memoization.
Common Key Types Tables, userdata, functions, threads. Strings, numbers, identifiers.
