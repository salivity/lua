MobDebug Protocol for Remote Lua Debugging

MobDebug enables remote debugging for the Lua programming language by implementing a variant of the DBGp (Common DeBuGger Protocol). This article outlines how MobDebug utilizes DBGp to bridge the gap between running Lua environments and integrated development environments (IDEs), detailing the communication architecture, operational workflow, and key features that make cross-platform Lua debugging possible.

Understanding the DBGp Protocol in MobDebug

DBGp is an open, language-agnostic protocol originally designed by ActiveState and the Xdebug project to standardize the communication between debugging engines and IDE user interfaces. Rather than developing a proprietary, closed system, MobDebug adopts DBGp conventions to exchange commands, state inspection requests, and execution events over standard network sockets.

By utilizing this protocol, MobDebug provides broad compatibility with various development tools, most notably ZeroBrane Studio, while maintaining a lightweight footprint suitable for resource-constrained Lua runtimes.

How MobDebug Implements DBGp

MobDebug operates primarily as a client-side module written in pure Lua (mobdebug.lua). It relies on standard LuaSocket or compatible networking libraries to manage socket communication.

Client-Server Architecture

In typical DBGp implementations, the target application acts as the client (the engine), while the IDE acts as the server (the debugger controller):

  1. Listener Setup: The IDE opens a listening TCP port (conventionally port 8172 in MobDebug environments, contrasting with DBGp's standard port 9000).
  2. Initiating the Connection: When require('mobdebug').start() is invoked within the Lua application, MobDebug connects back to the IDE via TCP.
  3. Command Loop: Once connected, the debugger engine halts or monitors execution using Lua's native debug.sethook API, awaiting structured commands from the IDE.

Protocol Mechanics and Commands

MobDebug implements a simplified, streamlined subset of the DBGp specification tailored for Lua's execution model. The exchange consists of plain-text commands sent over the socket:

  • Execution Control: Commands such as RUN, STEP, OVER, and OUT control execution flow by instructing the Lua debug hook to yield execution until the target condition is met.
  • Breakpoints: The SETB and DELB commands configure line-level breakpoints dynamically, enabling non-intrusive pauses during execution.
  • Variable Inspection and Evaluation: The EXEC and LOAD commands evaluate Lua expressions within the local stack frame context, returning serialized results back to the IDE for display.
  • Stack Navigation: Commands allow querying the call stack and inspecting local, upvalue, and global variables across different stack levels.

Key Advantages in Lua Environments

Adopting the DBGp model allows MobDebug to decouple the user interface from the execution environment completely. Because communication occurs entirely over TCP/IP, developers can debug Lua scripts running inside embedded engines, game frameworks (such as LÖVE or Corona/Solar2D), remote servers, or mobile devices without altering the host engine's architecture.
