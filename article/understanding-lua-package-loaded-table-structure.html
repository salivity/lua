Understanding Lua package.loaded Table Structure

In Lua, the package.loaded table serves as the primary internal cache for modules loaded through the standard require function. This article breaks down the internal structure of the package.loaded table, explains how its key-value pairs are created and maintained, and details how developers can inspect, mock, and manipulate this table to control module lifecycles and reloading behaviors.

Fundamental Structure

At its core, package.loaded is a standard Lua table stored in the global package library table. Its internal structure consists of simple key-value mappings:

  • Keys: Module names represented as strings (for example, "io", "math", or "myproject.utils").
  • Values: The resolved value returned by the module, or a boolean true if the module does not explicitly return a value. While values are commonly tables containing exported functions, they can technically be of any valid Lua data type, including functions, booleans, strings, or numbers.

Default Contents

When a Lua runtime environment initializes, package.loaded comes pre-populated with Lua's standard core libraries. By default, it contains mappings such as:

  • package.loaded["_G"]: Reference to the global environment table.
  • package.loaded["package"]: Reference to the package library itself.
  • Core standard libraries including "coroutine", "table", "string", "math", and if available in the host environment, "io", "os", and "debug".

Interaction with the require Function

The structure of package.loaded directly dictates how Lua's module resolution pipeline operates:

  1. Cache Lookup: When require(modname) is invoked, it checks package.loaded[modname].
  2. Immediate Return: If package.loaded[modname] evaluates to any value other than nil or false, require immediately returns that cached value, bypassing searchers and file loading.
  3. Module Loading: If the entry is missing or nil, Lua uses the searchers (or loaders in Lua 5.1) defined in package.searchers to find and load the module chunk.
  4. Caching the Result: After executing the module, if the loader function returns a non-nil value, Lua sets package.loaded[modname] to that return value. If the module returns nothing (nil), Lua assigns true to package.loaded[modname] to prevent re-executing the module on subsequent calls.
  5. Final Return: The value stored in package.loaded[modname] is returned to the caller.

Inspecting and Manipulating the Table

Because package.loaded is a regular, mutable Lua table, developers can inspect or modify its contents directly at runtime.

Forcing Module Reloads

To force a module to be reloaded from disk on the next require call, delete its entry from the cache by setting it to nil:

package.loaded["mymodule"] = nil
local mymodule = require("mymodule") -- Reloads the file from disk

Pre-registering or Mocking Modules

Entries can be injected manually before require is ever called. This is useful for dependency injection, embedded scripts, or unit testing:

package.loaded["virtual_module"] = {
    greet = function() return "Hello from memory!" end
}

local mod = require("virtual_module") -- Resolves immediately without filesystem lookups
