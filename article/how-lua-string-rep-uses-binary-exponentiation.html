How Lua string.rep Uses Binary Exponentiation

The string.rep function in the Lua programming language duplicates a given string \(n\) times with exceptional speed and memory efficiency. Instead of appending strings sequentially in an \(O(n)\) loop—which would cause heavy memory churn and trigger frequent garbage collection cycles—Lua utilizes an algorithm based on binary exponentiation (exponentiation by squaring). By treating string concatenation algebraically as a multiplication operation, Lua constructs the final duplicated string in \(O(\log n)\) doubling steps, preallocating memory to maximize throughput and minimize overhead.

The Problem with Naive String Duplication

In Lua, strings are immutable and interned. If you duplicate a string by repeatedly concatenating it in a loop:

local result = ""
for i = 1, n do
    result = result .. s
end

Each iteration creates a new string object and leaves the previous one for the garbage collector. This naive approach exhibits \(O(n^2)\) time complexity relative to the total byte length, resulting in severe CPU and memory penalties for large values of \(n\).

Even when utilizing a mutable buffer, writing a small string chunk \(n\) individual times requires \(n\) separate write operations, failing to take advantage of low-level CPU cache lines and block memory copy optimizations.

The Principle of Binary Exponentiation

Binary exponentiation is traditionally used to compute powers such as \(x^n\) in \(O(\log n)\) operations rather than \(O(n)\). It relies on the binary representation of the exponent \(n\):

  • If \(n\) is even: \(x^n = (x^2)^{n/2}\)
  • If \(n\) is odd: \(x^n = x \cdot (x^2)^{(n-1)/2}\)

Because string concatenation is associative and has an identity element (the empty string), it forms a monoid. Consequently, string duplication \(s \times n\) is mathematically identical to calculating \(s^n\), where concatenation replaces multiplication.

Step-by-Step Example

Suppose you want to duplicate string s by \(n = 13\) times. In binary, \(13\) is represented as 1101 (\(8 + 4 + 1\)).

Instead of adding s 13 times, the algorithm tracks two values: an accumulator (the partial result) and the current power-of-two base (s, s^2, s^4, s^8...):

  1. Bit 0 (Value = 1): The lowest bit is 1. Append the current base (\(s^1\)) to the result accumulator. Then, double the base: \(s \to s^2\).
  2. Bit 1 (Value = 0): The bit is 0. Do not append to the accumulator. Double the base: \(s^2 \to s^4\).
  3. Bit 2 (Value = 1): The bit is 1. Append the current base (\(s^4\)) to the accumulator. Double the base: \(s^4 \to s^8\).
  4. Bit 3 (Value = 1): The bit is 1. Append the current base (\(s^8\)) to the accumulator.

The process terminates after only 4 iterations (\(\lfloor\log_2(13)\rfloor + 1\)), having constructed \(s^1 + s^4 + s^8 = s^{13}\).

How Lua Implements string.rep Under the Hood

Lua implements string.rep in C inside its standard library (lstrlib.c). Rather than running this logic at the interpreted Lua level, it executes the pattern directly against raw memory buffers.

1. Preallocating Memory and Overflow Checks

Before copying any data, Lua calculates the final string size:

\[\text{Total Length} = n \times \text{length}(s) + (n - 1) \times \text{length}(\text{separator})\]

Lua validates that this multiplication does not cause an integer overflow and ensures the target size fits within the maximum allowable string size. Once validated, Lua allocates the exact buffer space required in a single step using its internal buffer utilities (luaL_Buffer).

2. Eliminating Garbage Collection Overhead

Because the memory buffer is allocated up front at the C level, Lua avoids creating intermediate Lua string objects during the duplication process. Intermediate doubled strings exist only within raw C buffers or memory segments, generating zero garbage collection pressure.

3. Exponential Block Copying with memcpy

Within the preallocated destination buffer, Lua uses the binary exponentiation pattern alongside standard C memcpy.

Instead of copying small string chunks repeatedly:

  1. Lua places the base pattern into the destination buffer.
  2. It iteratively copies progressively larger contiguous blocks of already-duplicated data.
  3. As the chunk size doubles (\(1\times, 2\times, 4\times, 8\times \dots\)), the number of required memcpy calls drops to \(\approx \log_2(n)\).

Large contiguous block transfers allow modern CPUs to leverage vector registers (SIMD) and sequential memory bandwidth, executing the duplication as close to the hardware's theoretical memory write speed as possible.

Summary of Efficiency Gains

  • Algorithmic Complexity: Reduces the number of discrete aggregation steps from linear \(O(n)\) to logarithmic \(O(\log n)\).
  • Single Allocation: Avoids reallocations and buffer resizing by computing the exact final size before copying data.
  • Zero GC Churn: Creates only the final Lua string object, entirely bypassing temporary heap allocations.
  • Hardware Optimization: Maximizes memory throughput by batching data transfers into exponentially growing memcpy operations.
