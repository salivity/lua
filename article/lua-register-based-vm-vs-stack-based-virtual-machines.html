Lua Register-Based VM vs Stack-Based Virtual Machines

This article examines the structural and performance differences between the register-based virtual machine (VM) introduced in Lua 5.0 and traditional stack-based virtual machines commonly found in runtimes like the JVM or Python. It covers the mechanics of instruction dispatch, execution efficiency, code density, and compiler complexity, illustrating why Lua chose a register-based approach to maximize its execution speed while maintaining a lightweight footprint.

Fundamental Architectural Differences

The primary distinction between stack-based and register-based virtual machines lies in how they store and retrieve operands for operations:

  • Stack-Based Virtual Machines: Operands are pushed onto and popped from an evaluation stack. Operations implicitly use the values at the top of the stack. An addition typically requires pushing two operands, invoking the add operation, and then popping or storing the result.
  • Register-Based Virtual Machines: Operands are accessed from an array of virtual registers. Instructions explicitly specify the source and destination registers using multi-address formats (such as three-address code: destination = source1 + source2).

Instruction Count and Dispatch Overhead

In interpreted programming languages, the instruction dispatch loop—the cycle of fetching, decoding, and jumping to the next bytecode instruction—carries significant overhead.

Because stack-based machines rely on zero-address instructions that manipulate the stack top, simple expressions require multiple operations. For example, evaluating a = b + c in a stack-based VM requires four instructions:

  1. LOAD b
  2. LOAD c
  3. ADD
  4. STORE a

In Lua's register-based VM, the same expression compiles into a single instruction:

  1. ADD R(a), R(b), R(c)

By handling operations in a single instruction, Lua cuts the total number of bytecode instructions executed by roughly 30% to 35%. Consequently, the VM spends far less time executing VM dispatch loop code, resulting in noticeable performance gains on modern hardware.

Instruction Size and Bytecode Density

While register-based architectures execute fewer instructions, individual instructions require more bits to encode explicit register addresses.

  • Stack-based bytecode typically uses variable-length instructions, often centered around single-byte opcodes. This allows programs to achieve high code density and smaller overall bytecode file sizes.
  • Lua's register-based bytecode uses fixed-size 32-bit instructions. Each instruction encodes an opcode and up to three register references or immediate values (e.g., standard formats like iABC or iABx). While individual instructions are larger, the reduction in total instruction count largely balances out the memory footprint.

Lua's Register Implementation

Lua does not map its virtual registers to physical CPU registers directly. Instead, Lua maps its registers to the activation record (the local stack frame) allocated for the executing function.

Each active function call in Lua has an array of values on Lua's internal data stack. A register index (such as R(1)) directly corresponds to an offset within that local frame. This design allows Lua to avoid transferring local variables between variable storage arrays and a separate evaluation stack, merging operand evaluation and local variable storage into the same memory space.

Compiler Complexity

The primary trade-off in adopting a register-based VM is increased compiler complexity:

  • Stack-based generation: Generating stack-based bytecode from an Abstract Syntax Tree (AST) is trivial. A depth-first traversal naturally produces the correct post-order execution sequence without tracking variable lifetimes.
  • Register-based generation: Register allocation requires managing virtual registers, tracking when variables go out of scope, and allocating or reusing register slots efficiently.

Lua resolves this by relying on a single-pass compiler that assigns registers directly to local variables and temporary values in lexical order. Because Lua uses an abundant pool of virtual registers (up to 255 per function), it avoids the complex graph-coloring algorithms used in native hardware compilers while retaining the benefits of register operations.

Summary

Lua transitioned from a stack-based architecture (used prior to version 5.0) to a register-based VM to minimize interpreter dispatch overhead. By using three-address instructions that map directly to the call frame, Lua drastically reduces the instruction count needed for program execution, yielding higher interpretation speeds at the cost of slightly larger individual instructions and a marginally more complex compiler.
