Lua 5.2 to 5.3: Bitwise Operators and String Formatting

The transition from Lua 5.2 to Lua 5.3 introduced significant enhancements to core data manipulation capabilities, most prominently the inclusion of native integer arithmetic. This architectural shift overhauled bitwise manipulation—moving from a separate, library-driven model to first-class syntax operators—while fundamentally expanding the string library with native binary serialization tools and updated formatting specifiers.

Bitwise Operators: From Library Calls to Native Syntax

The approach to bitwise logic represents one of the most substantial architectural differences between Lua 5.2 and 5.3.

Lua 5.2: The bit32 Library

In Lua 5.2, all numbers were represented internally as double-precision floating-point values by default. Because there was no dedicated integer type or syntax for bitwise manipulation, bitwise logic had to be executed through the built-in bit32 library.

Operations were function-based and strictly limited to 32-bit integers:

  • bit32.band(...) for bitwise AND
  • bit32.bor(...) for bitwise OR
  • bit32.bxor(...) for bitwise XOR
  • bit32.bnot(x) for bitwise NOT
  • bit32.lshift(x, disp) and bit32.rshift(x, disp) for logical shifts
  • bit32.arshift(x, disp) for arithmetic right shift

Before performing an operation, Lua 5.2 converted floating-point inputs into unsigned 32-bit integers, returning a float value representing the result modulo \(2^{32}\).

Lua 5.3: First-Class Infix Operators

Lua 5.3 introduced a dedicated integer subtype (typically standard 64-bit signed integers) alongside floats under the broader number type. As a result, the bit32 library was deprecated and removed from the default build in favor of native infix and unary operators:

  • & for bitwise AND
  • | for bitwise OR
  • ~ for binary XOR and unary bitwise NOT
  • >> for logical right shift
  • << for logical left shift

Because integers in Lua 5.3 default to 64 bits, these operators manipulate full 64-bit words rather than being restricted to 32-bit limits. Shifts automatically handle zero-filling, and negative shift operands reverse the shift direction.

String Formatting and Binary Serialization

String manipulation in Lua 5.3 evolved to complement the introduction of integers and to standardize the serialization of raw data.

Binary Data Packing: string.pack and string.unpack

In Lua 5.2, developers relied on external C modules (such as lpack) or custom pure-Lua routines to serialize and deserialize arbitrary binary structures.

Lua 5.3 introduced native binary packing directly into the string library:

  • string.pack(fmt, v1, v2, ...): Serializes values into a binary string according to the specified format string.
  • string.unpack(fmt, s [, pos]): Extracts values from a binary string based on the format string.
  • string.packsize(fmt): Calculates the static byte size required by a given format string.

The format string supports endianness specifiers (< for little-endian, > for big-endian, = for native), fixed-width signed and unsigned integers (i1 through i16, I1 through I16), floats, fixed-length strings (c), and length-prefixed strings (s).

Enhancements to string.format

While Lua 5.2 provided a standard C-like string.format implementation, Lua 5.3 expanded its capabilities:

  • Native Integer Specifiers: Modifiers like %d, %i, %o, %u, %x, and %X work natively with 64-bit integers without precision loss that could occur when casting large integers via floating-point doubles.
  • Pointer Formatting (%p): Lua 5.3 added the %p option to format values as pointer addresses, particularly useful for debugging tables, functions, and userdata.
  • Extended %q Specifier: In Lua 5.2, %q safely quoted strings for Lua consumption. Lua 5.3 expanded %q to safely format booleans, nil, numbers (including hexadecimal float representation for exact precision), and strings, allowing reliable serialization of arbitrary primitive values into valid Lua source code.
  • Meta-method Awareness: The %s modifier in Lua 5.3 automatically honors the __tostring metamethod on tables or userdata passed as arguments.
