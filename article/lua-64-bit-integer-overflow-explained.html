Lua 64-Bit Integer Overflow Explained

Modern versions of Lua, beginning with Lua 5.3, handle integers using 64-bit signed representation and implement standard two's-complement wrap-around arithmetic when operations exceed maximum limits. Rather than throwing an error or automatically promoting the result to a floating-point number, arithmetic operations that surpass the boundary wrap around cyclically to negative values. This article covers the internal mechanics of Lua's integer subtype, how overflow affects calculations and literals, and the rules governing integer limits.

The 64-Bit Integer Range in Modern Lua

In Lua 5.3 and subsequent releases (including Lua 5.4), the number type is split into two internal representations: integers and floats. By default, Lua uses standard signed 64-bit integers for the integer subtype.

The boundaries of this range are exposed through the standard math library:

  • Maximum value (math.maxinteger): \(2^{63} - 1\), or 9,223,372,036,854,775,807
  • Minimum value (math.mininteger): \(-2^{63}\), or -9,223,372,036,854,775,808

Arithmetic Wrap-Around Behavior

When standard integer arithmetic (such as addition, subtraction, or multiplication) produces a value greater than math.maxinteger, the calculation wraps around to the negative end of the spectrum using two's-complement rules (modulo \(2^{64}\)).

For example:

local max = math.maxinteger
print(max + 1 == math.mininteger) -- Outputs: true
print(max + 2 == math.mininteger + 1) -- Outputs: true

The reverse is also true for underflow. Subtracting from math.mininteger wraps back to the positive side:

local min = math.mininteger
print(min - 1 == math.maxinteger) -- Outputs: true

This behavior is deterministic and mirrors the low-level behavior of signed 64-bit integers in C. It does not generate runtime warnings or trigger execution errors.

Numeric Literals vs. Runtime Calculations

A distinction exists between arithmetic overflow during runtime and writing oversized numeric literals directly in Lua code.

When you write a numeric literal directly into a script that exceeds the 64-bit signed integer boundary, Lua attempts to parse it as a floating-point number (an IEEE 754 double-precision float) instead of an integer.

local literal = 9223372036854775808 -- One greater than math.maxinteger
print(math.type(literal)) -- Outputs: "float"

While this preserves the approximate magnitude, double-precision floats only have 53 bits of precision, resulting in a loss of precision for the least significant digits.

Division and Type Promotion

Different arithmetic operators affect how Lua handles types and limits:

  • Standard Division (/): Always returns a float, even if both operands are integers. Because it operates on floats, it does not wrap around as an integer; instead, exceeding float limits results in inf (infinity).
  • Floor Division (//): If both operands are integers, the operation remains an integer. If the result cannot be represented as an integer (for instance, math.mininteger // -1), Lua triggers an overflow wrap-around, returning math.mininteger.
  • Mixed Operations: If an integer operation includes a float, the integer is promoted to a float before the operation takes place, bypassing integer wrap-around rules entirely.

Bitwise Operators

Bitwise operators (&, |, ~, <<, >>) operate strictly on integers. Any float operands with integral values are converted to integers before evaluation. If a shift operation causes bits to push beyond the 64-bit boundary, the excess bits are discarded, maintaining the wrap-around characteristics of 64-bit two's-complement arithmetic.
