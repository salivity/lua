Guide to Busted Unit Testing and Assertions in Lua

Busted is a behavior-driven development (BDD) unit-testing framework for the Lua programming language designed to make tests readable and maintainable. This article explains how Busted organizes test suites through hierarchical blocks, manages test lifecycles with setup and teardown hooks, and verifies program behavior using its fluent and extensible assertion library.

Test Suite Structure

Busted structures test files using a nested block syntax inspired by frameworks like RSpec and Jasmine. This design groups related tests logically and defines their scope clearly.

  • describe: Defines the top-level test suite or a major component under test. It serves as an organizational container for related specifications.
  • context: An alias for describe, typically used to delineate specific scenarios, states, or input conditions within a broader component test.
  • it: Defines an individual test case (a specification). The code inside an it block executes the tested functionality and contains the assertions.
describe("Calculator", function()
    context("when adding numbers", function()
        it("correctly sums two positive integers", function()
            local result = 2 + 3
            assert.are.equal(5, result)
        end)
    end)
end)

Lifecycle Hooks

Busted manages test fixtures through lifecycle functions that run before or after test blocks. These hooks can be scoped to individual tests or entire suites:

  • before_each(fn): Executes before every it block in the current scope and its child scopes.
  • after_each(fn): Executes after every it block in the current scope.
  • lazy_setup(fn) / setup(fn): Executes once before any test in the block runs. lazy_setup executes only if tests within the block are actually executed.
  • lazy_teardown(fn) / teardown(fn): Executes once after all tests in the block have completed.

Hooks inherit hierarchically: an outer before_each executes before an inner before_each, ensuring dependencies are established in order.

Assertion Syntax

Busted integrates the luassert library to provide natural-language assertions. Assertions are formed using modifier chains that improve readability without altering logic.

Basic Equality and Truthiness

Assertions use chained properties to state expectations clearly:

  • assert.are.equal(expected, actual) checks value equality.
  • assert.are.same(tableA, tableB) performs deep comparisons of tables.
  • assert.is_true(value) and assert.is_false(value) verify boolean values.
  • assert.is_nil(value) checks for nil.

Negation and Modifiers

Modifiers alter or clarify the assertion chain:

  • assert.is_not.equal(expected, actual) negates the evaluation.
  • Modifiers like is, are, and has can be chained interchangeably to produce readable phrases (e.g., assert.is.truthy(val) or assert.has.errors(fn)).

Error Handling and Execution

Testing for runtime errors or raised exceptions is handled using functions:

it("raises an error on invalid input", function()
    assert.has_error(function()
        error("invalid operation")
    end, "invalid operation")
end)

Test Modifiers: Pending, Tags, and Focus

Busted provides inline keywords to control test execution directly from code:

  • pending: Replaces it to mark a test as unimplemented without failing the test run.
  • #tag: Appending #tag_name to describe or test names allows running specific subsets via the command line (e.g., busted --tags=unit).
  • expose / insulate: Isolates global variables within specific test files or blocks to prevent side effects across tests.
