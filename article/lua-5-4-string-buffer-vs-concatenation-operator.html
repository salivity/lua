Lua 5.4 String Buffer vs Concatenation Operator

This article examines how string buffers in Lua 5.4 dramatically improve performance over the standard concatenation operator (..) during dynamic string construction. While the .. operator introduces significant memory churn, repetitive string interning, and quadratic time complexity in iterative operations, the string buffer mechanism uses mutable, dynamically resizable memory buffers to deliver linear-time performance and minimal garbage collector overhead.

The Mechanics and Pitfalls of the .. Operator

In the Lua runtime, strings are strictly immutable and interned. Every unique string sequence is stored only once in an internal global hash table. While this allows fast string equality comparisons via pointer checks, it creates substantial overhead when dynamically assembling text.

When you use the binary concatenation operator (..), Lua does not append data in place. Instead, it must:

  1. Calculate the combined length of the two source strings.
  2. Allocate an entirely new memory block for the resulting string.
  3. Copy the bytes of both strings into the new memory block.
  4. Hash the resulting payload to verify or register it within the global string interning table.
  5. Abandon the intermediate source strings, leaving them to be reclaimed by the garbage collector (GC).

In an iterative pattern—such as accumulating lines in a loop—this pattern results in \(O(N^2)\) time complexity. As the accumulated string grows, each iteration copies progressively larger memory blocks. The process generates a massive volume of short-lived intermediate string objects, increasing memory fragmentation and triggering frequent GC cycles that stall execution.

How String Buffers Optimize Concatenation

The string buffer mechanism—accessible natively at the C API level via luaL_Buffer and exposed to Lua scripts through buffer modules—bypasses the limitations of string immutability by decoupling data staging from string creation.

1. In-Place Mutation and Contiguous Storage

Unlike standard Lua strings, a buffer operates as a mutable array of raw bytes allocated on the stack or the heap. Appending to a buffer writes data directly into existing, contiguous memory via memory copy operations (memcpy). Intermediate states are never converted into individual Lua string objects.

2. Exponential Capacity Growth

Buffers manage allocation through a geometric growth strategy (typically doubling capacity when current space is exhausted). This guarantees amortized \(O(1)\) append operations. Instead of reallocating memory on every addition, the buffer absorbs multiple write operations within its pre-allocated capacity, dropping overall memory allocation calls from \(O(N)\) to \(O(\log N)\).

3. Elimination of Intermediate Interning

Because data inside a buffer remains raw bytes until extraction, the Lua engine skips the computationally expensive process of hashing intermediate strings. The global string pool is left untouched during the entire accumulation phase.

4. Single-Pass Finalization

Once all data is collected, the buffer converts its aggregated memory chunk into a standard Lua string in a single step. The Lua VM allocates memory for the final size, performs a single hash calculation, interns the string once, and resets or frees the buffer.

Performance Summary

Using a string buffer converts what would be an \(O(N^2)\) algorithm using the .. operator into an \(O(N)\) linear-time process. By avoiding intermediate allocations, minimizing GC pressure, and eliminating redundant hashing, string buffers serve as the primary optimization technique for high-throughput string serialization, file parsing, and dynamic template generation in Lua 5.4.
