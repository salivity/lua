Lua C API Stack Indices: Positive vs Negative

The Lua C Application Programming Interface (API) communicates with the C runtime through a virtual, Last-In-First-Out (LIFO) stack. When interacting with this stack, developers must reference stack slots using integer indices. This article explains how positive and negative indexing schemes operate in the Lua C API, detailing how positive indices reference items from the bottom of the stack upward, while negative indices count downward from the top of the stack.

The Lua Virtual Stack

In the Lua C API, all data exchanges—such as passing arguments, reading return values, and manipulating variables—happen through a shared stack. Every element pushed onto the stack occupies a specific index. The API allows elements to be addressed using either positive (absolute) or negative (relative) indices.

Note that 0 is never a valid stack index in standard Lua C API operations.

Positive Indices: Bottom-Up (Absolute)

Positive indices represent absolute positions starting from the very bottom of the stack.

  • Index 1 points to the oldest element currently on the stack (the bottom).
  • Index 2 points to the second element pushed.
  • Index n represents the element \(n\) steps from the bottom, up to lua_gettop(L), which returns the total number of elements.

Use Case

Positive indices are most commonly used when handling function arguments passed from Lua to C. For example, if a Lua function passes three parameters to a C function, the first argument is always at index 1, the second at index 2, and the third at index 3, regardless of how many temporary values you later push onto the stack.

Negative Indices: Top-Down (Relative)

Negative indices provide a relative reference measured from the top of the stack, which represents the most recently pushed item.

  • Index -1 refers directly to the top element of the stack.
  • Index -2 refers to the element immediately beneath the top element.
  • Index -n refers to the \(n\)-th element down from the top, where -lua_gettop(L) refers to the bottom of the stack (the same element as index 1).

Use Case

Negative indices are ideal for inspecting or manipulating values immediately after an operation that pushes results to the stack. For instance, after calling a function like lua_getfield or lua_pcall, the newly produced value sits at index -1. This allows you to inspect results without tracking the exact absolute depth of the stack.

Index Mapping Overview

Consider a stack that contains three elements: "apple" (pushed first), "banana" (pushed second), and "cherry" (pushed last).

Value Positive Index Negative Index Stack Position
"cherry" 3 -1 Top of the stack
"banana" 2 -2 Middle
"apple" 1 -3 Bottom of the stack

In this scenario:

  • Both index 1 and index -3 access "apple".
  • Both index 2 and index -2 access "banana".
  • Both index 3 and index -1 access "cherry".

Summary of Stack Operations

  • Use positive indices when referring to fixed parameters, such as function arguments, whose absolute positions remain stable even as new items are added to the stack.
  • Use negative indices when working dynamically with newly pushed values or when you want to access elements relative to the current top of the stack without calculating the total stack size.
