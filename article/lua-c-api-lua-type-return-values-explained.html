Lua C API lua_type Return Values Explained

This article provides a technical overview of how the lua_type function operates within the Lua C API, explaining how it queries the virtual stack and returns distinct integer constants representing fundamental Lua data types. Readers will learn the mechanics behind these integer tags, the specific constant definitions provided by the API, and how to properly evaluate data types in C host programs.

The Role and Signature of lua_type

In the Lua C API, the lua_type function is the primary mechanism for inspecting the data type of an element located on the Lua virtual stack. Its C prototype is defined in lua.h:

int lua_type (lua_State *L, int index);

The function accepts the current execution thread (lua_State *L) and a stack index (index), which can be either positive (absolute) or negative (relative to the top of the stack). Upon invocation, it evaluates the value at that specific location and returns an int corresponding to a pre-defined macro.

Internal Mechanism: How Types Are Resolved

Internally, Lua represents every variable as a tagged value (typically a struct containing the raw data union alongside an integer type tag). When lua_type is called:

  1. Index Validation: The function checks whether the provided index points to a valid slot within the allocated stack bounds. If the index refers to an empty slot or is out of range (an acceptable, non-existent index), lua_type immediately returns LUA_TNONE (defined as -1).
  2. Tag Extraction: If the index is valid, the C API retrieves the internal TValue reference at that stack position and reads its type descriptor tag.
  3. Constant Mapping: The internal tag is returned as an integer that matches one of the public type constants defined in the public header lua.h.

The Defined Numeric Constants

The values returned by lua_type correspond directly to basic Lua types. These constants are explicitly defined in lua.h as follows:

  • LUA_TNONE (-1): Represents an invalid index or an empty stack location.
  • LUA_TNIL (0): The nil type.
  • LUA_TBOOLEAN (1): A boolean value (true or false).
  • LUA_TLIGHTUSERDATA (2): A raw C pointer (void*) managed by the host application rather than Lua's garbage collector.
  • LUA_TNUMBER (3): Any numeric value (integers or floating-point numbers).
  • LUA_TSTRING (4): An internalized string or byte array.
  • LUA_TTABLE (5): A Lua table (associative array).
  • LUA_TFUNCTION (6): A callable unit (Lua function, C function, or closure).
  • LUA_TUSERDATA (7): A full userdata block (memory managed by Lua's garbage collector with metatable support).
  • LUA_TTHREAD (8): A Lua coroutine.

Practical Application and Best Practices

In standard C code, developers evaluate lua_type using conditional statements or switch blocks to safely handle dynamic Lua inputs:

int type = lua_type(L, 1);

switch (type) {
    case LUA_TNUMBER:
        printf("Received a number: %f\n", lua_tonumber(L, 1));
        break;
    case LUA_TSTRING:
        printf("Received a string: %s\n", lua_tostring(L, 1));
        break;
    case LUA_TTABLE:
        printf("Received a table.\n");
        break;
    case LUA_TNONE:
        printf("No argument was provided at index 1.\n");
        break;
    default:
        printf("Received other type: %s\n", lua_typename(L, type));
        break;
}

Using lua_type is often preferable to checking types via convenience functions like lua_isstring or lua_isnumber. The lua_is* helper functions often check whether a value can be coerced into that type (for example, lua_isstring returns 1 for numeric values because numbers automatically convert to strings). By contrast, lua_type checks the strict, actual data type of the value without performing any type coercion or mutating the value on the stack. To convert the resulting integer constant into a human-readable string, the C API provides lua_typename(L, type), which returns strings such as "number", "string", or "no value".
