Lua table.insert Shifting Algorithm Explained

In the Lua programming language, inserting an element into a specific index of a sequence using table.insert relies on a linear, in-place backward-shifting algorithm. When an element is added at an arbitrary position rather than appended to the end, Lua shifts all subsequent elements one position to the right to make room for the new entry. This operation runs in linear time relative to the number of shifted elements, operating directly on the table's internal array storage without allocating temporary buffers.

The Shifting Mechanism in C Source Code

The standard Lua library defines table.insert inside ltablib.c through the C function luaB_tinsert. When invoked with three arguments—table.insert(t, pos, value)—the function checks boundaries and calculates the sequence length n. If pos is less than or equal to n, Lua executes a descending linear loop:

for (i = e; i > pos; i--) {
    lua_rawgeti(L, 1, i - 1);
    lua_rawseti(L, 1, i);  /* t[i] = t[i - 1] */
}
lua_settop(L, 3);
lua_rawseti(L, 1, pos);  /* t[pos] = v */

The algorithm copies each element from index i - 1 into index i, starting from the tail of the array (n + 1) and moving backward until it reaches pos. This reverse direction is critical: moving rightward from the end ensures that existing elements are preserved rather than overwritten by their left-hand neighbors. Once the slot at pos is freed, Lua assigns the target value into that position.

Algorithmic Complexity

The shifting procedure exhibits the following complexity metrics:

  • Worst-Case Time Complexity: \(O(n)\) occurs when inserting at index 1 (pos = 1). In this scenario, every existing element must be shifted right by one position.
  • Best-Case Time Complexity: \(O(1)\) occurs when inserting at n + 1 (or omitting the pos argument). No elements shift; the value is simply assigned to the next open index.
  • Average-Case Time Complexity: \(O(n)\) for arbitrary valid positions within the array portion of the table.
  • Auxiliary Space Complexity: \(O(1)\) because values are moved in place via raw stack manipulation within the Lua C API, avoiding secondary data structure allocations.

Internal Table Structure and Reallocation

Lua tables consist of two internal segments: an array part and a hash (node) part. When elements are kept in a contiguous sequence of integer keys, they reside in the array part.

If shifting an element causes the sequence length to exceed the current allocated capacity of the array part, Lua invokes an internal resizing routine (luaH_resizearray or rehash). Lua uses an exponential growth strategy, typically doubling the array capacity when resized. While the shift itself remains an \(O(n)\) loop, an individual insertion that triggers reallocation incurs an amortized cost to reallocate and copy the buffer in memory before completing the shift.

Performance Considerations

Because table.insert shifts items using sequential, single-element lookups and assignments (lua_rawgeti and lua_rawseti), repeated insertions at the front of a sequence result in quadratic \(O(n^2)\) time complexity. For use cases requiring frequent prepending or middle-of-the-list mutations, standard sequential tables are suboptimal; alternative approaches like maintaining explicit head/tail pointers, linked-node structures, or appending elements and reversing the list upon completion are commonly employed.
