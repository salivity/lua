Lua 5.4 Short vs Long String Size Threshold

In Lua 5.4, the runtime engine divides string handling into two distinct categories—short strings and long strings—to optimize memory allocation, equality checks, and hashing performance. This article explains the exact byte threshold that differentiates short strings from long strings in Lua 5.4, the architectural differences between the two implementations, and how this distinction impacts execution speed.

In version 5.4 of the Lua programming language, the threshold differentiating short strings from long strings is exactly 40 bytes. This constant is defined in the source code as LUAI_MAXSHORTLEN within the luaconf.h header file. Any string with a length less than or equal to 40 bytes is treated as a short string, while any string with a length of 41 bytes or more is categorized as a long string.

Short Strings (40 Bytes or Fewer)

Short strings are internalized, or "hash-consed," by the Lua virtual machine. When a short string is created, Lua checks a global hash table within the Lua state (global_State) to see if an identical string already exists. If it exists, the VM reuses the existing string reference rather than allocating new memory.

Because of internalization:

  • Only one copy of any given short string exists in memory.
  • String equality comparisons are executed in constant time, or \(O(1)\), because the VM only needs to compare memory pointers rather than comparing character by character.
  • The hash of the string is computed immediately upon creation.

Long Strings (41 Bytes or More)

Strings that exceed 40 bytes bypass the global internalization table. Each creation of a long string produces a distinct object in memory, even if another string with identical contents already exists in the same Lua state.

Long strings feature the following characteristics:

  • Creation is faster for large data blocks because Lua skips the global table lookup and does not immediately calculate a hash.
  • Hashes are calculated lazily, meaning Lua only computes the string's hash if the string is used as a key in a Lua table.
  • Equality comparisons are not guaranteed to be pointer-only. If the pointers differ, Lua must compare the string contents byte-by-byte, leading to \(O(N)\) comparison time in the worst case.

By setting the threshold at 40 bytes, Lua 5.4 balances fast table lookups and constant-time comparisons for identifiers and common words, while avoiding the overhead of hashing and deduplicating massive text buffers or binary payloads.
