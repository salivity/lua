Variable Scope in Lua Repeat Until Loops

In the Lua programming language, the repeat ... until loop features a unique scoping rule where the termination condition is considered part of the loop's inner scope. Unlike loops in many other languages where variables defined inside the loop body cannot be seen by the exit condition, Lua extends the lexical scope of the loop block through the until clause. This allows variables declared locally inside the body of the loop to be directly accessed and evaluated within the termination condition without requiring declaration outside the loop.

Lexical Scoping in the Termination Condition

According to the Lua reference manual, a block in a repeat ... until statement does not end at the until keyword; it ends after the condition expression itself.

Because the condition is technically evaluated inside the scope of the loop block, any local variable declared using the local keyword anywhere within the loop remains in scope for the until evaluation:

repeat
    local input = io.read()
    local isValid = (input ~= "")
until isValid

In this example, both input and isValid are declared within the loop body. In languages like C, C++, or Java, a similar do ... while construct would produce a compilation error because block-scoped variables fall out of scope before the condition is reached. Lua treats the condition as the final statement within the local scope of that iteration.

Iteration Lifecycles

Although the condition has access to loop-local variables, each cycle of a repeat ... until statement is an independent iteration with its own fresh local scope:

  1. When the loop starts an iteration, local variables are allocated and initialized.
  2. The body executes.
  3. The until condition evaluates the local variables bound to that specific iteration.
  4. If the condition evaluates to false or nil, the iteration ends, the local variables are destroyed (or left for garbage collection if not captured in a closure), and a new scope begins for the next iteration.

Contrast with the while Loop

The behavior of repeat ... until contrasts with Lua's while ... do ... end loop. In a while loop, the condition precedes the block:

-- This will cause an error or reference a global:
while not done do
    local done = checkStatus() -- 'done' cannot be seen by the while condition
end

To make a variable accessible to a while condition, it must be declared in an outer scope before the loop begins. The repeat ... until construct eliminates this requirement, preventing unnecessary variable pollution in the enclosing scope.

Practical Advantages

This scoping design simplifies code patterns involving user input, polling, and retry mechanisms. Developers can encapsulate transient data, calculations, and exit flags entirely within the loop structure:

local attempts = 0

repeat
    attempts = attempts + 1
    local success, response = pcall(fetchData)
until success or attempts >= 3

Here, success and response exist only within the context of the loop execution, maintaining clean boundaries and preventing external scopes from retaining stale state.
