Lua: Deep Copy vs Shallow Copy of Nested Tables

In Lua, understanding the difference between shallow and deep copying is essential when working with nested tables, as tables are reference types rather than value types. This article breaks down how shallow copying only duplicates the top-level references—leaving nested tables shared between copies—while deep copying recursively traverses the table structure to create completely independent duplicates. You will learn the mechanics behind each approach, observe the side effects on nested structures, and see how to implement both patterns in pure Lua.

Understanding Lua Table References

In Lua, variables do not hold table data directly; they hold a reference (pointer) to the memory address where the table resides. When you assign an existing table to a new variable using simple assignment (b = a), no data is copied. Both variables simply point to the exact same table in memory.

What is a Shallow Copy?

A shallow copy creates a new table and iterates over the original table's keys, assigning each key-value pair to the new table.

For primitive types like numbers, strings, and booleans, the values are duplicated. However, when a value is another table (a nested table), Lua copies the reference to that nested table rather than creating a new one. Consequently, both the original table and the shallow-copied table share the same inner tables.

Shallow Copy Implementation

local function shallow_copy(orig)
    local copy = {}
    for k, v in pairs(orig) do
        copy[k] = v
    end
    return copy
end

The Problem with Nested Tables in Shallow Copies

local original = {
    name = "Player 1",
    stats = { health = 100, mana = 50 }
}

local copy = shallow_copy(original)

-- Modifying a primitive top-level value
copy.name = "Player 2"
print(original.name) -- Output: "Player 1" (unaffected)

-- Modifying a nested table value
copy.stats.health = 80
print(original.stats.health) -- Output: 80 (unexpected mutation)

Because stats was copied by reference, mutating copy.stats.health alters original.stats.health.

What is a Deep Copy?

A deep copy creates a completely new table structure by recursively duplicating every level of the hierarchy. When the copying function encounters a nested table, it calls itself to create a distinct copy of that nested table. This guarantees that modifying any part of the copied structure—regardless of how deeply nested—will never affect the original table.

Deep Copy Implementation

local function deep_copy(orig, seen)
    -- If the value isn't a table, return it directly
    if type(orig) ~= "table" then
        return orig
    end

    -- Track visited tables to handle circular references
    seen = seen or {}
    if seen[orig] then
        return seen[orig]
    end

    local copy = {}
    seen[orig] = copy

    for k, v in pairs(orig) do
        copy[deep_copy(k, seen)] = deep_copy(v, seen)
    end

    -- Preserve metatables if necessary
    setmetatable(copy, deep_copy(getmetatable(orig), seen))

    return copy
end

Behavior with Nested Tables

local original = {
    name = "Player 1",
    stats = { health = 100, mana = 50 }
}

local copy = deep_copy(original)

copy.stats.health = 80
print(original.stats.health) -- Output: 100 (isolated and unchanged)

Key Differences Summary

  • Memory and Isolation: Shallow copies share nested table references, making them prone to unintended side effects. Deep copies allocate new tables for every nested level, providing total data isolation.
  • Performance: Shallow copying runs in \(O(n)\) time relative to the number of top-level keys, making it fast and lightweight. Deep copying traverses the entire data tree recursively, consuming more CPU cycles and memory.
  • Complexity: Deep copying requires safeguards against circular references (where a table references itself or an ancestor) and logic to decide whether metatables should be copied or shared. Shallow copying avoids this overhead entirely.
