How lua_tolstring Returns String Length in Lua C API

The lua_tolstring function in the Lua C API converts a Lua value at a given stack index into a C string, returning both a direct pointer to the raw character data and its exact byte length. Because Lua strings can contain arbitrary binary data—including embedded null bytes (\0)—standard C string handling using null terminators is insufficient. To provide binary safety, lua_tolstring uses an output pointer parameter to return the byte count alongside the returned const char*.

Function Signature and Parameters

The signature of lua_tolstring is defined in lua.h as follows:

const char *lua_tolstring(lua_State *L, int index, size_t *len);
  • L: The active Lua state.
  • index: The stack index of the value to inspect or convert.
  • len: A pointer to a size_t variable allocated by the caller, which receives the string's length in bytes. Passing NULL ignores the length output (which is how the macro lua_tostring is implemented).

Internal Retrieval Mechanism

Lua stores strings internally as immutable, length-prefixed objects (represented internally by the TString structure). Every Lua string explicitly records its length in bytes upon creation, meaning Lua does not need to scan memory or rely on a terminating null character to determine size.

When lua_tolstring is invoked:

  1. Type Resolution and Coercion: The function checks the type of the value at the specified stack index. If the value is a string, it proceeds directly. If the value is a number, Lua converts it in place on the stack to a string. If the value cannot be converted, lua_tolstring returns NULL.
  2. Length Assignment: If the len argument is non-null, the function dereferences the pointer (*len = ...) and assigns the exact byte count stored inside Lua's internal string structure.
  3. Pointer Return: The function returns a const char* pointing directly to the contiguous byte buffer inside Lua’s memory management system.

Binary Safety and Embedded Nulls

In standard C, strings terminate at the first zero byte (\0), making functions like strlen() unsafe for binary payloads. Lua strings, by contrast, are arbitrary 8-bit byte sequences. By populating the size_t *len out-parameter directly from Lua's internal string metadata, lua_tolstring guarantees that the caller receives the true length of the payload, regardless of whether zero bytes appear within the data.

size_t len;
const char *data = lua_tolstring(L, 1, &len);

if (data != NULL) {
    // Process binary data safely without relying on a null terminator
    fwrite(data, 1, len, stdout);
}

Lifetime and Immutability

The const char* returned by lua_tolstring points directly into memory managed by Lua's garbage collector. Lua appends a trailing \0 byte after the string payload for convenience when interfacing with standard C libraries, but the memory itself must be treated as strictly read-only. Modifying the contents of the returned pointer results in undefined behavior. Furthermore, the pointer is only guaranteed to remain valid as long as the corresponding string remains anchored on the Lua stack or is otherwise protected from garbage collection.
