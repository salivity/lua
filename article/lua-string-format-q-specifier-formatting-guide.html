Lua string.format %q Specifier Formatting Guide

The %q specifier in Lua's string.format function is designed to serialize values into valid Lua literals that can be safely read back by the Lua interpreter. This guide details how %q functions, the data types it supports across different Lua versions, and how it handles escaping and value representation.

Modifier and Flag Support

Unlike numeric or general string specifiers (such as %s, %d, or %f), the %q specifier does not accept standard formatting modifiers:

  • Width and Precision: You cannot specify minimum field widths (e.g., %20q) or precision limits (e.g., %.5q). Attempting to do so results in an error.
  • Flags: Alignment and sign flags such as -, +, 0, or # are not supported.

The formatting applied by %q is fixed and handled automatically by Lua based on the type of value supplied.

Type-Specific Formatting Behavior

Starting in Lua 5.2 and continuing through Lua 5.3 and 5.4, %q was expanded to accept types beyond standard strings. Its output varies depending on the input type:

1. Strings

When passed a string value, %q wraps the content inside double quotation marks ("...") and escapes characters that could break Lua syntax or corrupt data:

  • Double Quotes ("): Converted to \".
  • Backslashes (\): Converted to \\.
  • Newlines (\n) and Carriage Returns (\r): Converted to their literal escape sequences rather than actual line breaks.
  • Null Characters (\0) and Non-Printable ASCII: Converted to decimal or hexadecimal escape sequences (e.g., \000 or \x00) to guarantee safe execution when parsed by load or dostring.

2. Booleans and Nil

  • nil: Output as the literal keyword nil without quotes.
  • true / false: Output as the literal keywords true or false without quotes.

3. Numbers

In Lua 5.3 and newer, %q formats numbers so that their full precision is retained when re-read:

  • Integers: Output in standard decimal format (e.g., 42).
  • Floats: Output in standard floating-point form or in hexadecimal floating-point notation (e.g., 0x1.4p+3) whenever necessary to avoid precision loss.
  • Special Values: Handles special IEEE 754 float values such as inf, -inf, and nan in a syntax compatible with Lua.

4. Unsupported Types

Passing complex types to %q—such as tables, functions, threads (coroutines), or userdata—results in a runtime error. To format these types, you must serialize them manually or convert them using custom logic before calling string.format.
