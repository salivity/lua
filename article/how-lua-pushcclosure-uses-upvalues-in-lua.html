How lua_pushcclosure Uses Upvalues in Lua

This article explains how the Lua C API function lua_pushcclosure enables C functions to hold upvalues, turning standard stateless functions into stateful closures. It details the memory association process between C functions and Lua values, how the virtual stack operates during closure creation, how to retrieve and modify upvalues inside callback functions using pseudo-indices, and how Lua manages the lifecycle of these values through garbage collection.

In standard Lua C API programming, lua_pushcfunction binds a standard C function pointer (lua_CFunction) to Lua. However, standard C functions are strictly stateless and cannot preserve private data across calls without relying on global variables or external data structures. To solve this, Lua provides lua_pushcclosure, which creates a "C closure"—a callable object that bundles a C function pointer with one or more dedicated Lua values known as upvalues.

The process of binding upvalues relies on the Lua evaluation stack:

  1. Stack Preparation: Before invoking lua_pushcclosure, the host program pushes the desired upvalues onto the Lua stack in sequential order.
  2. Closure Creation: The host calls lua_pushcclosure(L, fn, n), where L is the Lua state, fn is the target C function, and n is the number of upvalues to associate.
  3. Internal Storage: Lua creates a new CClosure object in its internal garbage-collected memory. It pops the top n values from the stack and copies them directly into an array of upvalues allocated within that closure structure.
  4. Result: Lua pushes the newly created closure object back onto the top of the stack, ready to be assigned to a variable, table, or returned to Lua code.

When the closure is executed from Lua, the C function accesses its preserved upvalues using the macro lua_upvalueindex(i). This macro produces a pseudo-index, an integer value that behaves like a regular stack index in functions like lua_tonumber, lua_tostring, or lua_gettable, but references the closure’s internal upvalue array rather than the active call frame. Upvalues are indexed starting from 1 up to n, corresponding to the order in which they were originally pushed.

Upvalues are fully mutable during runtime. A C function can alter the contents of an upvalue by placing a new value onto the call stack and calling lua_replace(L, lua_upvalueindex(i)). This allows C closures to maintain state, implement counters, encapsulate private tables, or store user data references safely across independent invocations.

Memory management of upvalues is handled entirely by Lua's garbage collector. Because upvalues are directly referenced by the CClosure object, Lua ensures they are not collected as long as the closure itself is reachable. Once all references to the closure are dropped, both the closure object and its associated upvalues become eligible for garbage collection.
