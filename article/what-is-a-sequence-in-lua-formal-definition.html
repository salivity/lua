What Is a Sequence in Lua? Formal Definition

In the Lua programming language, a sequence is a specific structural property of a table where positive numeric keys form a continuous, unbroken range of integers starting at index 1. This article explains the precise formal definition of a sequence as stated in the Lua reference manual, clarifies how non-sequence keys affect this classification, and details how sequences directly determine the behavior of the length operator (#).

According to the official Lua Reference Manual, a table is formally defined as a sequence if and only if its set of positive numeric keys is equal to {1..n} for some non-negative integer n. In this context, n represents the length of the sequence. If n is equal to 0, the table represents an empty sequence.

The formal definition relies on several key characteristics:

  • Contiguous Positive Keys: The positive integer keys must start at 1 and proceed without interruption to n. For example, a table containing values at keys 1, 2, and 3 matches the set {1..3}, qualifying it as a sequence of length 3.
  • Presence of "Holes": If a table contains positive integer keys that skip a number—such as having keys 1, 2, and 4 where key 3 is nil—the set of positive keys is {1, 2, 4}. Because this set cannot be expressed as {1..n} for any integer n, the table is not a sequence. The missing indices are informally referred to as "holes."
  • Irrelevance of Non-Positive and Non-Numeric Keys: The formal definition strictly restricts only the positive numeric keys. A table can store other types of keys—such as strings, negative numbers, or non-integer floats—and still formally remain a sequence, provided its positive integer indices continue to strictly satisfy the {1..n} condition.

The concept of a sequence is essential in Lua because it dictates the correctness of the length operator (#). When applied to a table t that is a sequence, #t is guaranteed by the language specification to return the exact length n.

If t is not a sequence, the manual states that #t can return any integer index k such that t[k] ~= nil and t[k+1] == nil (or 0 if t[1] == nil). Consequently, for tables with holes, the length operator's output is non-deterministic and can vary based on internal hash table implementation details. Adhering to the formal sequence definition is the only way to ensure reliable table length calculations in Lua.
