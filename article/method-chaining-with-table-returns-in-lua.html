Method Chaining with Table Returns in Lua

This article explains how to implement clean and idiomatic method chaining in the Lua programming language by returning tables from methods. It covers the mechanics of using Lua's colon syntax and metatables to create fluent interfaces, demonstrates how to manage mutable and immutable state, and provides practical code examples for designing readable, chainable APIs.

The Core Concept

Method chaining (often called a fluent interface) allows multiple methods to be called sequentially on an object in a single line of code, such as object:stepOne():stepTwo():stepThree().

In Lua, this is achieved by designing methods to return a reference to the table instance—typically self—or a new table representing the next state.

Implementation Using Metatables and Colon Syntax

The standard and most memory-efficient way to build chainable objects in Lua is using metatables and the : method-call operator. The colon operator implicitly passes the calling table as the first parameter, named self.

local Calculator = {}
Calculator.__index = Calculator

function Calculator.new(initial_value)
    local instance = setmetatable({}, Calculator)
    instance.value = initial_value or 0
    return instance
end

function Calculator:add(n)
    self.value = self.value + n
    return self -- Return table for chaining
end

function Calculator:subtract(n)
    self.value = self.value - n
    return self -- Return table for chaining
end

function Calculator:multiply(n)
    self.value = self.value * n
    return self -- Return table for chaining
end

function Calculator:result()
    return self.value -- Terminal method: returns raw value
end

Usage

local total = Calculator.new(10)
    :add(5)
    :multiply(2)
    :subtract(4)
    :result()

print(total) -- Output: 26

Immutable Chaining Pattern

If mutating the existing table causes side effects or concurrency issues, you can return a newly constructed table from each method while sharing the prototype via __index.

local QueryBuilder = {}
QueryBuilder.__index = QueryBuilder

function QueryBuilder.new(base_table)
    return setmetatable({
        table_name = base_table,
        conditions = {},
        limit_count = nil
    }, QueryBuilder)
end

function QueryBuilder:where(condition)
    -- Create a copy of the existing state
    local new_instance = QueryBuilder.new(self.table_name)
    for k, v in ipairs(self.conditions) do
        new_instance.conditions[k] = v
    end
    table.insert(new_instance.conditions, condition)
    new_instance.limit_count = self.limit_count
    return new_instance
end

function QueryBuilder:limit(n)
    local new_instance = QueryBuilder.new(self.table_name)
    for k, v in ipairs(self.conditions) do
        new_instance.conditions[k] = v
    end
    new_instance.limit_count = n
    return new_instance
end

function QueryBuilder:build()
    local query = "SELECT * FROM " .. self.table_name
    if #self.conditions > 0 then
        query = query .. " WHERE " .. table.concat(self.conditions, " AND ")
    end
    if self.limit_count then
        query = query .. " LIMIT " .. tostring(self.limit_count)
    end
    return query
end

Usage

local base_query = QueryBuilder.new("users"):where("active = 1")
local page_query = base_query:limit(10):build()

print(page_query) -- SELECT * FROM users WHERE active = 1 LIMIT 10

Best Practices for Clean Chaining in Lua

  1. Distinguish Modifiers from Resolvers: Methods that alter state or configure an operation should strictly return self (or a cloned instance). Terminal operations (like :build(), :resolve(), or :result()) should return the final calculated value instead of the table.
  2. Consistent Syntax: Always use the colon (:) syntax for methods that require self. Avoid mixing dot-syntax function calls with method calls to maintain a consistent API.
  3. Guard Against Nil: When chaining methods, ensure that internal operations do not cause a method to fail silently or return nil, which causes a runtime error on subsequent method calls. If error handling is needed, collect errors inside the table state and inspect them in the terminal method.
