Guide to LUA_COMPAT_5_2 and LUA_COMPAT_5_3 in Lua

This article explains the purpose and implementation of the LUA_COMPAT_5_2 and LUA_COMPAT_5_3 preprocessor macros in the Lua source code. It covers how these build-time flags control backward compatibility between minor versions of the Lua runtime, what features they restore for legacy codebases, and how developers configure them during compilation.

The Purpose of Compatibility Macros

The Lua programming language evolves through minor version bumps (such as 5.2 to 5.3, or 5.3 to 5.4) that deliberately introduce breaking changes to both the Lua script API and the C API. To prevent existing codebases from breaking when upgrading the interpreter, Lua's maintainers include conditional compilation blocks guarded by macros such as LUA_COMPAT_5_2 and LUA_COMPAT_5_3.

Defining these macros instructs the C preprocessor to retain legacy behaviors, deprecated functions, and obsolete C API functions that would otherwise be excluded from the build.

The Function of LUA_COMPAT_5_2

The LUA_COMPAT_5_2 macro is primarily used in Lua 5.3 (and carried forward into Lua 5.4) to restore features deprecated or modified between Lua 5.2 and Lua 5.3.

When enabled, LUA_COMPAT_5_2 activates several backwards-compatible behaviors:

  • Math Library Compatibility: Restores functions like math.atan2 (superseded by standard math.atan), math.cosh, math.sinh, math.tanh, and math.pow (superseded by the ^ operator).
  • Bitwise Operations: Re-enables the external bit32 library in Lua 5.3, which was deprecated after native bitwise operators (&, |, ~, etc.) were introduced.
  • C API Compatibility: Restores older C functions and macros, such as legacy signatures for string buffers and functions like luaL_checkint and luaL_optint, which were replaced by integer-specific operations using lua_Integer.
  • Table Functions: Preserves legacy behaviors such as table.maxn.

The Function of LUA_COMPAT_5_3

The LUA_COMPAT_5_3 macro was introduced in Lua 5.4 to preserve features that were altered or removed after Lua 5.3.

When enabled, LUA_COMPAT_5_3 restores:

  • Garbage Collector Modes: Preserves the older generational and step options for collectgarbage that were restructured in Lua 5.4.
  • Math and String Functions: Restores math.log10 and preserves older variations of string formatting flags.
  • C API Functions: Re-enables deprecated C API calls, such as legacy bindings for lua_dump (which gained a strip parameter) and older userdata access patterns.
  • Coercion Semantics: Maintains older string-to-number coercion rules in specific contexts where Lua 5.4 tightened type checking.

How to Configure Compatibility Switches

These switches are defined in luaconf.h, the primary configuration header file in the Lua source distribution. By default, official release tarballs often define compatibility flags for the immediate predecessor (for example, Lua 5.4 typically enables LUA_COMPAT_5_3 by default).

To configure them explicitly, you can modify src/luaconf.h:

#define LUA_COMPAT_5_2
#define LUA_COMPAT_5_3

Alternatively, you can pass them as compiler definitions during the build process:

make linux MYCFLAGS="-DLUA_COMPAT_5_2 -DLUA_COMPAT_5_3"

To build a strictly modern, minimal Lua interpreter without any legacy baggage, comment out or #undef these macros in luaconf.h, or build using -DLUA_COMPAT_5_3=0. Disabling these switches slightly reduces the memory footprint of the binary and ensures that running scripts adhere strictly to modern Lua specifications.
