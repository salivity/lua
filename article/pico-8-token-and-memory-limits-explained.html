PICO-8 Token and Memory Limits Explained

PICO-8 is a popular fantasy console that enforces strict, artificial hardware constraints to evoke the creative challenges of 1980s game development. This guide outlines the specific token, code size, and memory limitations applied to Lua scripts on the PICO-8 platform, detailing the boundaries developers must navigate when building cartridges.

Token Limit

PICO-8 measures code complexity primarily through a token system rather than raw line counts:

  • Token Cap: 8,192 tokens.
  • What Counts as a Token: Each distinct programmatic element counts as one token. This includes variable names, keywords (such as if, while, function), operators (+, ==, and), literals (numbers, strings), and table accessors.
  • Exceptions: Certain syntax elements are free and do not consume tokens. These include comments, commas, semicolons, parentheses, brackets, and block closers like end.

Code Size Limits

In addition to the token count, PICO-8 enforces limits on file size to ensure cartridges fit within shareable formats:

  • Compressed Code Limit: 15,616 bytes (15.5 KB). The Lua code is compressed when saved to cartridge formats (such as .p8.png). If code exceeds 15,616 compressed bytes, the cartridge cannot be exported or saved as an image.
  • Raw Character Limit: 65,535 characters. Plaintext .p8 files cannot exceed 64 KB of total script text, regardless of compression.

Lua Dynamic Memory (RAM)

At runtime, the Lua interpreter manages memory independently from the console's virtual hardware:

  • Lua Heap: 2,048 KB (2 MB).
  • Usage: This dynamic memory is used for runtime variables, user-created tables, closures, and active strings. It is governed by Lua's automatic garbage collector.
  • Out of Memory: If dynamic allocations exceed 2 MB, the program halts with an "out of memory" runtime error. Developers can monitor memory usage using the stat(0) function.

System RAM and Hardware Memory

PICO-8 emulates a fixed memory map accessible via low-level memory functions like peek(), poke(), memcpy(), and memset():

  • Base RAM: 32 KB (addresses 0x0000 to 0x7FFF). This layout contains dedicated spaces for the sprite sheet, map, sprite flags, music, sound effects, and the 8 KB screen buffer (0x6000 to 0x7FFF).
  • Extended RAM: An additional 32 KB (addresses 0x8000 to 0xFFFF) is available as upper memory for custom data storage, accessible via bank switching or direct peeking and poking depending on the hardware configuration.
