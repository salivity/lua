Writing Stored Procedures in Tarantool Using Lua

This article explains how stored procedures work in the Tarantool in-memory database and demonstrates how to write, register, and execute them natively using Lua. You will learn the architecture behind Tarantool's embedded Lua runtime, the performance benefits of executing logic co-located with your data, and practical code examples for building atomic, high-throughput database procedures.

What Are Stored Procedures in Tarantool?

In traditional relational database management systems, stored procedures are written in database-specific procedural languages (like PL/SQL or T-SQL) and run within a separate execution environment inside the database engine. Tarantool takes a fundamentally different approach by embedding an ultra-fast LuaJIT (Just-In-Time) compiler directly into the database core.

In Tarantool, stored procedures are simply standard Lua functions. Because the database engine and the Lua runtime reside in the same memory space and thread of execution, there is zero network latency, no serialization overhead, and minimal context-switching cost between the data store and the business logic. Stored procedures can perform complex calculations, validate incoming data, and execute multiple database operations with microsecond-level latency.

Key Advantages

  • Data Colocation: Code executes directly where data lives in RAM, avoiding round trips between an external application server and the database.
  • ACID Transactions: Multiple space operations executed inside a Lua function can be wrapped in a single, cooperative transaction that guarantees atomicity and isolation.
  • Standard Ecosystem: Developers write standard Lua and can leverage third-party Lua rocks, C modules, and Tarantool's extensive standard library (handling HTTP, JSON, fiber concurrency, and crypto).

Writing Stored Procedures in Lua

Interacting with data inside a Tarantool Lua procedure is achieved using the built-in box module. Through box.space, functions can insert, update, delete, and select tuples directly.

1. Basic Function Definition

To make a Lua function accessible as a stored procedure that remote clients can invoke, define it in the global namespace or assign it to a global table.

-- Define a procedure that calculates user reward points
function calculate_bonus(user_id, multiplier)
    local user = box.space.users:get(user_id)
    if not user then
        return nil, "User not found"
    end

    local points = user[3]
    local bonus = points * multiplier
    return bonus
end

2. Transactional Procedures

Tarantool uses cooperative multitasking (fibers). Operations in a stored procedure can be executed atomically using box.atomic(), ensuring all operations succeed or none do:

function transfer_funds(from_id, to_id, amount)
    return box.atomic(function()
        local sender = box.space.accounts:get(from_id)
        local receiver = box.space.accounts:get(to_id)

        if not sender or not receiver then
            error("Invalid account ID")
        end

        if sender[2] < amount then
            error("Insufficient funds")
        end

        box.space.accounts:update(from_id, {{'-', 2, amount}})
        box.space.accounts:update(to_id, {{'+', 2, amount}})

        return true
    end)
end

3. Granting Privileges

For external clients to execute a stored procedure, appropriate permissions must be granted to the connecting database user:

-- Grant execution rights to a user named 'api_client'
box.schema.user.grant('api_client', 'execute', 'function', 'transfer_funds')

Calling Stored Procedures

Stored procedures can be invoked either locally within the Tarantool instance or remotely via language drivers (such as Python, Go, Java, or Node.js) using the binary protocol:

  • Locally (Tarantool Console):

    transfer_funds(101, 102, 50.00)

  • Remotely (via Tarantool Network Client):

    local net_box = require('net.box')
local conn = net_box.connect('127.0.0.1:3301')
local result = conn:call('transfer_funds', {101, 102, 50.00})

By leveraging embedded LuaJIT, Tarantool transforms database procedures from simple batch scripts into high-performance application backends capable of processing hundreds of thousands of complex operations per second.
