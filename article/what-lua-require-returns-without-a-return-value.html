What Lua require Returns Without a Return Value

In Lua, loading a module that does not explicitly return a value will cause the require function to return the boolean true. When a module file finishes execution without a return statement—or returns nil—Lua assumes the script ran successfully and defaults to storing true in its internal cache table, package.loaded. This article explains how Lua's module system handles missing return statements, why this fallback exists, and how it impacts your code.

The Default Behavior of require

When you import a file using require("module_name"), Lua executes the file's chunk. If the chunk returns any non-nil value (such as a table or a function), require sets package.loaded["module_name"] to that value and returns it to the caller.

However, if the module does not return anything, Lua evaluates the result as nil. To signify that the file was successfully executed and to avoid re-running it upon subsequent imports, Lua automatically assigns true to package.loaded["module_name"]. As a result, require returns true.

Code Example

Consider a file named logger.lua that defines functions globally or sets up side effects without an explicit return statement:

-- logger.lua
local message = "Logger initialized"
print(message)
-- Notice there is no 'return' statement here

If you import this module in your main script:

-- main.lua
local logger = require("logger")

print(type(logger)) -- Outputs: boolean
print(logger)       -- Outputs: true

The output confirms that the variable logger holds the boolean true rather than nil or an export table.

Why Lua Defaults to true

This design accommodates legacy Lua 5.0 patterns and modules that operate entirely via side effects, such as:

  • Injecting functions directly into the global environment (_G).
  • Registering handlers or monkey-patching existing tables.
  • Direct manipulation of package.loaded from inside the module itself.

By returning true, require ensures that subsequent calls to require("module_name") will not reload the file from the disk, since package.loaded["module_name"] is truthy.

Best Practice

While returning true by default prevents infinite loading loops, modern Lua conventions discourage relying on side effects or implicit return values. Best practice is to explicitly declare a local table, attach all public functions and variables to it, and return that table at the end of the module:

local M = {}

function M.say_hello()
    print("Hello, World!")
end

return M

Explicitly returning a table ensures that consumers of the module receive an object containing the expected functions, preventing runtime errors caused by trying to index a boolean value.
