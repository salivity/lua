Resolve Lua Circular Dependencies with Tables

Circular dependencies occur in Lua when two modules require each other, often causing one module to receive an empty or incomplete table because the initial module has not finished executing. This article explains how to resolve this problem cleanly using the table pass-through technique. By leveraging Lua’s reference-based table semantics and manipulating package.loaded, developers can expose a shared module table before loading the dependent module, ensuring mutual dependencies resolve reliably without architectural redesigns.

Understanding the Circular Dependency Problem

When require("module_a") is executed, Lua performs the following steps:

  1. Checks package.loaded["module_a"]. If it exists, Lua returns that value immediately.
  2. If it does not exist, Lua loads and compiles the file.
  3. Lua executes the module chunk and stores the returned value into package.loaded["module_a"].

If module_a requires module_b, and module_b simultaneously requires module_a, the loading process creates a deadlock. When module_b requests module_a, package.loaded["module_a"] is either nil (in older Lua versions or custom loaders) or a placeholder boolean/empty state, because module_a has not yet returned its table. As a result, module_b gets an incomplete reference, resulting in runtime errors such as indexing nil values.

The Table Pass-Through Solution

Lua passes tables by reference. If a module creates its export table and immediately registers it inside package.loaded before requiring the second module, the second module will receive that exact reference. Even if the table is currently empty, any fields, functions, or variables added to it later will be accessible to the dependent module at runtime.

This mechanism is called the table pass-through pattern.

Implementation Example

Consider two modules: node.lua and graph.lua. A Node needs to be added to a Graph, and a Graph needs to instantiate Node objects.

1. Define the First Module (node.lua)

Pre-populate package.loaded with the local module table prior to requiring graph.lua:

-- node.lua
local Node = {}

-- Register the table immediately in package.loaded
package.loaded["node"] = Node

-- Require the interdependent module
local Graph = require("graph")

Node.new = function(name)
    local self = { name = name }
    return setmetatable(self, { __index = Node })
end

Node.attachToDefaultGraph = function(self)
    -- Graph is fully populated by the time this method is called at runtime
    local defaultGraph = Graph.getDefault()
    defaultGraph:addNode(self)
end

return Node

2. Define the Second Module (graph.lua)

The second module can now safely require node.lua:

-- graph.lua
local Graph = {}
package.loaded["graph"] = Graph

local Node = require("node")

local defaultInstance = nil

Graph.new = function()
    local self = { nodes = {} }
    return setmetatable(self, { __index = Graph })
end

Graph.getDefault = function()
    if not defaultInstance then
        defaultInstance = Graph.new()
    end
    return defaultInstance
end

Graph.createAndAddNode = function(self, name)
    -- Node functions are available here because the reference is updated
    local node = Node.new(name)
    table.insert(self.nodes, node)
    return node
end

Graph.addNode = function(self, node)
    table.insert(self.nodes, node)
end

return Graph

Critical Rules for Table Pass-Throughs

To ensure the table pass-through pattern functions reliably, adhere to the following rules:

  • De-reference at Runtime, Not Load Time: Avoid accessing functions or properties of the imported module at the root file scope. Only invoke or index members inside function bodies (methods, callbacks, or factories) so they run after all files have fully finished loading.
  • Exact Module Naming: The key used in package.loaded["..."] must match the string passed to subsequent require("...") calls across your codebase.
  • Always Return the Same Table: Ensure the table returned at the end of the file matches the table registered in package.loaded (return Node). Creating a new table at the end will break the reference passed to the cyclic dependency.
