How to Attach a __gc Metamethod to Lua Userdata

In the Lua programming language, attaching a __gc finalizer metamethod to a full userdata object ensures that associated system resources, such as memory buffers or file handles, are safely cleaned up when the object is collected. This article provides a straightforward guide to registering and associating the __gc metamethod with userdata via the Lua C API, detailing the metatable setup and execution lifecycle across standard Lua versions.

The Role of the __gc Metamethod

Full userdata represents C data blocks managed directly by Lua's garbage collector. While the memory allocated for the userdata itself is automatically reclaimed, external resources referenced within that struct (such as pointers allocated via malloc, OS file descriptors, or sockets) require explicit deallocation. The __gc metamethod acts as a finalizer or destructor that the garbage collector automatically executes immediately before the userdata object is freed.

Step-by-Step Implementation via the C API

Attaching a finalizer to userdata requires creating a metatable, placing a C cleanup function into its __gc field, and setting this metatable on the newly allocated userdata.

1. Define the Finalizer Function

The finalizer must be a C function adhering to the lua_CFunction signature. It receives the userdata being collected as its single argument.

static int mydata_gc(lua_State *L) {
    MyStruct *data = (MyStruct *)luaL_checkudata(L, 1, "MyDataMeta");
    
    /* Clean up external resources */
    if (data->buffer) {
        free(data->buffer);
        data->buffer = NULL;
    }
    
    return 0;
}

2. Register the Metatable

When initializing your C module, register a metatable in the Lua registry using luaL_newmetatable, then add the __gc function to it:

int luaopen_mymodule(lua_State *L) {
    /* Create unique metatable in the registry */
    if (luaL_newmetatable(L, "MyDataMeta")) {
        /* Set the __gc field */
        lua_pushcfunction(L, mydata_gc);
        lua_setfield(L, -2, "__gc");
    }
    
    /* Register module functions */
    return 1;
}

3. Allocate Userdata and Bind the Metatable

When instantiating the object, use lua_newuserdata (or lua_newuserdatauv in Lua 5.4+) to allocate the memory, followed by luaL_setmetatable to assign the registered metatable:

static int mydata_create(lua_State *L) {
    MyStruct *data = (MyStruct *)lua_newuserdata(L, sizeof(MyStruct));
    data->buffer = malloc(1024);
    
    /* Associate the metatable containing the __gc metamethod */
    luaL_setmetatable(L, "MyDataMeta");
    
    return 1; /* Return userdata to Lua */
}

Important Version Differences

  • Lua 5.1: The __gc metamethod is strictly reserved for userdata. Setting __gc on standard Lua tables has no effect unless using LuaJIT or custom extensions.
  • Lua 5.2 and Later: Tables also support __gc, but for userdata, the metatable must contain the __gc field at the exact moment the metatable is bound. Modifying or adding __gc to a metatable after it has already been attached to a userdata instance will not register the finalizer in earlier Lua 5.2 implementations.
  • Lua 5.4: Userdata creation uses lua_newuserdatauv to support user values. Memory cleanup and finalization semantics for __gc remain consistent with prior versions.
