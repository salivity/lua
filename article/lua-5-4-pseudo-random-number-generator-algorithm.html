Lua 5.4 Pseudo-Random Number Generator Algorithm

Lua 5.4 officially introduced the xoshiro256** (XOR/shift/rotate) pseudo-random number generator into its standard library. This article examines the adoption of xoshiro256**, why it replaced the platform-dependent generators used in previous Lua versions, and how it improves randomness, performance, and cross-platform consistency for developers.

The Algorithm: xoshiro256**

Starting with version 5.4, Lua replaced its legacy random generation system with xoshiro256** (star-star), an all-purpose generator designed by David Blackman and Sebastiano Vigna. The name stands for "XOR / shift / rotate," representing the bitwise operations the algorithm uses to scramble its internal state.

Why Lua Replaced the Legacy Generator

Prior to Lua 5.4, functions like math.random() and math.randomseed() relied on the C runtime library's implementation of rand() and srand(). This design created several major problems:

  • Inconsistent Behavior: Because different operating systems and C compilers implement rand() differently, the same Lua script produced different random sequences on Windows, Linux, and macOS even when initialized with the same seed.
  • Low Statistical Quality: Many standard C libraries historically used weak Linear Congruential Generators (LCGs), which often suffer from poor randomness in lower-order bits and fail modern empirical randomness tests.
  • Short Periods: Traditional C rand() implementations frequently had short cycle periods (often \(2^{31} - 1\) or \(2^{32}\)), meaning sequences would repeat quickly in compute-heavy simulations.

Key Features of xoshiro256** in Lua 5.4

The integration of xoshiro256** brings several distinct improvements:

  • Massive Period: The generator maintains a 256-bit internal state, resulting in a period of \(2^{256} - 1\). A sequence will not repeat within any practical computational timeframe.
  • High Statistical Quality: The xoshiro256** algorithm passes rigorous statistical testing suites, such as BigCrush, eliminating common artifacts and biases found in older PRNGs.
  • Speed: The algorithm relies entirely on fast, low-level bitwise operations (shifts, rotations, and XORs) alongside standard addition and multiplication, making it exceptionally fast in pure software execution.
  • Deterministic Portability: Because Lua directly embeds the xoshiro256** implementation into its source code, any Lua 5.4 program given identical seeds will produce the exact same sequence of pseudo-random numbers regardless of the host operating system.

Enhancements to math.randomseed

Lua 5.4 also updated the math.randomseed() function to support the expanded state requirements of xoshiro256**:

  1. Multi-argument Seeding: math.randomseed(x, y) accepts up to two 64-bit integer arguments, allowing developers to set all 256 bits of the state explicitly.
  2. Automatic Seeding: Calling math.randomseed() without arguments automatically initializes the state using a non-deterministic seed provided by the host platform, eliminating the common requirement of manually passing os.time().
