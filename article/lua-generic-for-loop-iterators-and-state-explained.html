Lua Generic For Loop: Iterators and State Explained

In Lua, the generic for loop provides a powerful mechanism for traversing data structures through iteration. It operates by evaluating an expression list once to produce an iterator function, an invariant state, and an initial control variable value. This article breaks down the precise internal mechanics of the generic for loop, detailing how Lua passes these components, evaluates termination conditions, and manages variable scoping during each iteration.

Anatomy of the Loop Declaration

The syntax of a generic for loop in Lua is structured as follows:

for var_1, ..., var_n in explist do
    block
end

Here, var_1, ..., var_n represent the loop variables, and explist is an expression list that produces the iterator parameters.

Initialization Phase

Before the loop executes any iterations, Lua evaluates explist. This evaluation happens exactly once. The expression list must yield three primary values:

  1. Iterator Function (f): The function called at each iteration to produce new values.
  2. Invariant State (s): A constant value (typically a table) passed as the first argument to the iterator function on every call.
  3. Initial Variable (var): The initial value for the first loop variable, passed as the second argument to the iterator function during the first step.

If explist returns fewer than three values, Lua nil-pads the missing components. If it returns more, extra values are discarded (except in Lua 5.4, which supports an optional fourth "to-be-closed" value for resource cleanup).

The Iteration Step

After initialization, Lua executes the iteration cycle:

  1. Call Iterator: Lua calls the iterator function, passing the invariant state and the current control variable:

    var_1, ..., var_n = f(s, var)

  2. Evaluate Termination: Lua checks the first returned variable (var_1). If var_1 is nil, the loop terminates immediately, and control jumps past the end statement.

  3. Update Control Variable: If var_1 is not nil, it becomes the new value of the control variable (var = var_1) to be fed into the next cycle.

  4. Execute Block: Lua executes the statements within block, with var_1, ..., var_n scoped locally to this iteration.

  5. Repeat: The cycle repeats starting from step 1.

Equivalent Lua Implementation

The exact runtime behavior of the generic for loop can be modeled using an equivalent while construct with hidden local variables:

do
    local _f, _s, _var = explist
    while true do
        local var_1, ..., var_n = _f(_s, _var)
        _var = var_1
        if _var == nil then break end
        block
    end
end

State Management and Stateless Iterators

The separation of the invariant state (_s) and the control variable (_var) enables stateless iterators. Functions such as ipairs and pairs rely on this separation:

  • In ipairs(t), the invariant state is the table t, the initial variable is 0, and the iterator function returns i + 1, t[i + 1].
  • In pairs(t), the invariant state is the table t, the initial variable is nil, and the iterator function is Lua's primitive next(t, key).

Because the state _s never mutates via the loop itself and the control variable tracks the progress, a single iterator function can be reused across multiple loops simultaneously without allocating closures or creating memory overhead.
