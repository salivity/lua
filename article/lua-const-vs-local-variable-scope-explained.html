Lua Const vs Local Variable Scope Explained

In Lua 5.4, the <const> attribute was introduced to allow developers to define read-only variables. While developers often question how the scope of a const variable differs from a standard local variable, their lexical scope is fundamentally identical: both are strictly bound to the block, function, or chunk in which they are declared. The real distinction lies not in the boundaries of their scope, but in the lifecycle, mutability, and assignment constraints enforced within that scope.

Identical Lexical Scoping Rules

In Lua, there is no separate const keyword; instead, <const> is an attribute applied to a local variable declaration (local x <const> = 10). Because of this, <const> variables adhere to the exact same block scoping rules as standard local variables:

  • Block Lifetime: Both cease to exist once code execution exits the block (do ... end, if statement, loop, or function) where they were defined.
  • Shadowing: Both can shadow, or be shadowed by, variables of the same name defined in outer scopes.
  • Closure Capture: Both can be captured as upvalues by nested functions declared within their enclosing scope.
do
    local standard_var = "I am local"
    local const_var <const> = "I am const"
end

-- Neither variable is accessible here; both are out of scope.

Key Differences Within the Scope

Although their spatial visibility and lifetime are identical, <const> variables enforce strict operational semantics within their scope:

1. Mandatory Initialization

A standard local variable can be declared without a value, automatically defaulting to nil. A <const> variable must be assigned a value immediately upon declaration. Failing to assign a value results in a compile-time error.

local a          -- Valid: 'a' is initialized to nil
local b <const>  -- Syntax error: const variables must be initialized

2. Reassignment Restrictions

Within its enclosing block, a standard local variable can be reassigned freely. A <const> variable cannot be reassigned after its declaration; any attempt to overwrite it triggers a compile-time error.

local x = 5
x = 10 -- Valid

local y <const> = 5
y = 10 -- Compile error: attempt to assign to const variable

3. Shallow Immutability

The <const> attribute restricts variable reassignment, not object mutation. If a <const> variable holds a mutable data type, such as a table, the reference to that table cannot be altered, but the table's internal fields can still be modified throughout the variable's scope.

local config <const> = { timeout = 30 }

config.timeout = 60      -- Valid: modifies the table contents
config = { timeout = 60 } -- Compile error: attempts to reassign the variable

4. Compiler Optimizations

Because the value of a primitive <const> variable cannot change within its scope, the Lua 5.4 compiler can optimize variable access. In many cases, the compiler inlines simple constants (such as numbers or strings) directly into the bytecode, reducing register allocation overhead compared to standard mutable locals.
