How to Iterate Unicode Codepoints with Lua utf8.codes

This article explains the purpose and functionality of the utf8.codes iterator in the Lua programming language. It covers why traditional byte-based iteration fails with multi-byte UTF-8 strings, how utf8.codes solves this problem by yielding byte positions alongside Unicode codepoint values, and provides a clear example demonstrating its usage for robust text processing.

The Problem with Byte-Based Iteration

By default, Lua strings are byte sequences. Standard string functions—such as string.sub, string indexing patterns, or using a standard for i = 1, #str loop—operate strictly on individual bytes.

In UTF-8 encoding, a single character (codepoint) can consist of anywhere from one to four bytes. If you iterate through a non-ASCII string using byte-level operations, multi-byte characters are split into invalid fragments. This leads to corrupted output, broken text manipulation, and incorrect character counts.

The Purpose of utf8.codes

Introduced in Lua 5.3, the utf8 library provides native tools to handle UTF-8-encoded data. The specific purpose of utf8.codes is to act as a generator function for a generic for loop, allowing developers to traverse a UTF-8 string codepoint by codepoint rather than byte by byte.

When used in a loop, utf8.codes inspects the variable-length byte patterns of the string and yields two values on each iteration:

  1. Byte Position (p): The 1-based index where the current codepoint begins within the raw string.
  2. Codepoint Value (c): The numerical integer representing the Unicode codepoint.

Code Example

Below is a demonstration of how utf8.codes handles both standard ASCII characters and multi-byte Unicode characters accurately:

local text = "Lua 5.4 🚀"

for position, codepoint in utf8.codes(text) do
    -- utf8.char converts the numeric codepoint back into a printable character
    local char = utf8.char(codepoint)
    print(string.format("Position: %d | Codepoint: U+%04X | Character: %s", position, codepoint, char))
end

In this example, standard ASCII characters like L, u, and a advance the position by one byte. When the loop reaches the rocket emoji (🚀), it recognizes it as a 4-byte sequence, yields the full codepoint (U+1F680), and correctly advances the position index by four bytes for any subsequent iteration.

Key Benefits

  • Variable-Length Safety: It automatically calculates character boundaries, removing the need for manual byte-shifting or regular expression workarounds.
  • Integrity Checking: If utf8.codes encounters an invalid UTF-8 byte sequence, it raises an error, ensuring that corrupted or malformed data is not silently processed.
  • Position Tracking: By returning the initial byte offset alongside the codepoint, it enables fast operations with other Lua APIs that still require byte indices, such as slicing via string.sub.
