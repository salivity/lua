Lua Formatting and Layout Style Guide

This guide provides an overview of the widely accepted formatting and layout conventions within the Lua programming community. While Lua itself is syntactically flexible and lacks an official formatting tool like Go's gofmt, the community predominantly adheres to conventions established by the Lua-users wiki and the popular Olivine-Labs style guide. Following these standards ensures consistency, readability, and maintainability across Lua codebases.

Indentation and Line Length

  • Indentation: Use two spaces per indentation level. Avoid using tab characters to prevent rendering inconsistencies across different editors.
  • Line Length: Restrict lines to a maximum of 80 to 120 characters. If a statement exceeds this limit, break it into multiple lines using logical continuation points (such as after commas or operators).

Whitespace and Blank Lines

  • Binary Operators: Place a single space before and after binary operators (+, -, *, /, ==, ~=, =, ..).

    local total = price + tax
local message = "Hello, " .. name

  • Unary Operators: Do not place a space between a unary operator and its operand (e.g., -x, #my_table).

  • Commas and Semicolons: Always place a space directly after a comma, with no space preceding it. Semicolons are generally discouraged at the end of lines unless used to separate multiple statements on a single line.

  • Parentheses and Brackets: Do not add spaces directly inside parentheses, square brackets, or table braces.

    -- Good
local items = {1, 2, 3}
print(items[1])

-- Avoid
local items = { 1, 2, 3 }
print( items[ 1 ] )

  • Vertical Spacing: Use a single blank line between function definitions and logical code blocks. Avoid consecutive blank lines.

Table Formatting

Tables are central to Lua and require consistent layout rules:

  • Single-line Tables: Use for short, simple structures with minimal elements.

    local point = {x = 10, y = 20}

  • Multi-line Tables: Indent elements by one level. Place the opening brace on the declaration line and the closing brace on its own line, aligned with the variable definition. Always include a trailing comma on the final field to facilitate clean diffs when adding new entries.

    local user = {
  id = 101,
  name = "Alice",
  role = "Admin",
}

Control Structures

  • Conditionals: Do not enclose conditional expressions in parentheses unless required for operator precedence.

    -- Good
if isActive and count > 0 then
  process()
end

-- Avoid
if (isActive and (count > 0)) then
  process()
end

  • Blocks: Align then, do, and repeat with their corresponding closing keywords (end or until). Do not write statements on the same line as the conditional keyword.

Function Syntax and Calls

  • Syntactic Sugar: Omit parentheses when calling a function with a single literal string or table argument, provided it enhances readability.

    print "Quick message"
render {width = 800, height = 600}

  • Method Definitions: Use the colon syntax (:) when defining and invoking methods on object tables to automatically pass the self reference.

    function Account:deposit(amount)
  self.balance = self.balance + amount
end

String Literals

  • Use single quotes (') for short string literals and identifiers.
  • Use double quotes (") when the string itself contains single quotes to avoid escaping.
  • Use long brackets ([[...]]) for multiline strings or raw text blocks.

Comments

  • Place single-line comments on their own line preceding the code they describe, indented to the same level.
  • Insert a single space between the comment dashes and the text (-- This is a comment).
  • Reserve block comments (--[[ ... ]]) for multi-line documentation or temporarily disabling blocks of code.
