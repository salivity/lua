Lua Bitwise NOT Operator and Integer Boundaries

In Lua, the bitwise NOT operator (~) operates on standard signed integers using two's complement representation, cleanly mapping values between extreme integer limits without triggering runtime errors or arithmetic overflows. This article examines the exact behavior of applying ~ at and across integer limits, specifically focusing on how math.mininteger and math.maxinteger invert seamlessly according to two's complement arithmetic in standard 64-bit Lua implementations.

Integer Representation in Lua

Starting with Lua 5.3, the language natively supports integer subtypes. Standard builds use 64-bit signed integers stored in two's complement format:

  • Maximum Integer (math.maxinteger): 0x7FFFFFFFFFFFFFFF (\(9,223,372,036,854,775,807\))
  • Minimum Integer (math.mininteger): 0x8000000000000000 (\(-9,223,372,036,854,775,808\))

Because Lua represents integers in two's complement, every bit pattern maps to an exact integer value within this range.

The Mechanics of the Bitwise NOT Operator

The unary bitwise operator ~ flips every bit of its operand, changing all 0 bits to 1 and all 1 bits to 0. In mathematical terms for two's complement numbers, the bitwise inversion of an integer \(x\) satisfies the algebraic identity:

~x == -x - 1

Unlike standard arithmetic operations such as addition or subtraction, which wrap around silently on overflow, bitwise operations manipulate the underlying bit representation directly.

Inversion at Boundary Values

When the bitwise NOT operator is applied to values at the outer edges of the integer range, the behavior corresponds directly to the inverted bit pattern:

  1. Inverting math.maxinteger: math.maxinteger in binary consists of a 0 sign bit followed by sixty-three 1s: 01111111 11111111 11111111 11111111 11111111 11111111 11111111 11111111 Applying ~ flips the bits to a 1 sign bit followed by sixty-three 0s: 10000000 00000000 00000000 00000000 00000000 00000000 00000000 00000000 This resulting pattern represents math.mininteger. Therefore: ~math.maxinteger == math.mininteger

  2. Inverting math.mininteger: Inverting math.mininteger reverses the process. Flipping the single leading 1 bit and sixty-three trailing 0 bits yields a leading 0 and sixty-three 1 bits. Thus: ~math.mininteger == math.maxinteger

  3. Inverting Zero and Negative One: The boundary between positive and negative numbers behaves consistently:

    • ~0 yields -1 (all bits become 1).
    • ~(-1) yields 0 (all bits become 0).

Absence of Overflow Behavior

Standard arithmetic negation in two's complement cannot negate math.mininteger because \(-(-2^{63})\) exceeds \(2^{63} - 1\), causing integer wrap-around where -math.mininteger simply evaluates back to math.mininteger.

In contrast, the bitwise NOT operator does not suffer from asymmetry. Because ~x calculates -(x + 1), the boundary shift by one accounts for the extra negative integer in two's complement systems. Consequently, ~ cleanly transitions between math.mininteger and math.maxinteger deterministically and symmetrically across the boundaries.
