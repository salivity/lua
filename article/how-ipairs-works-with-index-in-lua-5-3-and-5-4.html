How ipairs Works with __index in Lua 5.3 and 5.4

This article explains how the standard ipairs iterator operates in Lua 5.3 and Lua 5.4 following the deprecation and removal of the __ipairs metamethod. It details how the iteration mechanism performs sequential integer lookups, how metatable indexing (__index) is invoked at each step, and how sequence boundaries and the length operator (#) relate to the termination of the loop.

Removal of the __ipairs Metamethod

In Lua 5.2, ipairs checked the metatable of its argument for a __ipairs metamethod, allowing objects to define custom iteration behaviors directly. Lua 5.3 deprecated __ipairs, and Lua 5.4 removed support for it entirely.

Because __ipairs is no longer recognized by the standard library, ipairs enforces a uniform traversal protocol across all types, relying entirely on primitive indexing operations (t[i]).

The Standard ipairs Mechanism

When invoked, ipairs(t) returns three values: an internal iterator function, the target table or object t, and the initial index integer 0.

On each iteration, the loop invokes the iterator function with t and the current index i. The iterator increments the index by 1 and performs a standard lookup equivalent to t[i + 1]:

local function ipairs_aux(t, i)
    i = i + 1
    local v = t[i]
    if v ~= nil then
        return i, v
    end
end

function ipairs(t)
    return ipairs_aux, t, 0
end

The iteration continues indefinitely until t[i] evaluates to nil.

Fallback to the __index Metamethod

Because the iterator accesses values through standard indexed access (t[i]), any lookup that fails to find an existing raw key in t delegates to the __index metamethod.

  1. Table with a Metatable: If t is a table lacking key i, Lua checks for getmetatable(t).__index. If __index is a table, Lua attempts __index[i]. If __index is a function, Lua executes __index(t, i).
  2. Non-Table Types (e.g., Userdata): If t is a userdata object configured with a metatable containing an __index metamethod, t[i] evaluates via __index directly.

As long as __index returns a non-nil value for a given integer index, ipairs accepts the result and advances to i + 1. The loop terminates as soon as __index returns nil.

Relationship with the Length Operator (#)

The standard ipairs implementation in Lua 5.3 and 5.4 does not call the length operator (#t) internally to establish a loop bound. Instead, it relies strictly on finding the first nil value via sequential lookups starting at index 1.

However, the mechanism directly intersects with sequence semantics and the __len metamethod:

  • Sequence Definition: In Lua, a sequence is a table where positive integer keys form a continuous range from 1 to n without internal nil values. The length operator # returns any index n where t[n] ~= nil and t[n + 1] == nil.
  • Behavior Alignment: Because ipairs stops at the first nil, the iteration naturally covers indices 1 through #t on any valid sequence.
  • Custom Objects and Proxies: When designing proxy tables or custom data structures, developers typically define both __index and __len. While ipairs does not query __len directly, providing a consistent boundary where __index(t, i) returns nil for all i > #t ensures that both #t and ipairs(t) reflect the same collection size and sequence boundary.
