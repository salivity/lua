Luacheck: Static Code Analysis and Linting for Lua

Luacheck is a specialized command-line tool that performs static analysis and linting for the Lua programming language. This article provides an overview of how Luacheck parses source code, tracks variable lifecycles, detects scope-related issues such as undefined globals or unused values, and integrates into continuous integration environments to maintain software quality without executing code.

Lexical Parsing and AST Generation

Luacheck begins its analysis by reading Lua source files and tokenizing the source stream. It translates the code into an Abstract Syntax Tree (AST), which represents the hierarchical syntactic structure of the program.

During this initial parsing stage, Luacheck catches syntax errors and malformed constructs before any deeper semantic checks begin. Because Lua has evolved across various versions (such as Lua 5.1, 5.2, 5.3, 5.4, and LuaJIT), Luacheck's parser can be targeted toward a specific standard. This allows it to validate version-specific syntax, such as bitwise operators introduced in Lua 5.3 or integer division, preventing runtime failures on mismatched runtime targets.

Scope Resolution and Global Variable Tracking

The core feature of Luacheck addresses Lua’s dynamic scoping model. In standard Lua, variables default to global scope unless explicitly declared with the local keyword. This frequently causes accidental global pollution and subtle runtime bugs.

To resolve this, Luacheck maps out lexical scopes and tracks all identifiers:

  • Global Access Detection: Luacheck maintains an internal manifest of valid standard globals based on the configured Lua version (such as table, string, print, and math). Any read or write to an unrecognized global variable is flagged as a potential bug or typo.
  • Custom Environment Whitelisting: Codebases interacting with external frameworks (like OpenResty, Love2D, or Neovim) introduce custom global variables. Luacheck allows developers to whitelist allowed globals or declare custom environments so legitimate framework APIs are not flagged.

Variable Lifecycle and Data Flow Analysis

Beyond tracking scope boundaries, Luacheck analyzes how variables are manipulated across execution branches:

  1. Unused Variables and Values: If a local variable is declared but never referenced, or if a variable is overwritten before its current value is read, Luacheck issues a warning. It recognizes standard conventions, such as variables prefixed with an underscore (_), indicating intentionally unused placeholders (e.g., in multi-return functions or loops).
  2. Shadowing: Luacheck identifies when an inner scope declares a variable with the same name as a variable in an outer scope, preventing confusing or unintended variable masking.
  3. Uninitialized Access: If a code branch attempts to read a local variable before an assignment guarantees a defined value, the analyzer highlights the potential reference error.
  4. Unreachable Code: The control-flow graph identifies unreachable lines following explicit return, break, or terminal function calls.

Configuration and Suppression

Luacheck is designed to adapt to specific project conventions via a .luacheckrc configuration file written directly in Lua.

Within this configuration, developers can:

  • Define global options such as standard library profiles (std = "lua54" or std = "ngx_lua").
  • Set per-path rules to apply stricter checks to production libraries while relaxing rules for test suites.
  • Disable specific warning codes entirely across the project.

For inline adjustments, Luacheck supports structured comments within the code itself. Developers can suppress false positives or intentional edge cases using directives such as -- luacheck: push ignore, -- luacheck: globals my_global, or -- luacheck: ignore 211 without altering the project-wide configuration.

CI/CD and Tooling Integration

Luacheck operates deterministically without evaluating or running the code, making it fast and lightweight. It provides multiple output formats, including plain human-readable text, structured tabular reports, and machine-readable formats like JSON or checkstyle XML.

Because it returns standard Unix exit codes reflecting the severity of detected warnings and errors, Luacheck readily integrates into automated build pipelines, pre-commit hooks, and code editor language servers to prevent code regressions before deployment.
