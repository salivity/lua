Reducing String Memory Churn in Lua Loops

In the Lua programming language, strings are immutable and interned, meaning every unique string created at runtime requires dynamic memory allocation, hashing, and garbage collector tracking. Inside tight or high-frequency loops, continuously generating temporary strings—such as coordinates, logs, or formatted text—triggers severe memory churn and frequent garbage collection cycles, degrading performance. Developers can circumvent this overhead by reusing preallocated buffer tables, caching repetitive values, using direct I/O streaming, or leveraging the Foreign Function Interface (FFI) in LuaJIT to manage raw byte arrays.

Understand the Root Cause: Immutability and Interning

Lua handles strings via an internal hash table. When a new string is generated via concatenation (..), string.format(), or tostring(), the Lua runtime hashes the string and searches the global string pool. If the string is missing, Lua allocates heap memory to store it. In tight loops running thousands or millions of times per second, creating temporary strings produces massive amounts of short-lived garbage, forcing the Garbage Collector (GC) to run frequently and stall execution.

Reuse Preallocated Buffer Tables

The standard method for building strings in Lua is appending components to a sequence and calling table.concat(). While this prevents the quadratic performance cost of the .. operator, creating a new table on every iteration introduces table allocation churn instead.

To eliminate allocations completely, preallocate a single table outside the loop and clear its entries without reallocating the underlying array:

-- Preallocate the buffer outside the high-frequency loop
local buffer = {}

for i = 1, 1000000 do
    -- Populate the reused buffer
    buffer[1] = "entity_"
    buffer[2] = i
    buffer[3] = "_active"
    
    local result = table.concat(buffer)
    
    -- Process the resulting string
    process_data(result)
    
    -- Clear the table for the next iteration without dropping the internal array
    for j = #buffer, 1, -1 do
        buffer[j] = nil
    end
end

Precompute and Cache Finite Values

If loop iterations produce strings from a bounded set of values (such as integers within a known range, statuses, or coordinates), precompute them into an array or lookup table before entering the loop.

-- Precompute string representations for byte values 0 to 255
local byte_to_string = {}
for i = 0, 255 do
    byte_to_string[i] = string.char(i)
end

-- Inside the loop, read directly from the table without allocations
for i = 1, stream_length do
    local b = get_byte(i)
    local char_val = byte_to_string[b] -- No string created; points to existing interned string
    handle_char(char_val)
end

Stream Data Instead of Constructing Intermediates

When strings are constructed solely to be written to a file, network socket, or external interface, avoid assembling them into a single string. Most output functions accept multiple arguments or allow incremental writes.

Instead of:

-- Allocates multiple temporary strings and a concatenated result
socket:send("ID:" .. id .. ";STATUS:" .. status .. "\n")

Write chunks directly to the sink:

-- Avoids intermediate string creation
socket:send("ID:")
socket:send(tostring(id))
socket:send(";STATUS:")
socket:send(status)
socket:send("\n")

Alternatively, pass multiple arguments directly if the API supports it, as standard file:write() does:

file:write("ID:", id, ";STATUS:", status, "\n")

Use LuaJIT FFI for Mutable Byte Buffers

For projects running on LuaJIT, the Foreign Function Interface (FFI) provides the most effective solution for bypassing the Lua string allocator entirely. By allocating a mutable C-style character buffer, byte manipulation can be performed in-place without touching Lua's string interning mechanism.

local ffi = require("ffi")

-- Allocate a single reusable raw buffer
local buf_size = 256
local raw_buffer = ffi.new("uint8_t[?]", buf_size)

for i = 1, 1000000 do
    -- Write bytes directly into the C buffer
    raw_buffer[0] = 0x48 -- 'H'
    raw_buffer[1] = 0x69 -- 'i'
    raw_buffer[2] = 0x00 -- Null-terminator
    
    -- Pass the raw pointer directly to native C functions or libraries
    ffi.C.write(1, raw_buffer, 2)
end

Using FFI structures avoids all Lua runtime allocations, keeps data off the Lua garbage collector's radar, and guarantees predictable frame times in performance-critical code paths.
