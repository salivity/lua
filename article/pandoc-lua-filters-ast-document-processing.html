Pandoc Lua Filters: AST Document Processing

Pandoc uses an embedded Lua interpreter to provide a fast, dependency-free mechanism for transforming documents via their Abstract Syntax Tree (AST). When Pandoc converts a file from one markup format to another, it first parses the input into an internal AST representation composed of blocks and inlines. Lua filters intercept this AST between the parsing and writing stages, allowing users to programmatically inspect, modify, delete, or replace document nodes using standard Lua scripts before final rendering.

The Pandoc AST Pipeline

Pandoc operates as a pipeline consisting of three main phases: Reader, Filter, and Writer.

  1. Reader: Reads the source format (e.g., Markdown, LaTeX, DOCX) and parses it into a native Pandoc AST.
  2. Filter: The AST is exposed to external or built-in filter mechanisms for programmatic manipulation.
  3. Writer: Converts the modified AST into the desired output format (e.g., PDF, HTML, EPUB).

Historically, Pandoc filters relied on piping the AST as JSON through external processes (such as Python scripts via pandocfilters or panflute). While flexible, this approach introduced serialization overhead and required external runtime dependencies. Pandoc solved this by embedding a Lua engine directly into the binary, allowing filters to run in-memory with near-native performance.

How Lua Interacts with the AST

Pandoc maps AST elements directly to Lua tables and functions using the global pandoc module. Elements in a document are divided into two primary types:

  • Blocks: Structural elements such as Header, Para, BlockQuote, CodeBlock, and Table.
  • Inlines: Elements within blocks such as Str, Emph, Strong, Link, and Image.

When a Lua filter script is executed with the --lua-filter=script.lua flag, Pandoc traverses the AST. If a function in the Lua script matches the name of an AST element, Pandoc calls that function, passing the element node as an argument.

Filtering Mechanics and Transformations

A filter function inspects the properties of an AST element and returns a value that determines the transformation:

  • Return an element: Replaces the current element with the returned node.
  • Return a list of elements: Replaces a single node with multiple new nodes (e.g., expanding a custom shortcode into several paragraphs).
  • Return an empty table ({}): Deletes the element from the document.
  • Return nil (or nothing): Leaves the element unchanged.

For example, to convert all second-level headers to uppercase, a Lua filter defines a Header function:

function Header(el)
  if el.level == 2 then
    return pandoc.walk_inline(el, {
      Str = function(s)
        return pandoc.Str(s.text:upper())
      end
    })
  end
end

Traversal and Execution Order

By default, Pandoc performs a depth-first traversal of the AST. It processes inner inline elements before the enclosing block elements. However, Lua filters allow users to customize this behavior.

A filter can return an array of filter tables to specify an explicit execution order:

return {
  { Image = function(img) ... end }, -- Runs first
  { Para = function(para) ... end }   -- Runs second
}

Filters can also alter the traversal strategy directly using the traverse option, choosing between standard traversal or a topdown approach where parent blocks are evaluated before their children.

Document-Level Metadata and the Pandoc Object

In addition to individual elements, Lua filters can inspect and modify global metadata and the entire document structure.

  • The Meta(meta) function receives the document's metadata block, enabling dynamic configuration adjustments (such as adding authors, modifying variables, or setting document dates).
  • The Pandoc(doc) function receives the entire document object containing both doc.blocks and doc.meta, providing full control over the complete AST hierarchy in a single pass.
