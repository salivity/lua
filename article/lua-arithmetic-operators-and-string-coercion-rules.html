Lua Arithmetic Operators and String Coercion Rules

In Lua, applying arithmetic operators to strings containing numerical representations triggers an automatic runtime conversion from string to number. This built-in coercion allows developers to perform mathematical calculations directly on strings without explicitly invoking conversion functions. Understanding how Lua parses formats, differentiates between integers and floating-point values, and handles non-numeric data is essential for writing predictable code and avoiding runtime errors.

The Automatic Coercion Mechanism

When an arithmetic operator (+, -, *, /, //, %, ^, or unary -) encounters an operand that is a string, Lua attempts to convert that string into a number before executing the operation.

print("10" + 5)    -- Output: 15
print("20" * "2")   -- Output: 40
print(-"5")         -- Output: -5

This coercion is bidirectional depending on the operator: arithmetic operators coerce strings into numbers, whereas the concatenation operator (..) coerces numbers into strings.

Accepted String Formats

Lua's coercion rules follow standard lexical conventions for numbers. When parsing a string operand during an arithmetic operation, Lua recognizes:

  • Standard Integers: "42", "-15"
  • Floating-Point Values: "3.1415", ".5"
  • Scientific Notation: "1e3" (1000.0), "2.5e-2" (0.025)
  • Hexadecimal Literals: "0x10" (16), "0xFF" (255)
  • Hexadecimal Floating-Point (Lua 5.2+): "0x1.8p3" (12.0)

Leading and trailing whitespace within the string is ignored during evaluation (e.g., " 25 " + 5 evaluates to 30).

Integer vs. Float Subtypes (Lua 5.3+)

Since Lua 5.3, the number type consists of two internal subtypes: integer and float. When a string is coerced into a number during an arithmetic operation:

  1. If the string contains only whole digits (or a hexadecimal whole number) and falls within the platform's integer range, Lua coerces it into an integer.
  2. If the string contains a decimal point, an exponent, or exceeds the integer range, Lua coerces it into a float.

The final result type follows standard Lua arithmetic rules: operations between integers produce integers (except for standard division / and exponentiation ^, which always return floats).

print(math.type("10" + 2))   -- integer
print(math.type("10.0" + 2)) -- float
print(math.type("10" / 2))   -- float (division always produces a float)

Invalid Numerals and Error Handling

If an arithmetic operator is applied to a string that cannot be parsed as a valid number, coercion fails immediately. Lua does not evaluate invalid conversions to nil or NaN; instead, it raises a fatal runtime error.

print("hello" + 5)   -- error: attempt to perform arithmetic on a string value
print("123a" * 2)    -- error: attempt to perform arithmetic on a string value

Strings containing trailing non-numeric characters (unlike functions such as C's strtod) will cause a total failure of the conversion.

Arithmetic Operators vs. Bitwise Operators

Automatic string coercion applies strictly to standard arithmetic operators. In Lua 5.3 and later, bitwise operators (&, |, ~, >>, <<) do not perform automatic string coercion. Passing a string to a bitwise operator will raise a runtime error, even if the string contains a valid integer numeral. To use bitwise operations on string values, the string must first be explicitly converted using tonumber().
