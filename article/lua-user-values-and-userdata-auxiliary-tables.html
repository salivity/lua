Lua User Values and Userdata Auxiliary Tables

This article explains user values in Lua, exploring what they are and how they allow developers using the Lua C API to attach auxiliary tables directly to full userdata objects. By leveraging user values, developers can seamlessly associate dynamic Lua data and tables with C-managed memory blocks while ensuring that the Lua garbage collector tracks all object references correctly.

What Are User Values in Lua?

In the Lua C API, a full userdata represents a block of raw C memory managed by the Lua garbage collector. While full userdata can possess metatables to define operations and methods, raw C memory cannot directly store Lua values such as strings, numbers, or tables without risk of those values being collected prematurely.

A "user value" (or uservalue) is an auxiliary Lua value stored directly alongside a full userdata object. The garbage collector automatically marks and traverses user values, ensuring that any Lua references stored within them remain alive for as long as the userdata exists. This mechanism bridges raw C pointers and the Lua runtime, allowing C data structures to hold references to arbitrary Lua objects.

Evolution Across Lua Versions

The implementation of user values has evolved across Lua releases:

  • Lua 5.1: Userdata used environment tables (lua_setfenv and lua_getfenv) to associate arbitrary tables with userdata.
  • Lua 5.2 and 5.3: The concept was formalized as a single user value per userdata, managed with lua_setuservalue and lua_getuservalue.
  • Lua 5.4: Lua introduced support for multiple user values per userdata, allocated using lua_newuserdatauv and manipulated via indexed functions lua_setiuservalue and lua_getiuservalue.

Attaching an Auxiliary Table to Userdata

Attaching an auxiliary table to a userdata enables Lua scripts or C functions to store dynamic attributes, event listeners, or cache entries on an otherwise static C struct.

Step 1: Allocating Userdata with User Value Slots

In Lua 5.4, specify the number of user value slots required when creating the userdata:

// Allocate userdata with 1 user value slot
void *data = lua_newuserdatauv(L, sizeof(MyCStruct), 1);

In Lua 5.2 or 5.3, memory allocation is performed with lua_newuserdata(L, sizeof(MyCStruct)), which implicitly allocates space for a single user value initialized to nil.

Step 2: Creating and Attaching the Table

To bind an auxiliary table, push a new table onto the stack and set it as the user value:

// Assume the userdata is at stack index 1
lua_newtable(L); // Push auxiliary table to stack index 2

// Populate the table if necessary
lua_pushstring(L, "custom_property");
lua_pushinteger(L, 42);
lua_settable(L, -3);

// Assign the table as the user value (Lua 5.4)
// Argument 1 is the userdata index, argument 2 is the user value index
lua_setiuservalue(L, 1, 1); 

// For Lua 5.2 / 5.3:
// lua_setuservalue(L, 1);

The function pops the table from the top of the stack and attaches it to the userdata.

Accessing and Modifying the Auxiliary Table

Once attached, the auxiliary table can be retrieved at any point to read or modify dynamic state:

// Retrieve the auxiliary table from the userdata at index 1
lua_getiuservalue(L, 1, 1); // Pushes the table onto the stack (Lua 5.4)
// For Lua 5.2 / 5.3: lua_getuservalue(L, 1);

if (lua_istable(L, -1)) {
    lua_pushstring(L, "custom_property");
    lua_gettable(L, -2); // Reads the property from the auxiliary table
    int value = lua_tointeger(L, -1);
    lua_pop(L, 1); // Pop value
}

lua_pop(L, 1); // Pop the auxiliary table

By delegating dynamic properties to an auxiliary table stored as a user value, C libraries maintain efficient memory layouts while allowing flexible, garbage-collected Lua state associations.
