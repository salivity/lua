Classes and Multiple Inheritance in Lua

This article demonstrates how to cleanly simulate object-oriented classes and multiple inheritance patterns in Lua. While Lua does not provide native class syntax, its metatable mechanism and the __index metamethod offer the flexibility required to build robust object systems. By using dynamic dispatch functions and method caching, developers can implement multi-parent inheritance hierarchies that remain both performant and easy to maintain.

Simulating Basic Classes

In Lua, a class is conventionally represented by a prototype table. When creating a new instance, you instantiate an empty table and assign the class table as its metatable, redirecting table lookups using __index.

local Account = {}
Account.__index = Account

function Account:new(balance)
    local instance = setmetatable({}, self)
    instance.balance = balance or 0
    return instance
end

function Account:deposit(amount)
    self.balance = self.balance + amount
end

When account:deposit(100) is invoked, Lua checks the instance table first. Failing to find deposit, it falls back to Account via __index.

Simulating Multiple Inheritance

To inherit from multiple base classes, __index cannot simply point to a single table. Instead, __index can be defined as a function that iteratively searches a list of parent classes in order.

The Class Factory

The following implementation creates a new class that accepts any number of base classes. It also caches resolved methods directly onto the derived class table to avoid redundant lookups on future method calls.

local function search(key, parents)
    for i = 1, #parents do
        local value = parents[i][key]
        if value ~= nil then
            return value
        end
    end
end

function createClass(...)
    local c = {}
    local parents = {...}

    -- Set the metatable with a dynamic lookup function
    setmetatable(c, {
        __index = function(table, key)
            local value = search(key, parents)
            if value ~= nil then
                table[key] = value -- Cache the result for faster future access
                return value
            end
        end
    })

    -- Ensure instances inherit from this new class
    c.__index = c

    function c:new(init)
        local instance = setmetatable(init or {}, c)
        return instance
    end

    return c
end

Usage Example

Consider two distinct traits: flying and swimming. A composite class can inherit behaviors from both base tables:

-- Define Base Class 1
local Flyer = {}
function Flyer:fly()
    print(self.name .. " is flying high.")
end

-- Define Base Class 2
local Swimmer = {}
function Swimmer:swim()
    print(self.name .. " is swimming in the water.")
end

-- Create Derived Class inheriting from both
local Duck = createClass(Flyer, Swimmer)

function Duck:new(name)
    local instance = setmetatable({ name = name }, self)
    return instance
end

-- Instantiate and execute
local donald = Duck:new("Donald")
donald:fly()   -- Output: Donald is flying high.
donald:swim()  -- Output: Donald is swimming in the water.

The Mixin Alternative

An alternative to dynamic lookup functions is the mixin pattern (shallow copying). This approach copies all methods from parent tables into the child class table at definition time:

function mixin(target, ...)
    for _, source in ipairs({...}) do
        for key, value in pairs(source) do
            if target[key] == nil then
                target[key] = value
            end
        end
    end
    return target
end

Dynamic Lookup vs. Mixins

  • Dynamic Lookup with Caching: Conserves memory initially and automatically reflects changes if a base class method is updated at runtime. Lookup performance is slightly slower on the first access, but optimal once cached.
  • Mixins: Simpler execution model and faster initial call times, but changes made to base classes after mixin application will not propagate to derived classes.

For complex hierarchies, the dynamic function with method caching provides the cleanest balance between memory usage, inheritance consistency, and performance.
