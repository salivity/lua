table.concat vs String Concatenation in Lua

This article explains why Lua's table.concat significantly outperforms the standard string concatenation operator (..) when joining large collections of strings. In Lua, strings are immutable and interned, meaning repeated concatenation inside loops leads to severe memory churn, excessive allocations, and quadratic time complexity. By gathering substrings into an array and combining them via table.concat, developers leverage a single C-level memory allocation that processes the entire operation in linear time.

The Problem with the .. Operator

In Lua, strings are immutable values. Once a string is created, its contents cannot be modified in place. When you use the concatenation operator (..) in a loop to build a larger string, Lua cannot simply append new bytes to the existing buffer:

local result = ""
for i = 1, 100000 do
    result = result .. "a"
end

In every iteration of this loop, Lua must:

  1. Allocate memory for a brand-new string large enough to hold both the accumulator (result) and the appended fragment.
  2. Copy the contents of both strings into the new memory block.
  3. Hash and intern the newly created string.
  4. Mark the previous intermediate string as garbage to be collected later.

Because the length of result grows on every cycle, the number of bytes copied increases incrementally: 1, 2, 3, ..., up to \(N\). This pattern causes the cumulative work to scale quadratically, resulting in an algorithmic time complexity of \(O(N^2)\). As the number of strings grows into the tens or hundreds of thousands, this creates an enormous amount of intermediate string garbage, forcing the Lua garbage collector to run frequently and degrading application throughput.

How table.concat Solves the Bottleneck

The table.concat function circumvents intermediate string creation by delegating the entire operation to the underlying C implementation (luaB_concat in the Lua standard library). Instead of continually allocating and discarding strings, you append fragments to a sequential table and join them all at once:

local buffer = {}
for i = 1, 100000 do
    buffer[i] = "a"
end
local result = table.concat(buffer)

This approach is dramatically faster due to how the function manages memory internally:

  • Single Pre-Calculated Allocation: table.concat inspects the array to calculate the total length of all elements combined (plus any optional delimiters). It then allocates a single memory buffer of the exact size required for the final string.
  • Direct Sequential Copying: Using efficient C-level memory copying routines (memcpy), Lua copies each table entry directly into its respective offset within the destination buffer. No intermediate Lua string objects are generated during this traversal.
  • Linear Time Complexity: Because each byte from each substring is read and copied only once into the final buffer, the operation completes in \(O(N)\) linear time, where \(N\) is the total length of the final output.
  • Minimal Garbage Collection Overhead: Since no temporary strings are instantiated, the garbage collector remains idle throughout the concatenation phase, saving CPU cycles and preventing latency spikes.

Performance Summary

Using the .. operator is suitable for joining a fixed, small number of strings (such as first_name .. " " .. last_name), where the engine can optimize multiple concatenations in a single statement. However, for dynamic lists, loops, file parsers, or serialization tasks, table.concat is the standard and necessary idiom in Lua to maintain high performance and low memory consumption.
