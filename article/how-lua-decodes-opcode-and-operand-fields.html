How Lua Decodes Opcode and Operand Fields

This article provides an overview of how the Lua virtual machine decodes its bytecode instructions. In Lua, every compiled virtual machine instruction is packed into a fixed 32-bit integer. The instruction decoder unpacks these 32-bit words into operational codes (opcodes) and operational arguments (operands) at runtime by applying predefined bit-masking and bit-shifting macros defined in the Lua core engine.

The 32-Bit Instruction Layout

Lua utilizes a register-based virtual machine. To optimize performance and memory footprint, every instruction is stored as an unsigned 32-bit integer (Instruction, defined as a uint32_t in standard C).

Depending on the instruction format, these 32 bits are divided into distinct segments. Across standard modern Lua versions (such as Lua 5.3 and 5.4), instructions follow several primary formats:

  • iABC: Uses fields for an opcode, operand A, operand B, operand C, and sometimes a 1-bit flag (k in Lua 5.4).
  • iABx: Uses fields for an opcode, operand A, and an unsigned 18-bit combined operand Bx.
  • iAsBx: Uses fields for an opcode, operand A, and a signed 18-bit combined operand sBx (typically used for relative jump offsets).
  • iAx: Uses an opcode and a single large 26-bit operand Ax for operations that require larger immediate references.

Bit Positions and Sizes

In Lua's source code (primarily located in lopcodes.h), the structure of an instruction is defined by field sizes and bit positions.

For example, in Lua 5.3:

  • Opcode: 6 bits (bits 0 to 5)
  • Field A: 8 bits (bits 6 to 13)
  • Field C: 9 bits (bits 14 to 22)
  • Field B: 9 bits (bits 23 to 31)
  • Field Bx: 18 bits (combines fields C and B, bits 14 to 31)

In Lua 5.4, the layout was adjusted to accommodate an extra 1-bit operand flag (k) and a 7-bit opcode, changing the exact widths, but the underlying decoding principles remain identical.

Extraction via Bitwise Shifting and Masking

The instruction decoder extracts fields without performance overhead by using preprocessor macros that leverage two primary bitwise operations: right shifting (>>) and bitwise AND (&).

To extract an arbitrary field, the decoder performs two steps:

  1. Shift Right: Shift the 32-bit instruction to the right by the field's starting bit position, bringing the least significant bit of the target field to bit position 0.
  2. Mask: Apply a bitwise AND with a bitmask corresponding to the width of the field, clearing any higher-order bits.

A utility mask generator is typically constructed using:

#define MASK1(n,p)   ((~((~(Instruction)0)<<(n)))<<(p))
#define MASK0(n,p)   (~MASK1(n,p))

To extract values, Lua defines accessor macros such as:

#define GET_OPCODE(i)   (cast(OpCode, ((i) >> POS_OP) & MASK1(SIZE_OP, 0))))
#define GETARG_A(i)     (cast_int(((i) >> POS_A) & MASK1(SIZE_A, 0)))
#define GETARG_B(i)     (cast_int(((i) >> POS_B) & MASK1(SIZE_B, 0)))
#define GETARG_C(i)     (cast_int(((i) >> POS_C) & MASK1(SIZE_C, 0)))
#define GETARG_Bx(i)    (cast_int(((i) >> POS_Bx) & MASK1(SIZE_Bx, 0)))

When fetching the opcode, GET_OPCODE(i) shifts the instruction by POS_OP (which is 0) and masks the value to ensure only the lower 6 or 7 bits are preserved, casting the result directly to the internal OpCode enumeration.

Decoding Signed Operands

Signed operands like sBx are primarily used for relative jumps where an instruction pointer needs to move forward or backward. Because raw bit manipulation extracts an unsigned integer, the signed value cannot simply be masked directly.

Lua handles this through excess-K (biased) representation rather than two's complement within the bitfield. The unsigned field Bx has a bias subtracted from it:

#define OFFSET_sBx      (MAXARG_Bx >> 1)
#define GETARG_sBx(i)   (GETARG_Bx(i) - OFFSET_sBx)

By subtracting half the maximum value of Bx, the unsigned value is mapped back to a centered range containing both negative and positive integers.

Execution in the Virtual Machine Loop

The actual extraction occurs inside Lua's core execution loop in lvm.c (inside the luaV_execute function):

  1. Fetch: The engine reads the instruction pointed to by the virtual program counter: Instruction i = *pc++;.
  2. Opcode Extraction: The engine evaluates GET_OPCODE(i).
  3. Dispatch: A large C switch statement receives the extracted opcode.
  4. Operand Extraction: Within individual switch cases, macros like GETARG_A(i), GETARG_B(i), or GETARG_C(i) are invoked inline to retrieve register indices, constants table indexes, or jump offsets.

By structuring decoding into inline bitwise macros, Lua extracts operational parameters directly in CPU registers without memory allocation or parsing overhead.
