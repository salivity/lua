Safe Mutual Recursion Without Stack Growth in Lua

In Lua, mutual recursion can run indefinitely without growing the call stack or triggering an "out of memory / stack overflow" error by relying on proper tail calls. This article explains the mechanics of Lua’s tail-call elimination, outlines the strict syntax rules required to maintain calls in the tail position, highlights common traps that invalidate optimization, and provides a working code implementation of safe, infinite mutual recursion.

Understanding Proper Tail Calls in Lua

Lua implements proper tail calls (tail-call elimination). When a function's final action is calling another function and returning that function's results directly, Lua does not allocate a new stack frame. Instead, the runtime reuses the current function's activation record (stack frame).

Because the stack does not grow with each consecutive tail call, two or more functions can alternate execution (mutual recursion) endlessly with \(O(1)\) memory usage.

The Syntax Rule for Tail Calls

To qualify as a proper tail call, the function invocation must match a specific syntax pattern:

return function_name(arguments)

If any operation occurs after the function returns, or if the return value is modified, the call is not in the tail position, and Lua is forced to allocate a new stack frame.

Examples That Break Tail Calls

  • Arithmetic/Modification: return func() + 1 (Addition must wait for the call to finish).
  • Missing Return: func(); return (The call finishes before the return statement executes).
  • Parentheses enclosing the call: return (func()) (Forces Lua to truncate the results to a single value, performing an operation after the call).
  • Variable Assignment: local res = func(); return res (Only some optimizers handle this, standard Lua requires direct return).

Implementing Safe Mutual Recursion

In Lua, local variables are lexically scoped. When two local functions call each other, at least one must be declared prior to its definition so the other can reference it.

Here is a safe, infinite mutual recursion pattern:

-- Step 1: Forward-declare local functions
local state_a, state_b

-- Step 2: Define function A with a proper tail call to B
state_a = function(count)
    if count % 1000000 == 0 then
        print("State A at step: " .. count)
    end
    -- Proper tail call: reuses current stack frame
    return state_b(count + 1)
end

-- Step 3: Define function B with a proper tail call to A
state_b = function(count)
    -- Proper tail call: reuses current stack frame
    return state_a(count + 1)
end

-- Step 4: Initiate the recursive loop
state_a(1)

Critical Considerations

  1. Local Forward Declaration: Omitting local state_a, state_b at the top causes function definitions to treat the missing reference as a global variable. While this still optimizes stack frames, global lookups add performance overhead and risk namespace pollution.
  2. Debug Hooks: Active debugging hooks (such as line hooks via debug.sethook) may alter how tail calls are tracked in debug stack traces, though the underlying interpreter still reuses the stack frame during normal execution.
  3. Pcall and Tail Calls: Calling a function via pcall or xpcall cannot be optimized as a tail call across the protected boundary, as the interpreter must keep the protected handler frame on the stack.
