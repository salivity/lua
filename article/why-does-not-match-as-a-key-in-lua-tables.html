Why {} Does Not Match as a Key in Lua Tables

In the Lua programming language, tables are compared by reference rather than by value or structure. When using table constructors like {} as keys in a lookup table, Lua assigns each instance a unique memory address rather than evaluating its empty contents. Consequently, two visually identical empty tables are treated as completely distinct entities, meaning retrieving a value using a newly constructed {} will fail to match a previously stored {} key and will return nil.

Reference Identity vs. Value Identity

Lua distinguishes between primitive value types and reference types:

  • Value Types: Types such as numbers, booleans, and strings are compared by value. If you use the number 42 or the string "key" twice, both instances point to the exact same value conceptually, and strings are interned by the Lua runtime.
  • Reference Types: Tables, functions, threads, and userdata are compared strictly by identity (their pointer address in memory).

Two tables are considered equal if and only if they refer to the exact same table in memory.

How the Table Constructor {} Works

Every time the {} constructor executes, the Lua virtual machine allocates a new block of memory for that table.

Consider the following operation:

local lookup = {}

lookup[{}] = "Found"
print(lookup[{}]) -- Output: nil

In this snippet:

  1. lookup[{}] = "Found" evaluates the expression {} on the left side, allocates Table A in memory, and maps Table A to "Found".
  2. lookup[{}] inside the print statement evaluates a completely separate constructor, allocating Table B in memory.
  3. Lua checks lookup for the presence of Table B. Because Table B has a different memory address than Table A, the lookup fails, returning nil.

You can observe this directly using the equality operator:

print({} == {}) -- Output: false

Retrieving Values with Table Keys

To use a table as a key and successfully retrieve its corresponding value later, you must retain a variable reference to the specific table instance that was inserted:

local lookup = {}
local myKey = {}

lookup[myKey] = "Found"
print(lookup[myKey]) -- Output: "Found"

Because myKey holds a reference to a single memory address, passing myKey during both the assignment and the retrieval refers to the exact same table.

Metatables Do Not Change Table Hashing

A common misconception is that the __eq metamethod can make two distinct tables match as keys in a lookup table. While __eq customizes behavior for the equality operator (==), Lua's internal table implementation relies on the memory address directly to hash and find reference-type keys. Custom equality methods will not alter how standard table indexing locates keys.

If value-based or structural table lookups are required, tables must first be serialized (for example, into a string representation) or indexed using a custom retrieval function rather than Lua's native indexing operator.
