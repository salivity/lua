Escape Sequences in Lua Strings

In the Lua programming language, double-quoted and single-quoted string literals follow the exact same escaping rules, allowing developers to embed control characters, byte values, and quotation marks directly into text. This article provides a comprehensive overview of all valid escape sequences recognized by Lua, covering standard C-style control characters, decimal and hexadecimal byte definitions, whitespace formatters, and modern Unicode code points.

Standard Control Sequences

Lua inherits most of its basic escape sequences from standard C. When enclosed in double quotes, these characters perform specific formatting actions:

  • \a — Bell: Produces an audible or visual alert signal.
  • \b — Backspace: Moves the cursor back one space.
  • \f — Form Feed: Moves to the next page or logical section.
  • \n — Newline: Moves the cursor to the beginning of the next line.
  • \r — Carriage Return: Returns the cursor to the beginning of the current line.
  • \t — Horizontal Tab: Advances to the next horizontal tab stop.
  • \v — Vertical Tab: Advances to the next vertical tab stop.

Literal and Quotation Escapes

Certain characters must be escaped inside double-quoted strings to prevent syntax errors or ambiguity:

  • \" — Double Quote: Allows the inclusion of a literal double quote inside double-quoted literals (e.g., "He said, \"Hello!\"").
  • \' — Single Quote: Represents a literal single quote. While unnecessary inside double-quoted strings, it remains syntactically valid.
  • \\ — Backslash: Escapes the backslash itself to produce a single literal \.

Numeric Byte Escapes

Lua allows arbitrary binary bytes to be inserted into strings using numerical representations.

  • \ddd — Decimal Escape: Matches up to three decimal digits (0 to 255), representing a raw byte value. For example, \0 represents the null byte, and \065 represents the uppercase letter A. If followed immediately by other digits, the sequence must contain three digits (e.g., \0495 creates the character for byte 49 followed by the digit 5).
  • \xhh — Hexadecimal Escape (Lua 5.2+): Represents a raw byte using exactly two hexadecimal digits (e.g., \x41 evaluates to A, and \xFF represents byte 255).

Unicode Code Points

  • \u{XXX} — UTF-8 Escape (Lua 5.3+): Encodes a Unicode character into its corresponding UTF-8 byte sequence. The sequence inside the curly braces consists of one or more hexadecimal digits specifying the code point (e.g., \u{20AC} outputs the Euro sign €, and \u{1F600} outputs the grinning face emoji).

Whitespace and Line Control

Lua provides mechanisms to format long multiline strings cleanly without introducing unwanted characters:

  • \z — Span-Skipping Escape (Lua 5.2+): Skips the following sequence of whitespace characters, including line breaks. This allows developers to break a long string literal across multiple lines in the source code without introducing newlines or indentation into the final string value.
  • \<newline> — Escaped Newline: Placing a backslash immediately before a physical line break inserts a regular newline character into the string while continuing the literal on the next line.
