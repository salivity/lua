How to Tune Lua GC Pause and Step Multipliers

This article provides a concise guide on optimizing the incremental garbage collector (GC) in the Lua programming language. By manipulating the garbage collector's pause and step multiplier settings using the built-in collectgarbage function, developers can reduce latency spikes, prevent out-of-memory errors, and balance memory footprint against CPU consumption.

Understanding the Key Parameters

Lua's incremental garbage collector relies on two primary tuning parameters:

  1. GC Pause (pause): Controls the amount of time the collector waits before beginning a new garbage collection cycle after the previous one finishes. The value represents a percentage of the total memory in use.
    • A value of 100 means the collector restarts as soon as memory usage matches the amount left after the last cycle.
    • A value of 200 means the collector waits until total memory usage doubles before initiating a new cycle.
    • Values smaller than 100 cause the collector to start immediately without waiting.
  2. Step Multiplier (stepmul): Controls how aggressively the collector runs relative to memory allocation. It determines how many collection steps occur for each unit of allocated memory.
    • A value of 100 makes the collector work at the same rate as program allocations.
    • Values greater than 200 force the collector to run much faster than the allocation rate, clearing objects quickly.
    • A value that is too low may cause the collector to fall behind memory allocation, leading to unbounded memory growth.

Configuring Settings via collectgarbage

The syntax for adjusting these parameters depends on the version of Lua being used.

Lua 5.1, 5.2, 5.3, and LuaJIT

In earlier versions and LuaJIT, parameters are updated using individual "setpause" and "setstepmul" options:

-- Set the pause to 150% (collector waits for memory to grow by 50%)
collectgarbage("setpause", 150)

-- Set the step multiplier to 250% (collector works 2.5x faster than allocation)
collectgarbage("setstepmul", 250)

Both options return the previous parameter value, allowing you to temporarily modify and later restore the collector's state.

Lua 5.4 and Later

Lua 5.4 introduced a revised API for the incremental collector through the "incremental" command, allowing parameters to be configured in a single call:

-- Signature: collectgarbage("incremental", pause, stepmul, stepsize)
-- Passing 0 keeps the current value for that parameter.

-- Set pause to 150, step multiplier to 250, and step size to default (0)
collectgarbage("incremental", 150, 250, 0)

Tuning Strategies for Common Scenarios

1. Real-Time and Latency-Sensitive Applications (e.g., Games)

In real-time loops, garbage collection pauses can cause dropped frames. The goal is to keep the collector active in small, frequent increments rather than large bursts:

  • Lower the Pause (e.g., 105–120): Starts cycles sooner so garbage never accumulates significantly.
  • Increase the Step Multiplier (e.g., 200–300): Ensures the collector finishes cycles promptly, preventing unfinished cycles from spilling into critical processing windows.
-- Example for a game loop (Lua 5.1 / LuaJIT)
collectgarbage("setpause", 110)
collectgarbage("setstepmul", 300)

2. Memory-Constrained Systems

When RAM is limited, keeping heap size small takes priority over minimizing CPU overhead:

  • Set Pause to 100 or less: Forces continuous cycles so deallocated memory is reclaimed as soon as possible.
  • Set Step Multiplier high (e.g., 400+): Makes collection runs aggressive enough to reclaim objects faster than incoming allocations consume space.
-- Aggressive memory reclamation (Lua 5.4)
collectgarbage("incremental", 100, 400, 0)

3. Throughput-Oriented Batch Workloads

For non-interactive batch processing, minimizing CPU cycles spent on collection is more important than immediate memory reclamation:

  • Increase the Pause (e.g., 200–400): Delays collection until substantial garbage accumulates, reducing the frequency of garbage collection cycles.
  • Moderate Step Multiplier (e.g., 150–200): Collects memory steadily without halting batch execution threads excessively.
-- High throughput configuration (Lua 5.1 / LuaJIT)
collectgarbage("setpause", 300)
collectgarbage("setstepmul", 150)
