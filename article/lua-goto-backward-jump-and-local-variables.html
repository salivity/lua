Lua Goto Backward Jump and Local Variables

In the Lua programming language, using a goto statement to jump backward across a local variable declaration is completely valid and does not cause a compilation error. When a backward jump targets a label positioned before a local variable's declaration, the program exits the scope of that variable, destroying it, and then re-allocates and re-initializes a fresh instance of the variable when execution flows forward again.

Scope Rules: Jumping Forward vs. Jumping Backward

Lua enforces strict scoping rules regarding labels and jumps. A goto statement is strictly forbidden from jumping forward into the scope of a local variable that is not visible at the jump site. Doing so results in a compile-time error such as <goto> jumps into the scope of local.

However, jumping backward across a local variable allocation is legal because it does not jump into an active scope. Instead, it jumps out of the variable's current scope and returns to an earlier execution state where the variable does not yet exist.

Variable Lifecycle and Re-allocation

When a backward jump executes:

  1. Scope Exit: The current local variable immediately goes out of scope and becomes eligible for garbage collection once no other references exist.
  2. Re-allocation: As execution proceeds forward from the label, the local declaration is encountered anew.
  3. Re-initialization: Lua creates a distinct, brand-new storage slot for the variable and assigns any initial value provided in the statement.

Consider the following loop structure using goto:

local count = 0

::repeat_loop::
local message = "Attempt: " .. count
print(message)

count = count + 1
if count < 3 then
    goto repeat_loop
end

In every iteration, the jump sends execution back to ::repeat_loop::. The variable message from the prior iteration is discarded, and a new message variable is created on the next line.

Interaction with To-Be-Closed Variables (Lua 5.4)

In Lua 5.4 and later, local variables can be marked with the <close> attribute to run a __close metamethod automatically upon leaving scope.

When a goto jumps backward across a <close> variable declaration, Lua guarantees that the variable's __close metamethod executes immediately at the moment of the jump. After the jump completes and execution re-encounters the declaration, a fresh to-be-closed variable is created. This ensures resources such as file handles or custom locks are safely cleaned up even in manual control loops created with goto.
