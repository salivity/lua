Wasmoon: Running Lua in JavaScript Environments

Wasmoon is a high-performance WebAssembly-based Lua interpreter designed to embed and execute Lua code directly inside JavaScript environments like modern web browsers and Node.js. This article explores the architecture of Wasmoon, how it bridges the runtime gap between JavaScript and Lua, its key integration capabilities such as bidirectional data sharing and asynchronous execution, and practical considerations for using it in web applications.

What Is Wasmoon?

Wasmoon is an open-source library that compiles the official Lua 5.4 C runtime into WebAssembly (Wasm) using Emscripten. Traditionally, executing Lua within a JavaScript project required either running a backend server with a native Lua runtime or using a pure JavaScript interpreter, which often suffered from significant performance penalties and incomplete language compatibility.

By leveraging WebAssembly, Wasmoon provides native-like execution speed, near-total compliance with the standard Lua 5.4 specification, and safe sandbox isolation, all while running entirely on the client side or within a Node.js process.

Architecture and Execution Model

At its core, Wasmoon operates through a primary wrapper class known as LuaEngine. When initialized, it instantiates a WebAssembly module that encapsulates the Lua state, virtual machine, and standard libraries.

Developers can inject Lua code as plain strings or compiled bytecode. Wasmoon executes this code within the WebAssembly linear memory, isolated from the host JavaScript environment, while providing high-level abstraction layers that manage data translation and execution contexts.

Bidirectional Interoperability

The defining feature of Wasmoon is its seamless interop layer between the JavaScript engine (such as V8) and the Lua virtual machine:

  • Variable and Primitive Mapping: Standard types—including numbers, strings, and booleans—are automatically converted between JavaScript and Lua primitives.
  • Objects and Tables: JavaScript objects and arrays can be passed directly into Lua, where Wasmoon wraps them as Lua userdata or proxies. Similarly, Lua tables can be accessed or converted into native JavaScript objects.
  • Function Calling: JavaScript functions can be registered into the Lua global state, allowing Lua scripts to invoke browser APIs or custom JavaScript utilities directly. Conversely, Lua functions can be extracted and called inside JavaScript as standard callbacks.

Asynchronous Execution and Promises

JavaScript relies heavily on asynchronous programming through Promises and the event loop, whereas Lua handles concurrency primarily via coroutines. Wasmoon bridges this difference by allowing Lua scripts to interact with JavaScript Promises. When a Lua script calls an asynchronous JavaScript function, Wasmoon can automatically suspend the Lua thread until the Promise resolves, yielding control back to the script without blocking the main browser thread.

Security and Sandboxing

Because Wasmoon runs Lua strictly within a WebAssembly sandbox, scripts do not have arbitrary access to the operating system or the local filesystem unless the host JavaScript environment explicitly exposes those capabilities. Developers can control access by selectively injecting APIs into the Lua global environment, making Wasmoon an ideal engine for safely running untrusted user scripts, game modding code, or customizable business logic directly inside the browser.
