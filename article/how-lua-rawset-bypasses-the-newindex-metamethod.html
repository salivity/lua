How Lua rawset Bypasses the __newindex Metamethod

This article explains how the rawset function works in Lua to set table values directly while bypassing the __newindex metamethod. It covers the mechanics of standard table assignment, the role of the __newindex fallback, how rawset interfaces directly with table storage at the engine level, and why this behavior is essential for avoiding infinite recursion when creating custom object systems.

Standard Table Assignment and __newindex

In Lua, assigning a value to a table key typically follows the syntax table[key] = value. When this statement executes, the Lua virtual machine performs the following sequence:

  1. It checks whether key already exists with a non-nil value in table.
  2. If the key exists, Lua directly updates the value.
  3. If the key does not exist, Lua checks the table's metatable for the __newindex field.
  4. If __newindex is absent, Lua creates the key and assigns the value directly.
  5. If __newindex is defined, Lua diverts the assignment:
    • If __newindex is a function, Lua calls it with three arguments: __newindex(table, key, value).
    • If __newindex is another table, Lua repeats the assignment on that target table (other_table[key] = value).

Under standard operation, the key is never created in the original table if a __newindex metamethod is present.

How rawset Bypasses the Metatable

The rawset function provides direct access to Lua's internal table storage mechanism. Its signature is:

rawset(table, key, value)

Unlike normal assignment, rawset bypasses the entire metamethod lookup chain at the virtual machine level. When invoked, Lua does not inspect the table for a metatable, nor does it check for the existence of __newindex. Instead, it invokes the internal C API routine (such as lua_rawset or internal hash insertion functions like luaH_set) to place the key-value pair directly into the table's internal array or hash part.

This operation returns the modified table and guarantees that:

  • No metamethod functions are triggered.
  • No delegation to fallback tables occurs.
  • The key is explicitly created or updated within the target table itself.

Preventing Infinite Recursion

The primary use case for bypassing __newindex is defining custom assignment logic without causing a stack overflow. When implementing __newindex to intercept, validate, or log assignments, using standard assignment syntax (table[key] = value) inside the metamethod triggers __newindex again recursively.

local proxy = {}
local mt = {
    __newindex = function(t, k, v)
        print("Assigning: " .. tostring(k))
        -- Using t[k] = v here would cause infinite recursion
        rawset(t, k, v) -- Safely assigns the value directly
    end
}
setmetatable(proxy, mt)

proxy.score = 100 -- Prints "Assigning: score" and writes into proxy directly

Because rawset does not consult the metatable, the assignment completes successfully in a single step, breaking the recursion cycle.
