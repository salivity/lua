Why #{...} Fails With Trailing Nils in Lua

In the Lua programming language, using #{...} to determine the number of arguments passed via the vararg expression (...) fails when trailing nil values are present because Lua tables cannot store nil as a value, and the length operator (#) only measures table sequence boundaries. Packing varargs into a table using {...} discards information about any arguments evaluated as nil at the end of the list. Consequently, the length operator only counts up to the last non-nil value, making #{...} an inaccurate method for counting variadic function parameters.

How Lua Handles Nil in Tables

In Lua, nil represents the absence of a value. When an element in a table is set to nil, Lua does not store a placeholder; it deletes the key entirely from the table.

When you write {...}, Lua evaluates the variarg expression and assigns each argument to an integer key starting at index 1. For example, calling a function with myFunc("a", "b", nil) produces a table equivalent to:

local args = { [1] = "a", [2] = "b" }

Index 3 is never created. Because the table has no record that a third argument was ever provided, the trailing nil is entirely lost during table construction.

The Mechanics of the Length Operator (#)

The # operator in Lua is defined in terms of a "border." A border in a table t is any integer index n such that t[n] ~= nil and t[n + 1] == nil.

For a sequence without holes (an unbroken series of non-nil integer keys starting from 1), #t returns the sequence's actual length. However, when trailing nil values are passed, the final border encountered by the # operator is the last non-nil element. If you pass ("hello", nil, nil) into {...}, the resulting table contains only { [1] = "hello" }. The # operator encounters t[1] ~= nil and t[2] == nil, reporting a length of 1 rather than 3.

If intermediate nil values are passed (such as ("a", nil, "c")), the behavior is even less predictable. Because multiple borders exist, the length operator can return any index that satisfies the border condition, making # completely unreliable for tables containing nil entries.

How to Accurately Count Varargs

To reliably determine the number of arguments passed to a function—including intermediate and trailing nil values—you should avoid #{...} and use one of the standard alternatives:

  1. select('#', ...): The select function operates directly on the vararg tuple without instantiating an intermediate table. Calling select('#', ...) returns the exact count of arguments passed, preserving all nil values.

    local function countArgs(...)
    local count = select('#', ...)
    return count
end

print(countArgs(1, 2, nil, nil)) -- Output: 4

  2. table.pack(...): Introduced in Lua 5.2, table.pack collects all varargs into a table and explicitly records the total count in a special field named n.

    local function packArgs(...)
    local args = table.pack(...)
    return args.n
end

print(packArgs(1, 2, nil, nil)) -- Output: 4

By relying on select('#', ...) or table.pack(...), programs can capture the true argument count without suffering from the sequence-truncation behavior inherent to {...} and the # operator.
